## 현재 목적

Spell의 핵심 재미, 전투 구조, 회로 문법, 자동화 성장, 소환수 운용, 주문·회로 스톡과 직접 시전 마나 구조를 기획 단계에서 확정한다. 세부 밸런스 수치는 PoC와 데이터 설계 단계에서 조정한다.

## 현재 확정된 방향

### 플랫폼과 입력

1. Godot 기반 Android 모바일 게임
2. 터치로 마법 회로를 직접 작성
3. 회로 작성 중 전투 시간 감속
4. 회로 성공 판정은 널럴하고 부정확 패널티는 낮게 설정
5. 정확 입력에는 손맛·효율 중심의 추가 보상 제공

### 주문 발견과 회로 문법

6. 주문은 직접 실험해 발견한 뒤 마도서 설계도로 등록
7. 한 주문의 메인 회로는 정확히 하나
8. 초반 최소 문법은 `메인 + 형상·전달`
9. 이후 보조 회로를 단계적으로 해금
10. 중반에 조건·기동 회로 해금
11. 반복 회로 자동완성은 하위 회로 스톡이 전담
12. 속성·매질의 독립 계층 여부는 미확정

### 마나

13. 마나는 기본 자동 회복과 플레이 행동 보너스를 함께 사용
14. 마나 회복 회로와 마나 절감 회로 추가
15. 마나는 직접 회로 시전에만 적용
16. 스톡 준비·발동·적용·충전에는 마나를 사용하지 않음
17. 회복·절감 조합의 무한 마나 순환 금지

### 소환수

18. 기존 동료 개념을 소환수 같은 마법적 존재로 대체
19. 기본 소환수 1체를 전투 전에 미리 소환하고 전투 시작부터 전개
20. 고정 역할 타입 없이 능력치·적성·스탠스로 효율 결정
21. 소환수는 전투·수호와 지정 스톡 생산 지원 담당
22. 소환수의 회로 직접 작성·구간 분담·협동 작성은 `SUPERSEDED`
23. 소환수는 완성 주문·하위 회로 스톡의 생산량 또는 충전 속도를 높임
24. 소환수는 플레이어 허가 없이 충전 대상을 변경하지 않음
25. 추가 편성·교체·동시 전개 수는 미확정

### 자동화 성장과 스톡

26. 자동화는 직접 그리기를 제거하지 않고 새 문법에 집중하게 하는 성장 기능
27. 이미 학습·숙련했고 성장 기준 이하인 주문·회로만 스톡화 가능
28. 현재 성장 단계의 신규·상위 회로는 직접 입력 영역으로 유지
29. 조건부 자동발동은 폐기
30. 완성 주문 스톡은 저장된 주문 전체를 원터치로 기동
31. 하위 회로 스톡은 현재 주문에 회로 한 구간을 원터치 자동 배치·연결
32. 스톡이 없어도 직접 회로 시전 가능

### 공용 준비 용량

33. 두 종류의 스톡은 하나의 공용 준비 용량을 공유
34. 하위 회로 스톡 1개는 준비 용량 1 사용
35. 완성 주문 스톡 1개는 구성 기능 회로 수만큼 준비 용량 사용
36. 동일 주문·회로 반복 편성 허용
37. 주문별·회로별 별도 최대 보유량 없음
38. 플레이어 성장에 따라 전체 준비 용량 증가
39. 연결·분기·합류가 독립 회로로 계산되는지는 미확정
40. 기존 최대 마나 예약 규칙은 `SUPERSEDED`

### 스톡 충전

41. 플레이어가 자동 충전할 스톡 대상 1종을 지정
42. 다른 준비 대상은 동시에 충전되지 않음
43. 플레이어 능력치와 소환수 생산 능력치가 충전 효율에 기여
44. 직접 시전·정확 입력·방어·연계는 충전을 추가 가속
45. 기준 충전시간은 `1.0 + 0.5 × (기능 회로 수 - 1)`
46. 동일 대상의 빈 스톡은 1회분씩 순차 충전
47. `1.0단위`의 실제 초 환산값은 미확정

### 충전 대상 전환

48. 전투 중 다른 준비 스톡으로 충전 대상 변경 가능
49. 대상별 다음 스톡 1회분 충전 진행도 보존
50. 대상 변경 시 전환 지연 동안 모든 충전 정지
51. 전환 완료 후 새 대상의 저장 진행도부터 재개
52. 현재 대상이 최대치에 도달해도 자동으로 다른 대상으로 넘어가지 않음
53. 전환 지연 시간과 전환 중 재변경 규칙은 미확정

### 직접 피해 시 충전·전환 일시정지

54. 직접 피해가 발생해도 충전 진행도와 전환 게이지는 전부 보존
55. 최종 직접 피해가 0이면 충전·전환을 정지하지 않음
56. 정지시간은 0.25초 집계 구간의 직접 피해 체력 손실 비율로 결정
57. 손실 비율은 `r = 0.25초 직접 피해 손실 합계 / 집계 시작 시 최대 체력`
58. 정지시간은 `clamp(r × 3.0, 0.10초, 0.80초)`
59. 같은 총 직접 피해라면 단발·다단 공격은 같은 정지시간을 목표로 함
60. 정지 종료 후 별도 입력 없이 자동 재개
61. 고정 0.5초·1.0초 상한 규칙은 `SUPERSEDED`

### 지속 피해와 스톡 방해 상태이상

62. 화상·독·출혈 등 지속 피해 틱은 체력을 감소시키지만 스톡 충전·전환을 정지하지 않음
63. 지속 피해 틱은 직접 피해의 0.25초 집계에 포함하지 않음
64. 스톡 방해 상태는 `마력 교란`, `주문 봉인`, 상위 `마력 봉쇄`로 구분
65. `회로 혼선`과 상태이상 기반 충전 대상 전환 방해는 사용하지 않음

#### 마력 교란

66. 스톡 충전 속도만 감소
67. 기획 기본값은 충전 속도 `30% 감소`, 실제 충전 속도 `70%`
68. 동일한 마력 교란은 중첩하지 않음
69. 재적용 시 감속률을 높이지 않고 지속시간만 갱신
70. 충전 대상과 진행도는 유지
71. 완성된 스톡은 정상 사용 가능
72. 30%와 실제 지속시간은 PoC에서 조정 가능한 `PLANNING_DEFAULT`

#### 주문 봉인

73. 완성 주문 스톡과 하위 회로 스톡의 사용을 모두 차단
74. 직접 회로 작성과 마나를 사용하는 직접 시전은 가능
75. 자동 충전·플레이어 및 소환수 생산 기여·대상 전환은 정상 진행
76. 보유 스톡과 충전 진행도는 유지
77. 봉인 중 완성된 스톡도 한도까지 저장
78. 봉인 해제 후 별도 복구 입력 없이 즉시 사용 가능

#### 상위 마력 봉쇄

79. 완성 주문 스톡과 하위 회로 스톡 사용을 차단
80. 직접 회로 작성과 직접 시전도 차단
81. 희귀 적·엘리트 기믹·보스급 패턴에만 제한
82. 적용 전 명확한 사전 경고 필요
83. 회피·차단·해제·패턴 파훼 중 적어도 하나의 대응 수단 필요
84. 장시간 또는 높은 빈도의 반복 적용 금지
85. 충전 진행도와 보유 스톡은 삭제하지 않음
86. 종료 후 별도 복구 입력 없이 스톡·직접 시전 기능 즉시 복원
87. 마력 봉쇄 중 자동 충전과 회로 UI의 세부 처리는 추후 상태이상 설계로 연기
