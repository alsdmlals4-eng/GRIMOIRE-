# Spell Active Context

## 현재 상태

- 작업 모드: `PLAN`
- 기획 상태: `PLANNING_IN_PROGRESS`
- 프로젝트 코어 상태: `CORE_CANDIDATE`
- 구현 상태: 미착수
- 기준 브랜치: `gpt/planning-spell-20260725`
- 기준 날짜: 2026-07-26

## 현재 목적

사용자와 Grill Me 방식으로 Spell의 핵심 재미, 전투 구조, 회로 문법, 자동화 성장, 소환수 운용, 자동스펠 스톡과 마나 예약 구조를 확정한다.

## 현재 확정된 방향

### 플랫폼과 입력

1. Godot 기반 Android 모바일 게임
2. 터치로 마법 회로를 직접 작성
3. 회로 작성 중 전투 시간 감속
4. 판정 기준은 널널하고 부정확 패널티는 낮게 설정
5. 정확 입력에는 손맛 중심의 추가 보상 제공

### 주문 발견과 마나

6. 주문은 직접 실험해 발견한 뒤 마도서 설계도로 등록
7. 마나는 기본 자동 회복과 플레이 행동 보너스를 함께 사용
8. 마나 회복 회로와 마나 절감 회로 추가
9. 회복·절감 조합으로 무한 마나 순환 금지

### 회로 문법

10. 한 주문의 메인 회로는 정확히 하나
11. 메인 회로 결합 금지
12. 초반 최소 문법은 `메인 + 형상·전달`
13. 메인과 형상·전달은 직접 학습 후 자동화 가능
14. 이후 보조 회로를 단계적으로 해금
15. 중반에 조건·기동 회로 해금
16. 공격·방어·탐색·강화·절감 등의 개별 목록은 아직 예시
17. 속성·매질의 독립 계층 여부는 미확정

### 소환수

18. 기존 동료 개념을 소환수 같은 마법적 존재로 대체
19. 기존 능력치·스탠스·전환 제약 원칙은 소환수에게 승계
20. 소환수는 전투 보호, 회로 자동작성, 협동 시전, 자동스펠 준비를 담당
21. 소환수 역할 타입은 없고 능력치·적성·스탠스로 효율 결정
22. 숙련한 보조 회로는 소환수가 자동작성 가능
23. 마기카로기아의 원형처럼 술자의 이미지·마법이 제한된 전투 공간에 구현되는 방향을 참고하되 고유 용어와 카테고리는 복제하지 않음
24. 기본 소환수 1체를 전투 전에 미리 소환하고 전투 시작부터 전개
25. 기본 1체를 위해 매 전투마다 동일한 소환 입력을 반복하지 않음
26. 추가 편성·교체·동시 전개 수와 소환 용량 공식은 미확정

### 자동화와 자동스펠

27. 자동화는 직접 그리기를 제거하지 않고 새 문법에 집중하게 하는 성장 기능
28. 자동화는 `기초 회로 자동화 → 소환수 자동작성 → 완성 주문 자동스펠`의 3단계
29. 자동스펠은 등록·숙련된 설계도만 사용 가능
30. 직접 시전은 신규 발견, 즉석 변형, 정확 입력 보상을 담당
31. 자동스펠은 원터치와 조건부 자동발동을 함께 사용하는 혼합형
32. 자동스펠은 주문별로 준비한 스톡을 소비
33. 원터치·조건부 발동 모두 해당 주문 스톡 1개 소비
34. 같은 주문에 여러 스톡을 배정하거나 여러 주문에 분산 가능
35. 플레이어 성장에 따라 전체 스톡 준비 한도 증가
36. 스톡이 없어도 직접 회로 시전은 가능

### 스톡 마나 예약과 충전

37. 스톡은 공용 게이지가 아니라 미리 지정한 자동스펠의 사용량
38. 플레이어는 충전할 자동스펠을 지정할 수 있음
39. 스톡 한 칸은 해당 주문의 기존 마나 비용 50%를 최대 마나에서 예약
40. 스톡 편성 중 예약 마나는 잠기며 실전 사용 가능 최대 마나가 감소
41. 빈 스톡도 예약량은 유지되고 해당 용량을 기반으로 재충전
42. 자동스펠 발동 시 동일 비용을 다시 전액 내는 이중 비용은 적용하지 않는 현행 설계
43. 전투 중 지정 주문의 빈 스톡은 자동으로 충전
44. 자동 충전 속도는 플레이어와 소환수 능력치에 비례
45. 직접 시전·정확 입력·방어·연계·소환수 지원은 충전을 추가 가속
46. 이전의 `시간 경과만으로는 스톡이 충전되지 않는다`는 규칙은 `SUPERSEDED`
47. 자동 충전과 조건부 발동이 무한 순환하지 않게 함
48. 동시 충전 주문 수와 대상 변경 규칙은 미확정

## 참고 결론 — 마기카로기아

- 제한된 전투 영역에 소환 존재가 구현되는 구조를 참고
- 술자의 이미지가 마법적 존재로 구체화될 수 있다는 정체성을 참고
- 소환 존재가 특정 영역의 주문 사용을 보조하는 구조를 회로 적성과 자동작성 효율로 변형
- 술자의 역량에 따라 소환 수가 제한되는 구조를 소환 용량 후보로 변형
- TRPG 판정, 원형 카테고리, 고유 명칭은 직접 사용하지 않음
