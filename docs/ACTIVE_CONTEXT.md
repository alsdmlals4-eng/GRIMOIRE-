## 현재 확정된 방향

### 플랫폼과 입력

1. Godot 기반 Android 모바일 게임
2. 터치로 마법 글자와 회로를 직접 작성
3. 회로 작성 중 전투 시간 감속
4. 성공 판정은 널럴하고 부정확 패널티는 낮음
5. 정확 입력에는 손맛·효율 중심 보상 제공

### 마법 글자·회로·주문

6. `마법 글자`는 마법적 의미를 가진 최소 기능 단위
7. `회로`는 글자의 위치·연결·적용 순서를 구성한 문법
8. `주문`은 메인 글자 1개와 보조 글자 0개 이상으로 완성한 마법 문장
9. 한 주문의 메인 글자는 정확히 하나
10. 메인 글자 하나만 정확히 작성해도 기본 주문 성립
11. 각 메인 글자는 고유한 기본 발현을 가짐
12. 형상·전달은 주문 성립 필수가 아니라 보조 글자의 하위 역할
13. 기존 `메인+형상·전달 필수` 규칙은 `SUPERSEDED_BY_GM-CIRCUIT-01`
14. 복수 메인 글자 결합 금지
15. 보조 글자는 형상·전달·출력·규모·시간·행동·효율·안정·조건·순서를 담당
16. 다수 보조 글자는 주문의 총 기능·출력·정밀도·범위를 확대할 수 있음
17. 글자 수가 늘면 작성 시간·마나 부담·준비 용량·충전시간도 증가
18. 강력함은 피해량뿐 아니라 범위·지속·행동·효율·안정·비전투 활용을 포함
19. 보조 글자를 가능한 만큼 붙이는 방식만 정답이 되지 않게 목적과 비용 차이를 유지
20. 주문은 직접 실험·현장 활용 성공 후 마도서 설계도로 등록
21. 속성·현상·기능을 메인 글자 계열로 나누는 최종 방식은 미확정

### 글자 학습과 자동화

22. 처음 배우는 메인·보조 글자는 직접 작성
23. 수업에서 메인 글자 단독 발동과 관련 보조 글자 조합을 학습
24. 현장에서 유효한 조합을 성공해야 완성 주문으로 등록
25. 반복 사용으로 숙련된 낮은 단계 글자만 하위 회로 스톡 후보
26. 완성된 등록 주문은 완성 주문 스톡 후보
27. 자동화는 반복 글자를 줄이고 새 글자·상위 조합에 집중하게 하는 성장 기능
28. 하위 회로 스톡은 숙련 글자 하나를 원터치 자동 배치·연결
29. 스톡은 삽입 위치와 예상 연결을 표시하고 최종 설계·기동은 플레이어가 담당
30. 조건부 자동발동은 사용하지 않음

### 마나

31. 마나는 자동 회복과 플레이 행동 보너스를 함께 사용
32. 마나 회복·절감 보조 글자 후보 존재
33. 마나는 직접 회로 시전에만 적용
34. 스톡 준비·충전·발동에는 마나를 사용하지 않음
35. 회복·절감 조합의 무한 마나 순환 금지
36. 마나 비용의 글자 수·종류별 계산은 미확정

### 소환수

37. 기본 소환수 1체를 전투 전에 미리 전개
38. 고정 역할 클래스 없이 능력치·적성·스탠스로 효율 결정
39. 소환수는 전투·수호·지정 스톡 생산 지원 담당
40. 소환수의 글자 직접 작성·협동 작성은 `SUPERSEDED`
41. 소환수는 플레이어 허가 없이 충전 대상을 변경하지 않음
42. 추가 편성·교체·동시 전개 수는 미확정

### 스톡 준비 용량과 충전

43. 완성 주문 스톡과 하위 글자 스톡은 공용 준비 용량 공유
44. 하위 글자 스톡 1개는 기능 글자 1개이므로 용량 1
45. 완성 주문 스톡 비용은 메인+보조의 기능 글자 총수
46. 메인 단독 기본 주문은 1글자·용량 1
47. 동일 주문·글자 반복 편성 허용
48. 주문·글자별 별도 최대 보유량 없음
49. 최대 마나 예약 규칙은 `SUPERSEDED`
50. 기준 충전시간은 `1.0 + 0.5 × (기능 글자 수 - 1)`
51. 메인 단독 1글자 주문의 기준 충전시간은 1.0단위
52. 자동 충전 대상은 한 번에 1종
53. 동일 대상의 빈 스톡은 1회분씩 순차 충전
54. 플레이어 능력치와 소환수 생산 능력치가 충전 효율에 기여
55. 직접 시전·정확 입력·방어·연계가 충전을 추가 가속
56. 실제 초 환산값과 생산 계산식은 미확정

### 충전 대상 전환과 피격

57. 전투 중 다른 준비 스톡으로 충전 대상 변경 가능
58. 대상별 다음 1회분 진행도 보존
59. 전환 시 짧은 지연 동안 모든 충전 정지
60. 새 대상은 저장 진행도부터 재개
61. 현재 대상이 최대치여도 자동 전환하지 않음
62. 전환 중 재선택 규칙과 실제 지연은 미확정
63. 직접 피해 발생 시 충전·전환 진행도 보존
64. 최종 직접 피해가 0이면 정지 없음
65. 직접 피해 정지 공식:

```text
r = 0.25초 직접 피해 손실 합계 / 집계 시작 시 최대 체력
정지시간 = clamp(r × 3.0, 0.10초, 0.80초)
```

66. 지속 피해 틱은 충전·전환을 정지하지 않음
67. 상태이상으로 진행도나 보유 스톡을 삭제하지 않음
68. 마력 교란은 충전 감속, 주문 봉인은 스톡 사용 차단, 마력 봉쇄는 스톡·직접 시전 차단
69. 상태이상 세부 데이터는 `DEFERRED_STATUS_DESIGN`

### 마법학교 세계관

70. 세계관 기본 틀은 `마법학교 + 현장실습 + 성장 모험`
71. 학교는 수업·교류·준비·연구·육성의 생활 허브
72. 실제 주문 발견과 활용 검증은 현장실습에서 주로 발생
73. 비밀학과·학교 음모를 필수 중심축으로 사용하지 않음
74. 신규 콘텐츠는 새로운 비밀 체계보다 기존 마법 글자의 활용 확장으로 추가
75. 현장 문제는 전투뿐 아니라 구조·봉인·복구·조사·환경 조작을 포함
76. 학교 운영·건설 경영은 현재 코어가 아님

### 3년제·6학기·장기 일정

77. 정규 교육 기간은 3년, 학년당 2학기, 총 6학기
78. 한 학기는 자유 일정 10회와 고정 사건 4회, 총 14구간
79. 기본 순서는 `자유3 → 초반 사건 → 자유2 → 중간 실습 → 자유3 → 핵심 사건 → 자유2 → 시험·평가`
80. 전체 자유 일정은 총 60회
81. 전투·대화·개별 활동의 미시 템포는 빠르게 유지
82. 학교생활·관계·숙련의 거시 템포는 충분히 길게 유지
83. DDD는 학기를 압축하는 원칙이 아니라 각 행동의 결과·보상을 빠르게 제공하는 원칙
84. 짧은 대화·탐색·기록 열람은 자유 일정 소모 없음
85. 반복 활동은 글자 숙련·관계·교수 과제·실습 준비로 누적 변화
86. 60회 자유 일정을 모두 고유 컷신으로 제작하지 않고 활동 템플릿을 변주

### 메인 글자 계열 수업

87. 학교 수업은 메인 글자 계열을 기준으로 분류
88. 공통 문법 과목은 글자 획·연결·안전·형상·전달·안정화 등 보편 문법 담당
89. 계열 과목은 현상 원리·메인 글자·기본 발현·계열 대표 보조 글자·활용·위험을 함께 교육
90. 응용 실습에서는 다른 계열에서 배운 보조 글자를 교차 활용 가능
91. 수업은 완성 주문을 자동 지급하지 않음
92. 기본 학습 단계는 `관찰 → 모사 → 메인 단독 발동 → 보조 조합 → 현장 활용 → 등록 → 숙련 → 스톡화`
93. 1학년은 여러 기초 계열을 넓게 경험하고 조기 영구 전문화를 피함
94. 2학년은 계열 선택·전문화·복합 보조 문법을 확대
95. 3학년은 독립 연구·다수 보조 글자·졸업 주문 설계를 담당
96. 메인 글자 계열의 최종 분류는 미확정

### 현장실습 자율성

97. 1학년은 학교 지정 실습 중심
98. 학교가 지역·목표·감독자·기본 팀을 정하지만 해결법은 플레이어가 선택
99. 2학년은 필수 지정 실습과 선택형 실습을 병행
100. 수강 계열·관계·연구 성향이 선택 실습 후보와 해결 선택지에 영향
101. 3학년은 학생이 주제·지역·팀·접근법을 제안
102. 학교는 위험 등급·안전 기준·감독을 승인
103. 3학년 제안형은 완전 자유 생성이 아니라 준비된 후보와 성장 데이터의 조합
104. 선택 실습을 하지 않아도 메인 진행은 영구 차단되지 않음
105. 실패는 보충 수업·재실습·복구 임무·관계 변화로 연결하며 즉시 게임오버로 처리하지 않음

### 주인공·관계·서사

106. 주인공은 일반 가정 출신 장학생 정식 신입생
107. 명문 혈통·왕족·환생 지식·만능 천재 설정을 코어로 사용하지 않음
108. 전문성과 정체성은 수업·관계·현장실습·글자 조합 선택으로 형성
109. 관계는 단순 호감도보다 정보·동행·연구·실습·해결 경로를 개방
110. 스토리는 필수 핵심층과 선택형 상세층으로 분리
111. 일반 사건은 짧은 대사+목표 카드, 긴급 임무는 경고+위험 카드
112. 감정·관계·승급·졸업 장면은 일반 대화창 사용
113. 자세한 내용은 NPC 재대화·질문 목록·조사·기록으로 제공
114. 선택 대화를 보지 않아도 메인 진행·기본 성장에 불이익 없음

- 미발견·미숙련 글자·주문의 스톡화 금지
- 소환수의 글자 직접 작성 재도입 금지
- 스톡에 마나 예약·발동 비용·개별 상한 추가 금지
- 수업을 완성 주문 구매 메뉴로 만들지 않음
- 수업만으로 주문 발견·등록·숙련 자동 완료 금지
- 학교를 튜토리얼 이후 버려지는 로비로 만들지 않음
- 학기를 3~4회 선택으로 압축하지 않음
- 60회 자유 일정을 모두 고유 컷신으로 제작하지 않음
- 3학년 제안형 실습을 무제한 자유 생성 시스템으로 만들지 않음
- 모든 실습을 전투 임무로 만들지 않음
- 선택 대화를 읽지 않았다는 이유로 핵심 정보를 놓치게 하지 않음

## GitHub 갱신 규칙

- 핵심 결정 변경 시 책임 원본·결정 원장·Active Context를 함께 갱신한다.

- 기획 PR은 Draft 상태로 유지한다.
- 구현 산출물을 기획 브랜치에 혼입하지 않는다.
