## 현재 목적

사용자와 Grill Me 방식으로 Spell의 핵심 재미, 전투 구조, 회로 문법, 자동화 성장, 소환수 운용, 주문·회로 스톡과 직접 시전 마나 구조를 확정한다.

## 현재 확정된 방향

### 플랫폼과 입력

1. Godot 기반 Android 모바일 게임
2. 터치로 마법 회로를 직접 작성
3. 회로 작성 중 전투 시간 감속
4. 판정 기준은 널럴하고 부정확 패널티는 낮게 설정
5. 정확 입력에는 손맛 중심의 추가 보상 제공

### 주문 발견과 마나

6. 주문은 직접 실험해 발견한 뒤 마도서 설계도로 등록
7. 마나는 기본 자동 회복과 플레이 행동 보너스를 함께 사용
8. 마나 회복 회로와 마나 절감 회로 추가
9. 마나는 직접 회로 시전에만 적용
10. 회복·절감 조합으로 무한 마나 순환 금지

### 회로 문법

11. 한 주문의 메인 회로는 정확히 하나
12. 메인 회로 결합 금지
13. 초반 최소 문법은 `메인 + 형상·전달`
14. 메인과 형상·전달은 직접 학습 후 하위 회로 스톡화 가능
15. 이후 보조 회로를 단계적으로 해금
16. 중반에 조건·기동 회로 해금
17. 공격·방어·탐색·강화·절감 등의 개별 목록은 아직 예시
18. 속성·매질의 독립 계층 여부는 미확정
19. 반복 회로 자동완성은 하위 회로 스톡이 전담

### 소환수

20. 기존 동료 개념을 소환수 같은 마법적 존재로 대체
21. 기본 소환수 1체를 전투 전에 미리 소환하고 전투 시작부터 전개
22. 기본 1체를 위해 매 전투마다 동일한 소환 입력을 반복하지 않음
23. 소환수 역할 타입은 없고 능력치·적성·스탠스로 효율 결정
24. 소환수는 전투·수호와 지정 스톡 생산 지원을 담당
25. 소환수의 회로 직접 작성, 구간 분담, 협동 작성은 `SUPERSEDED`
26. 소환수는 완성 주문·하위 회로 스톡의 생산량 또는 충전 속도를 높임
27. 소환수의 생산·동조·지속 능력치가 자동·능동 충전 효율에 영향을 줄 수 있음
28. 소환수는 플레이어 허가 없이 충전 대상을 변경하지 않음
29. 마기카로기아의 마법적 구현 존재와 주문 보조 방향을 참고하되 고유 용어와 분류는 복제하지 않음
30. 추가 편성·교체·동시 전개 수와 소환 용량 공식은 미확정

### 자동화 성장과 두 종류의 스톡

31. 자동화는 직접 그리기를 제거하지 않고 새 문법에 집중하게 하는 성장 기능
32. 플레이어 성장에 따라 자동화 가능한 주문·회로 단계가 상승
33. 일정 이하 단계이며 이미 학습·숙련한 주문과 회로만 스톡화 가능
34. 현재 성장 단계의 신규·상위 회로는 직접 입력 영역으로 유지
35. 신규 주문 발견, 즉석 변형, 상위 연결 판단, 정확 입력 보상은 직접 시전이 담당
36. 조건을 만족하면 주문이 임의로 발동하는 조건부 자동스펠은 폐기
37. 완성 주문 스톡은 저장된 주문 전체를 한 번의 터치로 기동
38. 하위 회로 스톡은 현재 주문에 저장된 회로 한 구간을 한 번의 터치로 자동 배치·연결
39. 완성 주문 스톡은 사용 시점·대상 판단을 플레이어가 담당
40. 하위 회로 스톡은 상위 회로·연결 방식·최종 기동을 플레이어가 담당
41. 같은 주문·회로에 여러 스톡을 배정하거나 여러 대상에 분산 가능
42. 스톡이 없어도 직접 회로 시전은 가능

### 스톡 준비 용량과 자원 제약

43. 완성 주문 스톡과 하위 회로 스톡은 하나의 공용 준비 용량을 공유
44. 준비 용량은 설계도에 포함된 기능 회로 개수를 기준으로 계산
45. 하위 회로 스톡 1개는 준비 용량 1 사용
46. 완성 주문 스톡 1개는 해당 주문을 구성하는 기능 회로 수만큼 준비 용량 사용
47. 고위 주문은 회로 수가 많아 별도 등급 가중치 없이 더 많은 용량 소비
48. 회로 개수는 선 길이·획수가 아니라 기능 회로 블록 기준
49. 플레이어 성장에 따라 전체 스톡 준비 용량 증가
50. 연결·분기·합류가 독립 회로로 계산되는지는 미확정
51. 스톡 제약은 회로 개수 기반 공용 준비 용량 하나만 사용
52. 주문별·회로별 별도 최대 보유량을 두지 않음
53. 동일 주문·회로 반복 편성은 총 준비 용량 안에서 허용
54. 완성 주문과 하위 회로 스톡 모두 최대 마나를 예약하지 않음
55. 스톡 준비 시 현재 마나를 선불로 소비하지 않음
56. 스톡 발동·적용·충전에 추가 마나 비용을 적용하지 않음
57. 기존 `완성 주문 비용 50% 최대 마나 예약` 규칙은 `SUPERSEDED`

### 스톡 충전

58. 플레이어가 자동 충전할 스톡 대상 1종을 지정
59. 지정한 주문 또는 회로의 빈 스톡만 전투 중 자동 충전
60. 다른 준비 대상은 동시에 자동 충전되지 않음
61. 자동 충전 속도는 플레이어 능력치와 소환수 생산 능력치에 비례
62. 직접 시전·정확 입력·방어·연계는 충전을 추가 가속
63. 소환수는 회로 작성 대신 자동 충전과 능동 충전 보너스를 강화
64. 이전의 `시간 경과만으로는 스톡이 충전되지 않는다`는 규칙은 `SUPERSEDED`
65. 스톡 1회분 기준 충전시간은 저장된 기능 회로 수에 따라 완만하게 증가
66. 공식은 `기준 충전시간(n) = 1.0 + 0.5 × (n - 1)`
67. 하위 회로 스톡은 1회로이므로 기준 충전시간 1.0단위
68. 완성 주문 스톡은 설계도에 포함된 기능 회로 수를 기준으로 계산
69. `1.0단위`는 실제 1시간이 아니라 PoC에서 초 단위로 환산할 상대 시간 단위
70. 동일 대상의 빈 스톡은 1회분씩 순차 충전
71. 플레이어·소환수 생산 능력치와 능동 행동 보너스는 기준 충전시간 이후 실제 충전시간에 적용

### 충전 대상 전환

72. 전투 중 현재 준비된 다른 주문·회로 스톡으로 충전 대상을 변경 가능
73. 기존 대상의 다음 스톡 1회분 충전 진행도는 대상별로 보존
74. 전환 요청 시 기존 대상 충전을 즉시 정지하고 진행도를 저장
75. 짧은 전환 지연 동안에는 어떤 대상도 충전되지 않음
76. 전환 완료 후 새 대상의 저장 진행도부터 충전 재개
77. 여러 준비 대상이 각자의 부분 충전 진행도를 보유할 수 있음
78. 부분 진행도 비축은 허용하지만 대상 변경마다 전환 지연을 지불
79. 자동 충전 대상은 계속 한 번에 1종만 유지
80. 소환수는 플레이어 허가 없이 전환 대상을 선택하지 않음
81. 현재 대상이 최대치에 도달해도 다른 대상으로 자동 전환하지 않음
82. 실제 전환 지연 시간과 전환 중 재변경 규칙은 미확정

### 실제 체력 피해 시 충전·전환 일시정지

83. 스톡 충전 중 플레이어 체력이 실제 감소하면 현재 충전 진행도를 전부 보존
84. 충전 대상 전환 중 플레이어 체력이 실제 감소하면 현재 전환 게이지 진행도를 전부 보존
85. 최종 체력 피해가 0이면 충전·전환을 정지하지 않음
86. 공격 접촉이나 피격 연출이 있어도 체력이 감소하지 않으면 정지하지 않음
87. 방어·보호막 적용 후 플레이어 체력이 1 이상 감소하면 피격 정지를 적용
88. 지속 피해와 환경 피해도 실제 체력을 감소시키면 정지 판정 대상
89. 피해량·공격 등급·최대 체력 대비 피해 비율과 관계없이 정지시간은 동일
90. 실제 체력 피해가 발생하면 충전 또는 전환을 0.5초 정지
91. 정지 중 추가 체력 피해가 발생하면 별도 시간을 합산하지 않고 남은 정지시간을 0.5초로 갱신
92. 갱신된 종료 시점은 `min(추가 피해 시점 + 0.5초, 첫 피해 시점 + 1.0초)`
93. 하나의 연속 피해 체인에서 첫 피해부터 최대 1.0초까지만 정지
94. 첫 피해와 추가 피해 모두에서 충전·전환 진행도는 전부 보존
95. 피격 정지 중 자동 충전, 플레이어·소환수 생산 기여와 능동 충전 보너스는 적용하지 않음
96. 이미 완성된 스톡은 피격 정지 중에도 정상 사용 가능
97. 정지 종료 후 별도 입력 없이 기존 진행 위치부터 자동 재개
98. 정지가 완전히 종료된 뒤 새 체력 피해가 발생하면 새로운 연속 피해 체인을 시작
99. 지속 피해 틱과 다단 공격을 몇 개의 피해 사건으로 묶을지는 미확정

- 핵심 결정 또는 기존 결정 변경 시 책임 원본·결정 원장·Active Context를 함께 갱신한다.
- 충돌하는 이전 결정은 삭제하지 않고 `SUPERSEDED`로 기록한다.
- 기획 PR은 Draft 상태로 유지한다.
- 구현 산출물을 기획 브랜치에 혼입하지 않는다.
