## 2. 학습 범위

```yaml
main_glyph: 열
connection_grammar: 흐름
optional_support_glyphs:
  - 집중
  - 분산
safe_grammar: 메인 1 + 연결 문법 + 선택 보조 0~1
```

- `열`: 열을 발생시키거나 기존 온기·온수·가열된 물체를 주문의 중심 현상으로 지정한다.
- `흐름`: 열이 향할 대상·경로·순서·순환을 구성한다.
- `집중`: 좁은 한 대상이나 경로에 열 전달을 모은다.
- `분산`: 여러 대상이나 넓은 구역에 열 전달을 나눈다.

직접 생성한 열만 사용해야 하는 것은 아니다. 환기구의 온기, 온수 관개, 가열된 배관 등 기존 열원을 선택해 이동시킬 수 있다. 물리적 밸브·격벽 조작, 동반 정령·소환수 행동과의 결합도 허용한다.

금지:

- 열이 냉기를 비용 없이 삭제한다.
- 환경 장치나 소환수 행동을 미학습 글자 효과로 위장한다.
- 교수 회로를 복사하면 자동으로 성공한다.
- 대표 패턴에 없다는 이유만으로 합리적인 해결법을 거부한다.

## 3. 해결 판정 계약

```yaml
solution_pattern:
  selected_approach: 해결 의도
  heat_source: 직접 생성 | 환기 온기 | 온수 관개 | 가열된 설비
  target: 열을 보낼 대상 또는 공간
  flow_path: 직접 | 순차 | 순환 | 우회 | 다중분기
  support: 없음 | 집중 | 분산
  helper: 없음 | 카시안 | 모트 | 수호 소환수 | 수동 장치
  prerequisite_clue: 조사한 사실
  primary_effect: 직접 변화
  main_cost: 남는 위험·손실·시간·관계 변화
```

유효 해결 조건:

1. 배운 글자의 의미로 설명 가능하다.
2. 출발점·목표·경로가 실제 환경과 연결된다.
3. 사건 위협 중 하나 이상을 제거·완화·봉쇄한다.
4. 남는 문제와 대가가 기록된다.
5. 교수 예시와 다르더라도 상황에 맞으면 허용한다.

## 4. 교수 예시의 정확한 역할

교수는 학교 회랑으로 퍼지는 냉기를 막기 위해 외벽에 열을 만들고 외곽 고리로 순환시킨다.

플레이어가 얻는 정보:

- 열을 실제 공간의 경로에 전달할 수 있다.
- 열이 지나간 곳부터 상태가 변한다.
- 냉기의 진행 방향이 달라질 수 있다.
- 하나의 회로는 하나의 제한된 문제만 해결할 수 있다.

플레이어가 얻지 않는 정보:

- 내부 사건의 정답
- 사용해야 할 목표와 우선순위
- 교수 회로의 고급 안전 부품
- 최적 해결 루트
- 평가 기준 답안

교수와 다른 방법의 예:

- 외곽 순환 대신 카시안의 탈출 통로를 가열한다.
- 직접 열 생성 대신 온수 관개를 이용한다.
- 온실 전체 대신 밸브 한 곳만 단계적으로 해빙한다.
- 열 사용을 최소화하고 격벽·밸브·철수로 봉쇄한다.
- 정령을 공격하지 않고 따뜻한 안전 구역으로 유도한다.

## 5. 루트별 대표 패턴 20개

### A. 시설 복구

#### A1. 열린 회수관 단계 해빙

```yaml
circuit: 열 + 흐름
heat_source: 직접 생성
path: 결빙 구간을 출구 쪽부터 순차 가열
target: 회수 밸브와 보조 배관
helper: 카시안이 회수 밸브를 먼저 개방
```

- 효과: 닫힌 압력을 다시 만들지 않고 배관을 단계적으로 해빙한다.
- 대가: 느리며 카시안과 묘목의 위험 시간이 길어진다.

#### A2. 균열 주변 정밀 해빙

```yaml
circuit: 열 + 흐름 + 집중
target: 균열을 막고 있는 얼음과 수동 장치
```

- 효과: 짧은 시간에 밸브와 점검구를 노출한다.
- 대가: 금속 변형·재파열 위험이 높다.

#### A3. 배관망 완만 해빙

```yaml
circuit: 열 + 흐름 + 분산
target: 여러 가는 배관과 핵 주변
```

- 효과: 국부 열충격을 줄이며 온실 전체 결빙을 완화한다.
- 대가: 출력이 약하고 완전 복구까지 오래 걸린다.

#### A4. 온수 관개 재배치

```yaml
circuit: 열 + 흐름
heat_source: 기존 온수 관개
path: 묘목 구역에서 핵심 배관 외벽으로 우회
target: 결빙된 핵심 배관
```

- 효과: 직접 열 생성을 줄이고 안정적으로 해빙한다.
- 대가: 묘목 뿌리 보온 자원을 빼앗는다.

### B. 생존 확보

#### B1. 탈출 통로 가열

```yaml
circuit: 열 + 흐름 + 집중
path: 상부 통로를 따라 카시안까지
target: 바닥·손잡이·격벽 장치
```

- 효과: 카시안이 스스로 이동할 시간을 확보한다.
- 대가: 통로 밖 시설과 묘목은 계속 얼어간다.

#### B2. 격벽 장치 해빙

```yaml
circuit: 열 + 흐름 + 집중
target: 얼어붙은 수동 격벽 축
helper: 카시안이 장치를 직접 조작
```

- 효과: 짧은 주문과 물리 협력으로 탈출구를 연다.
- 대가: 내부 냉기와 정령 문제가 남는다.

#### B3. 카시안·묘목 온기 분배

```yaml
circuit: 열 + 흐름 + 분산
targets: 카시안 안전 구역, 희귀 묘목 뿌리
```

- 효과: 두 대상의 생존 시간을 동시에 늘린다.
- 대가: 어느 쪽도 완전히 해빙되지 않고 시설 복구가 늦어진다.

#### B4. 묘목 보온과 자력 탈출

```yaml
circuit: 열 + 흐름
heat_source: 온수 관개
target: 핵심 묘목 뿌리
helper: 모트가 카시안의 안전 경로 관찰
```

- 효과: 묘목을 보호하면서 카시안이 직접 이동한다.
- 대가: 카시안 이동 실패 위험과 시설 포기가 남는다.

### C. 정령 안정화·교섭

#### C1. 따뜻한 안전 지점 생성

```yaml
circuit: 열 + 흐름
path: 누출 지점 반대편 빈 화단
target: 정령이 이동할 온도 완충 구역
```

- 효과: 정령이 냉기 누출에서 떨어질 선택지를 만든다.
- 대가: 정령이 의도를 이해하지 못하면 움직이지 않는다.

#### C2. 정령 주변 완만한 분산 가열

```yaml
circuit: 열 + 흐름 + 분산
target: 정령 무리 주변 공기와 바닥
```

- 효과: 급격한 자극 없이 냉기 과부하를 완화한다.
- 대가: 느리며 묘목과 배관의 위험이 계속된다.

#### C3. 누출 배관 순차 해빙

```yaml
circuit: 열 + 흐름
path: 서리가 가장 얇은 지점에서 균열 방향으로 순차 이동
target: 누출 배관 표면
```

- 효과: 냉기 공급의 원인을 드러내고 정령이 흡수하는 양을 줄인다.
- 대가: 균열 위치를 잘못 판단하면 파열이 커진다.

#### C4. 열 반응으로 균열 범위 좁히기

```yaml
circuit: 열 + 흐름 + 집중
target: 의심 구간을 짧게 순차 가열
helper: 모트가 정령 반응 변화 관찰
```

- 효과: 정상 금속과 균열 금속의 반응 차이로 원인을 좁힌다.
- 대가: 조사 목적의 주문이며 즉시 구조·복구하지 못한다.

### D. 현상 봉쇄

#### D1. 내부 열 순환 경계

```yaml
circuit: 열 + 흐름
path: 사용하지 않는 내부 순환관의 닫힌 고리
target: 온실 내부 확산 경계
```

- 효과: 냉기가 특정 구역 밖으로 퍼지는 속도를 낮춘다.
- 대가: 내부 냉기 총량과 압력은 줄지 않는다.

#### D2. 안전 구획 온도 유지

```yaml
circuit: 열 + 흐름 + 집중
target: 카시안·핵심 묘목이 있는 한 구획
helper: 카시안이 나머지 격벽을 폐쇄
```

- 효과: 제한된 자원으로 생존 구역을 유지한다.
- 대가: 나머지 온실을 포기한다.

#### D3. 다중 완충 지점 분산

```yaml
circuit: 열 + 흐름 + 분산
targets: 빈 화단, 완충 결정 주변, 사용하지 않는 배관
```

- 효과: 결빙 속도와 국부 열충격을 여러 곳으로 나눈다.
- 대가: 온실 전체에 작은 피해가 남는다.

#### D4. 밸브 재결빙 방지

```yaml
circuit: 열 + 흐름
heat_source: 환기 온기
path: 열린 회수 밸브 주변을 지속 순환
target: 출구 유지
```

- 효과: 전문 지원이 올 때까지 압력 배출 경로를 유지한다.
- 대가: 완전 해결이 아니며 지속 관리가 필요하다.

### E. 제압·시간 확보

#### E1. 따뜻한 기류 밀어내기

```yaml
circuit: 열 + 흐름 + 집중
heat_source: 환기 온기
path: 정령과 작업 구역 사이
target: 접근하는 정령 전면
```

- 효과: 정령을 해치지 않고 거리를 확보한다.
- 대가: 강한 기류와 열이 정령을 적대시킬 수 있다.

#### E2. 작업 구역 열 경계

```yaml
circuit: 열 + 흐름
path: 플레이어와 배관 둘레의 짧은 고리
target: 작업 공간
```

- 효과: 주문 작성과 밸브 조작 시간을 번다.
- 대가: 유리·묘목 열 손상 가능성이 있다.

#### E3. 냉기 공격 방향 전환

```yaml
circuit: 열 + 흐름
path: 냉기 진행선 옆의 비스듬한 열 경계
target: 빈 완충 구역 쪽
```

- 효과: 공격을 삭제하지 않고 피해가 적은 방향으로 휘게 한다.
- 대가: 새로운 도착 지점에 피해가 남는다.

#### E4. 모트 유인·격벽 협력

```yaml
circuit: 열 + 흐름
path: 모트가 움직일 따뜻한 경로
helper: 모트가 정령을 유인, 카시안이 격벽 폐쇄
target: 빈 화단 구획
```

- 효과: 정령을 처치하지 않고 공간적으로 분리한다.
- 대가: 모트의 위험과 정령 관계 하락이 남는다.

## 6. 대표 패턴 밖의 해결

다음과 같은 조합도 자동 거부하지 않는다.

- 작은 열을 여러 번 순차 적용해 금속 충격을 줄인다.
- 환기 온기와 직접 열을 서로 다른 대상에 나눈다.
- 열 주문은 밸브 유지에만 쓰고, 실제 해결은 카시안의 수동 조작과 철수로 완성한다.
- 정령을 따뜻한 구역으로 유도한 뒤 누출을 봉쇄한다.
- 시설 복구에서 시작했지만 첫 결과 뒤 생존 확보로 접근을 바꾼다.

판정은 교수 예시와의 일치가 아니라 다음을 본다.

```text
글자 의미가 맞는가
→ 실제 출발점과 경로가 있는가
→ 목표 변화가 설명되는가
→ 위험과 대가를 처리했는가
→ 사건 위협을 완화했는가
```

## 7. 조사와 주문 전 힌트

```text
감각적 관찰
→ 선택형 회로 조사
→ 환경·카시안·모트 조사
→ 접근 선택
→ 주문 초안
→ 예상 효과 확인
→ 수정 또는 Commit
```

### 감각적 관찰

- 따뜻한 기운이 느껴진다.
- 유리의 서리가 녹는다.
- 냉기의 방향이 바뀐다.
- 내부 압력계는 그대로다.

### 키워드 조사

- 시작 문양을 살펴 `열` 확인.
- 이동 선을 따라 `흐름` 확인.
- 고급 모서리 회로는 해독 불가.

### 예상 효과

```yaml
preview:
  primary_effect:
  speed:
  scope:
  pressure_change:
  likely_benefit:
  main_risk:
  unresolved_problem:
  confidence:
```

예상 효과는 플레이어 초안의 직접 변화와 주요 위험만 보여준다. 정답·성공률·결말·교수 방식과의 일치도는 표시하지 않는다.

---

## 8. 최소 인물 대화 원칙

- 교수: 안전선과 놓친 조건만 말한다. 자신의 예시를 따라 하라고 말하지 않는다.
- 카시안: 내부 밸브·압력·통로 정보를 제공하고 물리 조작에 협력한다.
- 모트: 정령 감정과 온도·마력 방향을 감각적으로 전달한다.

상급생은 이번 사건에 등장하지 않는다. 필수 정보는 인물 한 명에게 독점시키지 않는다.

---

## 9. 적대적 검토

### 교수 예시가 답안으로 보이는 위험

- 교수 목표와 플레이어 목표를 분리한다.
- 교수는 외부 확산만 막고 내부 문제를 남긴다.
- 교수 회로 전체는 고급 안전 부품 때문에 복제할 수 없다.
- 결과 평가에 교수 방식과의 일치 항목을 두지 않는다.

### 열이 만능 정답이 되는 위험

- 과열·열팽창·화상·묘목 손상·정령 적대 위험을 유지한다.
- 직접 열 생성과 기존 열원 사용에 서로 다른 자원 대가를 둔다.
- 물리 협력·봉쇄·철수 없이는 해결되지 않는 패턴을 포함한다.

### 20개 패턴이 숨은 정답표가 되는 위험

- 대표 패턴 밖의 합리적 해결을 의미 판정으로 허용한다.
- 패턴 ID와 목록을 플레이어 UI에 표시하지 않는다.
- 결과는 패턴 일치 여부가 아니라 세계 상태 변화로 설명한다.
