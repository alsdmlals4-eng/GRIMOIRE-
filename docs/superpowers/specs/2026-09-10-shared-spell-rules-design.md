상태: SPECIFIED_RECOMMENDED_BASELINE / IMPLEMENTATION_NOT_RUN / HUMAN_NOT_RUN.
사용자 승인 방향: 글자를 조합해 주문 시전, 결투 밖 무작위 손패 없음, 실습·온실·축제에도 같은 마법 사용. 사용자 `세부규칙은 네가 권장안대로 잡아줘`에 따른 설계 기준이며 수치·재미의 최종 검증이나 구현 승인이 아니다.

## 1. 경험과 경계

마법학교 학생이 배운 글자의 작용을 이해하고, 같은 주문을 다른 대상과 환경에 응용한다. 카드는 선택 도구이지 세계 전체가 카드게임이라는 설정이 아니다. 주문은 자유 텍스트·생성형 AI·필기 인식으로 판정하지 않는다. 마법사 종류 카드·별형 회로·체스·SD 이동을 재도입하지 않는다.

관찰 → 글자 1~2개 선택 → 주문 작용 확인 → 대상·방향 지정 → 비용·예상 변화 확인 → 명시 시전 → 변화·대가·복기.

비교: 모든 사건의 카드대결화 REJECT, 별도 생활마법 문법 REJECT, 공통 작용+상황별 판정 ADOPT. 어려움은 반응속도보다 대상 선택·상태 이해·자원 사용에서 만든다. 일상·수업은 낮은 압박, 실습은 제한된 위험, 결투는 대응, 축제는 응용과 이야기 결과를 담당한다. 활동은 스토리로 연결하며 메인 메뉴의 독립 모드 선택으로 바꾸지 않는다.

## 2. 입문 문법

- 배운 글자 하나는 단독 주문이다. 다른 두 글자는 조합 주문이다. 선택 순서는 결과를 바꾸지 않는다. 조합 이름은 고정 표시 사전으로 제공한다.
- 같은 글자 중복과 세 번째 글자는 입문 규칙에서 받지 않는다. 기존 선택을 유지하고 이유를 알린다. 이는 장기 전체 마법의 영구 한계가 아니라 첫 세션 규격이다.
- 배우지 않은 글자, 정의되지 않은 조합은 시전 불가다. 비용·시간을 쓰지 않는다. 미학습 조합도 구성 글자를 배웠고 정의가 있으면 미리보기·사용 가능하다. 도감 발견은 첫 사용에 한 번 기록한다.
- 초반에는 위력 슬라이더·별도 조준 기술·실패 확률을 넣지 않는다. 단독 비용 1, 조합 비용 2, 모든 기본 시전 시간 1행동을 시험값으로 둔다. 두 글자가 항상 상위호환이 아니라 작용을 바꾼다.
- 기본 대상은 한 개다. 방향이 필요한 주문만 화면에 명시된 목적지 한 개를 추가한다. 자동 최적 대상·자동 시전 없음. 좁은 범위 주문은 미리 정의된 영역 하나를 대상으로 하며 모든 물체의 자유 물리 시뮬레이션을 약속하지 않는다.

## 3. 첫 글자와 주문 사전

기존 네 ID를 비교 가능한 어휘로 사용하되 아래 의미는 새 설계다. 기존 attack 숫자를 공통 의미로 승계하지 않는다. 명칭은 한국어 표시, ID는 안정 식별자다.

| ID / 글자 | 기본 작용 | 할 수 없는 일 |
|---|---|---|
| EMBER / 불씨 | 선택 지점에 작은 열을 준다 | 냉각·소화·무조건 살균 |
| WIND / 바람 | 가벼운 대상이나 공기를 지정 방향으로 민다 | 무거운 물체 무제한 운반 |
| WARD / 막기 | 경계 하나에서 유입·통과를 잠시 차단한다 | 이미 생긴 오염이나 손상 삭제 |
| GATHER / 모으기 | 흩어진 가벼운 물질·마력을 한 지점에 모은다 | 성질이 다른 물질의 자동 분리·정화 |

| 조합 / 설명용 이름 | 일관된 작용 | 사용 조건·대가 |
|---|---|---|
| 불씨+바람 / 온기 흐름 | 열을 기류로 좁은 영역에 전달 | 마른 물질·휘발성 대상은 과열·확산 경고 |
| 불씨+막기 / 온기 장막 | 경계 안의 열이 빠져나가는 것을 억제 | 새 열을 무한 생성하지 않음. 과열도 가둘 수 있음 |
| 불씨+모으기 / 응축 불씨 | 작은 지점에 열을 집중 | 넓은 영역 처리 불가, 민감한 대상 손상 위험 |
| 바람+막기 / 흐름 전환 | 지정 경계에서 들어오는 기류·가벼운 투사 흐름을 돌림 | 고정 장벽 관통·모든 공격 반사 아님 |
| 바람+모으기 / 모으는 바람 | 흩어진 가벼운 물질을 지정 수용점으로 운반 | 수용점이 열려 있거나 포화되면 재확산 가능 |
| 막기+모으기 / 봉합 장막 | 작은 누출 지점의 마력을 모아 경계를 봉합 | 원인이 남아 있는 큰 누출의 영구 수리 아님 |

단독 4개+조합 6개 모두 대상 적합성·범위·지속·상태 반응을 갖는다. 구현 시 레시피별 예외 문장을 난립시키지 않고 작용 ID와 조건으로 판정한다. `열 민감`, `가벼움`, `기류 이동 가능`, `누출`, `닫힌 수용점` 등의 의미를 콘텐츠에서 선언한다. 화면에 없는 성질로 즉시 큰 손실을 주지 않는다.

## 4. 사건에서 사용 가능한 글자와 마력

배운 글자 전체에서 선택한다. 즐겨찾기는 탐색 편의이며 장착 제한이 아니다. 손패·드로우·버림·글자 영구 소모 없음. 기본 글자는 시전해도 잊지 않는다. 별도 소모품은 이번 규칙 밖이다.

첫 실습의 마력 예산은 6을 시험값으로 둔다. 임무 시작 시 현재 예산과 회복 조건을 안내한다. 사건 중 자동 회복·메뉴 재진입 회복 없음. 마력이 부족하면 해당 주문만 비활성화하고 일반 행동·도움 요청·안전 중단을 제공한다. 휴식은 안전한 스토리 지점에서만 회복한다. 재연습은 결과 확정 후 별도 시도 ID로 초기화하고 보상·발견을 중복 지급하지 않는다. 초기 마력 6은 장기 성장 최대치나 하루 전체 예산을 확정하지 않는다. 7/7/6과 마력20은 고정 규칙이 아니다.

일반 행동도 타당하면 상황을 바꾼다. 예: 수동으로 덮개 닫기, 장치 조작, 교수에게 도움 요청. 마법을 안 쓰는 선택을 무조건 열등하게 만들지 않는다. 도움은 진행 교착을 해소하되 학생이 독립 해결했다는 평가로 기록하지 않는다.

## 5. 시간·판정·미리보기

읽기·기본 관찰·선택·상세·취소·설정·앱 중단에는 시간과 마력을 쓰지 않는다. 새 정보를 얻는 정밀 조사와 실제 장치 조작은 비용을 표시한 행동이다. 이미 확인한 정보 다시 읽기는 무료다. 이 구분은 화면 문구로 공개한다.

기본 결과는 결정적이다. 같은 규칙 버전·상태·대상·주문은 같은 결과다. 숨은 주사위로 맞는 접근을 실패시키지 않는다. 모르는 대상은 성질 미확인과 가능한 위험 범위를 표시하며 초반 필수 해결 정보는 무료 관찰로 제공한다. 무효 대상은 시전 전 차단, 유효하지만 역효과인 대상은 경고 후 명시 시전 가능이다.

미리보기: 주문의 작용, 대상, 마력 비용, 시간 비용, 확인된 변화, 불확실성, 위험 변화의 원인을 분리한다. 조사하지 않은 사실이나 최적 해답을 미리보기가 누설하지 않는다. 해소기는 완전한 상태를 읽고, 미리보기 표시만 발견 정보에 따라 제한한다.

시전 명령 검증 → 비용 지불 → 주문/일반행동 효과와 지속 상태 적용 → 시간 경과에 따른 위험 변화 → 범위 보정 → 목표·위험 동시 판정 → 결과 영수증 저장. 중복 입력은 같은 영수증을 반환하고 재소비하지 않는다. 오래된 상태에서의 명령은 무소비 거절 후 미리보기를 갱신한다. 연출은 결과를 보여줄 뿐 판정하지 않는다.

## 6. 사건 시계

첫 복합 사건은 위험 시계 하나를 기본으로 하고 목표는 명확한 상태 조건으로 표현한다. 여러 단계의 노력이 정말 필요한 사건만 별도 목표 시계를 추가한다. 단순 실습에는 시계를 쓰지 않는다.

- 위험 칸수 기본 후보: 4/6/8, 사건이 직접 선택. 0은 당장 위험이 없다는 뜻이지 자동 해결이 아니다.
- 기본식: 새 위험 = clamp(기존 위험 + 행동 대가 + 시간 증가 - 완화, 0, 총칸).
- 시간 증가와 완화는 같은 행동에 모두 일어날 수 있다. 표시도 `시간 +1 / 수집 -2 / 합계 -1`로 구분한다.
- 위험 증가율은 사건 상태에 종속한다. 원인을 차단했으면 그 원인의 증가가 멈춘다. 특정 주문 사용 자체가 시계를 내리는 만능 열쇠는 아니다.
- 임시 장막은 생성 행동의 시간 처리와 다음 시간 소비 행동까지 유효하다. 재시전은 남은 시간을 갱신할 뿐 중첩하지 않는다. 지속을 종료할 때 추가 시간이 들지 않으며, 종료가 위험 변화를 유발하면 미리 알린다.
- 위험이 다 차면 해당 사건의 선언된 결과로 전환한다. 초반 학교 실습은 교수 개입·시설 폐쇄·일부 재료 손실 등으로 이어지며 영구 진행 불가를 만들지 않는다.
- 목표와 위험이 같은 행동에 완료되면 성취와 대가를 함께 기록한다. 위험 결과가 목표 성공을 취소하지 않는다.
- 목표 시계가 있는 경우 표준 진척 2, 제한 1, 큰 효과 3을 시험 범위로 둔다. 환경이 요구하는 적합성에 따라 정하며 글자 개수가 자동 진척량은 아니다. 이미 처리한 대상을 반복해 진척을 복제하지 않는다.

## 7. 네 가지 사용 예와 검산

### 수업 실습: 같은 작용의 학습

찬 물이 든 실습 용기와 열에 약한 표본을 구별한다. 용기에 불씨를 사용하면 가열 상태가 된다. 표본에 사용하면 손상 경고다. 시간 압박·확률 판정 없음. 정답 조합 강제 대신 대상의 성질을 읽는 것을 배운다. 완료 조건은 용기 가열이며 재가열로 보상을 반복하지 않는다.

### 온실: 첫 실습 사건의 예시, 메인 줄거리 아님

원인: 새는 꽃가루 장치. 시작 위험2/6, 누출 중 시간행동마다 +1. 목표는 누출 차단 AND 부유 꽃가루 제거. 닫힌 수집함은 무료 관찰로 확인 가능. 마력6.

| 행동 | 사건 상태 변화 | 위험 계산 | 남은 마력 |
|---|---|---|---:|
| 모으는 바람 → 수집함 | 현재 부유 꽃가루 제거, 누출은 계속 | 2+1-2=1 | 4 |
| 장치 덮개 수동 닫기 | 누출 차단, 첫 행동 말에 다시 생긴 꽃가루는 남음 | 1+0=1 | 4 |
| 모으는 바람 → 수집함 | 잔여 꽃가루 제거, 목표 달성 | max(0,1+0-2)=0 | 2 |

다른 타당한 경로: 먼저 덮개 닫기(위험2 유지) → 모으는 바람(2-2=0), 마력4 남김. 무료 관찰을 활용한 순서가 효율적이어도 첫 경로도 해결 가능하다. 모든 경로가 동등할 필요는 없다.
모으는 바람만 반복하면 누출이 계속되어 목표가 안 끝나고 마력이 소진된다. 꽃가루가 없는 상태에는 제거량0, 가득 찬 수집함에는 운반 불가를 표시한다. 원인 해결 없는 영구 안전 반복을 보상하지 않는다. 최종 장면에서는 여러 해결 경로의 재료·시간 차이를 추가 검토한다.

### 축제: 연출과 안전의 응용

가벼운 종이 장식을 바람으로 이동하고 모으는 바람으로 지정 위치에 모은다. 막기는 관객 쪽으로 넘어가는 흐름을 임시 차단한다. 불씨는 조명용 내열 용기에만 안전하며 종이에는 경고한다. 기본 공연은 목표 조건으로 평가하고, 시간제 공연에만 별도 마감 시계를 둔다. 품질은 안전·배치 등 공개 기준으로 평가하며 주문 횟수를 점수로 바꾸지 않는다. 공연 내용·점수·보상은 별도 콘텐츠 작업이다.

### 결투: 같은 작용, 제한된 가용 글자

손패4, 각 글자2개인 시험 덱8, 1~2장 선택, 교환 예산2, 미사용 손패 보존/사용분 버림/부족분 보충을 입문 후보로 유지한다. 예산은 빠르게 제어할 수 있는 마력의 교환 한도로 표시하며 사건 마력 잔량과 혼동하지 않는다. 예산2는 장기 마력20을 7/7/6으로 분배한 규칙이 아니다.

세 상태를 구분한다: INVALID는 조합/거리/대상 조건 불일치로 무소비 차단, VALID_NO_CHANGE는 적합하나 이미 완료된 상태로 변화 없음과 비용을 경고, VALID_CHANGE는 유익/유해 변화 모두 포함한다. 기본 UI는 무변화 시전을 권하지 않지만 강제 자동 취소하지 않는다. 모든 허용 시전은 비용과 시간을 쓴다.

| 주문 | 적합 대상·전제 | 사건의 정상 변화 | 무효/위험/무변화 경계 |
|---|---|---|---|
| 불씨 | 가열 가능한 지점 | cold→warm | heat_sensitive는 손상 경고, 이미 warm이면 과열 경고. 금속문 개방 등 별도 효과 없음 |

| 막기 | blockable_boundary | 임시 blocked 상태 | 부유물 제거 없음, 이미 닫힌 경계는 무변화 |
| 모으기 | gatherable + 비어 있는 국소 수용점 | 국소 물질을 모음, 흩어진 마력 집중 | 원격 이동 불가, 서로 다른 성질 자동 분리 불가 |
| 온기 흐름 | airflow_movable + heatable 영역 | 영역의 cold→warm | 종이/휘발성 물질 포함 시 손상·확산 경고 |
| 온기 장막 | 경계가 있는 warm 영역 | 임시 heat_retained | cold를 warm으로 만들지 않음, overheated이면 위험 유지 경고 |

| 흐름 전환 | redirectable_flow + 안전한 출구 | incoming 경로를 지정 출구로 전환 | 고정 장벽·비전환 공격 무효, 출구 관객이면 위험 경고 |

## 12. 입문 결투 시험 변환표

결계 최대16, 덱8(각2), 손패4, 교환예산2는 유지한다. 단독 비용1/조합2. 예산 잔액은 이월되지 않는다. 이 수치는 아래 새로운 효과의 밸런스 PASS를 의미하지 않는다.

공격에는 `heat`, `flow`, `fixed_pulse` 중 하나의 성질이 붙는다. 숫자 옆에 한국어 성질을 표시한다. 상대 고정 패턴은 흐름4/방어0 → 열3/흐름방패3 → 고정파동5/방어0 반복 후보다. 공격·방어·성질을 전부 예고하고 선택 후 바꾸지 않는다. 모든 일반 방어는 남아 있는 공격량을 막으며, 흐름방패만 별도로 해제 가능하다.

| 주문 | 결투 대상과 시험 결과 | 작용 일치 근거 |
|---|---|---|
| 불씨 | 상대 결계에 heat 공격3 | 작은 열로 결계 압박 |
| 바람 | 상대 결계에 flow 공격2 | 기류로 압박, 자동 자기 방어 없음 |
| 막기 | 자기 앞 경계에 이번 교환 방어4 | 통과 차단 |
| 모으기 | 자기 주변 잔류 마력에 집중1 획득 | 공격 없음. 다음 직접 공격 주문에 공격+1 후 소비 |
| 온기 흐름 | 상대 결계에 heat 공격3, 상대가 flow 공격이면 그 공격-1 | 열을 전달하며 맞은편 기류 일부 교란 |
| 온기 장막 | 예고된 heat 공격의 진입 경계에 열 차단5 | 들어오는 열을 경계에 가둠. 다른 성질에는 대상 부적합 |
| 응축 불씨 | 상대 결계에 heat 공격5 | 한 점의 집중 가열 |
| 흐름 전환 | 예고된 flow 공격을 최대3 전환, 전환한 양을 flow 반격 | fixed_pulse/heat는 대상 부적합. 무조건 반사 없음 |
| 모으는 바람 | 상대 흐름방패 최대3 해제, 다음 교환의 흐름방패 생성도 최대3 억제 | 이동 가능한 방패 마력을 지정 수용점으로 운반. 고정 방패 무효 |
| 봉합 장막 | 자기 손상 결계3 복구, 최대16 | 남아 있는 결계 균열 봉합. 결계0 이후 부활 없음 |

입문 결투장의 잔류 마력과 수용점은 공개된 연습 환경이다. 다른 장면에서 이 대상을 자동 생성하지 않는다. 집중은 최대1, 다음 교환 종료까지 지속하고 같은 주문 재사용은 기간만 갱신한다. 직접 공격(불씨/바람/온기 흐름/응축 불씨)에만 쓰며 반격·복구에는 쓰지 않는다. 방패 억제는 중첩하지 않고 남은 기간만 갱신한다. 결투 임시 방어는 해당 교환만 유효하며 사건의 장막 지속과 구분해 표시한다.

처리 순서:

1. 시작 상태와 명령 유효성 확인. 선택 카드/예산 소비. 이번 직접 공격에 시작 시점 집중을 반영·소비.
2. 양측의 이번 방어 생성. 방패 해제/기존 억제 적용. 복구·신규 집중 적용.
3. 조건부 공격 감소 → flow 전환량 계산 → 전환 후 원공격을 일반 방어로 차단.
4. 전환 반격은 상대의 남은 일반 방어로 차단한다. 반격에 재반격하지 않으며 같은 방어를 두 번 사용하지 않는다. 방어는 원공격에 먼저 사용한다.
5. 양측 잔여 피해 동시 적용 → 0 여부 판정 → 기간 감소 → 저장. 이미 결정된 공격은 중간 결과로 취소하지 않는다.

모으는 바람으로 새로 부여한 억제는 다음 교환 방어 생성에 한 번 적용한 뒤 종료한다. 집중 생성 교환 말에는 소멸하지 않는다. 봉합 복구는 피해보다 먼저 적용하고 최대치로 제한하므로 꽉 찬 결계에 복구를 예약해 피해를 상쇄할 수 없다. 최대 결계일 때는 무변화 경고다.

검산 예: 흐름4를 흐름 전환3으로 받으면 자기 피해1, 상대 방어0이면 반격3. 열3에 온기 장막5는 피해0. 흐름방패3에 응축 불씨5는 피해2. 집중1이 있을 때는 피해3. 결계14에서 봉합3 후 고정파동5를 받으면 min(16,14+3)-5=11.

방어/복구만 반복하는 교착은 연습 중단으로 회복 가능하다. 이번 버전에 자동 시간초과 패배·갑작스러운 적 강화는 넣지 않는다. 행동 수 경고와 재시작 안내는 보상 없이 제공한다. 순수 방어 전략의 평균 길이·극단 손패 승리 가능성은 시뮬레이션 후 조정한다. 다음 이야기 진입은 승리 강제가 아니라 연습 결과 확인이며 패배/중단도 복기로 연결한다.

## 13. 첫 세 사건의 상태 명세

공통: `ONGOING / SOLVED / ASSISTED / STOPPED` 결과, result_id당 이야기 반영 한 번. 목표와 위험 동시 완료는 `SOLVED`에 consequence를 추가한다. 도움으로 해결하면 `ASSISTED`, 자발적 중단은 `STOPPED`. 시도 재시작은 시도 상태만 초기화하고 이미 받은 보상/발견을 되돌리거나 복제하지 않는다. 아래 ID는 설계용이며 runtime 데이터 생성은 아직 하지 않았다.

### LESSON_HEAT_01 — 대상을 읽는 수업

- 시작: 마력6, vessel=cold, sample=intact, 온도 눈금 공개. 네 글자는 배운 상태로 실습을 시작하며 첫 안내만 불씨에 집중한다.
- 목표: vessel=warm. 시계 없음. 불씨 또는 온기 흐름이 warm으로 만든다. 응축 불씨는 hot이 되어 즉시 목표가 되지 않는다.
- 일반행동: 안전 받침에서 식히기 1행동(hot→warm). 덮개 열기만으로 즉시 냉각하지 않는다.
- 위험한 시전: 표본 가열은 경고 후 sample=damaged. 교수의 예비 표본으로 대체 가능하지만 consequence에 기록한다. 표본 손상은 용기 목표를 지우지 않는다.
- 마력0: 식히기/교수 도움/중단 가능. 무료 읽기 반복은 아무 값도 바꾸지 않는다.
- 복기: 사용 주문과 실제 대상 변화, 표본 보존 여부. 주문 사용횟수 보상 없음.

### GREENHOUSE_LEAK_01 — 원인과 잔여 위험

- 시작: 마력6, leak=open, cloud=present, capture_load=0, capture_capacity=3, hazard=2/6. 수집함은 닫힌 통이 아니라 일방향 필터 입구가 열려 있고 유출은 막힌 장치(`capture_ready`)다. 이전 '닫힌 수집함' 표현을 이 의미로 구체화한다.
- 목표: leak=closed AND cloud=absent. hazard=0만으로 종료하지 않는다.
- 덮개 닫기: 일반행동1, leak=closed. 이 행동부터 누출 시간증가0. 이미 닫혔으면 무변화 경고.
- 모으는 바람: 마력2/행동1, cloud가 있으면 제거하고 load+1, hazard-2. 이후 누출이 열려 있고 억제되지 않았으면 cloud=present와 hazard+1. capacity 초과는 무소비 차단.
- 막기/봉합: 각각 경계 차단/누출 억제의 임시 상태. 생성 행동과 다음 시간행동의 누출 증가를 막는다. 실제 덮개는 열린 채이므로 목표가 안 끝난다. 기간 종료 후 다음 시간행동부터 재누출한다.
- 일반행동 수동 청소: leak=closed일 때만 가능. 2단계(each1행동): 첫 단계는 일부 청소로 cloud=present 유지, 두 번째 완료에서 cloud=absent. hazard는 단계당1 감소하며0 아래로 내려가지 않는다. 누출이 다시 열리면 단계0으로 돌아간다는 사실을 사전 표시한다. 마력 없이도 닫기+청소로 해결 가능하다. 2026-09-11 상세화: '2단계'와 제거 시점의 모호함을 교정했다.
- 화염 사용: 장치는 heat_sensitive, 유효한 가열이지만 hazard+2의 손상 대가를 경고한다. 누출이 계속되면 시간+1도 별도 표시한다. 초반은 추가 HP 손실을 중복 부과하지 않는다.
- hazard=6: 교수 개입과 온실 구역 잠정 폐쇄. 미해결이면 ASSISTED, 같은 행동에 목표 달성이면 SOLVED+폐쇄 대가. 원인/잔여 상황과 시계가 같이 설명되어야 한다.
- 도움 요청은 비용 없이 ASSISTED로 전환한다. 안전 중단도 즉시 가능. 이것은 독립 해결 평가가 아니다.

### FESTIVAL_LIGHTS_01 — 안전한 연출 준비

- 축제 전체가 아니라 첫 공연 준비 사건. 마력6, lamp=cold, decorations=scattered, barrier_latch=open, audience_safe=true. 목표는 lamp=warm AND decorations=placed AND barrier_latch=closed. 필수 마감 시계 없음.
- 불씨→내열 조명 용기: lamp=warm, 비용1/행동1. 응축 불씨는 hot, 일반 식히기1행동으로 warm.
- 바람→가벼운 묶음 장식: 비용1/행동1로 placed. 모으는 바람은 흩어진 낱개까지 정돈하여 placed, 비용2/행동1. 두 상태는 같은 목표를 만족하며 비싼 조합을 필수로 만들지 않는다.
- 경계 잠금: 일반행동1로 latch=closed. 임시 막기는 안전한 작업 시간을 줄 뿐 영구 잠금 완료로 취급하지 않는다. 지속 효과 종료 후에도 목표가 유지되어야 한다.
- 관객 방향 출구·종이 가열은 사전 위험 경고. 실행 시 audience_safe=false를 기록하고 행사 담당자 개입으로 ASSISTED. 대형 재난이나 부상 서사를 이 작은 사건에 자동 추가하지 않는다.
- 평가: 독립/도움, 안전 유지, 배치 완료를 사실로 표시. 연속 시전 점수·무한 보상 없음. 마력 부족 시 담당자 도움 또는 장식 수동 배치2행동 가능, 조명은 담당자 도움으로 해결.
- 도달성 예: 불씨(1)+바람(1)+잠금(0)=마력2/행동3. 마력4 남김. 조합 경로도 가능하나 고득점 정답으로 강제하지 않는다.

## 15. 조사 기반 운영·성장·입력 기획 v0.3

사용자 `상세 규칙 및 기획사항은 네가 인터넷 조사,벤치마킹 및 권장안대로 판단해서 정리해줘`에 따른 후속 설계. 작은 수치마다 반복 승인 요구 없이 기준을 정리하되 세계관 핵심 변경·출시·비용·삭제·최종 사람 평가는 별도다. 아래는 설계 기준이며 구현 완료가 아니다. 새 게임 정의를 늘리기보다 손패 회복·진행·학습·결과의 빈틈을 닫는다.

### 15.1 손패가 막힐 때의 행동

입문 덱 8장 중 순서 없는 손패4의 70개 인스턴스 조합을 JavaScript로 열거했다. 직접 공격 글자 불씨/바람이 없는 것은 막기2+모으기2 한 가지다. 균등 초기 추첨을 가정한 조합 사실이며 전체 승률·매 교환 확률·패배 확률이 아니다. 해당 손패에도 방어/집중/복구가 있어 '사용 불가 손패'로 오인하지 않는다.

기본 대기는 카드를 보존하고 상대 행동을 받으며, 손패가 가득 차면 새 드로우가 없다. 이에 **정돈**을 결투 전용 권장 행동으로 추가한다:

- 손패 한 장을 지정하고 확인한다. 선택 취소는 무료다.
- 확정 시 주문을 쓰지 않고 이번 교환을 사용한다. 상대 예고 행동은 정상 해소된다. 추가 마력 비용은 없지만 공격/방어 기회를 포기한다.
- 반환 카드가 섞이지 않은 기존 뽑기 더미에서 한 장을 먼저 꺼내고, 반환 카드는 뽑기 더미 맨 아래로 보낸다. 기존 더미가 비면 기존 버림 더미를 저장 난수 상태로 섞어 대체 카드를 뽑은 뒤 반환 카드를 아래에 둔다.
- 두 더미에 대체 카드가 없으면 확정 전 무소비 차단한다. 자신이 반환한 카드를 즉시 다시 뽑지 않는다. 새 카드로 같은 교환에 시전할 수 없다.
- 해소·승패·집중/억제 기간은 대기와 동일하게 흐른다. 카드는 교환 결과와 함께 저장하고 중복 명령으로 다시 뽑지 않는다.
- 이번 초기 손패 막기2+모으기2에서는 나머지 네 장이 모두 불씨/바람이므로 정돈 후 직접 공격 글자 한 장을 확보한다. 이것은 해당 초기 상태에만 해당하는 보장이다.

튜토리얼 첫 손패는 각 글자 한 장으로 고정하고 '학습용 손패'를 표시한다. 안내를 건너뛰어도 최초 학습 시도에는 동일하다. 재연습은 저장된 seed의 일반 추첨이며 새 시도 시작만 새 seed를 받는다. 도감·설정 재진입으로 추첨이 바뀌지 않는다. 무작위 초기 손패에 따른 승리 가능성 검증은 별도로 남는다.

### 15.2 보상·성장과 학교생활

성장은 글자 수 증가뿐 아니라 기존 작용의 새로운 활용을 이해하는 방향이다. 입문 네 글자의 응용 검증 전 새 글자·장문 주문·새 수치 스탯을 늘리지 않는다.

보상 단위는 사건/발견/이야기 결과 ID다. 반복 시전 횟수·버틴 교환 수에 경험치나 통화를 붙이지 않는다. 같은 사건 재연습은 연습 기록만 남기며 첫 발견 보상은 재지급하지 않는다. 방어 빌드를 약화하거나 숨은 시간초과 패배를 넣어 보상 악용을 해결하지 않는다.

첫 학습 흐름의 권장 순서: 입학·인물 만남 → 안전한 수업 실습 → 안내 결투 → 첫 현장 실습 → 복기·관계 대화 → 후속 수업과 학교생활 → 축제 준비. 축제까지 모두 첫 세션에 압축하지 않는다. 전체 학기 수·달력·엔딩 수는 이 순서로 확정하지 않는다.

각 사건 이후에는 성공/도움/중단만이 아니라 보존한 대상, 남은 문제, 사용한 접근을 대사 조건으로 전달한다. 관계 변화는 누가 무엇을 관찰했는지 설명 가능한 사건 사실에 연결한다. 화염 계열을 골랐다는 이유만으로 성격·도덕성을 판정하지 않는다. 캐릭터별 대사·관계 수치·장기 분기는 아직 작성하지 않았으며 자동 생성 runtime을 추가하지 않는다.

온실은 전체 줄거리의 중심이 아닌 전이 검사 장소다. 축제는 전투 점수 경쟁으로 바꾸지 않는다. 반복 방문은 새 상태·사건·대화를 제공할 이유가 있을 때만 설계한다. 일상 메뉴·농사·경제·시간표 관리의 대량 추가는 보류한다.

### 15.3 공통 화면과 입력 계약

아래는 text-native 와이어프레임 기준이다. 그림이나 실제 Godot 화면이 아니다.

| 영역 | 사건 | 결투 |
|---|---|---|
| 상단 | 사건 목표·마력·필요한 시계 | 양측 결계·교환예산·상대 예고 |
| 중앙 장면 | 상호작용 대상과 현재 상태 | 상대·자기·예고된 공격·방패 대상 |
| 주문 구성 | 선택한 글자와 작용·대상·방향 | 동일 구성 영역 |
| 예상 결과 | 비용·시간·위험 변화·불확실성 | 피해·방어·조건·기간·소비 |
| 하단 선택 | 배운 글자 목록, 일반행동 | 손패, 대기, 정돈 |
| 최종 행동 | 시전 / 취소 | 시전 / 취소 |

중앙 장면에서 대상을 먼저 고르면 살펴보기만 수행하고 주문·시전은 자동 선택하지 않는다. 글자를 먼저 고르는 흐름도 동일 구성 상태에 합류한다. 주문 변경으로 기존 대상이 부적합해지면 대상 선택을 해제하고 이유를 표시한다. 선택한 글자는 유지한다.

탭/클릭만으로 완결 가능, 드래그는 선택적 보조다. 상세 열기와 선택·시전 입력을 분리한다. 시전은 유효한 대상·비용·최신 상태가 모두 있을 때만 활성화한다. 스크롤·빈 공간 터치로 마력이 소모되지 않는다.

상태 흐름: BROWSING → COMPOSING → TARGETING → READY → RESOLVING → RECEIPT → BROWSING 또는 STORY_RESULT. 취소는 READY까지 무소비, RESOLVING에서는 연출만 건너뛸 수 있다. 대상 먼저 관찰은 BROWSING 내부 동작이다. 상태 복귀는 저장된 command/result로 복원한다.

위험 표시는 원인·증가·완화·최종값을 분리한다. 색 외에 글자와 기호를 함께 사용한다. 긴 한국어는 핵심 작용 한 줄+펼쳐보기로 나누되 비용/대가를 펼쳐보기 뒤에 숨기지 않는다. 모바일 터치 크기와 세로 점유 비율은 실제 화면 검사 전 숫자로 확정하지 않는다.

### 15.4 도움과 이해 검증

힌트는 1) 대상 성질 확인 유도, 2) 관련 작용 설명, 3) 구체적인 한 접근 예시의 세 단계다. 자동 최적 조합 표시나 모든 대안의 우열 정렬은 하지 않는다. 안내 끄기/복습과 교수 도움은 별개다. 힌트 사용을 자원 벌금으로 처벌하지 않는다.

첫 검증 과제는 수업에서 이해한 작용을 다른 배치의 온실/축제에서 사용하고 결과를 설명하는 것이다. 통과율 숫자를 미리 발명하지 않는다. 관찰할 것은 선택 변경 이유, 예상과 실제 결과의 차이, 힌트 단계, 반복/중단 원인, 주문 의미를 다른 장면에서도 유지하는지다. 실제 모집·실행·Human 평가 NOT_RUN.

### 15.6 검토·작업 순서

설계 검토 스킬의 구조 설계 절차에 따라 기존 승인 방향 안에서 세부 기준을 작성했다. 새 runtime 구현은 이 변경에 포함하지 않는다. Base pin 유지, 열린 Draft PR read-only, 사용자 fixture 변경 보존.

5회 전체 범위 자체 검토: (1) 손패 열거를 패배 확률로 과장하지 않음, (2) 정돈은 같은 턴 무료 시전과 결합 금지, (3) 반복보상과 방어 플레이 분리, (4) 축제를 첫 세션/새 미니게임으로 압축하지 않음, (5) wireframe 문서를 실행·사람 UX 완료로 오인하지 않음. 각 회차에서 권위·의도·실제 소비처·저장/복구·자산/비용·증거 상한을 함께 확인했다. 독립 사람 검수는 아니다.

남은 순서: 학습/정돈을 포함한 입력 흐름 검토 → 새 규칙 버전의 구현 계획과 테스트 케이스 → 손패·장기전 시뮬레이션 → 필요한 화면/자산 명세 → 제작·Godot 통합 → runtime/사람 검증. 첫 손패70 열거만 실행했고 정돈 엔진·전체 결투 시뮬레이션은 NOT_RUN. 공용화는 반복 증거 전까지 프로젝트 교훈으로 유지한다.

### 16.3 현재 시험안의 약점과 채택 경계

상대 패턴/수치 표는 **BALANCE_REWORK_REQUIRED**다. 12절은 비교 기준이며 최종 채택값으로 구현하지 않는다. 이 교정은 새 강제 스탯·상성·장문 규칙을 추가하는 이유가 아니다. 현재 문서는 구현 가능한 일반 구조와 미검증 콘텐츠 수치를 구분한다.

### 16.4 후속 사건을 만드는 최소 계약

입문 이후 의미 있는 사건 하나에는 다음이 있어야 한다: 상황 문제, 보존할 가치, 두 가지 이상의 타당한 접근, 각 접근의 예고된 비용/대가, 해결 후 상태, 도움/중단 경로. 단순 일상 상호작용과 첫 조작 학습에는 이 복수 경로 조건을 강제하지 않는다.

테스트용 후속 상황 후보(기존 GREENHOUSE_LEAK_01을 조용히 교체하지 않음): 물질이 새는 장치를 즉시 정지하면 안전해지지만 진행 중인 시료 처리가 중단된다. 임시 차단으로 시간을 벌고 시료를 안전 용기에 옮긴 뒤 정지하면 마력/행동을 더 쓰되 시료를 보존한다. 손상이 되돌릴 수 없는 중요 서사라면 별도 결정이며, 첫 비교는 교체 가능한 실습 시료에 한정한다.

이 상황에서 선택지는 '좋음/나쁨' 버튼이 아니다. 시료 보존이라는 목표를 강제로 최고점으로 만들지 않으며, 위험이 높거나 마력이 부족한 상태에서는 즉시 정지가 합리적이다. 위험/자원/시료 상태를 바꾼 두 조건에서 선호 경로가 바뀌는지 검사한다. 단순 숫자 차이만 있고 결과 장면이 같으면 콘텐츠를 추가하지 않는다.

축제 후보는 안전 목표를 공통으로 두고 장식의 배치 방식에 표현 선택을 주는 것이다. 표현 선택은 새 전투 버프나 별도 미니게임을 요구하지 않는다. 아트·대사 소비처가 정의되기 전 분기 수를 늘리지 않는다.

### 16.5 나의 주문 기록과 인물 반응

기존 도감의 주문 기록에 첫 발견/최근 대표 사용 맥락을 연결한다. 별도 일기 시스템·자동 생성 문장·새 대시보드를 만들지 않는다. 기록 필드 후보는 spell_id, context_id, target_id, 결과 사실, 첫 발견 여부다. 표시 문장은 기획된 템플릿으로 만들며 사용 횟수 경쟁을 유도하지 않는다.

예시: '모으는 바람 — 온실에서 부유 꽃가루를 수집했다.' 이후 축제에서 다른 용도로 썼다면 같은 주문 항목에 새 맥락을 덧붙인다. 교수의 반응도 '훌륭하다' 반복보다 '원인을 막기 전에 확산부터 줄였구나'처럼 실제 순서/결과와 연결한다. 대사 예시는 초안이며 해당 인물의 확정 캐릭터성을 대신하지 않는다.

### 16.6 검증 계획과 범위 종료 기준

문서 검토만 무한히 반복하지 않는다. 현재 공통 작용·시전 경계·세 사건의 구조는 다음 구현 계획의 입력으로 충분하지만, 결투 최종 수치는 잠그지 않는다. 다음 작업은 새로운 기획 축 추가가 아니라 미검증 선택 가설을 확인할 검산/시뮬레이션 및 짧은 완성형 플레이 구간의 구현 계획이다.

| 검사 | 비교 과제 | 통과 판단 방식 | 상태 |
|---|---|---|---|
| 의미 일치 | 같은 주문을 수업/사건/결투에 적용 | 설명 불가능한 작용 변경 없음 | 문서 검사, runtime NOT_RUN |
| 선택 가치 | 연속 방패/강한 열/낮은 마력의 조건 비교 | 특정 조건에서만 장점이 생기는지, 불필요한 효과는 삭제 | NOT_RUN |
| 이해와 전이 | 안내 후 다른 배치의 사건을 독립 수행 | 조작 성공과 선택 이유 설명을 따로 관찰 | HUMAN_NOT_RUN |
| 차별화 체감 | 종료 후 기억나는 순간을 자유 응답 | 유도 없이 응용/학교생활 경험이 나오는지 | HUMAN_NOT_RUN |
| 불필요한 복잡성 | 도움 요청·오선택·취소·중단 관찰 | 새 용어가 판단에 기여하지 않으면 축소 | HUMAN_NOT_RUN |

성공 기준 숫자나 표본 규모는 빌드/테스터 조건을 정할 때 사전에 선언한다. 승률·클릭 수·긍정 답변만으로 재미 PASS 처리하지 않는다. 플레이어가 같은 최적 행동만 반복하면 새 카드부터 추가하지 않고 상황 목표/비용/정보/상대 패턴을 먼저 수정한다.

5회 자체 적대적 검토: (1) 기존 작품에 있는 조합을 독창성으로 과장하지 않음, (2) 복수 경로의 우월/열등 관계 인정, (3) 결투의 현재 억제/전문 방어 사장 조건 식별, (4) 기록/대사를 새 시스템 증식 없이 기존 소비처에 연결, (5) 가설·문서·시뮬레이션·사람 증거를 분리. 매회 정본/의도/consumer/저장/비용/자산/권리/완료 상한을 점검했다. 실제 코드 변경·이미지 생성·유료 도구·다른 PR 수정 없음. Base 승격은 반복 증거 전 보류한다.

## 17. 제한 산술 진단과 다음 구현 단위

2026-09-10 도구 내 JavaScript로 아래 9사례를 열거했다. `max(0, attack - guard)` 기반 산술 진단이며 기존 Godot 판정기를 실행한 것이 아니다. 손패 적법성, 드로우, 양측 생존, 초과 피해, 저장과 전체 승률은 제외한다. 16절 선택 가치 검사의 일부만 실행됐으며 전체 상태는 PARTIAL이다.

| 조건 | 비교 A | 비교 B | 산술 결과 |
|---|---|---|---|
| 열3 | 막기4 | 열 장막5 | 받는 피해 0 / 0 |
| 열4 | 막기4 | 열 장막5 | 0 / 0 |
| 열5 | 막기4 | 열 장막5 | 1 / 0 |
| 열6 | 막기4 | 열 장막5 | 2 / 1 |
| 차회 흐름방패0 | 불씨3, 억제 없음 | 불씨3, 억제3 | 주는 피해 3 / 3 |
| 차회 흐름방패3 | 불씨3, 억제 없음 | 불씨3, 억제3 | 0 / 3 |
| 방패0→3 | 모으기→불씨 | 불씨→불씨 | 총 주는 피해 1 / 3 |
| 방패3→0 | 모으기→불씨 | 불씨→불씨 | 4 / 3 |
| 방패0→0 | 모으기→불씨 | 불씨→불씨 | 4 / 6 |

모으기 비교는 두 경로 모두 적법한 카드가 있다는 가정이고 비용은 각각1+1, 교환 수2로 같다. 사용 글자 종류/남은 손패는 다르다. 2회 모두 생존하고 상대가 중간에 패배하지 않는 조건이다. 실제 현재 패턴의 열/방패3→고정파동/방패0 구간에서도 이 피해 차이를 시험할 이유는 생겼지만 매치 우세는 입증하지 않는다. 이미 모으기가 특정 조건에서 우세하므로 즉시 수치 상향은 하지 않는다.

판정: 전문 방어의 효용은 열5 이상에서 발생하지만 추가 카드 비용에 비례해 충분한지는 미검증. 연속 방패는 억제의 잠재 이득을 드러낼 비교용 조건이며 새 상대 패턴 채택이 아니다. 첫 온실은 쉬운 학습 경로를 유지한다. 축제의 비싼 동등 결과는 별도 추천 선택으로 강조하지 않는다. 불필요한 효과 삭제는 손패 포함 비교 뒤 결정한다.

외부 재조회: [Into the Breach 공식](https://subsetgames.com/itb.html)의 공격 예고를 ADAPT하여 알려진 현재 의도에서 선택을 비교한다. 미래 비공개 정보를 정책에 주지 않는다. [Blades 공식 시계](https://bladesinthedark.com/progress-clocks)의 장애물 중심 원칙을 ADAPT하여 온실 목표를 특정 주문 사용 횟수로 바꾸지 않는다. 자료는 위 수치의 타당성이나 재미를 증명하지 않는다.

다음 단위는 [독립 진단 구현 계획](../plans/2026-09-10-spell-balance-diagnostic.md)이다. 제품의 `src/core/card_duel/duel_rules.gd`는 구 수치/효과이며 이 문서와 다르므로 현재 제품 테스트 PASS를 새 규칙 PASS로 인용하지 않는다. 구현 가능성 PARTIAL: 순수 계산 경계는 있으나 새 의미/지속 상태는 별도 시험이 필요하다. 이번 변경은 문서뿐이다.

5회 자체 전체 범위 검토에서 각각 손패 가정, 조기 종료 제외, 미래정보 누출, 비교 패턴의 비승인 상태, 문서/제품 증거 혼동을 공격했다. 각 회차 공통으로 사용자 범위·정본·consumer·저장/롤백·비용/권리·검증 상한을 확인했다. 사용자 fixture와 열린4 Draft PR은 보존, Base pin 유지, Base 승격 없음. main 미병합이므로 post-merge readback은 NOT_RUN이다.
