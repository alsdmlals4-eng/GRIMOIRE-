## 1. 목적

플레이어가 `글자를 획득한다 → 회로로 주문을 설계한다 → 상황의 대상에 주문을 사용한다`는 세 책임을 혼동하지 않도록 주문 경험을 3개 화면으로 분리한다.

핵심 재미는 문양 인식 자체가 아니라 다음 인과를 이해하고 책임지는 데 있다.

```text
상황·위험 관찰
→ 필요한 의미 판단
→ 글자 획득·출처 선택
→ FIVE_POINT_STAR 회로 설계
→ 주문 Preview
→ 주문 확정
→ 대상 선택
→ 상세 예상 결과
→ 주문 사용
→ 결과·대가·복기
```

## 2. 범위와 비범위

### 포함

- 1단계 `글자 그리기`
- 2단계 `회로 배치`
- 3단계 `주문 사용`
- 공통 `사건 상태`와 상황 설명 Overlay
- 핵심 글자·보조 글자 역할 구분
- 보관함·스톡 준비 규칙
- 단계별 Preview·비용·대상 표시 책임
- Godot 컴포넌트 경계와 TDD 수용 조건

### 제외

- 최종 밸런스 수치 확정
- 새 인식 알고리즘 또는 7종 이상 Runtime 확장
- 최종 캐릭터·배경·VFX 제작
- 실제 Android/iOS·Screen Reader·사람 검증 완료 주장
- PR #77의 공용 UI Kit 구현을 이 문서에서 재구현

## 3. 공통 경험 계약

모든 화면은 플레이어에게 한 개의 중심 질문만 준다.

| 단계 | 중심 질문 | 완료 행동 |
|---|---|---|
| 글자 그리기 | 이 글자를 올바르게 완성해 획득할 수 있는가? | 보관함 저장 |
| 회로 배치 | 가진 글자로 어떤 주문을 설계할 것인가? | 주문 확정 |
| 주문 사용 | 완성된 주문을 어디에 사용하고 어떤 결과를 감수할 것인가? | 주문 사용 |

공통 상단 자원은 금화만 표시한다. 캐릭터 패널의 MP는 현재 보유 마나이며, 주문 비용은 해당 단계의 예상 비용 영역에만 표시한다. 보라색 보석·프리미엄 재화·복수 주문 비용은 사용하지 않는다.

### 자원 소비 시점

```text
1단계 보관함 저장
→ 새 글자를 Vault에 추가

2단계 주문 확정
→ 예약된 보관함·스톡 글자를 exactly-once 소비
→ 완성 주문을 생성
→ 마나는 소비하지 않음

3단계 주문 사용
→ 선택 대상 기준 최종 마나를 exactly-once 소비
→ 판정과 결과를 exactly-once 적용
```

주문 설계와 주문 사용을 분리하므로 현재 Runtime의 `대상 선택 뒤 Commit`과 `모든 Commit에서 마나 소비` 흐름은 이 결정으로 대체한다.

## 4. 사건 상태와 상황 설명 Overlay

`사건 상태` 기본 카드는 다음만 상시 표시한다.

- 위험도
- 현재 현상 한 줄
- 남은 시간 또는 긴급도
- `터치 시 상황 설명` 힌트

카드를 누르면 현재 화면 위에 상황 설명 Overlay가 열린다.

### Overlay 정보 순서

1. 무슨 일이 발생했는가
2. 현재 위험은 무엇인가
3. 어떤 해결 방향이 필요한가
4. 관찰된 키워드는 무엇인가

### 정답 노출 금지

상황 설명은 해결 목표를 알려주되 정확한 글자 조합을 지시하지 않는다.

```text
허용: 열을 분산하고 내부 압력을 안정화해야 한다.
금지: 열 + 흐름 + 분산 글자를 배치하라.
```

Overlay를 닫으면 현재 단계·선택·임시 예약·포커스를 그대로 복원한다.

## 5. 글자 역할 정본

### 핵심 글자 5종

핵심 글자는 주문의 주된 작용을 정하며 회로 중앙 Main 슬롯에 정확히 1개만 배치한다.

| ID | 이름 | 작용 |
|---|---|---|
| `HEAT` | 열 | 열 발생·전달 |
| `FLOW` | 흐름 | 에너지·물질의 이동과 방향 전환 |
| `PROTECT` | 보호 | 보호막·피해 완화 |
| `COOL` | 냉각 | 열 제거·과열 진정 |
| `MEND` | 수복 | 균열·파손·구조 손상 회복 |

### 보조 글자 5종

보조 글자는 외곽 Auxiliary 슬롯에서 핵심 효과의 방식·강도·범위·지속·안정성을 바꾼다.

| ID | 이름 | 작용 |
|---|---|---|
| `FOCUS` | 집중 | 범위를 좁히고 정밀도·성공률 보정 |
| `DISPERSE` | 분산 | 효과 범위 확장·국소 강도 완화 |
| `STABILIZE` | 안정 | 실패 편차·역류 위험 감소 |
| `SUSTAIN` | 지속 | 지속시간 증가·추가 마나 비용 |
| `AMPLIFY` | 증폭 | 출력 증가·마나와 위험 증가 |

기존 `BURST`는 별도 기본 글자가 아니라 `AMPLIFY`의 고위험 과부하 상태 또는 강화형으로 해석한다.

## 6. 보관함·스톡 계약

```yaml
vault_prepared_count: 1_to_5
stock_prepared_count: equals_vault_prepared_count
maximum_each: 5
initial_tutorial_recommendation: 3_and_3
standard_incident_recommendation: 5_and_5
```

보관함은 직접 그려 획득한 글자, 스톡은 사건·시스템이 제공한 Typed Glyph 자원이다. 같은 글자가 양쪽에 존재할 수 있으며 출처·필기 품질·수량을 분리 보존한다.

현재 배관 균열 사건의 5 대 5 준비 예시는 다음과 같다.

| 출처 | 핵심 | 보조 |
|---|---|---|
| 보관함 5 | 열, 흐름, 보호 | 집중, 분산 |
| 스톡 5 | 냉각, 수복 | 안정, 지속, 증폭 |

각 글자 카드는 문양, 이름, 핵심/보조 배지, 출처, 남은 수량, 필기 품질 또는 숙련도, 배치/예약 상태를 제공한다. 색상만으로 출처나 역할을 구분하지 않는다.

## 7. 1단계 — 글자 그리기

### 중심 질문

`지정된 글자를 완성하고 획득할 수 있는가?`

### 화면 구조

- 좌측: 캐릭터 상태, 사건 상태, 이번 글자·진행도, 사용 가능한 보관함 글자 최대 5개
- 중앙: 직접 필기 Canvas, 가이드 경로, 획 체크포인트, 현재 Stroke
- 우측: 글자 정보, 필기 판정, 획득 결과
- 하단: 지우기, 다시 그리기, 보관함 저장

### 데이터 흐름

```text
Stroke 입력
→ Recognition Adapter 판정
→ 필기 완성도·형태·인식 가능 상태
→ 사용자 저장 확인
→ Exact Glyph Vault에 exactly-once 추가
```

저장 확인 전에는 보관함 수량을 변경하지 않는다. 인식 실패·취소·화면 중단은 저장 0건이며 현재 상황과 재시도 맥락을 보존한다.

## 8. 2단계 — 회로 배치

### 중심 질문

`보관함과 스톡의 글자로 어떤 주문을 설계할 것인가?`

### 화면 구조

- 좌측: 캐릭터 상태, 사건 상태, `보관함 N`, `스톡 N`
- 각 출처 내부: 핵심 글자와 보조 글자를 한 화면에 구분 표시
- 중앙: 중앙 Main 1개와 외곽 Auxiliary 0~5개의 FIVE_POINT_STAR 회로
- 우측: 상황 설명, 연관 키워드, 주문 미리보기
- 하단: 미리보기, 주문 확정, 초기화, 되돌리기

### 단계 책임

- 대상 선택은 존재하지 않는다.
- 연관 키워드는 설계 참고 정보이며 실행 대상 버튼이 아니다.
- Preview에는 주문 이름, 효과 요약, **대상 미적용 기본 성공률**, 예상 마나를 표시한다.
- 마나는 `예상 비용: 마나 N`으로 한 번만 표시하되 이 단계에서는 소비하지 않는다.
- 회로 배치는 자원을 소비하지 않고 출처별 예약만 만든다.
- 초기화·되돌리기·취소는 예약을 원래 출처로 완전히 복구한다.
- 주문 확정은 예약된 글자만 exactly-once 소비하고 완성 주문을 만든다.

### 성공률 구분

2단계 성공률은 글자 숙련·회로 복잡도·보조 구성만 반영한 `BASE_SPELL_SUCCESS`다. 대상 난도·상황 상태·환경 저항은 반영하지 않는다.

## 9. 3단계 — 주문 사용

### 중심 질문

`완성된 주문을 어느 대상에 사용하고 어떤 결과를 감수할 것인가?`

### 화면 구조

- 좌측: 캐릭터 상태, 사건 상태, 완성된 주문 목록과 준비 슬롯
- 중앙: 상황 장면과 선택 가능한 대상 노드
- 우측: 주문 효과, 대상 선택, 상세 예상 결과
- 하단: 상세 예측, 다른 대상 보기, 주문 사용, 취소

### 단계 책임

- 직접 대상 선택은 이 단계에만 존재한다.
- 대상 변경 시 예상 결과와 위험을 다시 계산한다.
- 상세 예상 결과는 **대상 적용 최종 성공률**, 주요 효과, 가능한 위험, 최종 예상 비용을 제공한다.
- 마나는 `예상 비용: 마나 N`으로 한 번만 표시한다.
- 주문 사용 시점에만 최종 마나를 exactly-once 소비한다.
- 주문 사용은 선택된 대상에 결과를 exactly-once 적용한다.
- 숨은 대상 변경·숨은 추가 마나·중복 결과 적용을 금지한다.

### 성공률 구분

3단계 성공률은 `BASE_SPELL_SUCCESS`에 대상 난도·상황 상태·환경 저항을 적용한 `FINAL_TARGET_SUCCESS`다. 2단계보다 같거나 낮을 수 있으며 변화 이유를 Breakdown으로 설명한다.

## 12. 오류와 복구

| 오류 | 복구 계약 |
|---|---|
| 인식 실패 | 저장 없이 재시도, 사건 맥락 유지 |
| 보관함 가득 참 | 저장 차단 이유와 정리 경로 제공 |
| 출처 수량 부족 | 해당 카드·슬롯 원인 표시, 대체 글자 자동 사용 금지 |
| 회로 무효 | 원인 슬롯 표시, 예약 유지 또는 명시 취소 |
| 주문 확정 중 실패 | 글자 소비·완성 주문 생성 모두 0 또는 모두 성공 |
| 마나 부족 | 3단계 사용 차단, 완성 주문·대상 선택 유지 |
| Overlay 중단 | 원래 단계와 포커스 복귀 |
| 연타·중복 입력 | 저장·글자 소비·마나 소비·결과 exactly-once |

## 13. TDD 수용 계약

구현은 다음 RED 계약부터 시작한다.

1. 사건 상태를 누르면 상황 설명 Overlay가 열린다.
2. Overlay 종료 후 현재 단계·선택·예약·포커스가 유지된다.
3. 보관함 준비 수와 스톡 준비 수는 항상 같다.
4. 각 출처의 준비 글자는 5개를 초과하지 않는다.
5. 모든 글자는 핵심 또는 보조 역할을 정확히 하나 가진다.
6. 1단계 저장 확인 전에는 보관함이 변하지 않는다.
7. 2단계 배치는 자원을 예약하지만 소비하지 않는다.
8. 초기화·되돌리기는 예약을 완전히 복구한다.
9. 주문 확정은 예약된 글자만 정확히 한 번 소비하고 마나는 소비하지 않는다.
10. 2단계에는 대상 선택 컨트롤이 없다.
11. 2단계 성공률은 대상 난도를 포함하지 않는다.
12. 3단계에서만 대상 선택이 가능하다.
13. 3단계 성공률은 대상·상황 보정을 포함하고 이유를 설명한다.
14. 마나는 3단계 주문 사용에서만 정확히 한 번 소비된다.
15. 단계별 예상 비용 마나는 화면에 한 번만 표시된다.
16. 보라색 보석·프리미엄 재화 계약이 없다.
17. 주문 사용은 선택된 대상에 정확히 한 번 적용된다.
18. Reduced Motion에서도 정보·입력·결과가 동일하다.
19. 1280×720·Text130%·48dp 계약을 만족한다.
20. 자동 렌더 PASS를 사람·기기 PASS로 승격하지 않는다.

## 14. 대체 관계

`GM-STAR-CIRCUIT-MASTERY-BALANCE-01`의 다음 부분은 보존한다.

- FIVE_POINT_STAR
- Main 1개·Auxiliary 0~5개
- 글자별 숙련도
- 회로 복잡도 기반 성공률·마나 계산
- Typed Glyph Stock
- 명시 Preview와 exactly-once
