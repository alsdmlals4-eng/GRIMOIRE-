마법학교에서 배운 글자를 조합하고, 같은 주문으로 결투와 일상의 문제를 다르게 풀어낸다.

이 책은 사용자 확정 방향과 권장 상세 설계를 구분한다. 새 그림은 실제 게임의 독립 레이어로 사용할 후보이며 게임 촬영이 아니다. 최종 승인 후 구현을 시작할 설계 묶음이다. 균형·기기·사람 검수는 실제 빌드에서 확인한다.

# 01. 화면 아틀라스 | 학교에서 보낼 시간
@atlas

읽는 순서: 메인과 입학 → 대화와 수업 → 주문 조합 → 연습 결투 → 온실 실습 → 복기 → 축제 준비.

아틀라스의 배경·인물은 자산 후보다. 버튼·글자·시계·선택 테두리는 별도 UI로 구현한다. 새로운 화면의 runtime 촬영은 아직 없다. 배경을 완성 화면으로 오인하지 않도록 상세 화면에는 구조도를 붙였다.

# 02. 이 책의 범위와 승인 방법
| 구분 | 이번 책에서 다루는 내용 | 승인 이후 |
|---|---|---|
| 확정 방향 | 학생 주체, 카드 형태의 글자 조합, 이야기 진행, 사건·결투 공통 작용 | 유지하며 구현 |
| 권장 상세 | 첫 학교생활 구간, 입력·저장 계약, 초기 수치, 대사·상대 행동 | 승인하면 구현 기준 |
| 자산 후보 | 독립 배경, 학생·교수 초상, 글자 그림, 프레임·오브젝트 | 외형 승인 후 정본 등록·연결 |
| 미검증 | 전체 균형, 터치 가독성, 기기 성능, 청감, 출시 적합성 | 테스트로 판단; 문서로 PASS 불가 |

전 게임은 장기 학교생활이다. 첫 제작 구간은 입학부터 축제 준비·마무리까지의 한 학교생활 장이다. 온실 한 사건을 전체 게임으로 축소하지 않는다. 후속 학기는 아래 확장 계약을 따르며 장편 전체의 대사·모든 미래 자산을 이미 제작했다고 주장하지 않는다.

수정 요청은 장 제목과 항목을 말하면 된다. 예: '결투의 모으기를 더 직관적으로', '축제 준비의 일반행동을 늘리기'. 승인 범위는 이 책에 명시된 첫 구현 구간이며 자동 배포·유료 서비스 가입·역사 파일 삭제는 포함하지 않는다.

# 03. 핵심 경험과 하지 않을 것
| 경험 | 플레이어가 하는 일 | 보여 줄 증거 |
|---|---|---|
| 이해했다 | 대상 성질과 주문의 작용을 비교 | 왜 가능/불가능한지 한 문장 |
| 응용했다 | 수업에서 배운 작용을 다른 사건에 사용 | 같은 주문 이름, 달라진 대상과 결과 |
| 판단했다 | 비용·위험·보존 중 우선순위를 정함 | 결과와 대가를 나란히 제시 |
| 학생으로 성장했다 | 도움을 받던 일을 스스로 처리 | 구체적인 교수·동료 반응과 도감 기록 |

제외: 직접 필기 인식, 별형 회로, 마법사 소환 카드, 체스, 실시간 SD 이동, 무제한 자연어 주문, 모든 대화를 카드 전투로 전환, 반복 시전 경험치 농사.

차별화는 '카드를 사용한다'가 아니다. 같은 작용을 배움→연습→현장→공연에 재사용한 기억이 남는지가 핵심 가설이다. 시장 최초나 성공을 보증하지 않는다.

강점은 현재 문서 구조에서 확인한 잠재력이다. 사람의 재미가 입증된 것은 아니다. 초반에는 세계관 설명보다 대상 변화 하나를 먼저 체험하게 한다. 어려운 용어로 학생의 숙련을 표현하지 않는다.

| 학생 그림의 실제 투명도 문제 이력 | 알파 수치·밝고 어두운 바탕 경계 검사 | P0 / 자산 | alpha와 체크무늬 구분, 화면에서 사각 배경 없음 |
| 모바일에서 손패·대상·설명을 동시에 읽기 어려움 | 하단 1열 선택, 상세는 한 영역, 터치 우선 | P1 / UI | 작은 화면에서 글자 잘림·오입력 관찰 |

P0는 구현 착수 또는 통합을 막는 문제, P1은 짧은 완성형 구간에서 검증할 품질 항목이다. 그림 수·문서 쪽수로 해결률을 계산하지 않는다.

# 10. 학교생활의 큰 흐름
@flow 새게임|입학과 만남|안전한 수업|연습 결투|첫 실습|복기와 교류|후속 과제|축제 준비|장 마무리

이어하기는 저장된 story_node와 진행 중 사건을 그대로 복원한다. 메인에서 수업/실습/결투/축제를 모드처럼 고르지 않는다. 완료한 연습은 도감의 연습 메뉴에서 재방문하되 이야기 보상을 다시 받지 않는다.

장기 확장: 다음 학교생활 장도 수업→낯선 적용→인물과의 조정→행사/평가→새 과제의 구조를 사용한다. 학기 수·졸업까지 플레이 시간·엔딩 개수는 첫 장 검증 전 수량 약속을 하지 않는다. 초반부터 장편 결말을 특정 온실 사고로 고정하지 않는다.

| 3 | 사건 엔진 | 효과→시간→목표/위험 동시 판정 | 세 사건+후속 시료 상태 검사 |
| 4 | 이야기·저장 | 패배/도움/중단도 다음 노드, 중복 지급 | 새게임부터 장 종료 자동 순회 |
| 5 | 공통 화면·자산 | 탭만으로 시전/취소, 이미지 상태 연결 | Godot 실행 캡처·입력 검사 |

| 7 | 최종 통합 | 실제 장면·데이터·설명 일치 | 정확한 revision CI·runtime·사람 검수 |

게임 코드는 최종 승인 이후 변경한다. 구현자는 현재 checkout·열린 PR·실제 consumer를 재확인한다. 현재 브랜치의 문서/자산이 main에 자동 병합됐다고 가정하지 않는다.

# 35. 검증 사례와 재미 관찰
| 검증 묶음 | 필수 사례 | 증거 상한 |
|---|---|---|
| 의미 | 같은 주문의 사건/결투 작용, 없는 대상·포화 목적지 | 자동 검사 |
| 원자성 | 연타·동일 명령·오래된 preview·저장 실패 | 자동/오류주입 |
| 균형 | 70 초기 손패, 강열/연속방패, 방어 반복, 정돈 | 시뮬레이션; 재미 아님 |
| 사건 | 마력0, 위험5, 목표+위험 동시, 이미 해결한 대상 | 자동 상태 검사 |
| 학교생활 | 승/패/도움/중단 후 장 종료, 재연습 보상0 | story/runtime |
| 사람 | 이유 설명, 다른 상황에 응용, 기억나는 순간 | 동의한 플레이테스트 |
| 기기 | 작은 화면·큰 글자·중단/재개·성능·청감 | 실제 기기 |

첫 사람 검수는 장르 경험이 다른 5명 내외의 형성적 관찰을 권장한다. 모집 전 동의·기록 범위를 정하고 대표성/통계적 검증이라고 주장하지 않는다. 첫 수업과 다른 배치의 과제를 제시하고 '왜 그 주문인가'를 묻는다. 긍정 답변이나 승률만으로 재미 PASS를 붙이지 않는다.

# 36. 변경·유지·폐기와 승인 체크
| 대상 | 처리 | 이유·기대효과 |
|---|---|---|
| 그리기·별형·체스·마법사 카드 | 신규 흐름에서 제외 | 최신 사용자 방향 일치 |
| 학교생활·이야기·도감·상반신 | 유지·구체화 | 배움과 응용의 맥락 |
| 온실 | 첫 실습으로 유지 | 메인 줄거리 과대 확대 방지 |
| 새 수치 | 시험 기준, 검증 후 조정 | 문서 균형 확정의 오류 방지 |
| 오래된 파일·저장·미병합 PR | 보존, 참조 확인 후 별도 정리 | 사용자 작업과 복구 가능성 보호 |
| 불필요한 보조 대시보드 | 만들지 않음 | 원본·PDF·자산 manifest만 연결 |

최종 검토 질문: 첫 장의 범위와 순서가 맞는가? 공통 주문이 생활과 결투에서 같은 의미인가? 학생 외형과 화면 분위기가 맞는가? 도움·실패도 이야기로 이어지는가?

승인하면 위 구현 순서를 시작한다. 승인 전 이미지 후보는 정본 승격하지 않는다. 상세 수치의 플레이테스트 조정은 허용하되 코어 의미 변경은 별도 결정이다. 출시·유료 도구·외부 배포는 이 승인과 다르다.
