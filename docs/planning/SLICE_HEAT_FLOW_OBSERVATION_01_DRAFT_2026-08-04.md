## 1. 권장 문법 정리

```yaml
main_glyph: 열
known_connection_grammar: 흐름
optional_support_glyphs:
  - 집중
  - 분산
representative_known_circuit: 열 + 흐름
```

- `열`: 세계에 열 현상을 발생시키는 메인 글자다.
- `흐름`: 발생한 열을 대상과 경로를 따라 이동·순환시키는 연결 문법이다.
- `집중`: 열을 좁은 지점·경로에 모은다.
- `분산`: 열을 여러 대상·넓은 구역에 나눈다.
- `흐름`은 두 번째 메인 글자가 아니다.
- `열 + 흐름`은 하나의 메인 글자와 알려진 경로 문법으로 성립한다.

이 구조는 `메인 글자 1개 + 보조 글자` 상위 문법을 유지하면서 사용자가 요청한 `열+흐름 회로`를 표현한다.

---

## 2. 카시안의 사고

카시안은 1학년 실습에서 결빙된 보조 배관을 빠르게 해빙하려고 `열 + 흐름`을 사용한다.

```text
열 발생
→ 닫힌 보조 배관 안으로 빠르게 전달
→ 출구가 닫힌 상태에서 내부 온도와 압력 급상승
→ 배관 균열
→ 냉기 마력 누출
→ 중심 핵 안전 정지
→ 서리 정령 과부하
→ 자동 격벽 폐쇄와 카시안 고립
```

카시안의 실패는 글자를 잘못 쓴 입력 실패가 아니다.

```yaml
failure_type: SITUATION_DESIGN_FAILURE
missed_conditions:
  - 출구가 열려 있는가
  - 배관 내부 압력이 안전한가
  - 열이 도착한 뒤 빠져나갈 경로가 있는가
```

카시안은 사고를 숨기지 않고 내부 밸브·압력계·균열 위치를 전달하며 해결에 협력한다.

## 3. 교수의 외곽 안전 회로

에일린 교수는 온실 내부 사건을 해결하지 않는다. 학교 회랑으로 번지기 시작한 냉기만 외곽 안전 회로로 막는다.

### 회로 구성

```yaml
recognizable_parts:
  - 열
  - 흐름 경로
unknown_advanced_parts:
  - 경로 고정
  - 자동 온도 보정
  - 외곽 안전막 결합
objective: STOP_EXTERNAL_SPREAD_ONLY
```

교수는 온실 외벽의 한 지점에 `열`을 발생시키고, 그 열을 유리벽 전체를 따라 닫힌 고리로 흐르게 한다.

### 관찰되는 효과

```text
호박색 열이 회로를 따라 이동
→ 지나간 유리의 서리가 선형으로 녹음
→ 외부로 뻗던 냉기 안개가 따뜻한 경계에서 휘어짐
→ 냉기 진행 방향이 온실 안쪽과 완충 홈으로 되돌아감
→ 학교 회랑의 확산 위험 표시가 CONTAINED로 변경
```

해결되지 않는 것:

- 중심 핵 정지
- 내부 배관 과압과 균열
- 카시안 고립
- 서리 정령 과부하
- 희귀 묘목 동결

---

## 4. 말이 아닌 인식 방식

교수는 회로 이름이나 사용법을 설명하지 않는다.

허용 대사:

- `외부 확산은 막았다.`
- `내부 문제는 그대로다.`
- L2·L3 안전 경고

금지 대사:

- `열과 흐름을 사용해라.`
- `내 회로를 따라 그려라.`
- `배관을 이렇게 데우면 된다.`
- 정확한 출발점·목표·보조 글자 지시

### 플레이어 인식 3단계

#### 1. 회로 판독

플레이어가 배운 부분만 짧게 강조된다.

```text
[인식: 열]
[인식: 흐름 경로]
[미해독: 고정·자동 보정 구조]
```

#### 2. 인과 연출

- 열의 광점이 경로를 따라 실제로 이동한다.
- 열이 도착한 지점부터 서리가 녹는다.
- 냉기 안개가 따뜻한 경계에 닿아 방향을 바꾼다.
- 정지 화면 설명보다 순서가 보이는 애니메이션을 우선한다.

#### 3. 상태 변화 비교

```yaml
before:
  external_spread: RISING
  internal_pressure: CRITICAL
  greenhouse_core: STOPPED
after:
  external_spread: CONTAINED
  internal_pressure: CRITICAL
  greenhouse_core: STOPPED
```

플레이어는 `교수가 모든 것을 해결하지 않았다`는 사실과 `열을 흐르게 하여 한 문제만 해결했다`는 사실을 동시에 본다.

## 5. 선택형 관찰 기록

회로를 다시 살피면 행동 횟수와 실시간 시간을 소모하지 않는 관찰 카드가 열린다.

```text
알아본 부분
- 열이 회로 시작점에서 발생했다.
- 발생한 열이 유리벽을 따라 이동했다.
- 열이 지나간 곳부터 서리가 녹았다.

추론
- 열은 발생 지점에만 머물지 않는다.
- 흐름 경로가 있으면 원하는 곳까지 운반할 수 있다.
- 닫힌 출구에 열을 밀어 넣으면 카시안의 사고처럼 압력이 쌓일 수 있다.

알 수 없는 부분
- 모서리의 고정 회로
- 자동 온도·압력 보정
```

`복사`, `정답 적용`, `교수 회로 사용` 버튼은 제공하지 않는다.

---

## 6. 사건 플레이에 주는 방향

교수의 시연은 다음 가능성을 암시한다.

- 열을 얼어붙은 밸브까지 운반한다.
- 따뜻한 공기를 카시안의 탈출 경로로 보낸다.
- 열을 묘목과 카시안에게 나누어 생존 시간을 번다.
- 배관 표면을 순서대로 데워 열팽창 충격을 줄인다.
- 따뜻한 경계를 만들어 정령을 작업 구역에서 밀어낸다.

그러나 다음은 알려주지 않는다.

- 무엇을 먼저 구할지
- 어느 열원을 사용할지
- 어떤 경로가 열려 있는지
- 집중·분산을 쓸지
- 시설·묘목·정령 중 무엇을 포기할지

---

## 7. 적대적 검토

### 위험 A — 교수의 시연이 정답 공개가 됨

대응:

- 교수의 목표는 외부 확산 차단뿐이다.
- 플레이어의 목표는 내부 압력·구조·정령·묘목 중 우선순위를 정하는 것이다.
- 교수 회로에는 아직 배우지 않은 안전 부품이 포함된다.
- 플레이어는 원리만 인식하고 회로 전체는 복제할 수 없다.

### 위험 B — 열이 모든 루트의 만능 정답이 됨

대응:

- 열은 냉기를 삭제하지 않는다.
- 과도한 열은 배관 파열·묘목 손상·정령 적대·산소 흐름 변화를 만든다.
- 경로와 출구를 확인하지 않으면 카시안의 사고가 반복된다.
- 구조·봉쇄·교섭은 열의 양보다 대상·순서·대가 판단으로 차별화한다.

### 위험 C — 교수는 설명하지 않는데 시스템 문구가 대신 정답을 말함

대응:

- 관찰 카드는 사실과 인과만 기록한다.
- 추천 조합·성공률·최종 결말을 표시하지 않는다.
- `가능성`은 환경 대상 목록으로만 제시하고 자동 주문은 만들지 않는다.

### 위험 D — 기존 정본과 충돌

대응:

- 이 문서를 Draft로 유지한다.
- 승인 시 `흐름 메인` Slice 계약을 명시적으로 supersede한다.
- 전체 게임의 다계열 구조는 유지하고 Slice 대표 메인만 `열`로 보정한다.
