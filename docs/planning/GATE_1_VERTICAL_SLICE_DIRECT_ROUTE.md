# 스펠 Gate 1 — CORE_POC 없는 직접 Vertical Slice 경로

## 문서 상태

- 프로젝트: `스펠` (임시)
- 제품 단계: `CONCEPT_APPROVAL`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- Work Mode: `PLAN`
- 결정 ID: `GM-VS-ROUTE-01`
- 상태: `DIRECT_VERTICAL_SLICE_ROUTE_CONFIRMED_FOR_GATE_1`
- 사용자 결정: 2026-07-27, `COREPOC 없이 우리는 버티칼슬라이스로 갈거야`
- CORE_POC: `REMOVED_BY_USER_DECISION`
- CORE_POC 검증 책임: `ABSORBED_INTO_VERTICAL_SLICE`
- Vertical Slice 계약: `NOT_AUTHORED`
- Vertical Slice 구현: `NOT_STARTED`
- Gate 1 전체: `UNVERIFIED`

이 문서는 스펠이 독립적인 CORE_POC 산출물을 만들지 않고, 검증 책임을 포함한 Vertical Slice로 직접 이동하는 제품 경로를 책임진다.

> **스펠은 별도 CORE_POC를 제작하지 않는다. 직접 작성·의미 기반 조합·상황 반응·소환수 지원의 핵심 가설은 외부 플레이 가능한 Vertical Slice 안에서 검증한다.**

---

## 1. 최신 사용자 override

기존 경로:

```text
Gate 1 승인
→ CORE_POC 계약
→ CORE_POC 구현·검증
→ 결과 기반 재조정
→ Vertical Slice
```

최신 확정 경로:

```text
Gate 1 콘셉트 정리
→ Vertical Slice 계약 승인
→ 적대적 범위 검토
→ 사용자 Gate 1 승인
→ VERTICAL_SLICE_FULL_PROFILE 전환
→ Codex read-only Plan 검수
→ Validation-First Vertical Slice 구현
→ QA·외부 플레이테스트
→ Gate 3 판단
```

기존 `GM-POC-01`, `CORE_POC 계약 승인`, `CORE_POC 선행 구현` 요구는 `SUPERSEDED_BY_GM-VS-ROUTE-01`이다.

---

## 2. 제거되는 것과 유지되는 것

### 제거

- 별도 `CORE_POC` 문서와 구현 산출물
- POC 완료 후 다시 Vertical Slice 범위를 설계하는 이중 기획
- POC 전용 Scene·UI·데이터를 만든 뒤 폐기하는 중복 작업
- `CORE_POC 통과`를 Gate 2 진입 조건으로 사용하는 규칙

### 유지

- 직접 작성의 터치 손맛 검증
- 입력 실패와 설계 실패의 분리
- 완전 정지·감속·실시간 표현 비교
- 같은 메인 글자의 전투·환경 재사용
- 복수 유효 해법과 실패 원인 재설계
- 메인 동반 소환수와 전투 보조 소환수 역할 구분
- 모바일 화면 가림·인지 부하·성능·저장·복귀 검증

검증을 제거하는 것이 아니라 **검증 위치를 Vertical Slice 내부로 이동**한다.

---

## 3. Validation-First Vertical Slice 원칙

Vertical Slice는 완성된 콘텐츠를 먼저 늘리는 단계가 아니다. 다음 순서로 진행한다.

```text
핵심 인과를 실제 플레이로 연결
→ 첫 내부 검증 빌드
→ 실패 가설 수정
→ 최종 방향에 가까운 아트·UI·사운드 통합
→ 외부 플레이 가능한 Slice
```

내부 검증 빌드는 Vertical Slice 구현 과정의 체크포인트이며 별도 CORE_POC 제품 단계나 독립 산출물로 명명하지 않는다.

### 비타협 검증 인과

```text
상황 관찰
→ 메인·보조 글자 선택
→ 직접 작성
→ 적·환경의 설명 가능한 변화
→ 성공 또는 실패 원인 확인
→ 주문 재설계
→ 새 활용 기록
```

이 인과를 증명하지 못하면 Slice의 콘텐츠·연출·관계 분량을 확대하지 않는다.

## 4. 권장 Vertical Slice 후보

### `첫 현장실습 완결형` — 권장

```text
학교 도착·짧은 수업
→ 메인 글자 1개와 보조 글자 2개 학습
→ 교내 연습에서 결과 차이 확인
→ 메인 동반 소환수와 짧은 일상·준비 장면
→ 첫 현장실습 진입
→ 전투 문제 1개
→ 환경·구조 문제 1개
→ 새로운 활용 발견
→ 복귀·마도서 기록
```

이 후보는 승인된 플레이어 약속, 세일즈포인트 3개, 게임플레이 Loop, 경험 곡선, 2계층 소환수 구조를 한 번에 보여준다.

### 반드시 포함할 증거

- 직접 글자 작성과 즉각적 발현
- 같은 메인 글자에 보조를 바꾼 결과 비교
- 전투와 환경에서 동일 문법 재사용
- 최소 2개의 유효 해결법
- 입력 실패와 설계 실패의 다른 피드백
- 메인 동반 소환수의 학습·기록 연결
- 전투 보조 소환수의 수호 또는 견제
- 보조 소환수 유무에 따른 작성 시간·피격 변화
- 저장·중단·복귀 지점
- Android 실제 기기 플레이

## 5. 초기 포함·제외 경계

### 포함 후보

- 메인 글자 1개
- 보조 글자 2개

- 현장실습 구역 1개

- 메인 동반 소환수 1체
- 수호 또는 견제형 전투 보조 소환수 1체
- 최종 방향에 가까운 핵심 UI·아트·사운드

### 초기 제외

- 3년·6학기 전체
- 다수 학교 지역과 도시 생활
- 대규모 관계 분기
- 다수 보조 소환수 편성과 희귀도 경제
- 완성 주문 스톡
- 복잡한 소환수 충전·용량 관리
- 다중 상태이상과 광범위한 조합표
- 고정밀 자유 손글씨 인식
- 온라인·협동·풀보이스

## 6. 통과 기준

Vertical Slice는 단순 실행 가능만으로 통과하지 않는다.

### 핵심 재미

- 플레이어가 첫 5분 안에 `내가 마법을 썼다`고 인식한다.
- 메인 글자와 보조 글자의 역할 차이를 설명할 수 있다.
- 최소 두 가지 해결법 중 하나를 의도적으로 선택한다.
- 실패 원인을 이해하고 주문을 재설계한다.

### 모바일 UX

- 손가락 가림과 반복 피로가 핵심 행동을 방해하지 않는다.
- 입력 실패와 설계 실패를 즉시 구분한다.
- 작성 중 시간 처리 방식이 사고를 돕는다.
- 소환수 명령이 주문 설계보다 큰 인지 부하를 만들지 않는다.

### 루프·서사

- 수업에서 배운 원리가 현장 해결법으로 이전된다.
- 메인 동반 소환수가 정답 대행 없이 학습·관계·기록을 연결한다.
- 현장 결과가 마도서 기록과 다음 학습 목표로 이어진다.

### 제작성

- 두 번째 유사 수업 또는 문제를 같은 데이터 계약으로 만들 수 있다.
- 대표 장면이 일회성 하드코딩에 의존하지 않는다.
- 목표 Android 기기에서 성능·화면비·저장·복귀가 검증된다.

정확한 정량 임계값은 Vertical Slice 계약에서 확정한다.

---

## 7. 실패 시 처리

Vertical Slice에서 핵심 가설이 실패하면 전체 게임을 계속 확장하지 않는다.

우선 수정 순서:

```text
입력 판정·시간 처리·피드백
→ 글자 수와 조합 복잡도
→ 전투 압박
→ 전투 보조 소환수 조작량
→ 관계·학교 콘텐츠 분량
```

우선 제거 순서:

```text
완성 주문 스톡
→ 복잡한 소환수 충전·편성
→ 다중 상태이상
→ 대규모 관계 분기
→ 학기 전체 일정
```

비타협 코어인 의미 기반 글자, 직접 작성, 상황별 조합, 설명 가능한 세계 변화, 학습→실전→기록 순환은 실패 원인을 해결하기 전 임의로 제거하지 않는다.
