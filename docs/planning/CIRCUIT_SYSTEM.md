- 세부 회로 목록: `PROVISIONAL`
- 기준 브랜치: `gpt/planning-spell-20260725`
- 기준 날짜: 2026-07-26
- 상위 책임 원본: `docs/planning/SPELL_GAME_DESIGN.md`

이 문서는 회로 문법의 확정된 계층 방향과 아직 확정되지 않은 개별 회로 후보를 분리해 기록한다. 공격·방어·탐색·강화·절감 등의 명칭은 현재 방향을 설명하기 위한 예시이며 확정 목록이 아니다.

## 2. 확정된 문법 원칙

### 2.1 메인 회로는 항상 하나

한 주문에는 메인 회로를 정확히 하나만 사용한다.

```text
메인 회로 1개
+
형상·전달 회로
+
보조 회로
+
조건·기동 회로
```

- 메인 회로 결합은 허용하지 않는다.
- 후반 복잡성은 복수 메인이 아니라 보조, 조건, 연결 흐름과 소환수 분담으로 확장한다.

### 2.2 회로 계층의 역할

- 메인 회로: 주문이 무엇을 하는가
- 형상·전달 회로: 주문이 어떤 형태로 어디에 작동하는가
- 보조 회로: 주문의 성능·효율·행동 특성을 어떻게 바꾸는가
- 조건·기동 회로: 주문 내부 효과가 언제 또는 어떤 사건에 반응해 작동하는가
- 연결·흐름: 회로 간 적용 범위와 실행 순서를 어떻게 구성하는가

## 3. 단계별 해금과 자동화

### 3.1 초반

```text
메인 1개 + 형상·전달 1개
```

- 플레이어가 직접 그리며 기본 문법을 학습한다.
- 판정 기준은 널럴하게 설정한다.
- 정확한 입력에는 추가 보상을 제공한다.

### 3.2 성장 이후

- 이미 학습·숙련한 낮은 단계의 메인과 형상·전달은 하위 회로 스톡으로 준비할 수 있다.
- 회로 스톡을 터치하면 해당 회로가 현재 주문에 자동 배치·연결된다.
- 새로 해금된 보조 회로는 직접 그리며 기능을 익힌다.
- 숙련한 보조 회로는 소환수 자동작성 또는 하위 회로 스톡 후보가 될 수 있다.

### 3.3 중반

- 조건·기동 회로를 해금한다.
- 플레이어는 하위 회로를 스톡으로 자동완성하고, 조건·기동과 상위 연결 판단에 집중한다.
- 성장 기준을 만족한 낮은 단계 조건·기동 회로도 후속 단계에서 스톡화할 수 있다.

## 4. 메인 회로 방향

메인 회로는 주문이 무엇을 하는지를 결정한다.

후보 예시:

- 공격
- 방어
- 체력 회복
- 마나 회복
- 탐색
- 제어
- 이동
- 소환
- 변환

이 목록은 확정하지 않는다.

## 5. 형상·전달 방향

형상·전달은 주문이 어디에 어떤 형태로 나타나는지를 결정한다.

후보 예시:

- 투사체
- 광선
- 범위
- 장벽
- 오라
- 함정
- 접촉
- 자기 대상

이 목록은 확정하지 않는다.

## 6. 보조 회로 방향

보조 회로는 메인 주문의 성능과 행동을 변형한다.

| 보조 성격 | 후보 예시 |
|---|---|
| 출력 | 강화, 증폭 |
| 효율 | 절감, 회수 |
| 규모 | 확대, 집중 |
| 시간 | 가속, 지속, 지연 |
| 행동 | 관통, 연쇄, 분열, 추적 |
| 안정성 | 안정화, 정밀화, 보정 |

같은 보조 회로라도 메인에 따라 결과가 달라질 수 있다.

```text
확대 + 공격
→ 공격 범위 증가

확대 + 방어
→ 보호 영역 증가

확대 + 탐색
→ 탐지 반경 증가
```

## 7. 조건·기동 방향

조건·기동은 주문 내부의 효과 발동 시점과 사건을 정한다.

후보 예시:

- 적중 시
- 피격 시
- 방어 성공 시
- 일정 시간 후
- 마나가 일정 이하일 때
- 반복
- 순차 발동

조건·기동 회로는 폐기된 `조건부 자동스펠`과 다르다.

- 조건·기동은 플레이어가 직접 구성한 주문 내부 문법이다.
- 자동스펠은 조건 판정으로 임의 발동하지 않는다.
- 조건·기동이 포함된 완성 주문을 스톡화할 수는 있지만, 스톡 사용 시점은 플레이어가 결정한다.

## 8. 연결·흐름 문법

회로 종류뿐 아니라 연결 방식 자체가 주문 결과에 영향을 줄 수 있다.

```text
직접 연결
→ 연결된 메인에만 보조 적용

분기
→ 효과를 여러 경로로 전달

합류
→ 여러 회로 효과를 하나로 결합

방향
→ 실행 순서 결정
```

세부 연결 규칙은 아직 미확정이다.

## 9. 하위 회로 스톡

성장으로 자동화 가능 단계가 상승하면 이미 익힌 하위 회로를 스톡으로 저장할 수 있다.

```text
상위 주문 작성 시작
→ 하위 회로 스톡 선택
→ 한 번 터치
→ 저장된 회로 자동 배치·연결
→ 플레이어가 상위 회로와 연결 구조를 계속 작성
```

하위 회로 스톡의 목적:

- 반복 드로잉 피로 감소
- 상위 회로와 신규 문법에 집중
- 같은 하위 회로를 여러 주문에서 재사용
- 소환수와 플레이어의 작업 분담 단순화

가드레일:

- 미발견·미숙련 회로는 스톡화하지 않는다.
- 현재 성장 단계의 신규 회로는 직접 그려 학습한다.
- 회로 스톡이 연결 판단과 최종 기동까지 자동으로 처리하지 않는다.
- 회로 삽입 위치와 연결 결과를 사용 전에 미리 보여준다.

## 10. 소환수 자동작성과 회로 스톡

두 기능은 모두 반복 회로를 줄이지만 사용 감각이 다르다.

### 하위 회로 스톡

- 플레이어가 터치해 즉시 적용한다.
- 저장량을 소비한다.
- 현재 필요한 회로를 직접 선택한다.

### 소환수 자동작성

- 소환수 스탠스와 능력치에 따라 일정 시간 동안 회로를 작성한다.
- 플레이어와 동시에 다른 구간을 담당할 수 있다.
- 스톡이 없어도 숙련 조건과 소환수 상태가 허용하면 지원할 수 있다.

정확한 역할 중복과 우선순위는 후속 결정으로 남긴다.

## 11. 가드레일

- 복수 메인 결합 금지
- 개별 예시 목록을 확정 목록으로 오기하지 않음
- 초반부터 모든 회로 계층을 노출하지 않음
- 성장할수록 반복 입력은 줄이고 새 문법에 집중
- 하위 회로 스톡이 신규 회로 학습을 건너뛰는 수단이 되지 않게 함
- 조건·기동 회로와 폐기된 조건부 자동스펠을 혼동하지 않게 함

## 12. 미해결 사항

1. 속성·매질을 독립 회로 계층으로 둘 것인가.
2. 완성 주문 스톡과 하위 회로 스톡의 전체 한도를 공유할 것인가.
3. 하위 회로 스톡의 마나 예약 비용은 어떻게 계산할 것인가.
4. 소환수 자동작성과 하위 회로 스톡의 우선순위를 어떻게 정할 것인가.
5. 연결·분기·합류의 실제 모바일 조작 방식을 어떻게 구현할 것인가.
