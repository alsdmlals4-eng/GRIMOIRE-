## 2. 현재 확정된 방향

플레이어에게 우선 노출되는 회로는 크게 두 계층으로 구분한다.

```text
메인 회로
→ 주문이 무엇을 하는지 결정

보조 회로
→ 메인 주문의 성능·형태·효율을 수정
```

### 2.1 메인 회로

메인 회로는 주문의 핵심 목적과 능력 계열을 결정한다.

현재 예시 후보:

- 공격
- 방어
- 체력 회복
- 마나 회복
- 탐색
- 제어
- 이동
- 소환
- 변환

위 목록은 방향 설명용 예시이며 확정 목록이 아니다.

### 2.2 보조 회로

보조 회로는 메인 회로에 태그·특성·수치 변화를 추가한다.

현재 예시 후보:

- 강화
- 절감
- 증폭
- 확대
- 지속
- 가속
- 관통
- 연쇄
- 분열
- 추적
- 안정화
- 정밀화

위 목록도 방향 설명용 예시이며 확정 목록이 아니다.

## 3. 기본 주문 문법 후보

초기 학습 문법은 다음처럼 단순하게 유지한다.

```text
메인 회로 1개
+
보조 회로 0~1개
=
기초 주문
```

중기 이후에는 보조 회로 수, 메인 회로 결합, 조건·순서 문법을 단계적으로 확장할 수 있다.

## 4. 마나 회로의 현재 위치

역할별 혼합형을 채택한다.

- 마나 회복은 기본적으로 `메인 회로` 후보로 취급한다.
- 마나 절감은 기본적으로 `보조 회로` 후보로 취급한다.
- 공격 주문에 흡수 성질을 추가하는 등의 고급 변형은 별도 보조 회로나 복합 메인 회로 조합으로 검토한다.

```text
마나 회복 메인
→ 자원 회복을 목적으로 하는 독립 주문

공격 메인 + 절감 보조
→ 소비 마나를 줄인 공격 주문
```

## 5. 벤치마킹으로 확인된 추가 문법 후보

다음 요소는 유사 주문 조합 게임에서 반복적으로 나타나지만, Spell에 도입할지는 아직 확정하지 않는다.

### 5.1 형상·전달 문법

주문이 어떤 형태로 나타나고 어디에 적용되는지 결정한다.

예시 후보:

- 투사체
- 광선
- 범위
- 장벽
- 오라
- 함정
- 접촉
- 자기 자신

이 역할을 보조 회로의 하위 분류로 둘지, 별도의 `형상 회로`로 분리할지가 핵심 미해결 사항이다.

### 5.2 속성·매질 문법

주문이 어떤 에너지·물질·속성을 사용하는지 결정한다.

예시 후보:

- 화염
- 냉기
- 번개
- 바람
- 빛
- 그림자
- 생명
- 정신

속성을 메인 회로에 포함할지, 별도의 `속성 회로`로 분리할지는 세계관과 전투 상성 설계 이후 결정한다.

### 5.3 조건·기동 문법

주문이 언제, 어떤 조건으로 작동하는지 결정한다.

예시 후보:

- 지연
- 적중 시
- 피격 시
- 방어 성공 시
- 반복
- 유지
- 순차 발동
- 특정 체력·마나 조건

이 문법은 초반에 노출하지 않고 상위 조합 주문용 후보로 둔다.

### 5.4 연결·흐름 문법

연결선은 단순 장식이 아니라 보조 회로의 적용 범위와 주문 실행 순서를 표현할 수 있다.

후보 규칙:

- 보조 회로는 직접 연결된 메인 회로에만 적용
- 연결 방향으로 실행 순서 표현
- 분기로 다중 대상 또는 다중 효과 표현
- 합류로 두 효과의 결합 표현
- 반복 고리는 고급 회로에서만 제한적으로 허용

연결·흐름은 수집 가능한 회로 종류보다 `그리는 문법`으로 취급하는 것을 우선 검토한다.

## 6. 권장 단계별 확장

### 초반

```text
메인 1개 + 보조 0~1개
```

- 공격·방어·회복 같은 목적 이해
- 넓은 판정으로 회로 입력 학습
- 조합 결과를 즉시 예측 가능

### 중반

```text
메인 1개 + 형상 후보 1개 + 보조 1~2개
```

- 같은 메인 주문을 상황별 형태로 변형
- 숙달한 기초 회로 자동화
- 동료가 일부 구간 보조

### 후반

```text
메인 1~2개 + 형상·속성 후보 + 보조 + 조건·연결 문법
```

- 복합 주문 설계
- 플레이어와 동료의 회로 분담
- 순서·분기·조건을 활용한 상위 주문

위 단계와 개수는 구조 후보이며 확정 수치가 아니다.

## 7. 설계 가드레일

- 회로 목록을 늘리는 것보다 적은 회로가 다양한 상황에서 의미 있게 변형되도록 한다.
- 보조 회로가 모든 메인 회로에 동일한 결과를 내지 않아도 된다.
- 보조 회로의 적용 가능 여부와 결과를 그리기 전에 명확히 미리 보여준다.
- 숨겨진 호환 규칙을 암기하게 하지 않는다.
- 초반에는 주문 하나에 필요한 직접 입력 구간을 짧게 유지한다.
- 자유 조합은 무제한 수식 생성이 아니라 검증 가능한 문법과 등록 가능한 결과 안에서 운영한다.
- 연결 순서와 적용 범위가 결과에 영향을 준다면 UI에서 즉시 읽을 수 있어야 한다.
- 메인 회로와 보조 회로의 외형·색·연결점 형태를 명확히 구분한다.

## 8. 핵심 개선 제안

### 8.1 보조 회로의 문맥 변환

같은 보조 회로라도 메인 회로에 따라 의미가 달라지게 한다.

```text
공격 + 확대
→ 공격 범위 증가

방어 + 확대
→ 보호 범위 증가

탐색 + 확대
→ 탐지 반경 증가

마나 회복 + 확대
→ 주변 동료와 회복 공유 후보
```

이 구조는 적은 보조 회로로도 많은 주문 변형을 만든다.

### 8.2 호환성 미리보기

보조 회로를 선택하면 다음을 시전 전에 보여준다.

- 적용 가능 여부
- 바뀌는 효과
- 추가 마나 비용
- 추가 작성 구간
- 동료가 담당 가능한 부분

### 8.3 발견과 설계도의 연결

- 미발견 조합은 결과를 완전히 공개하지 않고 기능 힌트를 제공한다.
- 처음 성공한 조합은 마도서에 설계도로 등록한다.
- 등록된 설계도는 자동화와 동료 지원의 기준이 된다.
- 플레이어가 만든 설계도에 별칭을 붙이는 기능을 후보로 둔다.

## 9. 주요 위험

- 메인 회로 안에 목적·속성·형상까지 모두 넣으면 종류가 폭증한다.
- 모든 보조 회로를 모든 메인에 적용하면 밸런스 경우의 수가 과도하게 늘어난다.
- 형상·속성·조건을 전부 독립 회로로 만들면 모바일 입력과 UI가 과밀해진다.
- 조합 결과가 예상과 다르면 실험이 아니라 무작위 대입으로 느껴질 수 있다.
- 강한 보조 회로가 사실상 필수 슬롯이 되면 자유 조합이 사라진다.

## 10. 다음 결정 후보

1. 상위 주문에서 메인 회로를 두 개 이상 결합할 수 있는가.
2. 형상·전달 역할을 보조 회로에 포함할지 별도 회로로 분리할지.
3. 속성을 메인 회로에 포함할지 별도 속성 회로로 분리할지.
4. 보조 회로의 적용 범위를 연결선 방향으로 결정할지.
5. 한 주문에서 직접 그려야 하는 최대 회로 구간을 어느 정도로 제한할지.
