# Spell 마법 회로 시스템 — 방향성 설계

## 1. 문서 상태

- 상태: `PLANNING_IN_PROGRESS`
- 상위 방향: `GRAMMAR_DIRECTION_CONFIRMED`
- 세부 회로 목록: `PROVISIONAL`
- 기준 브랜치: `gpt/planning-spell-20260725`
- 기준 날짜: 2026-07-25
- 상위 책임 원본: `docs/planning/SPELL_GAME_DESIGN.md`
- 관련 결정: `GM-00-08`, `GM-00-09`

이 문서는 회로 문법의 확정된 계층 방향과 아직 확정되지 않은 개별 회로 후보를 분리해 기록한다. 공격·방어·탐색·강화·절감 등의 명칭은 현재 방향을 설명하기 위한 예시이며 확정 목록이 아니다.

## 2. 확정된 문법 원칙

### 2.1 메인 회로는 항상 하나

한 주문에는 메인 회로를 정확히 하나만 사용한다.

```text
메인 회로 1개
→ 주문의 핵심 목적 결정
```

- 두 개 이상의 메인 회로 결합은 허용하지 않는다.
- 공격과 회복처럼 목적이 두 개인 주문은 복수 메인이 아니라 보조·조건·특수 효과로 표현한다.
- 메인 하나 원칙으로 주문 결과의 가독성과 밸런스 범위를 통제한다.

### 2.2 형상·전달 회로는 별도 계층

형상·전달 회로는 주문이 어떤 형태로 나타나고 어디에 적용되는지를 결정한다.

```text
메인 회로
+
형상·전달 회로
=
주문의 최소 완성 단위
```

예시 후보:

- 투사체
- 광선
- 범위
- 장벽
- 오라
- 함정
- 접촉
- 자기 자신

위 목록은 미확정이다.

### 2.3 보조 회로는 이후 단계적으로 해금

보조 회로는 메인 주문에 성능·효율·행동 특성을 추가한다.

예시 후보:

- 강화
- 절감
- 증폭
- 확대
- 지속
- 가속
- 관통
- 연쇄
- 분열
- 추적
- 안정화
- 정밀화

보조 회로 개별 목록과 동시 연결 가능 수는 미확정이다.

### 2.4 조건·기동 회로는 중반 해금

조건·기동 회로는 주문이 언제, 어떤 사건에 반응해 발동하는지 결정한다.

예시 후보:

- 지연
- 적중 시
- 피격 시
- 방어 성공 시
- 반복
- 유지
- 순차 발동
- 특정 체력·마나 조건

조건·기동은 초반 핵심 입력에 포함하지 않는다.

## 3. 회로 계층 구조

```text
메인
→ 무엇을 하는가

형상·전달
→ 어떤 형태로 어디에 전달하는가

보조
→ 얼마나 강하게, 넓게, 효율적으로 작동하는가

조건·기동
→ 언제, 어떤 사건에 반응해 작동하는가

연결·흐름
→ 각 회로가 어떤 순서와 범위로 영향을 주는가
```

속성·매질 계층은 아직 미확정이다. 세계관과 상성 설계 이후 별도 회로로 분리할지 결정한다.

## 4. 단계별 학습과 자동화

### 4.1 초반 — 주문의 최소 문법 학습

```text
메인 1개
+
형상·전달 1개
=
기초 주문
```

- 플레이어가 두 회로를 직접 그린다.
- 주문 목적과 발현 형태의 관계를 익힌다.
- 넓은 판정으로 성공 경험을 우선한다.
- 이 단계에서는 보조·조건 회로를 노출하지 않는다.

### 4.2 초반 성장 — 기초 문법 자동화

- 숙련한 메인 회로는 자동화 가능하다.
- 숙련한 형상·전달 회로도 자동화 가능하다.
- 등록된 설계도를 목표 주문으로 선택하면 자동화된 구간이 먼저 배치된다.
- 플레이어는 새로 해금된 회로나 중요한 연결·기동에 집중한다.

### 4.3 초중반 — 보조 회로 해금

```text
자동화된 메인
+
자동화된 형상·전달
+
직접 그리는 보조 회로
```

- 보조 회로가 조금씩 추가된다.
- 같은 메인 주문을 위력·범위·효율·행동 방식으로 변형한다.
- 숙련한 보조 회로는 소환수가 대신 작성할 수 있다.
- 소환수 능력치·적성·스탠스에 따라 자동작성 효율이 달라진다.

### 4.4 중반 — 조건·기동 회로 해금

```text
메인 1개
+
형상·전달
+
보조
+
조건·기동
```

- 플레이어는 발동 조건과 실행 순서를 설계한다.
- 보조 회로를 소환수에게 맡기고 조건·기동을 직접 그리거나 반대로 분담할 수 있다.
- 등록·숙련된 완성 주문은 자동스펠 후보가 된다.

### 4.5 후반 — 복잡도보다 운용 선택 확장

- 메인 회로 수는 끝까지 하나로 유지한다.
- 난도는 메인 결합이 아니라 보조 조합, 조건, 연결 흐름, 소환수 분담으로 증가한다.
- 플레이어가 모든 회로를 직접 그리는 방향으로 피로도를 높이지 않는다.
- 반복 주문은 자동스펠로 운용하고 새로운 조합과 긴급 대응은 직접 시전한다.

## 5. 메인 회로 후보

메인 회로는 주문의 핵심 목적을 결정한다.

현재 방향 설명용 후보:

- 공격
- 방어
- 체력 회복
- 마나 회복
- 탐색
- 제어
- 이동
- 소환
- 변환

위 목록은 확정하지 않는다.

### 단일 메인 가드레일

- `공격 + 체력 회복` 같은 이중 메인 주문은 만들지 않는다.
- 공격 적중 시 회복은 `공격 메인 + 흡수 보조/조건`처럼 표현한다.
- 방어 성공 시 마나 회복은 `방어 메인 + 방어 성공 조건 + 회복 보조 효과`처럼 표현한다.
- 복합 효과가 있어도 주문의 핵심 목적은 하나로 읽혀야 한다.

## 6. 보조 회로의 문맥 변환

같은 보조 회로라도 메인과 형상에 따라 의미가 달라질 수 있다.

```text
공격 + 범위 + 확대
→ 공격 범위 증가

방어 + 장벽 + 확대
→ 보호 영역 증가

탐색 + 범위 + 확대
→ 탐지 반경 증가

마나 회복 + 오라 + 확대
→ 주변 대상과 회복 공유 후보
```

이 구조는 적은 보조 회로로 많은 주문 변형을 만든다.

## 7. 마나 회로의 위치

- 마나 회복은 메인 회로 후보다.
- 마나 절감은 보조 회로 후보다.

```text
마나 회복 메인 + 자기 자신 전달
→ 독립 회복 주문

공격 메인 + 투사체 + 절감 보조
→ 소비 마나를 줄인 공격 주문
```

회복과 절감의 수치·중첩·무한 순환 방지는 `MANA_SYSTEM.md`에서 관리한다.

## 8. 연결·흐름 문법

연결선은 단순 장식이 아니라 적용 범위와 실행 순서를 표현한다.

후보 규칙:

- 보조 회로는 연결된 주문 구조에만 적용
- 연결 방향으로 실행 순서 표현
- 분기로 다중 대상 또는 다중 효과 표현
- 합류로 여러 보조 효과를 한 기동점에 모음
- 반복 고리는 조건·기동 회로 해금 이후 제한적으로 허용

연결·흐름은 수집 가능한 회로 종류보다 `그리는 문법`으로 취급하는 것을 우선한다.

## 9. 속성·매질 후보

주문이 어떤 에너지·물질·속성을 사용하는지 결정하는 계층은 아직 미확정이다.

예시 후보:

- 화염
- 냉기
- 번개
- 바람
- 빛
- 그림자
- 생명
- 정신

검토할 선택지:

1. 메인 회로의 변형으로 포함
2. 형상·전달과 같은 별도 필수 회로
3. 보조 회로의 한 계열
4. 장비·소환수·지역 환경으로 부여

## 10. 자동화 구조

### 시스템 자동화

- 숙련한 메인 및 형상·전달 회로 자동 배치
- 플레이어가 직접 학습한 회로만 자동화 가능

### 소환수 자동작성

- 숙련한 보조 회로 또는 미완성 구간 작성
- 능력치·적성·스탠스에 따라 속도와 안정성 차이

### 자동스펠

- 마도서에 등록되고 숙련된 완성 주문 반복 운용
- 즉석 변형과 신규 발견은 직접 시전에서 수행

세부 내용은 `SUMMON_SYSTEM.md`와 `AUTO_SPELL_SYSTEM.md`에서 관리한다.

## 11. 호환성과 결과 미리보기

회로를 연결하기 전에 다음을 보여준다.

- 연결 가능 여부
- 바뀌는 주문 효과
- 마나 비용 변화
- 추가 작성 구간과 예상 시간
- 소환수가 담당 가능한 구간
- 자동스펠 등록 가능 여부

숨겨진 호환 규칙을 암기하게 하지 않는다.

## 12. 설계 가드레일

- 메인 회로는 항상 하나다.
- 회로 목록을 늘리기보다 적은 회로가 문맥에 따라 다양하게 작동하도록 한다.
- 초반에는 메인과 형상·전달만 노출한다.
- 보조와 조건을 동시에 대량 해금하지 않는다.
- 플레이어가 성장할수록 직접 그려야 하는 총 획수가 계속 증가하지 않게 한다.
- 자동화는 먼저 직접 학습하고 숙련한 회로에만 적용한다.
- 강한 보조 회로가 사실상 필수 슬롯이 되지 않게 한다.
- 자유 조합은 검증 가능한 문법과 등록 가능한 결과 안에서 운영한다.
- 연결 순서와 적용 범위는 UI에서 즉시 읽을 수 있어야 한다.
- 메인, 형상·전달, 보조, 조건·기동은 외형과 연결점으로 구분한다.

## 13. 주요 위험

1. 형상·전달까지 자동화되면 초반 이후 직접 그리기의 정체성이 약해질 수 있음
2. 보조 회로가 많아지면 최적 조합만 반복될 수 있음
3. 조건·기동이 중반에 한꺼번에 추가되면 학습 부담이 급증할 수 있음
4. 소환수와 자동스펠이 강해지면 방치형 전투로 변할 수 있음
5. 단일 메인 원칙에도 보조 효과가 복잡해져 사실상 다중 메인처럼 보일 수 있음
6. 속성 계층을 늦게 결정하면 회로 데이터 구조가 흔들릴 수 있음

## 14. 다음 결정 후보

1. 자동스펠은 원터치 시전, 조건부 자동발동, 혼합형 중 어느 방식인가.
2. 소환수는 전투마다 소환하는가, 전투 시작부터 존재하는가.
3. 속성을 별도 회로 계층으로 분리할 것인가.
4. 한 주문에서 허용되는 보조·조건 회로 수를 어떻게 제한할 것인가.
5. 직접 시전과 자동스펠의 성능 차이를 어디에 둘 것인가.
