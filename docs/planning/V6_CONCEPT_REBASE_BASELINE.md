## 2. 승인된 플레이어 경험

> **마법 글자의 의미를 이해하고 상황에 맞는 주문을 설계해 발견하는 지적 마법 판타지.**

우선순위:

```text
1. 조합하고 발견하는 지적 재미
2. 직접 쓰는 마법의 손맛
3. 숙련하고 자동화하는 성장감
```

2번과 3번은 1번을 약화시키지 않는 범위에서만 확대한다.

---

## 3. 승인된 플레이어 약속

> **마법학교 학생이 되어 글자의 의미를 배우고, 수업과 현장실습에서 주문을 직접 설계해 내가 생각한 해결법으로 세계를 바꾸는 모바일 마법 RPG.**

설계 필터:

```text
배움
→ 글자와 문제의 원리를 이해

설계
→ 상황에 맞는 주문 구조를 선택·작성

세계 변화
→ 적·환경·사건이 설명 가능한 방식으로 변화
```

---

## 4. 목표 플레이어·세션

> 집·카페·휴식 시간처럼 잠깐 집중할 수 있는 환경에서 10~15분 동안 하나의 수업·현장실습·마법 발견 단위를 완주하고, 장기적으로 학교생활과 주문 연구를 축적하려는 모바일 플레이어.

- Micro 상황: 약 30초~2분
- 전투·문제 묶음: 약 3~5분
- 기본 세션: 약 10~15분
- 선택형 상세 감상: 대화·조사·기록으로 자율 연장

정확한 시간은 `PLAYTEST_TUNING_REQUIRED`다.

## 6. 승인된 기본 Loop

```text
수업
→ 교내 연습
→ 일상
→ 현장실습
→ 복귀·정리
→ 다음 수업·연구
```

핵심 문장:

> 수업에서 알고, 연습에서 할 수 있게 되고, 실전에서 다르게 써 보며, 일상에서 그 경험의 관계와 의미가 누적된다.

일정은 `고정 핵심 사건 + 자유 일정` 혼합형이다.

---

## 7. 승인된 경험 곡선

```text
학교 도착·목표 소개
→ 첫 메인 글자 직접 작성
→ 즉시 세계 변화
→ 보조 글자 하나로 작은 설계
→ 짧은 관계 장면
→ 첫 모의 현장실습
→ 새 활용 발견·기록
→ 반복 숙련 후 하위 글자 스톡
```

- 첫 5분에 직접 작성과 설계의 차이를 증명한다.
- 자동화는 숙련 이후의 반복 감소다.
- 첫 자동화는 하위 글자 스톡부터 시작한다.

## 8. 비타협 프로젝트 코어

1. 의미를 가진 마법 글자
2. `메인 글자 1개 + 보조 글자 0개 이상`
3. 신규·미숙·중요 글자의 직접 작성
4. 상황에 따른 주문 변형 판단
5. 즉각적이고 설명 가능한 세계 변화
6. 수업→연습→실전→발견·기록→다음 학습

지원 시스템:

- 마법학교
- 일상·관계
- 마도서·발견 기록
- 숙련·하위 글자 스톡
- 메인 동반 소환수
- 전투 보조 소환수

변경 가능한 외피:

- 3년·6학기와 학기 일정 수
- 학교 규모·지역·관계 분기량
- 실시간·감속·단계형 전투
- 완성 주문 스톡
- 보조 소환수 편성·수·성장
- 정확한 세션·저장 단위

## 9. 승인된 세일즈포인트

> **마법 글자를 직접 쓰고 조합해, 수업에서 배운 원리로 전투와 환경의 새로운 해답을 발견하는 모바일 마법학교 RPG.**

1. 손으로 직접 쓰는 마법
2. 상황에 맞게 만드는 주문
3. 수업에서 배우고 실전에서 발견하는 마법학교

전달 우선순위:

```text
첫 시각적 훅
= 직접 쓰는 마법

장기 핵심 재미
= 의미 기반 조합·상황 반응·발견

장기 성장 프레임
= 수업·실습·마도서·관계
```

## 10. 벤치마킹·SWOT·VRIO·제작성

- 직접 입력 / 조합 문제 해결 / 마법학교 학습 성장의 세 그룹으로 분석
- 결합 희소성: `RARE_IN_REVIEWED_SET`
- 시장 가치와 장기 재미: `UNPROVEN`
- VRIO: `VRIO_POTENTIAL_NOT_PROVEN`
- 작은 2D 모바일 CORE_POC: `FEASIBLE_WITH_STRICT_SCOPE`
- 3년·6학기 전체: `NOT_YET_FEASIBLE_AS_COMMITTED_SCOPE`

CORE_POC 강화 조건:

- 완전 정지 / 감속 / 실시간 비교
- 입력 실패 / 설계 실패 분리
- 전투 문제와 환경·구조 문제 포함
- 같은 메인 글자의 다른 보조·상황 재사용
- 복수 유효 해법과 실패 원인 재설계

## 11. 확정된 2계층 소환수 구조

```text
메인 동반 소환수
= 항상 같은 개체가 동행
= 수업·연습·일상·현장실습·복귀·기록
= 관계·서사·학습 연속성 중심

전투 보조 소환수
= 전투 준비 또는 전투 중 호출
= 공격·견제·수호·지정 충전 지원
= 전투 종료 후 기본적으로 해제
```

핵심 분리:

- 메인 동반자는 `누구와 계속 함께하는가`를 책임진다.
- 전투 보조는 `이번 전투에서 어떤 도움을 받을 것인가`를 책임진다.
- 두 계층은 별도 슬롯과 성장 책임을 가진다.
- 기존 `전투 시작 전 기본 소환수 1체 미리 전개`는 `SUPERSEDED_BY_GM-MASCOT-01`이다.

공통 금지:

- 글자·회로 직접 작성
- 보조 글자 자동 선택
- 회로 자동 연결
- 주문 자동 설계·실행
- 문제 정답 제시
- 소환수만으로 전투 자동 해결

## 12. 뾰족한 재미

```text
상황과 위험을 읽는다
→ 필요한 현상과 변형을 선택한다
→ 핵심 글자를 직접 작성하고 숙련 반복은 스톡으로 삽입한다
→ 결과가 적·환경·문제를 어떻게 바꾸는지 확인한다
→ 새 활용을 발견하거나 실패 원인을 이해한다
→ 다음 주문을 더 영리하게 설계한다
```

목표 감정:

- 발견
- 영리함
- 이해했다는 숙련감
- 내 설계가 작동했다는 주체성

## 13. 주요 보호 결정

- 복수 메인 글자 결합 금지
- 신규·미숙·중요 글자는 직접 작성
- 스톡 없이 직접 시전 가능
- 숙련 보조만 하위 글자 스톡 후보
- 입력 실패와 설계 실패 분리
- 메인 동반자는 항상 같은 개체
- 전투 보조는 전투에서 호출
- 소환수는 글자·조합·정답을 대행하지 않음
- 필수 정보는 선택형 상세 대화에만 숨기지 않음
- `무한 자유 조합`, `무엇이든 가능한 마법`, `완전한 손글씨 인식`을 약속하지 않음
- 사용자 승인 전 `CORE_CONFIRMED` 금지
- 현재 단계에서 구현과 Codex 실행 금지
