## 2. 플레이어 약속

> 마법학교 학생이 되어 글자의 의미와 상황의 조건을 배우고, 직접 작성·Stock·소환수의 주기 지원을 상황에 맞게 운용해 주문을 설계하며, 명시적으로 구현한 결과와 대가를 책임지고 마도서에 기록하는 마법 RPG.

## 3. 핵심 재미

> 정답 주문을 찾는 것이 아니라, 같은 글자 의미를 현재 상황에 맞게 설계하고 명시적으로 구현한 뒤, 설명 가능한 세계 변화와 포기한 대상을 받아들이는 재미.

핵심 판단은 다음 세 가지다.

1. 지금 상황에서 무엇을 바꿀 것인가.
2. 어떤 의미·범위·출력·위험을 선택할 것인가.
3. 직접 작성·Stock·소환수 중 어떤 수단을 언제 사용하며 무엇을 지키고 포기할 것인가.

직접 필기는 이 판단을 몸으로 느끼게 하는 대표 입력이지만, 필기 속도·반복량 자체가 게임의 최종 목표는 아니다. Stock과 소환수는 반복 입력을 줄이고 플레이어가 상황 판단과 주문 설계에 집중하도록 돕는다.

## 5. Stock 피로 완화 계약

### 승인된 최소선

- Stock은 직접 작성 반복 피로를 줄이기 위한 보조 시스템이다.
- 현재 정본의 최소 근거는 `같은 문제에서 이미 확인한 글자는 Token으로 재선택 가능` 규칙이다.
- 플레이어가 Stock을 직접 선택하는 경우 현재 대상·환경·위험·비용을 다시 검토하고 명시적으로 Commit한다.
- 신규·미숙·중요 글자와 새로운 핵심 판단은 직접 작성 또는 직접 작성한 요소의 명시적 조립을 우선한다.
- 소환수는 주기 행동으로 Stock을 충전할 수 있다.
- Stock이 자동 최적 조합이나 정답 추천으로 변질되어서는 안 된다.

### 자동 사용 경계

- 플레이어가 Stock을 고른 것만으로 자동 시전하지 않는다.
- 단, 활성 소환수의 고유 주기 행동으로 지정된 `[주문]`이 사용되는 것은 승인된 예외다.
- 소환수의 주기 주문·Stock 충전은 명확한 출처·주기·대상 또는 적용 규칙을 표시해야 한다.

### 아직 미확정

다음은 이번 승인으로 확정하지 않는다.

- Stock의 저장 단위가 글자·조합·완성 주문·충전량 중 무엇인지.
- 획득·등록·교체·삭제 규칙.
- 용량·슬롯·최대 충전량.
- 플레이어 사용 비용·시간·횟수.
- 소환수의 Stock 충전량·주기·상한.
- Chapter·세션·영구 보존 범위.
- 상황 불일치 시 수정·분해·재작성 방식.

후속 책임 Decision:

`GM-STOCK-SYSTEM-01`.

## 6. 소환수 주기 지원 계약

소환수는 직접 작성 반복 피로와 시간 압박을 낮추는 **주기적 자동 지원 시스템**으로 분류한다. 플레이어가 직접 모든 주문을 반복 작성하지 않아도 되지만, 어떤 소환수를 상시 동반하거나 언제 `[소환]`할지는 플레이어의 운용 판단으로 남긴다.

### 메인 소환수

- 메인 소환수는 별도 `[소환]` 주문 없이 상시 활성 상태다.
- 상시 효과 또는 일정 시간마다 발동하는 주기 행동을 가진다.
- 주기 행동은 `[주문]` 사용 또는 `[스톡]` 충전 중 하나 이상의 형태가 될 수 있다.
- 메인 소환수가 모든 상황에서 항상 최적 해법이 되어서는 안 된다.

### 기타 소환수

```text
상황 판단
→ 사용할 소환수 선택
→ [소환] 주문 작성 또는 승인된 Stock 사용
→ 명시적 Commit·비용 적용
→ 소환수 활성
→ 일정 시간마다 지정 주문 사용 또는 Stock 충전
→ 종료·해제·교체
```

- 기타 소환수는 기본적으로 비활성이다.
- 플레이어가 `[소환]` 주문을 통해 호출해야 효과가 적용된다.
- 소환 전에는 대상 상황·비용·위험을 검토하고 명시적으로 Commit한다.
- 소환 후 주기 행동은 자동으로 발생할 수 있다.

### 승인된 자동화

- 소환수별 지정 또는 장착된 주문의 주기적 자동 사용.
- 소환수별 규칙에 따른 Stock 충전.
- 메인 소환수의 상시 또는 주기 지원.
- 기타 소환수의 활성 기간·조건 동안 주기 지원.

### 핵심 재미 보호 장치

- 소환수는 새로운 상황의 의미 조합과 모든 핵심 결정을 독점하지 않는다.
- 자동 주문의 종류·예고·주기·대상 또는 적용 규칙을 플레이어가 이해할 수 있어야 한다.
- 소환수의 자동 행동도 Atomic Result Ledger를 사용해 한 번만 적용한다.
- Pause·Background·Save/Resume에서 중복 Tick·중복 주문·중복 Stock 충전이 없어야 한다.
- 메인 소환수 상시 지원과 여러 소환수의 중첩이 무한 Stock·무한 자동시전·무위험 방치 플레이를 만들지 않아야 한다.
- 자동 행동의 결과·비용·부작용·기여 소환수를 전투 결과와 마도서에서 설명할 수 있어야 한다.

### 아직 미확정

- 소환수별 주기 시간.
- 사용 주문의 출처가 고유 주문·플레이어 장착 주문·Stock 주문 중 무엇인지.
- 자동 주문의 대상 선택 규칙.
- Stock 충전 대상·우선순위·상한.
- 소환 지속시간·해제·교체·재소환 대기시간.
- 동시 소환 수와 중첩 규칙.
- `[소환]` 주문의 글자 구성·마나·시간·실패 규칙.
- 메인 소환수와 기타 소환수의 역할·출력 차이.
- 비전투 Situation에서의 소환수 주기 행동.
- Pause·Offline·Background 시간의 주기 진행 여부.

## 7. 승인된 R1~R7 개선 원칙

### R1 — Core Fun Contract

모든 시스템과 콘텐츠는 다음을 검사한다.

```text
상황을 읽게 하는가
→ 의미 있는 선택을 만드는가
→ Commit 전에 검토할 수 있는가
→ 결과와 대가가 설명되는가
→ 마도서·성장·다음 상황으로 환류하는가
```

두 항목 이하만 만족한다면 핵심 시스템이 아니라 보조·자동 처리·삭제 후보로 재분류한다.

### R2 — 직접 작성의 역할 제한

- 신규·미숙·중요 글자는 직접 작성.
- 이미 확인한 요소는 Stock·Token·명시적 조립으로 반복 피로 완화.
- 메인 소환수와 소환된 보조 소환수의 주기 행동으로 반복 주문·Stock 충전 지원.
- 플레이어 Stock 사용은 상황 검증과 Commit을 생략하지 않음.
- 소환수 자동 행동은 지정된 규칙을 따르며 무제한 최적 해법이 되지 않음.

### R3 — 전투 압박의 대상

전투 압박은 필기 속도보다 불완전한 정보와 제한된 시간에서 어떤 결과를 감수하고 어떤 소환수를 언제 호출할지 결정하는 데 둔다. Recognition·Animation·Save·시스템 지연은 플레이어 조작 시간과 분리한다.

### R4 — 제작 시스템의 코어 종속

제작은 글자 의미를 재료·촉매 조건에 적용하거나 다음 Situation의 해법·위험·부작용을 바꾸거나 실패를 발견·기록으로 환류해야 한다.

### R5 — 숨김 평가의 공개 증거

정확한 점수는 숨기되 `기초 이해 / 비전투 응용 / 현장 책임 / 연구·제작 / 복기·설명`의 대표 증거를 마도서와 학기말 평가에 제시한다.

### R6 — Vertical Slice 우선순위

```text
상황 판독·의미 조합·Commit·세계 변화
→ 직접 작성·Stock·소환수 피로 완화의 상호작용
→ 비전투·전투의 다른 응용
→ 마도서 복기·결과 설명
→ 자유일정의 조건 변화
→ 제작 대표 통합 사례 1개
→ 장기 커리큘럼·평가 Preview
```

시간 초과 시 핵심 판단과 Stock·소환수 상호작용 검증이 아니라 Preview·이동·중복 설명·제작 단계·자유일정 반복부터 줄인다.

### R7 — 시스템 분류 유지

새 시스템을 추가할 때 `핵심 플레이 / 핵심 진행 / 적용 모드 / 보조·운용 / 전달·안전 인프라` 중 하나의 책임을 명시한다. 여러 책임을 동시에 소유하는 시스템은 분리하거나 단일 권위 소유자를 지정한다.
