## 2. 플레이어 약속

> 마법학교 학생이 되어 글자의 의미와 상황의 조건을 배우고, 직접 작성·Stock·소환수의 도움을 상황에 맞게 선택해 주문을 설계하며, 명시적으로 구현한 결과와 대가를 책임지고 마도서에 기록하는 마법 RPG.

## 3. 핵심 재미

> 정답 주문을 찾는 것이 아니라, 같은 글자 의미를 현재 상황에 맞게 설계하고 명시적으로 구현한 뒤, 설명 가능한 세계 변화와 포기한 대상을 받아들이는 재미.

핵심 판단은 다음 세 가지다.

1. 지금 상황에서 무엇을 바꿀 것인가.
2. 어떤 의미·범위·출력·위험을 선택할 것인가.
3. 무엇을 지키고 무엇을 포기할 것인가.

직접 필기는 이 판단을 몸으로 느끼게 하는 대표 입력이지만, 필기 속도·반복량 자체가 게임의 최종 목표는 아니다.

## 4. 승인된 시스템 계층

### A. 비타협 핵심 플레이

```text
상황·조건·위험 판독
→ 글자 작성 또는 승인된 피로 완화 수단 선택
→ 의미 조합·상황 검증
→ 비용·위험·결과 경향 검토
→ 명시적 Commit
→ 원자적 결과 적용
→ 설명 가능한 세계 변화
→ 마도서 기록·복기
```

비타협 시스템:

- 상황·조건·위험 판독.
- 글자 직접 작성·후보 확인.
- 의미 조합·상황 검증.
- 명시적 Commit과 원자 결과 적용.
- 설명 가능한 세계 변화.
- 마도서 기록·복기.

### B. 핵심 진행

- 학습 나선 Chapter.
- 다계열 수강·전문화 커리큘럼.

- 결과 태그·숨김 소폭 학기 평가·학기말 종합 평가.

### C. 핵심을 시험하는 적용 모드

- 제작·미니게임.

적용 모드는 핵심 재미를 다른 조건에서 시험한다. 전투·제작·현장실습 자체가 상황 판독과 의미 설계보다 상위 핵심이 되지 않는다.

## 5. Stock 피로 완화 계약

### 승인된 최소선

- Stock은 직접 작성 반복 피로를 줄이기 위한 보조 시스템이다.
- 현재 정본의 최소 근거는 `같은 문제에서 이미 확인한 글자는 Token으로 재선택 가능` 규칙이다.
- 신규·미숙·중요 글자와 새로운 핵심 판단은 직접 작성 또는 직접 작성한 요소의 명시적 조립을 우선한다.
- Stock 사용 후에도 현재 대상·환경·위험·비용에 대한 상황 검증을 다시 수행한다.
- Stock 선택만으로 자동 시전하지 않으며 최종 결과에는 명시적 Commit이 필요하다.
- Stock이 자동 최적 조합이나 정답 추천으로 변질되어서는 안 된다.

### 아직 미확정

다음은 이번 승인으로 확정하지 않는다.

- Stock의 저장 단위가 글자·조합·주문 중 무엇인지.
- 획득·등록·교체·삭제 규칙.
- 용량과 슬롯 수.
- 전투 중 사용 비용·시간·횟수.
- Chapter·세션·영구 보존 범위.
- 상황 불일치 시 수정·분해·재작성 방식.

후속 책임 Decision:

`GM-STOCK-SYSTEM-01`.

## 6. 소환수 피로 완화 계약

소환수는 직접 작성의 의미 판단을 빼앗지 않으면서 작성 부담과 시간 압박을 줄이는 보조 시스템으로 분류한다.

현재 승인된 소환수 역할:

- 메인 동반 정령은 위험·불안정을 감지하고 관계·발견·복기를 연결한다.
- 수호형 보조 소환수는 다음 공격 피해를 완화하고 작성 Draft를 보호하며 작성 시간을 확보한다.
- 소환수는 상황에 대한 다른 관점·준비·보호·제한적 보조 행동을 제공할 수 있다.

현재 정본에서 금지된 자동화:

- 소환수가 글자를 대신 작성.
- 소환수가 글자 조합을 결정.
- 소환수가 대상을 대신 선택.
- 소환수가 주문을 자동 시전.
- 소환수가 항상 최적 해법을 추천.

사용자가 말한 피로 완화가 위 금지 범위를 넘어 직접 작성·조합·시전 대행을 포함한다면 기존 정본과 충돌한다. 그 경우 별도 Decision에서 허용 범위와 비용·실패·상황 재검증을 결정해야 한다.

후속 책임 Decision:

`GM-SUMMON-FATIGUE-DELEGATION-01`.

## 7. 승인된 R1~R7 개선 원칙

### R1 — Core Fun Contract

모든 시스템과 콘텐츠는 다음을 검사한다.

```text
상황을 읽게 하는가
→ 의미 있는 선택을 만드는가
→ Commit 전에 검토할 수 있는가
→ 결과와 대가가 설명되는가
→ 마도서·성장·다음 상황으로 환류하는가
```

두 항목 이하만 만족한다면 핵심 시스템이 아니라 보조·자동 처리·삭제 후보로 재분류한다.

### R2 — 직접 작성의 역할 제한

- 신규·미숙·중요 글자는 직접 작성.
- 이미 확인한 요소는 Stock·Token·명시적 조립으로 반복 피로 완화.
- 재사용해도 현재 상황 검증과 Commit을 생략하지 않음.
- 자동 최적 추천·자동 시전 금지.

### R3 — 전투 압박의 대상

전투 압박은 필기 속도보다 불완전한 정보와 제한된 시간에서 어떤 결과를 감수할지 결정하는 데 둔다. Recognition·Animation·Save·시스템 지연은 플레이어 조작 시간과 분리한다.

### R4 — 제작 시스템의 코어 종속

제작은 글자 의미를 재료·촉매 조건에 적용하거나 다음 Situation의 해법·위험·부작용을 바꾸거나 실패를 발견·기록으로 환류해야 한다.

### R5 — 숨김 평가의 공개 증거

정확한 점수는 숨기되 `기초 이해 / 비전투 응용 / 현장 책임 / 연구·제작 / 복기·설명`의 대표 증거를 마도서와 학기말 평가에 제시한다.

### R6 — Vertical Slice 우선순위

```text
상황 판독·의미 조합·Commit·세계 변화
→ 비전투·전투의 다른 응용
→ 마도서 복기·결과 설명
→ 자유일정의 조건 변화
→ 제작 대표 통합 사례 1개
→ 장기 커리큘럼·평가 Preview
```

시간 초과 시 핵심 작성 판단이 아니라 Preview·이동·중복 설명·제작 단계·자유일정 반복부터 줄인다.

### R7 — 시스템 분류 유지

새 시스템을 추가할 때 `핵심 플레이 / 핵심 진행 / 적용 모드 / 보조 / 전달·안전 인프라` 중 하나의 책임을 명시한다. 여러 책임을 동시에 소유하는 시스템은 분리하거나 단일 권위 소유자를 지정한다.
