# Spell 통합 게임 설계 — 초기 코어

## 1. 문서 상태

- 프로젝트명: `Spell` (임시명)
- 상태: `PLANNING_IN_PROGRESS`
- 프로젝트 코어 상태: `CORE_CANDIDATE`
- 기준 브랜치: `gpt/planning-spell-20260725`
- 기준 날짜: 2026-07-25
- 엔진: Godot
- 목표 플랫폼: Android / Google Play
- 구현 상태: 미착수

이 문서는 현재 사용자와 합의한 초기 기획의 책임 원본이다. 아직 합의되지 않은 수치와 세부 규칙은 확정값으로 취급하지 않는다.

---

## 2. 한 문장 코어 후보

> 직접 마법 회로를 연구하고 조합해 주문을 발견한 뒤, 숙달한 회로와 성장한 동료의 작업을 지휘하여 더 복잡한 주문을 함께 완성하는 모바일 실시간 마법 전투 게임.

---

## 3. 핵심 플레이어 판타지

플레이어는 완성된 스킬 버튼을 누르는 마법사가 아니라, 마법의 구조를 이해하고 손으로 회로를 작성하는 마법 사용자다.

성장은 단순 피해량 상승이 아니라 다음 변화로 체감된다.

```text
내가 직접 기초 회로를 배운다.
→ 회로를 조합해 새로운 주문을 발견한다.
→ 발견한 주문을 설계도로 기록한다.
→ 숙달한 반복 회로를 자동화한다.
→ 동료의 능력과 스탠스를 지휘한다.
→ 플레이어와 동료가 회로를 분담한다.
→ 더 복잡한 상위 조합 주문을 완성한다.
```

## 4. 프로젝트 코어 후보

### 4.1 PROJECT_CORE

1. 터치로 마법 회로를 직접 그리는 행위
2. 기초 회로를 연결해 새로운 주문을 발견하는 행위
3. 숙달한 기초 회로를 자동화하고 더 높은 회로를 직접 다루는 성장
4. 플레이어와 동료가 회로 구간을 분담해 상위 주문을 완성하는 협동
5. 주문 완성 과정에서 마나, 적 공격 시간, 회로 작성 시간을 판단하는 전투 압박

### 4.2 CORE_SUPPORT

1. 주문 마도서와 설계도 등록
2. 동료 능력치와 스탠스 지휘
3. 집중 모드의 시간 감속
4. 적 공격 예고와 대응 주문 선택
5. 회로 숙련도와 자동완성 효율 성장
6. 널널한 성공 판정과 정확 입력 추가 보상

### 4.3 아직 확정되지 않은 요소

- 장르 세부 분류
- 세션 길이
- 전투의 스테이지 구조
- 세계관과 주인공 설정
- 회로 분류 체계와 구체 명칭
- 동료 수와 편성 수
- 마나 회복 방식
- 실패와 패배의 장기적 의미
- 과금 및 광고 정책

## 5. 핵심 전투 구조

### 5.1 기본 전투

- 적은 일정한 공격 주기 또는 공격 예고 후 플레이어를 공격한다.
- 플레이어는 마나를 소비해 마법 회로를 작성하고 주문을 발동한다.
- 마나 제한으로 무한 난사를 방지한다.
- 플레이어는 적의 공격 예고, 남은 마나, 주문 작성 시간, 동료 행동을 함께 판단한다.

### 5.2 집중 모드

회로 입력을 시작하면 전투 시간이 완전히 멈추지 않고 크게 느려진다.

```text
평상시
→ 적과 동료가 정상 속도로 행동

회로 입력 시작
→ 전투 시간 감속
→ 적 공격 타이머도 느리게 진행
→ 플레이어와 동료가 회로 작성

회로 완성 또는 입력 종료
→ 정상 속도로 복귀
→ 주문 및 전투 결과 전개
```

잠정 PoC 범위:

- 회로 입력 중 시간 배율 후보: 25~35%
- 주문 또는 회로 단계별 입력 제한시간 적용 검토
- 입력 실패 시 시간 또는 마나 손실 검토
- 집중 상태 무한 유지 방지 필요

위 수치는 테스트 전 잠정치이며 확정하지 않는다.

## 6. 마법 회로 성장 구조

### 6.1 초기

- 플레이어가 기초 회로를 직접 그린다.
- 형태, 기능, 연결 규칙을 몸으로 익힌다.
- 새로운 조합 주문은 직접 실험하여 발견한다.

### 6.2 중기

- 숙달한 기초 회로를 자동화하거나 저장한다.
- 플레이어는 중급 회로와 연결 회로에 집중한다.
- 발견한 주문을 목표 주문으로 지정할 수 있다.
- 동료가 반복 회로 또는 미완성 구간을 보조한다.

### 6.3 후기

- 자동화된 기초 회로와 중급·고급 회로를 결합한다.
- 플레이어와 동료가 여러 회로 구간을 동시에 작성한다.
- 최종 연결 또는 기동은 플레이어가 담당한다.
- 상위 조합 주문은 플레이어의 판단, 동료 운용, 회로 숙련을 모두 요구한다.

### 6.4 자동화 원칙

자동화는 핵심 재미를 제거하지 않는다.

> 이미 숙달한 반복 입력을 줄이고, 플레이어가 더 복잡한 회로 설계와 중요한 기동에 집중하게 하는 성장 기능이다.

## 7. 주문 발견과 마도서

채택 구조: `발견 후 설계도 등록형`

```text
새로운 회로를 획득하거나 배운다.
→ 회로의 기능과 연결 조건을 확인한다.
→ 직접 조합을 실험한다.
→ 유효한 주문을 처음 완성한다.
→ 주문이 마도서에 설계도로 등록된다.
→ 이후 목표 주문으로 지정할 수 있다.
→ 자동화 회로와 동료 지원을 사용할 수 있다.
```

### 주문 상태 후보

| 상태 | 플레이 방식 |
|---|---|
| 미발견 | 회로를 직접 선택하고 연결하여 실험 |
| 발견 | 마도서에 등록되고 목표 주문 지정 가능 |
| 숙련 | 일부 기초 회로 자동화 가능 |
| 숙달 | 동료와 회로 구간 분담 및 상위 조합 지원 |

### 가드레일

- 마도서는 처음부터 정답을 제공하는 목록이 아니다.
- 플레이어가 직접 발견한 마법 지식을 축적하는 기록이다.
- 힌트는 제공할 수 있지만 최종 발견은 플레이어 행동으로 성립해야 한다.

## 8. 동료 시스템

### 8.1 고정 타입 폐기

동료를 전투형, 수호형, 회로형 등 고정 타입으로 나누지 않는다.

모든 동료는 원칙적으로 다음 행동을 수행할 수 있다.

- 자동 공격
- 플레이어 보호
- 회복 또는 적 방해
- 기초 회로 자동작성
- 조합 회로 부분 작성
- 협동 주문 보조

동료 차이는 역할 제한이 아니라 능력치, 성장 상태, 플레이어가 지정한 스탠스에 의해 발생한다.

```text
동료의 능력치
×
플레이어가 지정한 현재 스탠스
=
전투 중 실제 행동과 효율
```

### 8.2 능력치 잠정 후보

현재 구조 후보:

| 능력치 | 주요 영향 |
|---|---|
| 전투 | 공격, 수호, 적 방해 효율 |
| 회로 | 자동작성 속도, 담당 가능한 회로 난도 |
| 동조 | 플레이어와 동시 작업 및 협동 주문 효율 |
| 지속 | 지원 빈도, 집중 유지, 연속 작업 능력 |

실제 MVP에서는 3~4개로 제한하는 것을 우선 검토한다. 명칭과 계산식은 미확정이다.

### 8.3 동료 스탠스

플레이어가 전투 중 동료의 행동 우선순위를 정한다.

#### 전투 스탠스

- 적 공격과 위험 제거 우선
- 플레이어가 회로를 그릴 시간을 확보
- 회로 자동작성 비중 감소

#### 회로 지원 스탠스

- 반복적인 기초 회로 자동작성 우선
- 목표 주문의 완성 시간 단축
- 최소한의 전투 행동만 수행

#### 협동 스탠스

- 플레이어가 작성 중인 회로와 목표 주문 분석
- 미완성 구간 중 처리 가능한 부분을 선택
- 플레이어와 동시에 회로를 작성

#### 수호 스탠스

- 플레이어 보호와 적 공격 차단 우선
- 고난도 회로를 안전하게 그릴 시간을 제공

스탠스 명칭과 최종 개수는 미확정이다.

### 8.4 스탠스 변경 규칙

채택 구조: `전투 중 변경 가능 + 전환 제약`

- 플레이어는 전투 중 언제든 스탠스 변경을 명령할 수 있다.
- 동료는 현재 행동 또는 회로 작업을 정리한 뒤 새 스탠스로 전환한다.
- 짧은 전환 시간 또는 재지정 대기시간이 존재한다.
- 명령 자원을 별도로 소모시키는 방식은 현재 우선안이 아니다.
- 긴급 전환 시 현재 회로 작업을 중단하고 플레이어가 남은 구간을 인계받는 선택을 검토한다.

### 8.5 자동완성과 협동 주문

```text
1. 플레이어가 상위 조합 주문을 목표로 지정한다.
2. 주문을 구성하는 필수 회로 구간이 표시된다.
3. 플레이어가 회로 작성을 시작한다.
4. 협동 또는 회로 지원 스탠스의 동료가 미완성 구간을 분석한다.
5. 동료가 능력치로 처리할 수 있는 구간을 선택한다.
6. 플레이어와 동료가 서로 다른 구간을 동시에 작성한다.
7. 필수 구간이 완성되면 플레이어가 최종 연결 또는 기동을 수행한다.
8. 조합 주문이 발동한다.
```

동료 성장에 따라 다음 효율이 증가한다.

- 자동완성 시작 대기시간 감소
- 회로 작성시간 감소
- 담당 가능한 회로 난도 상승
- 동시에 보조 가능한 회로 구간 증가
- 회로 정확도와 협동 효율 상승

### 8.6 동료 가드레일

- 동료는 목표 주문을 대신 선택하지 않는다.
- 동료는 상황에 맞는 정답 주문을 자동 결정하지 않는다.
- 플레이어는 동료가 담당 중인 회로를 직접 먼저 완성할 수 있다.
- 동료가 모든 중간 회로를 작성해도 최종 연결 또는 기동은 플레이어가 담당한다.
- 초보자는 동료 도움을 기다려 안정적으로 완성할 수 있다.
- 숙련자는 동료와 다른 구간을 동시에 작성해 더 빠르게 완성할 수 있다.

## 9. 회로 정확도와 성공 보상

채택 구조: `단계형 정확도 판정 + 실패 완화 + 정확 입력 추가 보상`

### 9.1 설계 원칙

회로 판정은 플레이어를 실수로 처벌하기보다 성공을 넓게 인정하고, 더 정확하게 그렸을 때 추가적인 즐거움을 제공해야 한다.

```text
널널한 성공 기준
→ 대부분의 합리적인 입력은 주문 발동

낮은 부정확 패널티
→ 다소 흔들린 입력도 플레이 흐름 유지

명확한 정확 입력 보상
→ 잘 그렸을 때 더 강한 손맛과 성취 제공
```

### 9.2 판정 단계 후보

정확한 명칭과 수치는 PoC 전까지 확정하지 않는다.

| 판정 후보 | 기본 결과 | 설계 의도 |
|---|---|---|
| 공명·정확 | 주문 정상 발동 + 추가 보상 | 정확한 입력을 적극적으로 칭찬 |
| 안정·허용 | 주문 정상 발동 | 넓은 허용 범위의 기본 성공 |
| 흔들림·부정확 | 주문 발동 + 매우 낮은 효율 감소 | 실패보다 흐름 유지 우선 |
| 구조 불성립 | 주문 미완성 또는 재입력 기회 | 핵심 노드·연결 자체가 없을 때만 적용 |

### 9.3 정확 입력 보상 후보

정확 입력 보상은 한 번에 모두 적용하지 않고 PoC에서 손맛이 좋은 후보를 선별한다.

- 주문 위력 또는 범위 소폭 증가
- 마나 일부 환급 또는 다음 회로 마나 절감
- 시전·기동 속도 증가
- 추가 투사체, 지속시간, 연쇄 횟수 등 주문 특성 강화
- 동료 협동 게이지 또는 회로 숙련도 추가 획득
- 시각·음향·진동을 통한 강한 `공명 성공` 피드백

### 9.4 실패 완화 가드레일

- 초급·중급 회로는 조금 부정확하다는 이유만으로 완전 실패시키지 않는다.
- 부정확 판정의 피해·효율 패널티는 낮게 유지한다.
- 허용 오차는 손가락 입력과 다양한 모바일 화면을 고려해 널널하게 설정한다.
- 기본 회로에서 자기 피해, 전체 마나 소실, 예측 불가능한 오작동을 기본 패널티로 사용하지 않는다.
- 구조 불성립은 필수 연결점 누락, 시작·종료점 불성립 등 주문 문법 자체가 성립하지 않을 때만 적용한다.
- 실패 시 어느 구간이 부족했는지 즉시 보여주고 빠르게 다시 그릴 수 있게 한다.
- 고급·위험 회로의 역류 같은 강한 실패는 별도 선택형 콘텐츠로 검토하며 기본 경험에 적용하지 않는다.

### 9.5 숙련의 의미

정확도는 주문을 사용할 자격을 가르는 문턱이 아니라, 같은 주문을 더 효율적이고 화려하게 다루는 숙련 축이다.

```text
초보자
→ 넓은 판정으로 주문을 성공시키는 즐거움

숙련자

```

## 11. 현재 핵심 설계 위험

### P0 후보

1. 터치 회로 인식이 실제 손가락 입력을 공정하게 받아들이지 못하면 프로젝트 코어가 붕괴한다.
2. 자동화와 동료 지원이 강해질수록 플레이어가 직접 그릴 이유가 사라질 수 있다.
3. 자유 조합 경우의 수가 지나치게 많으면 1인 개발 범위를 초과한다.

### P1 후보

1. 집중 모드 무한 유지 악용
2. 동료 스탠스 전환을 자주 반복하는 것이 정답이 되는 문제
3. 상위 주문이 복잡해질수록 모바일 화면이 과밀해지는 문제
4. 회로 발견이 실험보다 무작위 조합 대입으로 변하는 문제
5. 동료 능력치가 지나치게 많아져 캐릭터 이해가 어려워지는 문제
6. 정확 입력 보상이 지나치게 강해져 사실상 필수 판정으로 변하는 문제
7. 판정 피드백이 모호해 플레이어가 왜 보상을 받았는지 이해하지 못하는 문제
