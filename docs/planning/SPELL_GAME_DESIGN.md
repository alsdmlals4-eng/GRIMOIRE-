- 제품 단계: `CONCEPT_APPROVAL`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- Work Mode: `PLAN`
- 프로젝트 코어 상태: `CORE_CANDIDATE`
- 세계관 코어 상태: `WORLD_CORE_CANDIDATE`

이 문서는 현재 사용자와 합의한 상위 설계의 책임 원본이다. 세부 수치와 콘텐츠 목록은 테스트 전 확정값으로 취급하지 않는다.

## 2. 한 문장 코어 후보

> 마법학교 학생이 되어 마법 글자를 배우고 직접 조합하며, 숙련된 반복 글자는 스톡으로 간결하게 사용하고 소환수의 충전 지원을 지휘해 새로운 주문과 활용법을 발견하는 모바일 실시간 마법 전투·육성 게임.

## 3. 플레이어 약속

플레이어는 완성된 스킬 버튼만 누르는 마법사가 아니다.

```text
마법 글자의 의미를 배운다
→ 메인 글자와 보조 글자를 직접 연결한다
→ 현장에서 새로운 활용과 주문을 발견한다
→ 반복 보조를 숙련해 스톡으로 준비한다
→ 소환수의 전투·수호·스톡 충전을 지휘한다
→ 더 복잡한 주문과 현장 문제를 해결한다
```

성장은 피해량 증가뿐 아니라 다음으로 체감한다.

- 새로운 메인·보조 글자 이해
- 직접 작성 안정성과 정확도
- 반복 입력의 스톡화
- 소환수 생산·수호 운용
- 더 복잡한 보조 글자 조합
- 수업·연구·현장실습의 선택권 증가
- 주문의 전투·생활·구조·탐사 활용 확대

## 4. 프로젝트 코어 후보

### 4.1 PROJECT_CORE

1. 터치로 마법 글자와 회로를 직접 작성하는 행위
2. 메인 글자와 보조 글자를 조합해 주문을 발견하는 행위
3. 숙련된 반복 글자를 스톡으로 자동 삽입하고 새 조합에 집중하는 성장
4. 소환수의 전투·수호·지정 스톡 충전을 지휘하는 운용
5. 적 행동, 작성 시간, 마나, 보유 스톡과 충전 대상을 판단하는 실시간 전투
6. 마법학교 수업과 현장실습을 오가며 글자·관계·전문 분야를 성장시키는 장기 육성

### 4.2 CORE_SUPPORT

1. 주문 마도서와 설계도 등록
2. 집중 모드의 전투 시간 감속
3. 완성 주문 스톡과 하위 글자 스톡
4. 소환수 스탠스와 생산·동조
5. 메인 글자별 레벨과 Lv.4~5 전문화
6. 보조 글자 미숙·숙련·달인 등급
7. 학년별 보조 글자 표준 운용량
8. 널럴한 성공 판정과 정확 입력 추가 보상
9. 선택형 상세 서사와 사건 기록

### 4.3 현재 코어가 아닌 요소

- 소환수의 회로·글자 직접 작성
- 소환수와 플레이어의 동시 회로 작성
- 소환수 보조 묶음 자동 연결
- 복수 메인 글자 주문
- 조건부 완전 자동 발동
- 학교 경영·건설 시뮬레이션
- 비밀학과·학교 음모 중심 서사
- 매일 단위의 과도한 일정 미세관리

## 5. 마법 글자 문법

```text
마법 글자
→ 마법적 의미를 가진 최소 기능 단위

회로
→ 글자의 위치·연결·적용 순서

주문
→ 메인 글자 1개 + 보조 글자 0개 이상
```

### 5.1 메인 글자

- 주문의 핵심 현상을 결정한다.
- 메인 글자 하나만으로 기본 주문이 성립한다.
- 한 주문에 메인 글자는 정확히 하나다.
- 계열은 현상·물질·개념 중심이다.
- 공격·방어·생활·구조·탐사는 계열이 아니라 활용 결과다.

### 5.2 보조 글자

보조 글자는 다음 역할을 담당한다.

- 형상
- 전달
- 출력
- 규모
- 시간
- 행동
- 효율
- 안정
- 조건
- 순서·분기

보조 글자가 늘면 주문의 기능과 위력은 확대되지만 다음 비용도 증가한다.

- 직접 작성 시간
- 마나 부담
- 연결 판단 복잡도
- 완성 주문 스톡 준비 용량
- 스톡 충전시간

## 6. 글자 성장

### 6.1 메인 글자

```text
Lv.0 미습득
→ Lv.1 입문
→ Lv.2 숙련
→ Lv.3 응용
→ Lv.4 전문화
→ Lv.5 전공·개인 연구
```

- Lv.1~3은 공통 기반이다.
- Lv.4~5는 각 현상 특성에 맞는 전문 활용 분기다.
- 수업·직접 작성·현장 활용·시험·연구로 성장한다.
- 메인 레벨은 기본 발현·안정성·효율·복합 주문 수용력을 강화한다.

### 6.2 보조 글자

```text
미숙
→ 숙련
→ 달인
```

- 미숙은 직접 작성 중심이다.
- 숙련부터 하위 글자 스톡 후보가 된다.
- 달인은 복합 연결·작성 정확도·스톡 충전 효율 후보에 기여한다.
- 숙련도가 높아도 기능 글자 수와 스톡 비용은 할인되지 않는다.

### 6.3 학년별 표준 운용량

| 학년 | 보조 글자 표준 안전 운용량 |
|---:|---:|
| 1학년 | 2개 |
| 2학년 | 4개 |
| 3학년 | 6개 |

우수한 계열 성적·연구·실기 성과는 관련 계열의 추가 운용 인증을 제공할 수 있다.

## 7. 기본 전투

### 7.1 전투 준비

```text
기본 소환수 1체 선택
→ 완성 주문·하위 글자 스톡 편성
→ 자동 충전 대상 1종 지정
→ 소환수 스탠스 선택
→ 소환 상태로 전투 시작
```

### 7.2 주문 운용 방식

#### 직접 시전

```text
메인 글자·필요한 보조 글자 직접 작성
→ 연결·대상·기동
```

신규·미숙 글자, 즉석 변형과 핵심 판단을 담당한다.

#### 하위 글자 스톡

```text
복합 주문 작성 중 숙련 글자 스톡 터치
→ 글자 한 개 자동 배치·연결
→ 최종 작성·기동 계속
```

자주 반복하는 숙련 보조 글자의 입력을 줄인다.

#### 완성 주문 스톡

```text
등록 주문 스톡 선택
→ 대상·방향 지정
→ 즉시 기동
```

긴급 방어, 반복 적 처리와 즉시 대응을 담당한다.

### 7.3 소환수

소환수는 다음을 담당한다.

- 자동 공격과 적 방해
- 수호와 작성 시간 확보
- 지정 스톡의 충전 속도·생산량 강화
- 직접 작성·정확 입력·방어·연계에서 얻는 능동 충전 보너스 강화

소환수는 다음을 하지 않는다.

- 회로판에 글자·선·연결 직접 작성
- 숙련 보조 글자 자동 삽입
- 플레이어 허가 없는 주문 판단·완성
- 플레이어 허가 없는 충전 대상 변경

## 8. 스톡 시스템

### 8.1 종류

| 종류 | 결과 | 플레이어 책임 |
|---|---|---|
| 하위 글자 스톡 | 숙련 글자 하나 자동 배치·연결 | 삽입 시점·위치·상위 구조 |
| 완성 주문 스톡 | 등록 주문 전체 즉시 기동 | 사용 시점·대상·방향 |

### 8.2 공용 준비 용량

```text
하위 글자 스톡 1개
= 준비 용량 1

완성 주문 스톡 1개
= 구성 기능 글자 수
```

### 8.3 충전

```text
기준 충전시간(n)
= 1.0 + 0.5 × (n - 1)
```

- 자동 충전 대상은 한 번에 1종이다.
- 진행도는 대상별로 보존한다.
- 소환수가 충전·생산을 지원한다.
- 스톡은 마나를 소비·예약하지 않는다.
- 스톡이 없어도 직접 시전할 수 있다.

## 9. 집중 모드

회로 입력을 시작하면 전투가 멈추지 않고 감속한다.

```text
평상시
→ 적과 소환수 정상 행동

회로 입력 시작
→ 전투 시간 감속
→ 플레이어 직접 작성·스톡 삽입

입력 종료
→ 정상 속도 복귀
→ 주문 결과 전개
```

감속 배율, 입력 제한과 실패 비용은 `PLAYTEST_TUNING_REQUIRED`다.

## 10. 1학년 전투 학습

```text
메인 글자 단독 발동
→ 보조 글자 2개 직접 조합
→ 핵심 보조 글자 숙련
→ 하위 글자 스톡 편성·사용
→ 소환수로 지정 스톡 충전
→ 완성 주문 스톡 사용
→ 현장실습에서 세 수단 조합
```

- 두 종류 스톡은 1학년부터 사용한다.
- 첫 학기 안에 직접 작성·스톡·소환수 생산 지원을 경험한다.
- 1학년 전체를 직접 작성만 하는 긴 튜토리얼로 만들지 않는다.

## 11. 학교 육성

- 중심 학교는 단일 명문 마법학교다.
- 주인공은 일반 가정 출신 장학생 정식 신입생이다.
- 교육 과정은 3년제·학년당 2학기·총 6학기다.
- 한 학기는 자유 일정 10회와 고정 사건 4회로 구성한다.
- 수업은 메인 글자 계열별로 나누며 관련 메인·보조 글자를 배운다.
- 수업은 완성 주문을 자동 지급하지 않는다.
- 현장 활용에 성공한 주문만 마도서에 등록한다.

### 현장실습 자율성

```text
1학년
→ 학교 지정 중심

2학년
→ 지정 핵심 실습 + 선택 실습

3학년
→ 학생 제안 + 학교 위험·안전 승인
```

## 12. 서사와 DDD

### 필수 핵심층

- 현재 상황
- 행동 이유
- 목표
- 위험과 실패 조건
- 중요한 선택 결과

### 선택형 상세층

- NPC 재대화
- 장소·회로 흔적 조사
- 사건 기록·마도서 열람
- 관계·학교 역사·인물 감정

### 표현 방식

- 일반 사건: 짧은 대사 + 목표 카드
- 긴급 임무: 경고 + 목표·위험 카드
- 중요한 관계·승급·졸업: 일반 대화창

DDD는 학기와 이야기를 무조건 줄이는 것이 아니라, 행동과 결과 사이 반복 입력을 줄이고 Micro→Session→Meta 보상을 명확히 하는 원칙이다.

## 13. Core Loop

```text
학교 수업·일정 선택
→ 메인·보조 글자 학습과 숙련
→ 스톡·소환수·마도서 준비
→ 현장실습 진입
→ 위험 관찰
→ 직접 작성·스톡·충전 판단
→ 주문 발동과 문제 해결
→ 주문·활용 발견
→ 보고·관계·성장
→ 다음 수업·실습 선택
```

## 14. CORE_POC 핵심 가설

1. 메인·핵심 보조를 직접 작성하는 것만으로 주문 주체성이 유지되는가.
2. 하위 글자 스톡이 조합 재미를 제거하지 않고 반복 피로만 줄이는가.
3. 완성 주문과 하위 글자 스톡의 역할 차이를 즉시 이해하는가.
4. 소환수의 생산 지원이 전투 판단으로 체감되는가.
5. 1학년 `메인 1 + 보조 2`가 충분한 조합 재미를 제공하는가.
6. 직접 작성과 스톡 UI가 모바일 화면에서 혼잡하지 않은가.
7. 짧은 기본 주문과 복잡한 주문이 모두 유효한가.
