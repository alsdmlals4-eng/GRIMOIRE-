# Spell 통합 게임 설계 — 초기 코어

## 1. 문서 상태

- 프로젝트명: `Spell` (임시명)
- 상태: `PLANNING_IN_PROGRESS`
- 프로젝트 코어 상태: `CORE_CANDIDATE`
- 기준 브랜치: `gpt/planning-spell-20260725`
- 기준 날짜: 2026-07-25
- 엔진: Godot
- 목표 플랫폼: Android / Google Play
- 구현 상태: 미착수

이 문서는 현재 사용자와 합의한 초기 기획의 상위 책임 원본이다. 세부 시스템은 등록된 하위 책임 문서에서 관리하며, 아직 합의되지 않은 수치와 규칙은 확정값으로 취급하지 않는다.

## 2. 한 문장 코어 후보

> 직접 마법 회로를 연구하고 조합해 주문을 발견한 뒤, 숙달한 회로와 성장한 동료의 작업을 지휘하여 더 복잡한 주문을 함께 완성하는 모바일 실시간 마법 전투 게임.

## 3. 핵심 플레이어 판타지

플레이어는 완성된 스킬 버튼을 누르는 마법사가 아니라, 마법의 구조를 이해하고 손으로 회로를 작성하는 마법 사용자다.

```text
내가 직접 기초 회로를 배운다.
→ 회로를 조합해 새로운 주문을 발견한다.
→ 발견한 주문을 설계도로 기록한다.
→ 숙달한 반복 회로를 자동화한다.
→ 동료의 능력과 스탠스를 지휘한다.
→ 플레이어와 동료가 회로를 분담한다.
→ 더 복잡한 상위 조합 주문을 완성한다.
```

## 4. 프로젝트 코어 후보

### PROJECT_CORE

1. 터치로 마법 회로를 직접 그리는 행위
2. 회로를 연결해 새로운 주문을 발견하는 행위
3. 숙달한 기초 회로를 자동화하고 더 높은 회로를 직접 다루는 성장
4. 플레이어와 동료가 회로 구간을 분담해 상위 주문을 완성하는 협동
5. 주문 완성 과정에서 마나, 적 공격 시간, 회로 작성 시간을 판단하는 전투 압박

### CORE_SUPPORT

1. 주문 마도서와 설계도 등록
2. 동료 능력치와 스탠스 지휘
3. 집중 모드의 시간 감속
4. 적 공격 예고와 대응 주문 선택
5. 회로 숙련도와 자동완성 효율 성장
6. 널널한 성공 판정과 정확 입력 추가 보상
7. 메인·보조 회로를 통한 주문 목적과 변형의 분리
8. 기본 자동 회복과 회로 기반 마나 운용

## 5. 핵심 전투 구조

- 적은 일정한 공격 주기 또는 공격 예고 후 플레이어를 공격한다.
- 플레이어는 마나를 소비해 마법 회로를 작성하고 주문을 발동한다.
- 회로 입력을 시작하면 전투 시간이 완전히 멈추지 않고 감속된다.
- 플레이어는 적의 공격 예고, 남은 마나, 주문 작성 시간, 동료 행동을 함께 판단한다.
- 정확한 입력은 추가 보상을 주지만, 합리적인 부정확 입력도 넓게 성공으로 인정한다.

## 6. 마법 회로 성장 구조

### 초기

- 기초 회로를 직접 그린다.
- 형태, 기능, 연결 규칙을 익힌다.
- 미발견 조합을 실험한다.

### 중기

- 숙달한 기초 회로를 자동화하거나 저장한다.
- 중급 회로와 연결 문법에 집중한다.
- 발견한 주문을 목표 주문으로 지정한다.
- 동료가 반복 회로 또는 미완성 구간을 보조한다.

### 후기

- 자동화된 기초 회로와 상위 회로를 결합한다.
- 플레이어와 동료가 여러 회로 구간을 동시에 작성한다.
- 최종 연결 또는 기동은 플레이어가 담당한다.

자동화는 핵심 재미를 제거하지 않고, 이미 숙달한 반복 입력을 줄여 더 복잡한 회로에 집중하게 하는 성장 기능이다.

## 7. 회로 문법 방향

현재 플레이어에게 우선 노출되는 회로 상위 분류는 다음 두 가지다.

```text
메인 회로
→ 주문이 무엇을 하는지 결정

보조 회로
→ 메인 주문의 효과·효율·형태를 수정
```

- 공격, 방어, 체력 회복, 마나 회복, 탐색 등의 메인 목록은 방향 설명용 예시이며 미확정이다.
- 강화, 절감, 증폭, 확대 등의 보조 목록도 방향 설명용 예시이며 미확정이다.
- 형상·전달, 속성·매질, 조건·기동, 연결·흐름은 벤치마킹으로 도출된 확장 후보다.
- 세부 책임 원본은 `docs/planning/CIRCUIT_SYSTEM.md`다.
- 벤치마킹 근거는 `docs/planning/BENCHMARK_CIRCUIT_GRAMMAR.md`다.

## 8. 주문 발견과 마도서

채택 구조: `발견 후 설계도 등록형`

```text
새로운 회로를 획득하거나 배운다.
→ 직접 조합을 실험한다.
→ 유효한 주문을 처음 완성한다.
→ 마도서에 설계도로 등록한다.
→ 이후 목표 주문과 자동화·동료 지원에 사용한다.
```

마도서는 처음부터 정답을 제공하는 목록이 아니라 플레이어가 발견한 지식을 축적하는 기록이다.

## 9. 동료 시스템

- 동료에게 전투형·회로형 같은 고정 타입을 부여하지 않는다.
- 동료 차이는 능력치, 성장 상태, 플레이어가 지정한 스탠스에 의해 발생한다.
- 플레이어는 전투 중 스탠스를 바꿀 수 있지만, 현재 행동 정리와 전환 제약이 존재한다.
- 상위 조합 주문 작성 중 동료는 처리 가능한 미완성 회로 구간을 선택해 대신 그릴 수 있다.
- 동료가 중간 구간을 보조해도 목표 주문 선택과 최종 기동은 플레이어 책임이다.

## 10. 회로 정확도와 성공 보상

채택 구조: `단계형 판정 + 실패 완화 + 정확 입력 추가 보상`

- 허용 오차는 모바일 손가락 입력을 고려해 널널하게 설정한다.
- 부정확 판정의 피해·효율 패널티는 낮게 유지한다.
- 구조 불성립이 아닌 단순 오차는 플레이 흐름을 크게 끊지 않는다.
- 정확 판정은 강한 시각·음향·진동과 소폭 효율 보상으로 칭찬한다.
- 정확 판정을 놓쳤다고 기본 성공이 열등하거나 무가치하게 느껴져서는 안 된다.

## 11. 마나 시스템

채택 구조:

```text
기본 자동 회복
+
플레이 행동 보너스
+
회로 기반 자원 운용
```

- 마나는 천천히 자동 회복되어 고갈 후 복귀 가능성을 보장한다.
- 정확 입력·방어·연계 성공에는 추가 회복 또는 비용 환급 후보를 둔다.
- 마나 회복은 메인 회로 후보, 마나 절감은 보조 회로 후보로 둔다.
- 회복·절감 조합으로 순마나가 무한 증가하지 않도록 제한한다.
- 세부 책임 원본은 `docs/planning/MANA_SYSTEM.md`다.

## 12. 현재 코어 루프 후보

```text
적의 상태와 공격 예고를 확인한다.
→ 목표 주문과 동료 스탠스를 판단한다.
→ 집중 모드에서 메인·보조 회로를 작성하고 연결한다.
→ 자동화된 기초 회로와 동료 보조를 활용한다.
→ 플레이어가 최종 연결 또는 기동을 수행한다.
→ 정확도에 따른 기본 발동 또는 공명 보상을 얻는다.
→ 주문 결과와 마나·시간·생존 상태를 확인한다.
→ 새로운 조합을 발견하고 설계도로 기록한다.
→ 반복 회로를 자동화하고 더 높은 주문에 도전한다.
```

## 13. 현재 핵심 설계 위험

### P0

1. 터치 회로 인식이 실제 손가락 입력을 공정하게 받아들이지 못하는 문제
2. 자동화와 동료 지원이 강해질수록 플레이어가 직접 그릴 이유가 사라지는 문제
3. 자유 조합 경우의 수가 1인 개발 범위를 초과하는 문제
4. 메인 회로 안에 목적·속성·형상을 모두 넣어 종류가 폭증하는 문제

### P1

1. 집중 모드 무한 유지 악용
2. 동료 스탠스 연속 전환이 정답이 되는 문제
3. 상위 주문의 모바일 화면 과밀
4. 회로 발견이 무작위 대입으로 변하는 문제
5. 보조 회로 호환성과 결과가 불명확한 문제
6. 정확 입력 보상이 사실상 필수 판정으로 변하는 문제
7. 회복·절감 조합의 무한 마나 순환

## 14. 첫 PoC 핵심 가설

| 가설 | 최소 검증물 | 통과 신호 |
|---|---|---|
| 손으로 회로를 그리는 행위가 반복해도 재미있다 | 기초 회로 3종과 공격 주문 2종 | 플레이어가 다시 시도하려 함 |
| 집중 감속이 긴장과 조작 편의를 함께 제공한다 | 정상 시간과 감속 비교 | 감속 중에도 압박을 느끼며 완성함 |
| 자동화가 직접 그리기를 제거하지 않는다 | 기초 자동화 + 중급 수동 입력 | 자동화 후 더 복잡한 입력을 선호함 |
| 동료와 구간 분담이 협동처럼 느껴진다 | 동료 자동작성 1구간 | 동료 행동을 예측하고 자신의 구간을 선택함 |
| 널널한 판정과 정확 보상이 함께 즐겁다 | 허용·정확 판정 | 흐름이 유지되고 정확 성공을 다시 노림 |
| 메인·보조 문법을 쉽게 이해한다 | 메인 2종, 보조 2종 | 조합 결과를 사전에 예측함 |
| 마나 회복·절감이 실제 선택을 만든다 | 회복 메인·절감 보조 후보 | 위력·시간·효율 사이에서 선택이 나뉨 |
