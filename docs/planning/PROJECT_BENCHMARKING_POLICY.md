# GRIMOIRE 벤치마킹 선행 원칙

## 1. 문서 상태

```yaml
status: ACTIVE_PROJECT_WORK_PRINCIPLE
project: "GRIMOIRE: 세계를 다시 쓰는 법"
work_mode: PLAN
policy_id: GR-BENCHMARK-FIRST-01
effective_date: 2026-07-31
```

## 2. 원칙

새 시스템, 핵심 규칙, 콘텐츠 구조 또는 UX 흐름을 설계할 때는 설계안을 먼저 확정하지 않는다. 관련 사례를 제한된 범위에서 벤치마킹하고, 적용·변형·배제 근거를 기록한 뒤 프로젝트 설계로 전환한다.

이 원칙은 매 작업마다 대규모 시장조사나 장르 전수조사를 반복하라는 의미가 아니다. 현재 결정 질문에 직접 도움이 되는 사례만 선택한다.

## 3. 필수 발동 조건

다음 중 하나를 새로 만들거나 의미 있게 변경하면 벤치마킹을 먼저 수행한다.

- 플레이어가 반복해서 사용하는 핵심 시스템
- 승리·실패·성장·자원·조합의 핵심 규칙
- 에피소드, 세션, 일정, 던전, 전투 등 콘텐츠 구조
- 주요 화면 전환, 입력, 오류 복구, 정보 위계 등 UX 흐름
- 기존 코어 경험을 바꿀 수 있는 플랫폼 적응
- 제작량·운영 비용이 큰 구조적 선택

## 4. 비발동 조건

다음은 설계 의미가 바뀌지 않으면 새 벤치마킹을 요구하지 않는다.

- 오탈자·문장 교정
- 상태·SHA·날짜·링크 동기화
- 이미 승인된 구조의 단순 데이터 입력
- 설계를 바꾸지 않는 명백한 버그 수정
- 동일 결정 질문에 대해 최근 완료된 벤치마킹이 유효한 경우

비발동 판단이 애매하면 짧은 비교 패스를 사용한다.

## 5. 조사 규모

### QUICK

- 대상: 국소 UX·규칙 조정
- 사례: 직접 사례 2개 이상, 인접 사례 1개 이상
- 산출물: 한 페이지 비교표와 적용·배제 판정

### STANDARD

- 대상: 새 시스템, 핵심 규칙, 콘텐츠 구조
- 사례: 5~7개
- 산출물: 결정 질문, 비교축, 사례별 교훈, 위험, GRIMOIRE 적용 계약

### DEEP

- 대상: 프로젝트 코어 재개방, 장르·시장 방향, 출시 전략, 대규모 구조 전환
- 조건: 사용자의 명시적 요청 또는 기존 근거로 결론을 내릴 수 없는 경우
- 산출물: 별도 Evidence Pack과 적대적 검토

기본값은 `QUICK` 또는 `STANDARD`다. 매번 `DEEP`를 반복하지 않는다.

## 6. 조사 순서

```text
결정 질문 정의
→ 비교축 정의
→ 직접 벤치마크 선정
→ 인접 벤치마크 선정
→ 공식·1차 자료 우선 확인
→ 장점·비용·실패 위험 추출
→ ADOPT / ADAPT / REJECT 판정
→ GRIMOIRE 설계안 작성
→ 적대적 검토
→ 사용자 승인
```

## 7. 사례 선정 규칙

- 유명도보다 현재 결정 질문과의 관련성을 우선한다.
- 동일한 장점만 보여 주는 사례를 중복 수집하지 않는다.
- 최소 하나는 성공 패턴, 최소 하나는 과밀·피로·불투명성 위험을 검토할 수 있어야 한다.
- 공식 사이트, 개발자 설명, 공식 매뉴얼을 우선한다.
- 실제 불편이나 장기 사용 문제는 신뢰 가능한 리뷰·커뮤니티 자료를 보조 근거로 사용할 수 있다.
- 추론은 사실과 분리해 `PROJECT_INFERENCE`로 표시한다.
- 다른 작품의 고유 명칭·서사·아트·UI를 복제하지 않고 설계 원리만 추출한다.

## 8. 필수 비교표

| 항목 | 내용 |
|---|---|
| 결정 질문 | 이번 설계가 답해야 하는 한 문장 |
| 사례 | 작품·제품·도구 |
| 관찰 | 실제로 사용하는 구조 |
| 유효 이유 | 플레이어 문제를 어떻게 해결하는가 |
| 위험 | 피로·혼란·범위·제작비·독창성 문제 |
| 판정 | `ADOPT / ADAPT / REJECT` |
| 프로젝트 계약 | GRIMOIRE에서 지킬 구체 규칙 |

## 9. 완료 조건

벤치마킹 완료는 자료를 모은 상태가 아니다. 다음이 모두 있어야 한다.

- 결정 질문과 비교축
- 선택한 사례의 근거 출처
- 적용·변형·배제 판정
- GRIMOIRE 고유 코어와의 차이
- 범위·UX·제작 위험
- 설계 문서와 정본 라우팅 연결

- 사용자용 GDD Sheet: 관련 PR 병합 후 계약된 탭에 동기화

## 11. 예외

긴급한 보안·데이터 손상·빌드 차단 버그는 우선 복구할 수 있다. 다만 수정이 플레이 규칙이나 UX를 바꾸면 복구 후 별도 벤치마킹과 설계 검토를 수행한다.

## 12. 현재 적용

2026-07-31 GRIMOIRE 기획 완결 패스의 다음 항목에 `STANDARD` 벤치마킹을 적용한다.

- 마법 글자 조합과 복수 해법
- PC 마우스·펜 작성 UX
- 학교 일정과 자유일정 환류
- 마도서 기록과 발견 보상
- 데모 콘텐츠·시간·제작량 경계
