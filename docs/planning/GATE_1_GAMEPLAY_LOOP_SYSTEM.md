# 스펠 Gate 1 게임플레이 Loop 구조

## 문서 상태

- 프로젝트: `스펠` (임시)
- 제품 단계: `CONCEPT_APPROVAL`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- Work Mode: `PLAN`
- 결정 ID: `GM-LOOP-01`
- 상태: `LOOP_STRUCTURE_CONFIRMED_FOR_GATE_1`
- 사용자 승인: 2026-07-27, `권장안대로 진행`
- 상위 플레이어 약속: `GM-PROMISE-01`
- 구현 상태: `NOT_STARTED`
- 수치 상태: `PLAYTEST_TUNING_REQUIRED`

이 문서는 승인된 플레이어 약속을 실제 반복 경험으로 변환하는 `Micro / Combat / Session / Semester Loop`의 책임 원본이다.

> 마법학교 학생이 되어 글자의 의미를 배우고, 수업과 현장실습에서 주문을 직접 설계해 내가 생각한 해결법으로 세계를 바꾸는 모바일 마법 RPG.

## 1. 채택 구조

스펠의 기본 성장 순환은 다음과 같다.

```text
수업
→ 마법 글자·원리·설계법을 배운다

교내 연습
→ 안전한 환경에서 직접 작성·조합·사용한다

일상
→ 학생·교수·라이벌·소환수와 관계를 쌓고 실습 관점을 얻는다

현장실습
→ 실전 문제와 전투에서 배운 원리를 응용·변형한다

복귀·정리
→ 새 주문·활용법·실패 원인·관계 결과를 기록한다

다음 수업·연구
→ 실전에서 드러난 부족함과 관심 분야를 다시 학습한다
```

핵심 문장:

> 수업에서 알고, 연습에서 할 수 있게 되고, 실전에서 다르게 써 보며, 일상에서 그 경험의 관계와 의미가 누적된다.

## 2. 일정 운영 방식

`고정 핵심 사건 + 자유 일정` 혼합형을 채택한다.

### 고정 축

- 학기 시작 사건
- 필수 기초 수업
- 중간 현장실습
- 학기 핵심 사건·현장실습
- 시험·발표·평가

고정 축은 핵심 문법, 주요 인물, 학기 갈등과 난이도 곡선을 보장한다.

### 자유 일정

고정 사건 사이에서 다음 중 하나를 선택한다.

- 선택 수업
- 교내 연습
- 자유 연구
- 현장실습 준비·사전 조사
- 일상·관계 활동
- 소환수 교감
- 휴식·정비

자유 일정은 플레이어의 전문 계열, 주문 숙련, 관계, 동행 가능 인물과 추가 해결 관점을 변화시킨다. 자유 일정을 선택하지 않았다는 이유로 필수 진행을 영구 차단하지 않는다.

## 3. Micro Loop

개별 문제 하나를 해결하는 약 30초~2분 단위다.

```text
문제·위험 관찰
→ 필요한 현상 결정
→ 메인 글자 선택
→ 보조 글자 조합
→ 직접 작성 또는 숙련 스톡 삽입
→ 주문 기동
→ 적·환경·목표 변화 확인
→ 성공·실패 원인 이해
→ 유지·수정·다른 주문 선택
```

### Micro Loop 성공 조건

- 플레이어가 왜 그 결과가 발생했는지 이해할 수 있다.
- 한 번의 결과가 다음 주문 선택을 바꾼다.
- 정답 주문 하나를 암기하는 구조보다 복수의 유효한 해결법을 허용한다.
- 실패는 무반응이 아니라 원인 피드백과 재설계 기회를 제공한다.

## 4. Combat Loop

약 3~5분 전투·문제 묶음의 반복이다.

```text
현장 상태 파악
→ 첫 주문으로 적·환경 반응 확인
→ 이동·방어·소환수 지원으로 작성 시간 확보
→ 주문을 유지·변형·교체
→ 스톡 사용과 직접 작성의 우선순위 판단
→ 핵심 위협 또는 목표 해결
→ 발견·피해·소비·실패 원인 기록
```

### 전투 역할 경계

- 직접 작성: 새 글자, 미숙 글자, 핵심 판단, 즉석 변형
- 하위 글자 스톡: 숙련 반복 한 단위의 자동 배치·연결
- 완성 주문 스톡: 제한된 긴급 대응과 준비 전술
- 소환수: 전투·수호·지정 스톡 생산·충전 지원

스톡과 소환수는 주문 설계를 대체하지 않는다. 조건부 완전 자동 발동과 소환수의 글자·회로 직접 작성은 허용하지 않는다.

## 5. 수업 Session Loop

목표 시간은 약 10~15분이다.

```text
짧은 상황·원리 소개
→ 교수·학생 시범
→ 안내 작성과 기본 발현
→ 제한 조건이 있는 설계 과제
→ 직접 조합·사용
→ 결과 비교와 수정
→ 새 글자·연습 과제·마도서 기록
```

### 수업 원칙

- 수업은 완성 주문 목록을 지급하는 메뉴가 아니다.
- 설명 직후 플레이어가 직접 작성하거나 조합한다.
- 기본 정보는 짧게 제공하고 원리·역사·사례는 선택형 상세 대화로 확장한다.
- 수업의 성공은 지문 암기가 아니라 글자와 결과의 인과 이해다.

## 6. 교내 연습 Session Loop

```text
연습 목표 선택
→ 사용할 메인·보조 글자 구성
→ 직접 작성
→ 허수아비·장치·모의 환경에 사용
→ 결과·마나·작성 시간 확인
→ 조합 수정
→ 안정적 재현 시 숙련 기록
```

교내 연습은 실패 비용이 낮고 원인 피드백이 강한 안전한 설계 공간이다. 강한 주문 제작보다 작성 감각, 보조 글자 차이, 짧은 주문과 복잡한 주문의 비용을 학습시키는 데 우선순위를 둔다.

## 7. 현장실습 Session Loop

```text
짧은 브리핑
→ 준비한 글자·스톡·동행 확인
→ 현장과 위험 관찰
→ 첫 문제·전투에서 예상 주문 사용
→ 적·환경 반응 확인
→ 주문 재설계 또는 다른 활용 발견
→ 핵심 목표 해결
→ 복귀·결과·관계·마도서 기록
```

### 현장실습 원칙

- 학교는 문제와 안전 조건을 제시하되 해답까지 지정하지 않는다.
- 전투뿐 아니라 구조·보호·탐색·복구·생활 문제를 같은 마법 문법으로 해결한다.
- 수업에서 배운 기본 경로는 존재하지만 관계·조사·연구로 추가 관점을 얻을 수 있다.
- 실패는 즉시 게임오버보다 감독 개입, 보충 수업, 재실습, 복구 임무와 관계 변화로 이어진다.

## 8. 일상 Session Loop

```text
인물·장소·활동 선택
→ 짧은 기본 장면
→ 대화·행동 선택
→ 관계·정보·감정 변화
→ 필요하면 상세 대화·조사·기록 열람
→ 이후 수업·실습 변화 저장
```

### 일상의 역할

- 동행 인물과 팀 관계 변화
- 교수의 추가 설명·연구 과제 개방
- 라이벌의 다른 설계 관점 제공
- 실습 지역 사전 정보와 추가 해결 관점 제공
- 소환수 교감과 반응 변화
- 성공·실패 이후 후속 대화와 학교생활 전개

일상은 호감도 수치만 올리는 메뉴가 아니다. 관계 변화는 다음 수업·실습의 대화, 정보, 동행, 접근법을 변화시켜야 한다. 다만 필수 해결 정보를 관계 콘텐츠에만 숨기지 않는다.

## 9. Semester Loop

```text
학기 시작
→ 새 수업·교수·학생·갈등 소개

기초 수업
→ 새 글자와 원리 학습

자유 일정
→ 연습·연구·관계·준비 선택

중간 현장실습
→ 초반 학습의 실전 검증

복귀·보충
→ 실패 분석·추가 수업·관계 반응

심화 수업·자유 일정
→ 응용 조합과 전문 방향 강화

학기 핵심 현장실습
→ 독립적인 해결법 설계

평가·발표
→ 주문·관계·연구 결과 정리

다음 학기
→ 새 수업·권한·문제 복잡도 확대
```

정확한 자유 일정 수와 고정 사건 수는 기존 `10 + 4`를 참조 후보로 보존하되, 콘텐츠 제작량과 10~15분 세션 구조를 검토하기 전까지 확정 수치로 사용하지 않는다.

## 10. 학년별 Loop 변화

### 1학년

- 학교 지정 수업·실습 중심
- 글자 판독, 직접 작성, 기본 조합 학습
- 문제는 지정하지만 해결법은 플레이어가 선택
- 실패 시 감독 개입과 보충 학습

### 2학년

- 필수 수업·실습과 선택 수업·실습 병행
- 계열 선택과 교차 응용 확대
- 동행·준비·접근법 선택 비중 증가

### 3학년

- 연구·전문 분야와 학생 제안형 실습 중심
- 학교는 위험·안전 기준을 승인
- 화력보다 자율성·책임·문제 복잡도·독립 설계 능력으로 성장 표현

3년·6학기 구조 자체는 콘텐츠 범위 검증 전까지 `NEUTRAL_SCOPE_RISK`다.

## 11. 중단·복귀 지점

모바일 환경을 위해 다음 시점에서 상태 저장과 안전 복귀를 지원하는 방향을 채택한다.

- 수업의 설명·시범 종료 후
- 설계 과제 시작 전과 결과 확정 후
- 현장실습 브리핑·준비 완료 후
- 전투·문제 묶음 사이
- 핵심 목표 해결 직후
- 복귀·보상·마도서 기록 완료 후
- 일상 장면의 선택 결과 확정 후

전투 한가운데의 완전한 상태 복원 범위는 Godot 저장 구조와 CORE_POC 이후 결정한다. 현재 Gate 1에서는 전투·문제 묶음을 3~5분 이하의 복귀 가능한 단위로 나누는 것을 우선한다.

## 12. 보상과 데이터 흐름

```text
수업
→ 글자·원리·연습 과제

연습
→ 작성 숙련·조합 이해·스톡 후보

현장실습
→ 새 활용·주문 발견·평가·실패 기록

일상
→ 관계·정보·동행·추가 관점

복귀·정리
→ 마도서·숙련·관계·학기 상태 갱신

다음 수업·실습
→ 이전 결과를 반영한 새 선택과 문제
```

각 활동은 최소 하나의 가시적 변화를 제공해야 한다.

- 새로운 이해
- 새로운 설계 선택
- 세계·환경 변화
- 관계 변화
- 다음 활동 후보 변화

## 13. 보호 원칙

- 수업은 완성 주문 상점이 아니다.
- 현장실습은 배운 주문을 그대로 재생하는 시험이 아니다.
- 일상은 전투와 무관한 호감도 메뉴가 아니다.
- 자유 일정은 필수 진행을 영구 차단하지 않는다.
- 모든 세션에 수업·전투·일상을 억지로 동시에 넣지 않는다.
- 세션마다 중심 활동 하나를 두고 다른 축의 결과만 연결한다.
- 장문 대화 없이도 목표·위험·핵심 규칙을 이해할 수 있어야 한다.
- 직접 작성·조합 판단이 스톡·소환수·자동화에 의해 제거되지 않는다.

## 14. 미검증 항목

- 실제 수업·실습 세션이 10~15분 안에 완결되는지
- 전투·문제 묶음 3~5분이 모바일 중단 환경에 적합한지
- 자유 일정 선택이 의미 있는 차이를 만드는지
- 수업 설명과 직접 플레이의 적정 비율
- 일상 관계 변화가 제작량 대비 충분한 체감을 주는지
- 실패 후 보충·재실습이 반복 노동이 되지 않는지
- 한 학기의 고정 사건·자유 일정 개수
- 3년·6학기 콘텐츠 범위의 1인 개발 가능성
