## 2. 결정 질문

Mobile Landscape 한 화면에서 적·행동 예고·남은 시간·환경 위험·플레이어 자원과 직접 작성의 캔버스·획·인식 후보·비용·`[구현]`을 어떻게 배치해야, 상황을 놓치지 않으면서도 손가락과 Stylus로 정확하게 쓸 수 있는가?

이 결정은 완성 아트나 픽셀 수치를 잠그지 않는다. **영역 관계·정보 우선순위·확장/축소 상태·입력 안전성**을 Wireframe 계약으로 잠근다. 정확한 비율·크기·시간은 `TEST_VALUE`다.

## 3. A안 — 상황 보존형 확장 우측 Writing Focus Panel / 권장

### 기본 관찰 상태

```text
┌────────────────────── 전투·상황 영역 ──────────────────────┬──── 작성 진입 ────┐
│ 상단: 적 의도·남은 시간·환경 위험                            │ 문자 슬롯·쓰기 버튼 │
│ 중앙: 적·환경·효과                                           │ 현재 조합 요약       │
│ 좌측: 플레이어·동반자·마나                                   │                    │
│ 하단: 최근 결과·상황 행동                                    │                    │
└──────────────────────────────────────────────────────────────┴──────────────────┘
```

### 작성 Focus 상태

```text
┌──────── 상황 보존 영역 ────────┬──────────── 확장 Writing Panel ────────────┐
│ 적·환경은 축소하되 계속 표시    │ 상단: 대상·주문 슬롯·마나·예상 비용          │
│ 적 의도·타이머는 고정 유지       │ 중앙: 큰 직접 작성 캔버스                     │
│ 플레이어 핵심 상태만 압축        │ 하단: 인식 후보·의미·Undo·삭제·취소·[구현]   │
└─────────────────────────────────┴────────────────────────────────────────────┘
```

### 규칙

- 기본 상태에서는 장면과 적을 중심으로 보여 주고 우측에는 작성 진입과 현재 조합 요약만 둔다.
- Writing Panel을 열면 우측 영역이 확장되지만 적·대상·환경 위험·타이머를 화면에서 제거하지 않는다.
- 캔버스는 Panel 내부에서 가장 큰 단일 입력 영역으로 배치한다.
- 인식 후보는 낮은 확신 상태에서 자동 확정하지 않고 의미·획 차이와 함께 선택하게 한다.
- `[구현]`은 캔버스와 분리된 고정 위치에 두고 마나·문법·상황 조건을 만족할 때만 활성화한다.
- Undo·현재 획 삭제·전체 지우기·취소·구현을 서로 다른 위치와 형태로 구분한다.
- 전투 타이머는 작성 중 계속 진행하되, 결과 해석·연출 중에는 기존 승인대로 일시 정지한다.
- 작성 Panel을 닫으면 Draft를 유지하고 전투 상황으로 돌아간다. 명시적 전체 취소에서만 Draft를 폐기한다.
- 비전투와 제작은 같은 Writing Focus Panel 계약을 사용하되 타이머·적 상태 대신 대상·재료·안전 조건을 표시한다.

장점:

- 작성 공간을 확보하면서도 주문을 쓰는 이유와 긴급성을 잃지 않는다.
- 전투·비전투·제작이 같은 Panel 계약을 공유해 학습과 QA가 단순해진다.
- 기존 승인인 적 중심 전투·우측 작성·즉시 `[구현]`과 가장 잘 맞는다.
- Panel 축소 시 Draft를 유지해 작은 화면의 반복 작성 피로를 줄인다.

위험:

- 상황 보존 영역과 Writing Panel 모두에 정보가 많으면 여전히 과밀할 수 있다.
- 우측 Panel 폭이 기기 비율에 따라 캔버스 또는 적 시야를 침범할 수 있다.

보정:

- 작성 중 상황 보존 영역은 적 의도·타이머·대상·환경 위험·핵심 HP만 남기고 나머지를 접는다.
- Panel 비율은 고정 픽셀이 아니라 Safe Area와 기기 종횡비에 따라 `TEST_VALUE` 범위에서 조정한다.
- 캔버스 위에 버튼·툴팁·손가락 유도선을 겹치지 않는다.

## 4. B안 — 전체 화면 Writing Takeover

```text
전투 화면
→ 전체 화면 작성 모드
→ 작은 적 Thumbnail·타이머
→ 후보 선택·구현
→ 전투 화면 복귀
```

장점:

- 가장 큰 작성 캔버스와 높은 획 정확도를 확보한다.
- 버튼과 후보를 여유 있게 배치하기 쉽다.

위험:

- 적·환경·보존 대상이 Thumbnail로 축소돼 상황 판단과 주문 설계의 연결이 약해진다.
- 화면 전환 비용과 전투 중 불안이 커진다.
- 비전투·제작에서도 앱형 독립 화면처럼 느껴질 수 있다.

## 5. C안 — 항상 열린 소형 우측 Writing Panel

전투·비전투 모든 장면에서 우측 작은 Panel을 고정하고 별도 확장 없이 그 안에서 계속 작성한다.

장점:

- 화면 상태 변화가 적고 적·환경을 가장 넓게 유지한다.
- 구현 구조가 단순하다.

위험:

- 손가락 작성 면적이 부족해 판독 실패와 손 피로가 증가한다.
- 후보·Undo·비용·구현 버튼이 캔버스를 침범한다.
- 접근성 확대와 작은 기기 대응이 어렵다.

## 6. 권장 판정

`A — 상황 보존형 확장 우측 Writing Focus Panel`을 권장한다.

핵심 이유:

- GRIMOIRE의 작성은 별도 퍼즐이 아니라 현재 상황을 바꾸기 위한 행위이므로 적·대상·환경을 계속 볼 수 있어야 한다.
- 동시에 Mobile 직접 작성은 충분한 캔버스가 없으면 핵심 재미가 인식 오류·손 피로로 대체된다.
- 확장 Panel은 두 요구를 동시에 만족시키며 승인된 Scene-first Focus Flow와 기존 Battle 계약을 그대로 연결한다.

## 7. A안 승인 시 확정되는 것

- 기본 관찰 상태에서는 장면·적 중심, 우측에는 작성 진입과 조합 요약을 둔다.
- 작성 시 우측 Panel을 확장하고 상황 보존 영역을 압축한다.
- 적 의도·타이머·대상·환경 위험은 작성 중에도 계속 표시한다.
- 캔버스는 Panel의 최대 단일 영역이며 버튼과 겹치지 않는다.
- 후보·비용·문법·`[구현]`은 캔버스와 분리한다.
- Panel 축소·일시 닫기에는 Draft를 유지하고 전체 취소에서만 폐기한다.
- 비전투·제작·전투가 같은 Writing Focus Panel 계약을 공유한다.
- 정확한 Panel 비율·Touch target·캔버스 크기·후보 수·타이머 배치는 `TEST_VALUE`다.
- Grill Me counter는 `10/10`이 되어 `GM-PREMERGE-ADVERSARIAL-GATE-01`과 Draft PR #36 병합 검토가 발동한다.
