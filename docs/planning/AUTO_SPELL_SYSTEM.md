# Spell 자동스펠 시스템 — 초기 방향

## 1. 문서 상태

- 상태: `PLANNING_IN_PROGRESS`
- 방향 상태: `DIRECTION_CONFIRMED`
- 발동 방식: `MIXED_CONFIRMED`
- 스톡 구조: `CONFIRMED`
- 세부 충전 규칙: `UNRESOLVED`
- 기준 브랜치: `gpt/planning-spell-20260725`
- 기준 날짜: 2026-07-25
- 관련 결정: `GM-00-11`, `GM-00-12`

자동스펠은 모바일에서 반복 드로잉으로 발생하는 피로도를 줄이기 위한 기능이다. 직접 그리기를 제거하는 방치형 전환이 아니라, 이미 학습한 주문을 미리 준비해 반복 사용하고 플레이어가 새로운 회로·조건·전투 판단에 집중하도록 하는 운용 계층이다.

## 2. 자동화의 세 단계

Spell의 자동화는 하나의 기능으로 통합하지 않고 단계별로 구분한다.

### 2.1 회로 자동화

- 플레이어가 직접 학습하고 숙련한 기초 회로를 자동으로 배치한다.
- 초반 핵심인 `메인 + 형상·전달`이 우선 자동화 대상이다.
- 플레이어는 이후 추가된 보조·조건 회로에 집중한다.

### 2.2 소환수 자동작성

- 소환수가 숙련된 보조 회로나 미완성 구간을 대신 작성한다.
- 소환수 능력치, 적성, 스탠스에 따라 속도와 안정성이 변동한다.
- 플레이어와 동시에 서로 다른 구간을 작성할 수 있다.

### 2.3 자동스펠

- 마도서에 등록되고 일정 숙련 조건을 만족한 완성 주문을 자동 운용한다.
- 전체 회로를 매번 손으로 다시 그리지 않아도 반복 사용할 수 있다.
- 자동스펠은 미리 준비한 `스톡`을 소비해 발동한다.

## 3. 해금 조건

자동스펠 후보 주문은 최소한 다음 과정을 거쳐야 한다.

```text
회로 획득·학습
→ 직접 조합 성공
→ 주문 발견
→ 마도서 설계도 등록
→ 반복 사용 또는 숙련 조건 달성
→ 자동스펠 등록 가능
→ 전투 전에 스톡으로 준비
```

미발견 주문과 처음 사용하는 회로를 자동으로 해결하지 않는다.

## 4. 스톡 시스템

### 4.1 기본 정의

스톡은 완성된 주문을 미리 구축해 저장한 사용 횟수다.

```text
등록된 주문 선택
→ 자동스펠 스톡으로 준비
→ 전투 중 원터치 또는 조건에 따라 발동
→ 스톡 1개 소비
```

- 스톡은 재사용 대기시간만 기다리면 무한히 나오는 일반 스킬 버튼과 다르다.
- 스톡이 남아 있어야 해당 자동스펠을 발동할 수 있다.
- 같은 주문을 여러 스톡 준비할지, 여러 주문에 나누어 배치할지는 플레이어의 전투 준비 판단이 된다.
- 자동스펠 스톡이 소진되어도 직접 회로를 그려 주문을 시전할 수 있다.

### 4.2 성장

- 플레이어 성장에 따라 준비 가능한 전체 스톡 수가 증가한다.
- 정확한 초기 스톡 수, 최대치, 성장 간격은 아직 확정하지 않는다.
- 스톡 증가는 편의성과 전술 선택의 확장이지 직접 시전 삭제를 의미하지 않는다.
- 과금 없이는 정상적인 스톡 성장이 막히는 구조를 사용하지 않는다.

### 4.3 비용 원칙

현재 우선 원칙은 다음과 같다.

- 스톡은 회로 작성 시간을 절약한다.
- 자동스펠도 기본 마나 규칙을 무시하지 않는다.
- 스톡을 준비했다고 해서 주문 마나가 무조건 무료가 되지는 않는다.
- 스톡 준비 시점에 마나를 선납할지, 발동 시 소비할지는 후속 결정으로 남긴다.

## 5. 혼합형 발동

자동스펠마다 다음 두 방식 중 하나를 지정할 수 있다.

### 5.1 원터치 스톡

- 플레이어가 아이콘을 눌러 저장된 주문을 사용한다.
- 반복 드로잉 피로를 줄이면서 사용 시점 판단을 유지한다.
- 발동 시 해당 주문의 스톡 1개를 소비한다.

### 5.2 조건부 스톡

- 체력, 마나, 적 거리, 피격, 시간, 방어 성공 등의 조건을 설정한다.
- 조건이 충족되고 스톡이 남아 있을 때 자동 발동한다.
- 조건이 충족되어도 스톡이 없으면 발동하지 않는다.
- 조건부 슬롯과 조건 규칙 수는 제한해 완전 방치형 전투를 방지한다.

### 5.3 혼합 운용 예시

```text
주력 공격 주문
→ 원터치 스톡

긴급 방어 주문
→ 피격 조건 스톡

체력 회복 주문
→ 체력 기준 조건 스톡
```

예시는 방향 설명용이며 자동스펠 목록과 조건 목록은 미확정이다.

## 6. 직접 시전과 자동스펠의 역할 차이

### 직접 시전

- 전투 상황에 맞게 보조·조건 회로를 즉석 변경할 수 있다.
- 정확 판정 추가 보상을 획득할 수 있다.
- 소환수와 회로 구간을 유동적으로 분담한다.
- 새로운 조합을 발견할 수 있다.
- 스톡이 없어도 마나와 시간이 허용하면 시전할 수 있다.
- 숙련 플레이에서는 자동스펠보다 더 빠르거나 효율적일 수 있다.

### 자동스펠

- 반복 입력 피로를 줄인다.
- 안정적인 기본 성능을 제공한다.
- 등록된 설계도를 그대로 사용한다.
- 즉석 변형과 신규 발견 기능은 제한한다.
- 준비된 스톡만큼만 사용할 수 있다.
- 원터치 또는 지정 조건으로 발동한다.

자동스펠은 직접 시전의 완전한 상위 호환이 아니다.

## 7. 자동스펠 편집 범위

- 자동스펠은 등록된 설계도 하나를 기준으로 한다.
- 전투 중 자동스펠 회로를 실시간으로 자유 교체하지 않는다.
- 변형하려면 새 설계도로 저장하거나 직접 시전한다.
- 소환수가 자동스펠의 일부 회로를 준비해 발동 안정성이나 준비 효율을 높일 수 있다.
- 플레이어가 직접 개입해 마지막 기동을 수행하는 반자동 모드는 후보로 유지한다.

## 8. 피로도 완화 목표

```text
처음 배우는 회로
→ 직접 그림

숙련한 메인 + 형상·전달
→ 회로 자동화

새로 해금된 보조·조건
→ 직접 그림

숙련한 보조 회로
→ 소환수가 자동작성 가능

반복 사용하는 완성 주문
→ 스톡으로 미리 준비해 자동스펠 사용

새로운 조합·고난도 대응
→ 다시 직접 시전
```

플레이어는 게임이 진행될수록 더 많은 선을 반복해서 그리는 것이 아니라, 이미 익힌 부분은 저장·자동화하고 새롭게 판단해야 하는 부분만 직접 다룬다.

## 9. 가드레일

- 자동스펠 스톡만으로 모든 전투가 해결되지 않게 한다.
- 새로운 주문 발견은 직접 회로 조합으로만 가능하게 한다.
- 정확 입력 보상과 즉석 변형은 직접 시전의 고유 가치로 남긴다.
- 자동스펠에 광고 시청이나 과금이 필수인 구조를 두지 않는다.
- 스톡 수로 과도한 불편을 만들어 유료 확장을 강제하지 않는다.
- 자동스펠이 마나 규칙과 회복·절감 회로를 무시하지 않는다.
- 조건부 자동발동이 집중 모드와 적 공격 대응 판단을 완전히 제거하지 않게 한다.
- 스톡이 소진되었을 때 직접 시전이 불가능해지는 구조를 사용하지 않는다.

## 11. 미해결 사항

1. 소비된 스톡은 전투 사이에만 보충되는가, 전투 중에도 다시 충전할 수 있는가.
2. 스톡 준비 시 마나를 선납하는가, 발동 시 마나를 소비하는가.
3. 전체 스톡 한도와 주문별 스톡 한도를 분리할 것인가.
4. 조건부 자동스펠 슬롯과 조건 규칙 수는 몇 개인가.
5. 자동스펠에서도 플레이어가 최종 기동에 개입할 수 있는가.
6. 직접 시전의 효율 보상을 어느 수준으로 둘 것인가.
