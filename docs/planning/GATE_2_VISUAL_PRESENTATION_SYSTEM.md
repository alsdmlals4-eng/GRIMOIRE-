# 스펠 Gate 2 시각 표현 구조

## 1. 문서 상태

- 결정 ID: `GM-VISUAL-PRESENTATION-01`
- 전투 화면 후속 결정: `GM-BATTLE-PRESENTATION-01`
- 사용자 승인: 2026-07-27
- 상태: `LANDSCAPE_HYBRID_2D_WITH_SEPARATE_TACTICAL_BATTLE_CONFIRMED`
- 제품 단계: `PROTOTYPE_AND_VERTICAL_SLICE`
- Gate 1: `APPROVED`
- 프로젝트 코어: `CORE_CONFIRMED`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- 구현: `NOT_STARTED`
- Codex: `NOT_RUN`
- 이미지·사운드 대량 제작: `BLOCKED_BY_ART_STYLE_AND_ASSET_SPEC`
- 다음 차단 결정: `ART-STYLE-01`

이 문서는 화면 방향, 학교·탐색 카메라, 대화 화면, 별도 전투 화면, 마법 작성 오버레이와 화면비 대응을 책임진다.

> **스펠은 가로형 하이브리드 2D로 표현한다. 학교·자유일정·비전투 탐색은 고정·장면 기반 3/4 시점으로 보여 주고, 대화는 같은 배경 위에 반신 일러스트를 겹친다. 전투는 별도의 고정 3/4 전술 전투장으로 전환하며, 마법 작성 시 전투장을 감속·암전한 오버레이를 사용한다.**

---

## 2. 최상위 화면 구조

```text
학교·자유일정·비전투 탐색
= 가로형 고정·장면 기반 3/4 필드

대화
= 같은 장소 배경 + 반신 일러스트 + 대화창

전투
= 별도 고정 3/4 전술 전투장

마법 작성
= 현재 필드 또는 전투장을 감속·암전 + 전용 작성 오버레이

전투 종료
= 결과를 반영한 원래 필드 장면으로 복귀
```

### 비타협 원칙

- 화면 체계가 달라도 동일한 장소·사건의 연속으로 느껴져야 함
- 전투 진입과 복귀 시 목표·대상·환경 변화의 인과 유지
- 마법 작성 중 대상·위험·보조 소환수 상태 확인 가능
- 화려함보다 글자 궤적·대상·위험·결과 인과 우선
- 큰 자유 이동 학교·자유 카메라·대형 전투 맵은 초기 Slice 제외

## 3. 화면 방향·화면비

- 기본 방향: `LANDSCAPE`
- 기준 구도: `16:9`
- 확장 대응: `18:9~20:9`
- 세로 모드: 초기 Slice 미지원
- 자동 회전: 비활성 후보
- 정확한 내부 해상도: `ASSET-SPEC-01`

화면비 대응:

```text
16:9
= 핵심 UI·작성 패널·연출 안전 구도

18:9~20:9
= 좌우 배경·월드 영역 확장
= 핵심 정보는 16:9 안전 구도 유지
```

- 노치·카메라 홀·제스처 안전 영역 고려
- 넓은 화면 때문에 작성 패널의 필수 입력 면적이 줄어들지 않음
- UI를 단순 확대·축소해 가독성을 해결하지 않음

## 4. 학교·자유일정·탐색 화면

### 카메라

- `FIXED_SCENE_BASED_3_QUARTER_VIEW`
- 장면 전환 또는 제한된 연출 이동만 허용
- 자유 회전·자유 줌·넓은 맵 추적 카메라 제외

### 장면 구조

```text
배경 레이어
→ 건축·지형·원경

상태 레이어
→ 수업 / 시험 / 자유일정 / 축제 / 손상 / 복구

상호작용 레이어
→ SD 캐릭터·메인 동반 소환수·대상 오브젝트

효과 레이어
→ 마법·위험·환경 반응

UI 레이어
→ 목표·자원·위험 경고

대화·작성 레이어
→ 상황에 따라 상단 표시
```

### 이동

- 출입구·핫스폿·짧은 경로 선택으로 장면 단위 이동
- 위치 탐색보다 상황 관찰과 주문 설계가 중심
- 넓고 빈 복도·맵 제작 금지
- 카메라를 돌려야만 보이는 필수 정보 금지

---

## 5. 학교 장면 재사용

하나의 학교 장면 세트를 다음 상태로 변형한다.

- 기본 수업
- 실기시험
- 자유일정 대화·휴식
- 학교축제

재사용 수단:

```text
동일한 건축·카메라·기준선
+ 조명 변화
+ 장식 오버레이
+ NPC 배치
+ 상호작용 오브젝트
+ BGM·환경음 상태
```

축제를 위해 별도 대형 맵을 만들지 않는다.

---

## 6. 대화 화면

```text
기존 장소 배경 유지
+ 캐릭터 반신 일러스트
+ 이름·대화창
+ 메인 동반 소환수 반응 슬롯
+ 필요한 경우 관계·상태 아이콘
```

- 기본 강조 화자 1명, 필요한 경우 2명까지
- 자유일정의 짧은 교류는 기존 장소와 반신 조합 우선
- 필수 정보는 표정·음성만으로 전달하지 않음
- 초상과 배경이 대화 텍스트 대비를 방해하지 않음

세부 책임 원본: `docs/planning/GATE_2_CHARACTER_PRESENTATION_SYSTEM.md`

## 7. 별도 전술 전투장

### 최신 사용자 결정

기존의 `필드와 같은 장면에서 전투` 규칙은 다음으로 대체한다.

```text
필드에서 위험·적·환경 목표 확인
→ 짧은 전투 전환 연출
→ 별도 고정 3/4 전술 전투장
→ 상황 관찰·대상 선택·주문 작성·환경 변화
→ 전투 결과 확정
→ 원래 필드로 복귀
```

상태: `SUPERSEDED_BY_GM-BATTLE-PRESENTATION-01`

### 전투장 구성

- 주인공 3.5~4등신 SD
- 적 1~2종
- 수호 또는 견제형 전투 보조 소환수 1체
- 보호 대상·장애물·위험원·구조 대상 등 환경 오브젝트
- 위험 범위·주문 대상·현재 목표
- 마법 작성 오버레이

### 제작 경계

- 작은 고정 전투장
- 자유 카메라·대형 이동 맵·복잡한 위치 조작 제외
- 필드와 동일한 SD 비율·기본 골격 재사용
- 전투장 전용 탐색·관계·성장 프레임워크 추가 금지

### 필드와의 연속성

- 필드의 색·건축·핵심 오브젝트를 전투장에 계승
- 전투 전 관찰한 대상과 동일한 식별 요소 유지
- 손상·복구·구조 결과를 필드 복귀 후 반영
- 전투 전환은 짧고 반복 가능한 연출 사용

## 8. 마법 작성 오버레이

### 기본 전환

```text
주문 작성 진입
→ 현재 화면 감속
→ 배경 밝기·채도 감소
→ 작성 패널 활성화
→ 대상·위험·지원 상태 유지
→ 글자 작성·조합
→ 주문 발동
→ 오버레이 해제
→ 결과를 필드 또는 전투장에서 표시
```

### 시간 처리

- 시각 기본 후보: `WORLD_SLOWDOWN_WITH_DIMMING`
- 완전 정지·감속·실시간 최종안: `PLAYTEST_TUNING_REQUIRED`
- 감속 비율: `NOT_YET_TUNED`

### 고정 정보 예산

- 현재 목표
- 선택한 메인 글자
- 선택한 보조 글자
- 마나 또는 사용 가능 횟수
- 위험 경고
- 전투 보조 소환수 핵심 지원 상태

작성 화면 밖으로 분리:

- 관계 상세
- 마도서 전체
- 시험 세부 점수
- 소환수 성장·편성 상세
- 장문 설명

### 가독성

- 작성 궤적은 배경·효과와 명도·두께·형태로 분리
- 위험 경고는 색상 하나에만 의존하지 않음
- 암전 중에도 주문 대상과 피격 위험을 실루엣·아이콘·테두리로 유지
- 발동 FX가 글자 궤적과 위험 정보를 덮지 않음
- 화면 흔들림·섬광·입자 밀도 조절 가능
- 손가락이 시작점·끝점·판정 피드백을 지속적으로 가리지 않음

## 9. 캐릭터·소환수 표현

### 캐릭터

- 필드·전투: 3.5~4등신 SD
- 대화: 반신 일러스트
- 필드와 전투는 같은 디자인·기본 골격 재사용

### 메인 동반 소환수

- 학교·대화·현장에 지속 등장
- 필드 소형 전신과 작은 반응 초상 또는 반응 연출
- 정답이나 최적 주문을 먼저 제시하지 않음
- 초기 Slice는 초기 성장 형상 1개

### 전투 보조 소환수

- 전투장에서 수호 또는 견제 역할을 명확한 실루엣으로 표현
- 지원 범위와 남은 상태를 월드 효과와 최소 UI로 표시
- 플레이어 주문·적·위험 경고보다 큰 시각 점유율 금지

- `docs/planning/GATE_2_CHARACTER_PRESENTATION_SYSTEM.md`
- `docs/planning/GATE_2_SUMMON_GROWTH_AND_FORM_SYSTEM.md`

## 10. 모드 전환

### 탐색 → 대화

- 필드 카메라와 배경 유지
- 반신 일러스트와 대화창 추가

### 탐색 → 전투

- 장소·대상·목표를 짧게 강조
- 전술 전투장으로 전환

### 전투 → 작성

- 전투장 카메라 유지
- 감속·암전과 작성 패널 적용
- 대상·위험·보조 소환수 상태 유지

### 작성 → 결과

- 작성 패널 해제 후 필드 또는 전투장에서 결과 표시
- 성공·부분 성공·입력 실패·설계 실패 원인을 구분

### 전투 결과 → 필드

- 전투 결과 태그 확정
- 필드 배경·오브젝트·NPC 상태에 변화 반영

### 결과 → 기록

- 마도서 기록 UI로 전환
- 발견한 대상·장소·주문을 다시 연결

- 대상 선택·위험 경고

## 14. 검증 기준

### 화면 구조

- 수업·시험·축제·현장·전투가 같은 게임으로 인식됨
- 탐색·대화·전투·작성 전환 시 장소와 목표를 잃지 않음
- 16:9와 18:9~20:9에서 핵심 정보 안전 영역 유지

### 전투 연속성

- 필드에서 관찰한 대상이 전투장에서 동일하게 인식됨
- 전투 결과가 필드 환경에 반영됨
- 별도 전투 화면이 일반적인 무관계 전투 인스턴스로 느껴지지 않음

### 제작성

- 학교 장면 하나를 수업·시험·자유일정·축제 상태로 재사용
- 필드 SD를 전투에서 재사용
- 화면비마다 별도 자산을 만들지 않음

### 미검증

- 정확한 감속 비율
- 내부 해상도
- 터치 작성 영역 크기
- 전투장 이동 범위
- 실제 Android 가독성·성능
- 실제 아트·FX·사운드 조합
