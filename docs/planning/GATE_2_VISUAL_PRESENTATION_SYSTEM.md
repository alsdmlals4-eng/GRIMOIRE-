# 스펠 Gate 2 시각 표현 구조

## 1. 문서 상태

- 결정 ID: `GM-VISUAL-PRESENTATION-01`
- 사용자 승인: 2026-07-27, `확정`
- 상태: `LANDSCAPE_HYBRID_2D_CONFIRMED`
- 제품 단계: `PROTOTYPE_AND_VERTICAL_SLICE`
- Gate 1: `APPROVED`
- 프로젝트 코어: `CORE_CONFIRMED`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- 구현: `NOT_STARTED`
- Codex: `NOT_RUN`
- 이미지·사운드 제작: `NOT_STARTED`
- 다음 차단 결정: `GM-CHARACTER-PRESENTATION-01`

이 문서는 스펠 Vertical Slice의 화면 방향, 카메라, 학교·현장 표현, 대화 화면, 마법 작성 오버레이와 화면비 대응을 책임진다.

> **스펠은 가로형 하이브리드 2D로 표현한다. 학교와 현장은 고정·장면 기반 3/4 시점으로 보여주고, 대화는 같은 배경 위에 캐릭터 초상을 겹치며, 마법 작성 시 월드를 감속·암전한 전용 오버레이를 사용한다.**

---

## 2. 최상위 화면 구조

```text
가로형 화면
+ 고정·장면 기반 3/4 월드
+ 동일 장면 위 대화 초상 레이어
+ 동일 장면 위 마법 작성 오버레이
+ 결과에 따른 배경·오브젝트·캐릭터 상태 변화
```

### 비타협 원칙

- 학교·시험·축제·현장실습을 서로 다른 화면 체계로 만들지 않는다.
- 탐색·대화·주문 작성은 같은 장소와 상황의 연속으로 느껴져야 한다.
- 마법 작성 중에도 주문 대상·환경 위험·보조 소환수의 지원 상태를 파악할 수 있어야 한다.
- 큰 자유 이동 학교나 자유 카메라는 Vertical Slice 범위에서 만들지 않는다.
- 시각적 화려함보다 글자 궤적·대상·위험·결과 인과의 가독성을 우선한다.

## 3. 화면 방향·화면비

### 3.1 방향

- 기본 방향: `LANDSCAPE`
- 세로 모드: Vertical Slice 범위에서 지원하지 않음
- 자동 회전: 기본적으로 비활성 후보

### 3.2 구도 기준

- 기준 구도: `16:9 LANDSCAPE`
- 확장 대응: `18:9 ~ 20:9 LANDSCAPE`
- 정확한 내부 렌더 해상도: `ASSET-SPEC-01`에서 확정

### 3.3 화면비 대응 원칙

```text
16:9
= 기준 연출·UI 안전 구도

18:9~20:9
= 좌우 월드 여백 확장
= 핵심 UI·작성 영역은 안전 구도 유지
```

- 넓은 화면에서 배경과 월드 가시 영역을 좌우로 확장한다.
- 중요한 인물·목표·작성 패널을 화면 가장자리 확장 영역에만 배치하지 않는다.
- 노치·카메라 홀·제스처 영역을 고려한 안전 영역을 둔다.
- 화면비 차이 때문에 작성 패널의 필수 입력 면적이 줄어들어서는 안 된다.
- 단순 화면 확대·축소로 UI 가독성을 해결하지 않는다.

## 4. 월드와 카메라

### 4.1 기본 카메라

- 표현: `FIXED_SCENE_BASED_3_QUARTER_VIEW`
- 카메라 이동: 장면 전환 또는 제한된 연출 이동만 허용
- 자유 회전·자유 줌·넓은 맵 추적 카메라: 초기 Slice 제외

### 4.2 장면 구성

```text
배경 레이어
→ 건축·지형·원경

상태 레이어
→ 수업 / 시험 / 축제 / 손상 / 복구 상태

상호작용 레이어
→ 캐릭터·소환수·적·대상 오브젝트

효과 레이어
→ 마법·위험·환경 반응

UI 레이어
→ 목표·자원·위험 경고

대화·작성 레이어
→ 상황에 따라 상단에 표시
```

### 4.3 이동과 탐색

- 거대한 자유 이동 학교가 아니라 `장면 단위 이동`을 사용한다.
- 장소 이동은 출입구·핫스폿·짧은 경로 선택으로 표현한다.
- 같은 학교 장면 세트를 수업·시험·자유일정·축제 상태로 재사용한다.
- 현장실습은 전투 문제와 환경 문제를 같은 장소 안의 상태 변화로 연결한다.
- 위치 탐색 자체보다 상황 관찰과 주문 설계가 주요 판단이 되게 한다.

### 4.4 금지

- 탐색을 위한 넓은 빈 복도·맵
- 카메라를 돌려야만 보이는 필수 정보
- 줌 배율에 따라 판정이 달라지는 주문 대상
- 3D 원근에 가까운 복잡한 깊이 정렬
- 배경 그림마다 다른 카메라 각도와 캐릭터 기준선

## 5. 학교·현장 화면 재사용

### 5.1 학교 장면 세트

최소 구성:

- 기본 수업 상태
- 실기시험 상태
- 학교축제 상태
- 자유일정 대화·휴식 상태

재사용 방식:

```text
동일 배경 구조
+ 조명 상태
+ 장식 오버레이
+ NPC 배치
+ 상호작용 오브젝트
+ BGM·환경음 상태
```

축제를 위해 별도 대형 맵을 만들지 않는다.

### 5.2 현장실습 장면

한 장면 안에서 다음을 처리한다.

```text
브리핑·관찰
→ 적 출현 또는 위험 활성화
→ 전투 문제
→ 환경·구조 문제
→ 복구·변화 결과
```

전투와 환경 문제의 배경·대상 상태가 연결되어, 주문 결과가 세계를 변화시켰다는 감각을 유지한다.

## 6. 대화 화면

### 6.1 기본 구성

```text
기존 장소 배경 유지
+ 캐릭터 반신 또는 초상
+ 이름·대화창
+ 메인 동반 소환수 반응 슬롯
+ 필요한 경우 관계·상태 아이콘
```

정확한 캐릭터 비율·전신·반신·초상 사용 규칙은 `GM-CHARACTER-PRESENTATION-01`에서 확정한다.

### 6.2 원칙

- 장소와 사건의 연속성을 위해 대화 시 배경을 완전히 교체하지 않는다.
- 한 화면에서 동시에 강조하는 화자는 기본 1명, 필요한 경우 2명까지로 제한한다.
- 메인 동반 소환수는 항상 큰 초상을 요구하지 않고, 반응 슬롯·작은 초상·연출 등으로 표현할 수 있다.
- 필수 정보는 초상 표정이나 음성만으로 전달하지 않고 텍스트·아이콘을 함께 사용한다.
- 자유일정의 짧은 교류는 신규 배경보다 기존 장소와 초상 조합을 우선한다.

## 7. 마법 작성 오버레이

### 7.1 기본 전환

```text
주문 작성 진입
→ 월드 감속
→ 배경 밝기·채도 감소
→ 작성 패널 활성화
→ 대상·위험·지원 상태 유지 표시
→ 글자 작성·조합
→ 주문 발동
→ 오버레이 해제와 세계 변화 강조
```

### 7.2 시간 처리

- 시각 표현 기본 후보: `WORLD_SLOWDOWN_WITH_DIMMING`
- 완전 정지·감속·실시간 최종 판정: `PLAYTEST_TUNING_REQUIRED`
- 감속 비율: `NOT_YET_TUNED`

사용자가 승인한 화면 구조는 감속형을 기본으로 삼되, M0에서 완전 정지·감속·실시간을 비교하여 실제 플레이 규칙을 확정한다.

### 7.3 고정 정보 예산

작성 중 고정 표시는 다음으로 제한한다.

- 현재 목표
- 선택한 메인 글자
- 선택한 보조 글자
- 마나 또는 사용 가능 횟수
- 위험 경고
- 전투 보조 소환수의 핵심 지원 상태

다음은 작성 화면 밖으로 분리한다.

- 관계 상세
- 마도서 전체
- 시험 세부 점수
- 소환수 성장·편성 상세
- 장문 설명

### 7.4 가독성 규칙

- 작성 궤적은 배경·효과와 명도·두께·형태로 분리한다.
- 위험 경고는 색상 하나에만 의존하지 않는다.
- 월드를 어둡게 하더라도 주문 대상과 피격 위험은 실루엣·아이콘·테두리로 유지한다.
- 발동 결과 효과는 작성 궤적과 같은 순간에 화면을 완전히 덮지 않는다.
- 화면 흔들림·섬광·입자 밀도는 조절 가능해야 한다.
- 손가락이 시작점·끝점·판정 피드백을 지속적으로 가리지 않게 한다.

## 8. 전투·소환수 표현

### 8.1 전투

- 학교와 동일한 3/4 장면 체계를 사용한다.
- 플레이어·적·환경 목표·보조 소환수를 한 화면에서 읽을 수 있어야 한다.
- 카메라가 적을 추적해 주문 대상을 화면 밖으로 밀어내지 않는다.
- 전투 중 핵심 행동은 상황 관찰·주문 작성·이동 또는 회피로 제한한다.

### 8.2 메인 동반 소환수

- 학교·대화·현장에 지속적으로 존재한다.
- 위치·작은 반응·초상 등 화면에 맞는 표현을 사용한다.
- 정답이나 최적 주문을 시각적으로 먼저 제시하지 않는다.

### 8.3 전투 보조 소환수

- 현장 전투에서 수호 또는 견제 역할 하나를 명확한 실루엣으로 보여준다.
- 지원 범위와 남은 상태를 월드 효과와 최소 UI로 표시한다.
- 플레이어 주문·적·위험 경고보다 더 큰 시각 점유율을 갖지 않는다.

## 9. 모드 전환

### 탐색·관찰 → 대화

- 카메라와 배경 구도를 유지한다.
- 캐릭터 초상과 대화창을 레이어로 추가한다.

### 탐색·전투 → 작성

- 카메라를 바꾸지 않고 월드 감속·암전과 작성 패널을 적용한다.
- 대상·위험·소환수 상태를 유지한다.

### 작성 → 결과

- 작성 패널이 사라진 뒤 주문 결과를 월드에서 보여준다.
- 성공·부분 성공·실패 원인이 대상과 환경 변화로 읽혀야 한다.

### 결과 → 기록

- 결과 요약 후 마도서 기록 UI로 전환한다.
- 기록 UI는 월드 플레이와 구분되지만, 발견한 대상·장소·주문을 다시 연결한다.

## 10. 자산 제작 영향

### 10.1 배경

필요 방향:

- 가로형 3/4 고정 장면
- 좌우 확장이 가능한 레이어 구조
- 학교 기본·시험·축제 상태 변형
- 현장 전투·환경·복구 상태 변형
- 캐릭터 기준선과 상호작용 지점 일관성

### 10.2 캐릭터

현재 필요한 표현 슬롯:

- 필드·장면용 캐릭터 표현
- 대화용 초상 또는 반신
- 메인 동반 소환수의 필드·대화 반응
- 전투 보조 소환수의 전투 실루엣

정확한 비율·애니메이션·표정 수량은 다음 결정에서 확정한다.

### 10.3 효과

- 글자 궤적
- 작성 성공·입력 오류·설계 오류 피드백
- 대상 선택·위험 경고
- 주문 결과 변화
- 보조 소환수 수호 또는 견제
- 축제의 표현 성향 결과

효과는 글자 궤적과 위험 정보를 가리지 않아야 한다.

### 10.4 사운드

이 문서는 사운드 수량·음색을 확정하지 않는다. 다만 다음 화면 상태를 구분해야 한다.

- 학교 평시
- 시험 긴장
- 축제 활기
- 현장 위험
- 작성 집중
- 발동·성공·부분 성공·실패
- 보조 소환수 지원

세부 방향은 `AUDIO-DIRECTION-01`에서 확정한다.

## 11. 접근성·안전 규칙

- 위험·대상·결과를 색상만으로 구분하지 않는다.
- 음향 단서에는 시각적 대응 표시를 제공한다.
- 작성 궤적의 두께·대비·잔상 시간을 조절 가능하게 설계한다.
- 섬광·화면 흔들림·입자 밀도를 낮출 수 있게 한다.
- 텍스트와 터치 대상은 Android 안전 영역을 지킨다.
- 초상·배경이 대화 텍스트 대비를 방해하지 않는다.

---

## 12. 범위 제외

- 세로 화면용 별도 UI와 자산
- 자유 이동형 대형 학교
- 자유 카메라 회전·줌
- 탐색용 다수 배경과 긴 이동 구간
- 모든 대화의 전신 일러스트
- 모든 캐릭터의 고프레임 필드 애니메이션
- 3D 또는 2.5D 원근 시스템
- 세션별 별도 화면 엔진
- 작성 중 월드를 완전히 숨기는 구조

## 13. 검증 기준

### 화면 구조

- 수업·시험·축제·현장이 같은 게임의 장면 체계로 인식된다.
- 탐색·대화·작성 전환 시 장소와 목표를 잃지 않는다.
- 16:9와 18:9~20:9에서 필수 정보와 작성 영역이 안전 영역 안에 유지된다.

### 마법 작성

- 작성 중 대상·위험·소환수 지원 상태를 파악할 수 있다.
- 글자 궤적과 배경·FX가 구분된다.
- 입력 오류·설계 오류·발동 결과가 서로 다른 피드백을 가진다.

### 제작성

- 학교 장면 하나를 수업·시험·자유일정·축제 상태로 변형할 수 있다.
- 현장 장면 하나에서 전투·환경·복구 상태를 처리할 수 있다.
- 배경·캐릭터·효과 자산이 화면비마다 별도 제작되지 않는다.

### 미검증

- 실제 Android 기기 가독성·성능
- 실제 아트·FX·사운드 조합

상태는 `PLAYTEST_TUNING_REQUIRED`, `ASSET_SPEC_REQUIRED` 또는 `NOT_RUN`이다.
