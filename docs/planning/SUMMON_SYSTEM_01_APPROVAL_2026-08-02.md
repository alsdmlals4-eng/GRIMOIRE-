사용자는 소환수 상세 수치를 권장안대로 진행하도록 승인했다. 아래 값은 Prototype·Vertical Slice 기본값이며 사람 검증 후 허용 범위 안에서 튜닝할 수 있다.

## 2. 역할

> 소환수는 직접 작성의 반복 피로와 시간 압박을 줄이고, 어떤 지원을 언제 활성화할지 선택하게 하는 예측 가능한 주기 지원 시스템이다.

소환수는 플레이어 대신 새로운 상황의 의미를 해석하거나 자동 최적 해법을 선택하지 않는다.

## 3. 활성 구조

```text
메인 소환수 1체 = 항상 활성
보조 소환수 = 기본 비활성
보조 소환수 1체 = [소환] 주문 Commit 후 제한 시간 활성
```

Slice 동시 상한:

| 구분 | 상한 |
|---|---:|
| 메인 소환수 | `1체 상시` |
| 기타 활성 소환수 | `최대 1체` |
| 총 표시·행동 소환수 | `최대 2체` |

- 보조 소환수를 새로 호출하면 기존 보조 소환수는 해제된다.
- 메인 소환수는 교체 대상이 아니다.
- 보조 소환수가 다른 소환수를 자동 호출하는 연쇄를 금지한다.

## 4. Active Pressure Clock

소환수의 지속시간과 Tick은 적 공격 타이머와 같은 `Active Pressure Clock`을 사용한다.

진행:

- 플레이어가 관찰·작성·후보·조합을 검토하며 조작할 수 있는 상태.
- 일반 `1.0×` 또는 접근성 감속 배율.

정지:

- 플레이어 주문·소환수 주문·적 공격의 시스템 해결.
- Pause.
- 강제 튜토리얼.
- Focus loss.
- App background.
- Save/Load 처리.
- 플레이어 입력을 막는 Recognition·Loading.

규칙:

- `0.5×` 작성 보조 감속을 쓰면 적 공격과 소환수 Tick이 모두 같은 비율로 느려진다.
- Offline·Background catch-up은 없다.
- 복귀 시 누적된 여러 Tick을 한꺼번에 적용하지 않는다.

## 5. 메인 소환수 기본값

Slice 메인 소환수의 대표 역할은 `Stock Support`다.

| 항목 | 기본값 |
|---|---:|
| 활성 | 상시 |
| 첫 Tick 준비 시간 | Active Pressure `20초` |
| 충전량 | 확인 글자 Token `1개` |
| Focus Task 상한 | `1회` |
| 대상 글자 | 가장 최근에 플레이어가 직접 작성·확인한 글자 |
| Rack이 가득 찼을 때 | `READY` 1회 보류, 추가 누적 없음 |

- 최근 직접 확인 글자가 없으면 Tick은 READY 상태로 대기한다.
- 플레이어가 글자를 직접 확인한 뒤 다음 안전 시점에 해당 Token을 충전한다.
- 메인 소환수는 모든 상황에 유효한 공격 주문을 자동 사용하지 않는다.
- 메인 소환수의 상시 가치는 `관계·위험 감지·Stock 보조`에 둔다.

## 6. 보조 소환수 호출

### `[소환]` 주문

```text
상황 확인
→ 보조 소환수 선택
→ 소환 문장·Seal 작성 또는 승인된 소환 Token 사용
→ 비용·지속·주기 행동 확인
→ [소환] Commit
→ 마나 소비
→ 보조 소환수 활성
```

Slice 기본값:

| 항목 | 기본값 |
|---|---:|
| 소환 비용 | 최대 마나의 `20%` |
| 활성 지속시간 | Active Pressure `30초` |
| 재소환 대기시간 | 해제·종료 후 Active Pressure `20초` |
| 동시 보조 소환 | `1체` |
| 수동 해제 | 가능, 비용 환불 없음 |
| 첫 소환 입력 | Focus Task 첫 호출은 직접 작성·확인 |
| 같은 Task 재소환 | 확인된 소환 Seal Token 사용 가능 |

- 마나 부족·문법 실패·취소는 비용과 Token을 소비하지 않는다.
- 소환 성공 후 자동 행동은 승인된 예외이며 각 행동마다 플레이어 Commit을 다시 요구하지 않는다.
- 보조 소환 교체도 새 `[소환]` Commit과 비용을 요구한다.

## 7. 보조 소환수 주기 유형

### A. 주문 지원형

| 항목 | 기본값 |
|---|---:|
| Tick 간격 | Active Pressure `10초` |
| 활성당 최대 행동 | `3회` |
| 출력 | 비교 가능한 플레이어 보조 주문 효과의 `60%` |
| 주요 Situation 기여 상한 | 시작 불안정도·핵심 환경 목표의 `25%` |

### B. Stock 지원형

| 항목 | 기본값 |
|---|---:|
| Tick 간격 | Active Pressure `12초` |
| 활성당 최대 충전 | `2개` |
| Focus Task 소환수 합산 충전 상한 | 메인 포함 `3개` |

Slice 대표 보조 소환수는 `수호형 주문 지원형 1체`다.

## 8. 자동 주문 경계

자동 주문은 다음 계약을 따른다.

- 소환수별 고유·장착 주문 중 사전에 표시한 하나만 사용한다.
- 동적 최적 주문 선택 AI를 사용하지 않는다.
- 대상 규칙은 소환 전 표시한다.
- Slice 수호형 대상 규칙은 `다음에 선언된 적 공격의 대상`이다.
- 자동 주문은 불안정도를 `1` 아래로 낮추지 못한다.
- 치명 환경 목표를 자동으로 완료하거나 마지막 책임 선택을 대신하지 못한다.
- 자동 주문이 전투·Situation 승리의 마지막 Event가 될 수 없다.
- 자동 결과의 출처·효과·부작용·기여 소환수를 Result와 Grimoire에 기록한다.

## 9. Slice 수호형 기본값

기존 `수동으로 다음 공격 1회 완화` 구조를 다음 주기형으로 교정한다.

| 항목 | 기본값 |
|---|---:|
| 유형 | 주문 지원형 |
| 활성 | `[소환]` Commit 후 30초 |
| Tick | 10초 |
| 행동 | 다음 선언 공격 대상에게 보호 주문 |
| 피해 완화 | 해당 공격 최종 피해의 `35%` |
| 환경 피해 완화 | 해당 Event 환경 피해의 `25%` |
| 보호 중첩 | 중첩 불가, 높은 값 하나만 적용 |
| 활성당 최대 | `3회` |

- 보호 주문은 적 공격 타이머를 정지하지 않는다.
- 보호는 Draft를 직접 저장하는 능력이 아니라 피해로 인한 작성 중단 위험을 줄인다.
- 공격이 오지 않으면 보호가 READY 상태로 1회 대기하며 중첩 충전하지 않는다.

## 10. 메인·보조 중첩

- 메인 Stock 지원과 보조 보호 지원은 동시에 작동할 수 있다.
- 같은 효과 유형 두 개는 중첩하지 않는다.
- 동일 Event에 여러 보호가 적용되면 가장 높은 값 하나만 사용하고 나머지는 소비하지 않는다.
- 메인 소환수와 보조 소환수가 같은 Tick 시각에 도달하면 내부 Event 순서는 `보호·위험 대응 → Stock 충전 → 기타 지원`으로 고정한다.
- 각 Event는 고유 `summon_event_id`를 사용한다.

## 11. Save·Resume

저장 필드:

- 메인 소환수 ID와 READY 상태.
- 활성 보조 소환수 ID.
- 남은 지속시간.
- 다음 Tick까지 남은 Active Pressure 시간.
- 이미 실행한 행동 횟수.
- 재소환 대기시간.
- 보류 Stock Token.
- 적용 완료 `summon_event_id`.

복귀 규칙:

- 마지막 Snapshot 시점에서 정확히 이어간다.
- Background 경과 시간을 차감하지 않는다.
- 만료·Tick·Stock 충전을 복귀 순간에 몰아서 적용하지 않는다.
- 이미 처리한 Event를 재적용하지 않는다.

## 12. 비전투 사용

- 시간 압박이 있는 비전투 Focus Task에서는 동일 Active Pressure Clock을 사용한다.
- 시간 압박이 없는 학교·대화·마도서 화면에서는 주기 Tick을 진행하지 않는다.
- 비전투 무압박 장면의 소환수는 관계 반응·위험 감지·명시적 1회 지원으로만 작동한다.
- 메뉴 방치로 Stock을 충전하지 못한다.

## 13. 이전 계약 대체

이 Decision은 `GM-BATTLE-RULES-01`의 수호형 소환수 항목 중 다음 규칙을 대체한다.

대체됨:

- `플레이어가 수동으로 발동한다`.
- `다음 공격 1회만 완화한다`.
- `자동 발동을 제공하지 않는다`.
- `글자 선택·작성·조합·대상 지정·시전을 대신하지 않는다`의 전면 금지 표현.

유지·재해석:

- 적 공격 타이머를 정지하지 않는다.
- 상시 무적·무제한 반복을 제공하지 않는다.
- 핵심 의미 설계와 최종 Situation 해결은 플레이어가 담당한다.
- 소환수의 지정 자동 주문은 허용하지만 자유 AI 해법 선택은 금지한다.

충돌 시 `GM-SUMMON-SYSTEM-01`을 우선한다.

## 15. 튜닝 허용 범위

사람 검증 후 별도 구조 재승인 없이 조정 가능한 범위:

- 메인 Stock Tick `18~25초`.
- 보조 지속시간 `25~35초`.
- 주문형 Tick `8~12초`.
- Stock형 Tick `10~15초`.
- 소환 비용 최대 마나 `15~25%`.
- 보호 완화 `25~40%`.
- 자동 주문 출력 `50~70%`.

별도 재승인이 필요한 변경:

- 보조 소환수 동시 2체 이상.
- Offline·Background Tick.
- 자동 주문의 Situation 종결 허용.
- 동적 최적 대상·주문 AI.
- 메인 소환수의 범용 공격 자동화.
