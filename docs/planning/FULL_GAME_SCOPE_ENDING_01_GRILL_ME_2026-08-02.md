## 3. 세 단계 범위

### 3.1 Internal Vertical Slice

- 기존 46분 목표·53분 콘텐츠 상한의 내부 검증용 대표 세션.
- 수업 연습·비전투 응용·제작 미니게임·현장실습·마도서 기록·학기말 평가 Mock을 압축 검증한다.
- 정식 데모 전체 분량과 동일하지 않다.
- 구현 순서는 이 Slice를 먼저 검증한 뒤 Year-One Demo Build로 확장한다.

### 3.2 Year-One Demo Build — A 범위

```text
프롤로그·입학
→ 1학기: 공통 기초와 첫 현장 책임
→ 2학기: 복수 계열 수강·연구·제작 확장
→ 3학기: 심화 후보·복합 사건·최종 현장
→ 학년말 종합 평가
→ 첫 독자적 세계 재작성과 다음 학년 진로 선택
```

후보 범위:

- 1학년 3학기.
- 핵심 Chapter 6~8개.
- 메인 계열 3개 내외 + 공통 보조 문법.
- 미니게임 가족 4~6개 재사용·변주.
- 주요 학교 Hub 1개, 현장 권역 2~3개와 상태 변주.
- 필수 메인 콘텐츠와 선택 연구·교류·제작 콘텐츠 병행.
- 데모 종결은 `첫 독자적 마법 원리 증명과 책임 있는 세계 변화`.

이 범위는 일반적인 짧은 체험판보다 크며, 사실상 `1학년 완결형 데모/프롤로그 에디션`에 가깝다. 배포 형태·가격·저장 승계는 후속 출시 Gate에서 결정한다.

### 3.3 Three-School-Year Full Game — B 범위

```text
입학
→ 기초·복수 계열 수강
→ 전문화·상급 연구
→ 복합 현장과 세계 책임 확대
→ 최종 연구·졸업
→ 대규모 세계 재작성과 진로 결말
```

후보 범위:

- 3개 학년·6~9학기.
- 핵심 Chapter 12~18개 이상.
- 메인 계열 5개 이상과 복수 전문화 후보.
- 교수·동급생·현장 권역·연구 프로젝트의 장기 변화.
- 학년별 완결과 다음 학년 질문을 연결.
- 최종 엔딩은 졸업과 플레이어의 독자적 마법 원리가 세계 규칙에 남기는 대규모 변화.

## 4. Demo와 Full Game의 관계

- 데모 A는 본편 B와 다른 평행 설정이 아니라 본편의 1학년 정본이다.
- 데모에서 만든 저장·마도서·관계·수강·결과 태그를 본편으로 승계할 수 있도록 데이터 경계를 설계한다.
- 저장 승계의 실제 구현·계정 방식·플랫폼 정책은 후속 Gate의 `TEST_VALUE`다.
- 데모 엔딩은 완결감을 제공하지만 2·3학년의 핵심 질문과 전문화 성장을 남긴다.
- 본편은 데모 내용을 단순 반복하지 않고 2학년부터 새 상황 질문·계열 조합·책임 규모를 확장한다.

## 5. 범위 보호 규칙

1. 3년 전체를 한 번에 제작하지 않는다. `Vertical Slice → Year-One Demo → Full Game` 단계 Gate를 사용한다.
2. Year-One Demo가 검증되기 전 2·3학년 전용 대형 Asset·계열 캠페인·지역을 본제작하지 않는다.
3. 학년마다 완전히 새로운 시스템을 추가하지 않고 기존 문자·재료·미니게임·장소·인물 상태를 재조합·심화한다.
4. 계열별 별도 캠페인을 의무화하지 않고 공통 사건을 계열별 해법·대가로 변주한다.
5. 2·3학년 분량은 Demo 지표·사람 테스트·Mobile 성능·QA 비용 검증 후 잠근다.
6. 데모는 1학년 전체를 목표로 하지만, 현재 46–53분 Vertical Slice를 건너뛰지 않는다.
7. 정확한 학기·Chapter·계열·미니게임·재료·레시피·장소·플레이 시간은 `TEST_VALUE`다.

## 6. 적대적 판정

장점:

- 완전한 마법학교 입학→전문화→졸업 성장 서사를 보존한다.
- 1학년 데모가 독립된 완결과 본편 확장 기반을 함께 제공한다.
- 데모에서 실제 다계열·제작·학기말 평가 구조를 충분히 검증할 수 있다.

주요 위험:

- Year-One Demo 자체가 일반 체험판보다 매우 커서 개발비와 출시 전략이 불명확해질 수 있다.
- 3년 전체에서 계열·관계·결과 태그·미니게임 조합 QA가 폭증한다.
- 1학년과 2·3학년 사이에 콘텐츠 품질·대표성 격차가 생길 수 있다.

보정:

- 제품 단계를 명시적으로 세분화한다.
- Demo 완성·검증 전 Full Game의 후반 제작 약속을 잠근다.
- 신규 시스템 수보다 기존 시스템의 상황·책임·조합 심화를 우선한다.
