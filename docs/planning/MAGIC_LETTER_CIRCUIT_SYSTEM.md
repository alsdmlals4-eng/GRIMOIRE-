- 상태: `PLANNING_IN_PROGRESS`
- 결정 상태: `DIRECTION_CONFIRMED`
- 프로젝트 코어 상태: `CORE_CANDIDATE`
- 기준 날짜: 2026-07-27
- 관련 결정: `GM-CIRCUIT-01`
- 기존 결정 대체: `GM-00-08`, `GM-00-09` 일부
- 상위 설계: `docs/planning/SPELL_GAME_DESIGN.md`

## 1. 핵심 개념

Spell의 회로 작성은 **마법 글자를 조합해 주문 문장을 만드는 행위**로 정의한다.

```text
마법 글자
→ 마법적 의미를 가진 최소 기능 단위

회로
→ 여러 마법 글자의 위치·연결·적용 순서를 구성한 문법

주문
→ 메인 글자 1개와 선택적인 보조 글자를 연결해 완성한 마법 문장
```

게임 UI와 세계관에서는 `메인 회로`, `보조 회로`라는 명칭을 유지할 수 있지만, 교육과 서사에서는 이를 `메인 글자`, `보조 글자`로 설명한다.

## 2. 주문 성립 규칙

한 주문에는 **메인 글자가 정확히 하나** 필요하다.

```text
메인 글자 1개
= 가장 단순한 기본 주문 성립
```

- 메인 글자 하나만 정확히 작성해도 주문은 정상 발동한다.
- 형상·전달 글자는 더 이상 주문 성립의 필수 조건이 아니다.
- 각 메인 글자는 고유한 `기본 발현`을 가진다.
- 기본 발현은 해당 계열의 가장 단순하고 안전한 사용 형태다.
- 복수 메인 글자를 한 주문에 넣는 구조는 사용하지 않는다.

기존의 `초반 최소 문법 = 메인 + 형상·전달` 결정은 `SUPERSEDED_BY_GM-CIRCUIT-01`로 처리한다.

## 3. 메인 글자

메인 글자는 주문의 중심 의미와 발생 현상을 결정한다.

```text
메인 글자
→ 무엇을 발생시키거나 변화시키는가
→ 기본 발현은 무엇인가
→ 어떤 계열의 보조 글자와 잘 결합하는가
```

메인 글자 계열의 최종 목록은 아직 확정하지 않는다. 후보 방향은 현상·물질·개념을 중심으로 구성할 수 있다.

예시 후보:

- 열·불꽃
- 물·유동
- 바람·압력
- 빛
- 생명·회복
- 힘·충격
- 보호·차단
- 이동·공간
- 감지
- 소환
- 변환

위 목록은 교육 계열 구조를 설명하기 위한 후보이며 확정 데이터가 아니다.

## 4. 보조 글자

보조 글자는 메인 글자의 기본 발현을 강화·변형·정밀화한다.

```text
메인 글자 1개
+
보조 글자 0개 이상
=
완성 주문
```

기존의 형상·전달·일반 보조·조건·기동 회로는 모두 **보조 글자의 하위 문법**으로 재정리한다.

### 보조 글자 하위 역할

| 역할 | 의미 | 후보 예시 |
|---|---|---|
| 형상 | 어떤 모양·범위로 나타나는가 | 투사체, 장벽, 원형, 선형, 오라 |
| 전달 | 어디에 어떻게 도달하는가 | 접촉, 발사, 광선, 지정, 추적 |
| 출력 | 얼마나 강하게 발생하는가 | 증폭, 집중, 분산 |
| 규모 | 범위·수량·대상 수를 어떻게 바꾸는가 | 확대, 다중화, 분열 |
| 시간 | 얼마나 빠르고 오래 지속되는가 | 가속, 지속, 지연 |
| 행동 | 발생 후 어떤 방식으로 움직이는가 | 관통, 연쇄, 귀환, 추적 |
| 효율 | 마나와 부산물을 어떻게 다루는가 | 절감, 회수, 재활용 |
| 안정 | 주문을 얼마나 정밀하고 안전하게 유지하는가 | 안정화, 보정, 고정 |
| 조건 | 어떤 상황에서 내부 효과가 작동하는가 | 적중 시, 방어 성공 시, 일정 시간 후 |
| 순서 | 여러 보조 효과의 적용 순서를 정한다 | 선행, 후행, 반복, 분기 |

## 5. 보조 글자가 많을수록 강해지는 원칙

보조 글자가 추가될수록 주문의 **총 기능·출력·정밀도·적용 범위**는 확대될 수 있다.

```text
메인만 사용
→ 빠르고 단순한 기본 주문

메인 + 소수 보조
→ 목적이 분명한 실전 주문

메인 + 다수 보조
→ 강력하고 복합적인 고위 주문
```

다만 `강력하다`는 항상 순수 피해량만 증가한다는 뜻이 아니다.

- 범위가 넓어질 수 있다.
- 더 오래 유지될 수 있다.
- 적을 추적하거나 여러 대상을 처리할 수 있다.
- 마나 효율이나 안정성이 좋아질 수 있다.
- 특정 상황에 자동으로 반응하는 내부 문법을 가질 수 있다.
- 구조·봉인·복구·탐색 등 비전투 성능이 확대될 수 있다.

### 복잡도 비용

보조 글자가 늘어나면 다음 비용도 함께 증가한다.

- 직접 작성 시간
- 마나 비용 또는 마력 부담
- 연결 판단의 복잡도
- 완성 주문 스톡의 준비 용량
- 스톡 충전시간

따라서 `가능한 보조 글자를 전부 붙이는 것`이 항상 최적은 아니다. 상황에 맞는 문장을 짧고 정확하게 구성하는 주문과, 많은 글자를 투자한 고위 주문이 서로 다른 역할을 갖는다.

## 6. 회로와 연결 문법

마법 글자가 단어라면 회로는 문장 구조다.

```text
직접 연결
→ 메인 글자에 보조 효과 적용

분기
→ 하나의 효과를 여러 대상·경로로 나눔

합류
→ 여러 보조 효과를 하나의 결과에 집중

순서
→ 어떤 보조 효과를 먼저 적용할지 결정
```

연결선의 길이와 획수 자체는 독립 기능으로 계산하지 않는다. 연결·분기·합류를 별도 기능 글자로 계산할지는 후속 문법 설계에서 정한다.

## 7. 예시 문장

### 기본 주문

```text
불꽃 메인
→ 기본 불꽃 발생
```

### 실전 주문

```text
불꽃 메인
+ 투사체 형상
+ 발사 전달
→ 화염탄
```

### 고위 주문

```text
불꽃 메인
+ 투사체 형상
+ 확대
+ 분열
+ 추적
+ 지속
→ 넓은 지역의 여러 대상을 추적하며 지속 연소시키는 복합 주문
```

### 비전투 활용

```text
불꽃 메인
+ 집중
+ 안정화
+ 지속
→ 얼어붙은 장치 해빙·온실 온도 유지·재료 가공
```

예시는 문법 이해용이며 최종 주문 목록이 아니다.

## 8. 학습·숙련·스톡화

```text
수업에서 마법 글자 학습
→ 직접 따라 쓰기
→ 메인 글자만으로 기본 주문 성공
→ 관련 보조 글자 조합 실습
→ 현장에서 새로운 활용 발견
→ 마도서 설계도 등록
→ 반복 사용으로 숙련
→ 하위 글자 또는 완성 주문 스톡화
```

- 처음 배우는 글자는 직접 작성한다.
- 숙련된 낮은 단계 글자는 하위 회로 스톡 후보가 된다.
- 완성된 주문 문장은 마도서에 등록한 뒤 완성 주문 스톡 후보가 된다.
- 소환수는 글자를 직접 작성하지 않고 지정 스톡의 생산을 지원한다.

## 9. 스톡 시스템 재해석

기존 스톡의 `기능 회로 수`는 앞으로 **기능 마법 글자 수**로 해석한다.

```text
메인 글자만 사용한 완성 주문
→ 기능 글자 1개
→ 준비 용량 1
→ 기준 충전시간 1.0단위

메인 글자 1 + 보조 글자 3
→ 기능 글자 4개
→ 준비 용량 4
→ 기준 충전시간 2.5단위
```

기존 충전시간 공식은 유지한다.

```text
기준 충전시간(n)
= 1.0 + 0.5 × (n - 1)
```

여기서 `n`은 완성 주문에 포함된 기능 마법 글자 수다.

## 10. 가드레일

- 주문 성립에 보조 글자를 강제로 요구하지 않는다.
- 메인 글자 하나에 여러 독립 현상을 과도하게 압축하지 않는다.
- 복수 메인 글자 결합으로 복잡도를 해결하지 않는다.
- 보조 글자 추가가 항상 순수 피해량 증가만 의미하지 않게 한다.
- 보조 글자를 많이 붙이는 방식만 정답이 되지 않게 비용과 목적 차이를 유지한다.
- 초반부터 모든 보조 문법을 한꺼번에 가르치지 않는다.
- 처음 배우는 글자를 스톡으로 건너뛰지 않는다.
- 설정상 재능이 플레이어의 조합 판단을 자동으로 대신하지 않는다.

## 11. 추후 결정

- 메인 글자 계열의 최종 분류
- 각 메인 글자의 기본 발현
- 공통 보조 글자와 계열 전용 보조 글자의 구분
- 같은 보조 글자 반복 사용 가능 여부
- 보조 글자 간 상충·중복·감쇠 규칙
- 마나 비용의 글자 수·종류별 계산
- 연결·분기·합류를 독립 기능 글자로 계산하는지 여부
