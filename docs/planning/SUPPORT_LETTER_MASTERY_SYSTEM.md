## 1. 목적

보조 글자는 메인 글자처럼 `Lv.0~Lv.5`를 가지지 않고, 데이터 부담을 줄인 **3단계 숙련 등급**으로 성장한다.

```text
미숙
→ 숙련
→ 달인
```

이 구조의 목적은 다음과 같다.

- 보조 글자 수가 많아져도 육성 메뉴와 수치가 폭증하지 않게 한다.
- 처음 배운 글자는 직접 작성하며 기능을 이해하게 한다.
- 반복해서 익힌 글자는 하위 글자 스톡으로 간결하게 사용할 수 있게 한다.
- 달인 단계에서는 복합 주문과 상위 연구에서 해당 보조 글자의 전문성을 체감하게 한다.

소환수는 보조 글자를 직접 작성·배치하지 않는다. 소환수는 지정된 하위 글자 또는 완성 주문 스톡의 충전·생산을 보조한다.

## 2. 숙련 단계

### 2.1 미숙

- 수업이나 연구를 통해 글자의 의미와 작성법을 습득한 상태다.
- 직접 작성으로 사용할 수 있다.
- 작성 오차와 마나 부담이 상대적으로 크다.
- 아직 하위 글자 스톡에 등록할 수 없다.
- 현장 활용과 반복 훈련을 통해 `숙련`을 목표로 한다.

### 2.2 숙련

- 안정적으로 재현할 수 있고 다른 글자와의 연결 규칙을 이해한 상태다.
- 직접 작성의 안정성과 효율이 향상된다.
- **하위 글자 스톡 후보**가 된다.
- 등록된 완성 주문에 안정적으로 포함할 수 있다.
- 1학년부터 핵심 기초 보조 글자 일부를 숙련 단계까지 성장시킬 수 있다.

### 2.3 달인

- 다양한 메인 글자와 복합 구조에서 해당 보조 글자를 높은 수준으로 운용한다.
- 직접 작성의 속도·정확도·복합 연결 안정성이 향상된다.
- 다수 보조 글자와 조건·순서 구조에서 사용하기 쉬워진다.
- 해당 하위 글자 스톡의 충전 효율 또는 능동 충전 보너스에 기여할 수 있다.
- 소환수가 해당 글자 스톡을 충전할 때 적성 보너스를 받는 조건 후보가 될 수 있다.
- 정확한 배율·시간·보너스는 `PLAYTEST_TUNING_REQUIRED`로 남긴다.

`달인`이 새로운 기능을 자동으로 추가하거나 글자 수 비용을 줄이지는 않는다.

## 3. 성장 과정

```text
수업에서 글자 습득
→ 직접 따라 쓰기
→ 메인 글자와 조합
→ 다른 상황에서 반복 활용
→ 현장실습에서 기능 검증
→ 과제·시험·연구 인증
→ 숙련 단계 상승
```

성장 근거 후보:

1. 직접 작성 성공과 정확도
2. 서로 다른 메인 글자와의 조합 경험
3. 전투·구조·생활·탐사 등 다른 목적의 활용
4. 현장실습 성공 기록
5. 담당 교수의 과제·시험·연구 인증

단순히 같은 버튼을 반복하거나 수업 일정만 선택해 최고 등급에 도달하지 않는다.

## 4. 학년과의 관계

### 1학년

- 기본 형상·전달·안정 보조 글자를 습득한다.
- 핵심 보조 글자 일부를 `숙련`까지 성장시킨다.
- `메인 1 + 보조 2` 주문을 직접 작성과 하위 글자 스톡으로 나누어 경험한다.
- 소환수가 지정 스톡의 충전을 돕는 구조를 함께 학습한다.

### 2학년

- 계열 전용 보조와 조건·순서 글자를 확대한다.
- 관심 보조 글자를 `달인` 후보로 성장시킨다.
- 서로 다른 수업에서 배운 보조 글자를 교차 조합한다.

### 3학년

- 전공 메인 글자 전문화와 맞는 보조 글자군을 달인 수준으로 연구한다.
- 다수 보조 글자의 연결·분기·조건 구조를 독립 설계한다.
- 졸업 주문과 현장실습에서 숙련 증거를 제시한다.

학년 상승은 숙련 등급을 자동 지급하지 않는다. 학년은 상위 수업·실습·연구에 대한 접근 권한을 제공한다.

## 5. 소환수와의 관계

```text
플레이어
→ 보조 글자를 학습·작성·조합

숙련 보조 글자
→ 하위 글자 스톡으로 준비 가능

소환수
→ 플레이어가 지정한 하위 글자·완성 주문 스톡의 충전 지원
```

- 소환수는 플레이어가 배우지 않은 글자를 대신 제공하지 않는다.
- 소환수는 현재 회로판에 글자·선·연결을 직접 작성하지 않는다.
- 소환수의 주문 보조는 스톡 생산량·충전 속도·능동 충전 보너스로만 표현한다.
- 소환수가 지원해도 해당 글자의 기능 글자 수와 스톡 비용은 변하지 않는다.

## 6. 스톡과의 관계

- `숙련` 이상인 보조 글자만 하위 글자 스톡 후보가 된다.
- 등록·숙련된 완성 주문만 완성 주문 스톡 후보가 된다.
- 숙련 단계는 스톡 사용 자격과 충전 효율 후보에 영향을 줄 수 있다.
- 숙련이 높아도 기능 글자 수는 여전히 1개로 계산한다.
- 숙련이 높다는 이유로 스톡 준비 용량을 할인하지 않는다.
- 소환수는 플레이어가 지정한 스톡 대상 1종의 충전을 보조한다.

## 7. DDD 적용

```text
새 보조 글자 습득
→ 즉시 메인 글자와 직접 조합
→ 결과 차이 확인
→ 반복 활용으로 숙련
→ 하위 글자 스톡 해금
→ 소환수의 스톡 충전 지원으로 반복 입력 감소
→ 더 새로운 글자와 고위 조합에 집중
```

성장의 보상은 단순 수치 증가가 아니라 **반복 입력의 감소와 주문 설계 자유도의 증가**로 즉시 체감하게 한다.

## 8. 가드레일

- 모든 보조 글자를 한 회차에 달인으로 만들게 하지 않는다.
- 미숙 단계부터 자동화해 학습과 직접 작성 경험을 제거하지 않는다.
- 숙련 등급을 올리기 위해 무의미한 동일 주문 반복을 강제하지 않는다.
- 달인 단계가 메인 글자 전문화보다 더 복잡한 분기 시스템이 되지 않게 한다.
- 숙련 단계가 보조 운용량 `2→4→6`을 대체하지 않는다.
- 소환수가 보조 글자를 직접 작성·배치·연결하지 않는다.
- 소환수의 스톡 충전 지원이 스톡 준비 용량 비용을 우회하지 않는다.

## 9. 추후 데이터 설계

- 미숙→숙련→달인의 정확한 요구량
- 직접 작성 정확도와 숙련 상승의 관계
- 달인 보조 글자의 스톡 충전 보너스
- 조건·순서·분기형 보조 글자의 숙련 판정
- 보조 글자별 계열 적합성과 상충 규칙
