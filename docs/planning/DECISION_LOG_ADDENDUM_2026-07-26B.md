## GM-00-23 — 충전 대상 변경 시 진행도 보존과 전환 지연

### 채택안

`진행도 유지 + 전환 지연`

### 최신 규칙

- 전투 중 충전 대상을 다른 준비 스톡으로 변경할 수 있다.
- 기존 대상의 다음 스톡 1회분 충전 진행도는 대상별로 보존한다.
- 전환 요청 시 현재 대상 충전을 정지하고 진행도를 저장한다.
- 전환 지연 동안에는 어떤 대상도 충전하지 않는다.
- 전환 완료 후 새 대상의 저장 진행도부터 재개한다.
- 자동 충전 대상은 한 번에 1종만 유지한다.
- 소환수는 플레이어 허가 없이 충전 대상을 변경하지 않는다.

상태: `CONFIRMED`

최신 책임 원본: `docs/planning/STOCK_TARGET_SWITCH_SYSTEM.md`

## GM-00-24 — 피격 시 진행도 보존과 자동 재개

### 채택안

`진행도 전부 보존 + 일시정지 + 자동 재개`

### 최신 규칙

- 스톡 충전 중 실제 체력 피해를 받으면 현재 진행도를 그대로 보존한다.
- 대상 전환 중 실제 체력 피해를 받으면 전환 게이지를 그대로 보존한다.
- 피격 정지 종료 후 별도 입력 없이 자동 재개한다.
- 정지 중에는 자동 충전, 플레이어·소환수 생산 기여와 능동 충전 보너스를 적용하지 않는다.
- 정지 중 발생한 충전 보너스는 종료 후 소급 적립하지 않는다.

상태: `CONFIRMED`

최신 책임 원본: `docs/planning/STOCK_HIT_PAUSE_SYSTEM.md`

## GM-00-25 — 완전 차단 공격은 피격 정지 미발생

### 채택안

`플레이어 체력이 실제로 감소했을 때만 피격 정지`

### 최신 규칙

- 피격 정지 판정은 공격 접촉이나 연출이 아니라 실제 체력 감소를 기준으로 한다.
- 소환수, 보호막, 회피, 무적 또는 상쇄로 최종 체력 피해가 0이면 충전과 전환을 유지한다.
- 방어 적용 후에도 실제 체력이 감소하면 해당 감소량을 피격 정지 계산에 사용한다.
- 지속 피해와 환경 피해도 실제 체력을 감소시키면 계산 대상이다.

상태: `CONFIRMED`

최신 책임 원본: `docs/planning/STOCK_HIT_PAUSE_SYSTEM.md`

### 과거 채택안

## GM-00-27 — 0.5초 고정 정지와 연속 정지 1.0초 상한

### 과거 채택안

`기본 0.5초 + 추가 피해 시 0.5초 갱신 + 첫 피해부터 최대 1.0초`

상태: `SUPERSEDED_BY_GM-00-28`

폐기 이유:

- 타격 수가 많은 공격이 같은 총 피해량의 단발 공격보다 더 강하게 충전을 방해할 수 있다.
- 타격 횟수보다 실제 체력 손실을 방해 강도로 사용하는 편이 최신 의도에 부합한다.

## GM-00-28 — 실제 체력 손실 비율 기반 피격 정지

### 채택안

`타격당 계산 폐기 + 짧은 구간의 실제 체력 손실 합산 + 최대 체력 대비 손실 비율로 정지시간 결정`

### 확정 방향

- 정지시간은 타격 횟수로 계산하지 않는다.
- 짧은 피해 집계 구간 안에서 실제로 감소한 체력을 합산한다.
- 합산 체력 손실을 피해 집계 시작 시점의 최대 체력으로 나눈 비율을 사용한다.
- 같은 총 체력 손실이라면 단발 강타와 다단 공격은 같은 정지시간을 목표로 한다.
- 진행도는 피해량과 관계없이 전부 보존한다.
- 정지 종료 후 별도 입력 없이 자동 재개한다.
- 완전 차단으로 실제 체력 손실이 0이면 정지하지 않는다.

### 비율식

```text
체력 손실 비율 r
= 피해 집계 구간의 실제 체력 감소 합계 / 집계 시작 시 최대 체력
```

상태: `CONFIRMED`

최신 책임 원본: `docs/planning/STOCK_HIT_PAUSE_SYSTEM.md`

## GM-00-29 — 균형형 비례 수치 확정

### 채택안

`B — r × 3.0, 최소 0.10초, 최대 0.80초, 피해 집계 구간 0.25초`

### 확정 계산식

```text
체력 손실 비율 r
= 0.25초 피해 집계 구간의 실제 체력 감소 합계
  / 집계 시작 시 최대 체력

피격 정지시간(초)
= clamp(r × 3.0, 0.10, 0.80)
```

| 최대 체력 대비 손실 | 정지시간 |
|---:|---:|
| 1% | 0.10초 |
| 5% | 0.15초 |
| 10% | 0.30초 |
| 20% | 0.60초 |
| 30% 이상 | 0.80초 |

### 다단 피해 집계

- 첫 실제 체력 피해부터 0.25초 동안의 실제 체력 손실을 합산한다.
- 같은 집계 구간의 다단 피해는 타격 수가 아니라 총 체력 손실로 한 번 계산한다.
- 각 타격에 최소 0.10초를 반복 적용하지 않는다.
- 집계 중 추가 피해가 발생하면 누적 손실 비율로 정지 종료 시점을 재계산한다.
- 집계 구간 종료 후 발생한 피해는 새 집계로 처리한다.

### 설계 의도

- 미세 피해는 최소 0.10초의 짧은 방해만 제공한다.
- 중간 피해는 손실 비율에 따라 선형적으로 정지시간이 증가한다.
- 큰 피해는 최대 0.80초에서 제한해 스톡 생산이 장시간 봉쇄되지 않게 한다.
- 같은 총피해를 주는 단발·다단 공격의 스톡 방해력을 유사하게 맞춘다.
- 부분 방어로 실제 체력 손실이 감소하면 정지시간도 비례해 감소한다.

상태: `CONFIRMED`

최신 책임 원본: `docs/planning/STOCK_HIT_PAUSE_SYSTEM.md`

## 최신 스톡 충전 순환

```text
지정 대상 1종 충전
→ 회로 수 기반 기준 충전시간 적용
→ 플레이어 행동과 소환수 생산 지원으로 가속
→ 필요 시 대상 변경
→ 진행도 보존 후 전환 지연
→ 실제 체력 피해 발생
→ 0.25초 동안 실제 체력 손실 합산
→ 최대 체력 대비 손실 비율 r 계산
→ clamp(r × 3.0, 0.10초, 0.80초) 적용
→ 진행도 보존
→ 정지 종료 후 자동 재개
```

## 후속 미해결 결정

1. 지속 피해를 매 틱 별도 집계로 볼 것인가, 상태효과 주기 단위로 묶을 것인가.
2. 수호·동조 능력치가 계산된 피격 정지시간을 추가 감소시키는가.
3. 전환 지연의 실제 초 단위 값은 얼마인가.
4. 전환 지연 중 다시 대상을 변경하면 어떻게 처리하는가.
5. 플레이어·소환수 생산 능력치의 최종 계산식은 무엇인가.
6. 최소 충전시간 하한은 얼마인가.
7. 연결·분기·합류를 독립 기능 회로로 취급하는가.
8. 전체 준비 용량의 초기값과 성장 증가량은 얼마인가.
