# 스펠 Gate 1 Vertical Slice 계약 — 승인본

## 1. 문서 상태

- 프로젝트: `스펠` (임시)
- 제품 단계: `PROTOTYPE_AND_VERTICAL_SLICE`
- Gate 1: `APPROVED`
- 프로젝트 코어: `CORE_CONFIRMED`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- Work Mode: `PLAN`
- 계약 결정 ID: `GM-SLICE-01`
- 위험 처리 결정 ID: `GM-GATE1-RISK-01`
- 최종 승인 결정 ID: `GM-GATE1-APPROVAL-01`
- 계약 상태: `APPROVED_AT_GATE_1_WITH_P0_AMENDMENT`
- 검증 방식: `VALIDATION_FIRST_VERTICAL_SLICE`
- 제작성: `CONDITIONAL_PASS_CANDIDATE`
- 구현: `NOT_STARTED`
- Codex: `NOT_RUN`
- CORE_POC: `REMOVED_BY_USER_DECISION`

승인 증거는 `docs/planning/GATE_1_FINAL_APPROVAL.md`가 책임진다.

> **첫 Vertical Slice는 마법학교의 축약된 한 학기를 네 개의 핵심 세션과 세 번의 자유일정으로 체험하며, 배우고·시험받고·표현하고·실전에 응용해 자신의 주문 활용을 발견하는 45~50분 목표의 완결형 데모다.**

---

## 2. 승인된 전체 구조

```text
프롤로그·학교 도착
→ 첫 수업·교내 연습
→ 자유일정 A
→ 첫 실기시험
→ 자유일정 B
→ 학교축제
→ 자유일정 C
→ 첫 현장실습
→ 귀환·마도서 기록
→ 다음 학기 예고
```

### 세션 책임

```text
수업·연습 = 배움과 원리 비교
시험 = 제한 조건 안에서 이해 증명
학교축제 = 표현·개성·관계·비전투 활용
현장실습 = 위험 속 우선순위·재설계·발견
자유일정 = 휴식·준비·교류의 완충
귀환·기록 = 결과 해석·다음 학습 연결
```

### 구조 원칙

- 수업 후·시험 후·축제 후 자유일정을 정확히 1회 제공한다.
- 한 자유일정에서는 중심 행동 하나만 선택한다.
- `휴식`은 정식 전략이며 손해 전용 선택이 아니다.
- 자유일정은 시험·축제·현장실습 참가를 차단하지 않는다.
- 필수 정보와 유일한 정답을 특정 자유일정에 독점시키지 않는다.
- 각 핵심 세션과 자유일정은 저장·중단·복귀 경계를 가진다.
- 네 핵심 세션은 같은 마법 문법과 문제 계약을 공유한다.
- 세션별 독립 미니게임·전용 프레임워크를 만들지 않는다.

---

## 3. 공통 Situation Challenge 계약

수업·시험·학교축제·현장실습의 모든 플레이 문제는 다음 구조를 사용한다.

```text
상황 목표
→ 관찰 가능한 상태
→ 사용 가능한 메인·보조 글자
→ 제한 조건
→ 방향성 결과 미리보기
→ 주문 작성
→ 세계 상태 변화
→ 성공·부분 성공·실패 원인
→ 기록·후속 반응
```

### 세션 차이를 만드는 데이터

- 위험 수준
- 시간 압박
- 허용 자원
- 평가 방식
- 결과 성격
- 소환수 허용 여부
- 실패 후 복구 방식
- 관계·기록 후속 반응

### 가드레일

- 모든 문제는 `메인 글자 1개 + 보조 글자 0개 이상` 문법을 공유한다.
- 두 번째 문제를 새 전용 Scene·시스템 없이 추가할 수 있어야 한다.
- 방향성 미리보기는 정답 대신 대상·범위·위험·소모 경향만 보여준다.
- 각 문제는 `Problem Differentiation Matrix`로 판단 차이를 검수한다.

### Problem Differentiation Matrix

각 문제 명세는 다음 항목을 가진다.

```text
세션
→ 플레이어가 읽어야 할 정보
→ 핵심 판단
→ 허용 해법 2개 이상
→ 금지되는 단순 반복 해법
→ 실패 원인
→ 결과 피드백
→ 다음 세션으로 전달되는 학습
```

이 표가 작성되기 전 시험·축제·현장용 대량 자산을 제작하지 않는다.

## 4. 세션 차별화

| 세션 | 핵심 판단 | 압박 | 결과 | 실패 처리 |
|---|---|---|---|---|
| 수업·연습 | 원리 이해·결과 비교 | 없음 또는 매우 낮음 | 즉각적 인과 설명 | 수정 유도 |
| 실기시험 | 제한 조건 안의 선택·효율 | 횟수·시간·마나 중 하나 | 항목별 평가 | 진행 차단 없이 평가 하락 |
| 학교축제 | 표현·개성·관계 | 전투 압박 없음 | 복수의 긍정적 표현 결과 | 분위기·완성도 차이 |
| 현장실습 | 위험 속 우선순위·재설계 | 적·환경·시간 압박 | 성공·부분 성공·피해 | 안전 지점 재시도·원인 기록 |

플레이테스트 후 플레이어가 다음을 자기 말로 구분할 수 있어야 한다.

```text
수업은 이해하는 곳
시험은 증명하는 곳
축제는 표현하는 곳
현장은 응용하는 곳
```

## 5. 프롤로그·첫 수업·교내 연습

```text
학교 도착·현재 목표 소개
→ 메인 동반 소환수와 첫 관계
→ 교수의 짧은 시범
→ 메인 글자 1개 직접 작성
→ 즉각적인 세계 변화
→ 보조 글자 2개 학습
→ 같은 메인 글자에 서로 다른 보조 적용
→ 안내형 비교 문제
→ 결과 정리
```

필수 증거:

- 첫 직접 작성이 시작 후 5분을 넘지 않는다.
- 15분 안에 메인·보조 글자의 역할 차이를 이해한다.
- 같은 메인 글자가 보조에 따라 달라지는 결과를 확인한다.
- 입력 실패와 설계 실패가 다른 피드백을 가진다.

## 6. 자유일정 시스템

### 슬롯

1. 수업·연습 후, 시험 전
2. 시험 후, 학교축제 전
3. 학교축제 후, 현장실습 전

### 공통 행동 원형

```text
휴식
= 컨디션·집중 회복과 안전 보정

준비
= 시험 복습·축제 준비·현장 조사 또는 보조 소환수 조율

교류
= 메인 동반자 또는 핵심 인물과 관계·관점·짧은 정보 획득
```

슬롯별 준비 문맥:

- 자유일정 A: 시험 복습
- 자유일정 B: 축제 준비
- 자유일정 C: 현장 조사 또는 보조 소환수 조율 중 하나

기본 흐름:

```text
현재 상태와 다음 중요 일정 확인
→ 휴식 / 준비 / 교류
→ 행동 1개 선택
→ 짧은 플레이·대화·정리
→ 결과 태그 저장
→ 다음 중요 일정
```

금지:

- 필수 일정 영구 차단
- 특정 선택만 가능한 유일 정답
- 관계 선택 때문에 필수 정보 누락
- 자유일정별 독립 대형 미니게임
- 선택 하나당 신규 지역·전투·장문 분기
- 세 원형 중 절대 우위 고정

## 7. 첫 실기시험

```text
시험 규칙·제한 조건 확인
→ 문제 관찰
→ 주문 설계·직접 작성
→ 결과 판정
→ 실패 원인 확인·재설계
→ 교수 피드백
```

표시 평가 축:

1. 상황 적합성
2. 주문 설계
3. 실행 안정성

원칙:

- 정답 하나를 강요하지 않는다.
- 최소 두 가지 유효 해결법을 허용한다.
- 입력 실수와 잘못된 설계를 별도 평가한다.
- 전투 보조 소환수는 사용 금지 또는 제한한다.
- 낮은 성적은 진행 실패가 아니라 피드백과 준비 차이다.

---

## 8. 학교축제

```text
축제 활동 선택
→ 짧은 준비·관계 장면
→ 비전투 마법 활동
→ 작은 문제 발생
→ 자유로운 주문 활용
→ 표현 성향·관계·기록 변화
```

범위:

- 대표 비전투 문제 하나만 제작한다.
- 별도 축제 맵을 만들지 않는다.
- 학교 장면 세트에 장식·NPC·음악 상태를 적용한다.
- 공연 효과 조정, 장식 복구, 제한 재료 주문 경연, 방문객 지원 중 하나를 선택한다.

축제 결과 태그:

- `ELEGANT`
- `PRACTICAL`
- `SPECTACULAR`

성공·실패보다 플레이어가 선택한 표현 성향을 기록한다.

---

## 9. 첫 현장실습

```text
현장 브리핑
→ 메인 동반 소환수와 상황 관찰
→ 전투 보조 소환수 호출
→ 전투 문제 1개
→ 환경·구조 문제 1개
→ 같은 메인 글자의 다른 목적 활용
→ 실패 원인 확인·주문 재설계
→ 새로운 활용 발견
→ 귀환
```

필수 증거:

- 전투 문제와 환경 문제를 모두 포함한다.
- 같은 메인 글자를 다른 목적으로 재사용한다.
- 최소 두 가지 유효 해결법이 있다.
- 보조 소환수가 수호 또는 견제로 작성 시간을 확보한다.
- 보조 소환수 유무에 따른 작성 시간·피격·완주율을 비교한다.
- 소환수가 주문 설계와 글자 작성을 대행하지 않는다.

Slice에서는 보조 소환수의 `수호` 또는 `견제` 하나만 구현한다.

---

## 10. 귀환·마도서 기록

```text
시험·축제·현장 결과 요약
→ 발견한 주문 활용 기록
→ 실패 원인과 다음 연구 목표 기록
→ 메인 동반 소환수의 관계 반응
→ 다음 수업·학기·전문화 가능성 예고
```

완료 감정:

- 학교에서 한 기간을 보냈다는 감각
- 같은 원리가 시험·축제·현장에서 다르게 쓰였다는 이해
- 자신의 주문 활용을 발견했다는 성취
- 다음 학기를 계속하고 싶은 기대

메인 동반자 관계 단계는 Slice에서 최대 3단계다.

## 11. 시간 예산

| 구간 | 권장 상한 |
|---|---:|
| 프롤로그·수업·연습 | 10~12분 |
| 자유일정 A | 2~4분 |
| 실기시험 | 7~10분 |
| 자유일정 B | 2~4분 |
| 학교축제 | 8~12분 |
| 자유일정 C | 2~4분 |
| 현장실습 | 12~16분 |
| 귀환·기록 | 2~4분 |

제품 계약:

- 목표 중앙값: `45~50분`
- 허용 상한: `60분`
- 연속 플레이 강제 없음
- 현장실습 도달 전 필수 대화·이동 누적 15분 초과 금지
- 정확한 세부 시간: `PLAYTEST_TUNING_REQUIRED`

## 12. 저장·복귀 계약

필수 저장 지점:

- 핵심 세션 시작·완료
- 자유일정 선택 전·완료
- 현장실습 전투 문제 완료 후
- 귀환·기록 완료 후

최소 저장 상태:

```text
schema_version
current_step
learned_glyphs
free_schedule_A_choice
exam_result_band
free_schedule_B_choice
festival_result_tag
free_schedule_C_choice
field_result_tag
companion_relation_band
support_summon_ready_tag
grimoire_discoveries
```

Save Schema v1에서 enum, 기본값, 알 수 없는 태그 처리, 롤백 경계와 이전 버전 로드 정책을 확정한다.

초기 제외:

- 대화 한 줄 단위 저장
- 자유 위치 저장
- 전투 도중 임의 저장
- 다수의 세밀한 관계 수치
- 모든 주문 궤적 기록

복귀한 플레이어는 10초 안에 현재 일정·목표·직전 선택·보유 글자·사용 가능한 소환수를 확인할 수 있어야 한다.

## 13. 모바일 작성 화면 정보 예산

작성 중 고정 표시:

- 현재 목표
- 선택한 메인 글자
- 선택한 보조 글자
- 마나 또는 사용 가능 횟수
- 위험 경고

소환수 상세, 마도서, 관계, 시험 세부 점수는 작성 화면 밖으로 분리한다.

접근성 계약은 Art Bible에서 확정한다.

- 색상만으로 상태를 구분하지 않는다.
- 글자·위험·성공·실패는 형태 또는 움직임으로 중복 전달한다.
- 과도한 플래시와 화면 흔들림을 제한한다.
- 무음에서도 핵심 판정과 위험을 확인할 수 있어야 한다.

## 14. 최소 콘텐츠 범위

### 포함

- 메인 글자 1개, 보조 글자 2개
- 직접 작성 심볼 3개
- 넓은 허용 범위의 입력 판정
- 학교 장면 세트 1개
- 축제 장식 상태 1개
- 현장실습 구역 1개
- 교수 1명
- 학생 또는 핵심 관계 인물 1명
- 메인 동반 소환수 1체
- 수호 또는 견제형 보조 소환수 1체
- 적 1종, 필요 시 변형 1종
- 교내 연습 문제 1개
- 실기시험 문제 1개
- 학교축제 비전투 문제 1개
- 현장 전투 문제 1개
- 현장 환경 문제 1개
- 자유일정 3회
- 핵심 UI·아트·사운드
- 저장·중단·복귀

### 제외

- 3년·6학기 전체
- 다수 시험 과목
- 다수 축제 부스와 별도 대형 축제 맵
- 다수 현장실습 지역
- 대규모 관계·연애 분기
- 다수 보조 소환수 편성
- 희귀도 경제·복잡한 진화
- 완성 주문 스톡
- 복잡한 소환수 충전·용량
- 다중 상태이상·광범위한 조합표
- 고정밀 자유 손글씨 인식
- 온라인·협동·풀보이스

- 구현 순서를 역전하지 않는다.

## 16. 통과 기준

### 핵심 마법

- 첫 5분 안에 `내가 마법을 썼다`고 인식한다.
- 15분 안에 메인·보조 글자 역할을 설명한다.
- 같은 문법을 시험·축제·현장에서 다르게 사용한다.
- 최소 두 가지 유효 해결법 중 하나를 의도적으로 선택한다.
- 입력 실패와 설계 실패를 구분하고 재설계한다.

### 학교생활

- 수업·시험·축제·현장의 역할을 구분한다.
- 축약된 학교 기간을 경험했다고 인식한다.
- 자유일정이 휴식과 준비로 기능한다.
- 자유일정 선택이 작은 차이를 만들지만 진행을 차단하지 않는다.

### 소환수

- 메인 동반자가 학습·관계·기록을 연결한다.
- 전투 보조 소환수가 작성 시간을 확보한다.
- 두 소환수 계층을 구분한다.
- 어느 소환수도 주문 설계·글자 작성을 대행하지 않는다.

### 모바일 UX·기술

- 손가락 가림과 반복 피로가 핵심 행동을 방해하지 않는다.
- 완전 정지·감속·실시간을 비교한다.
- 저장·복귀가 안정적이다.
- 목표 Android 기기와 주요 화면비에서 플레이 가능하다.
- 작성 화면 정보 예산을 지킨다.

### 제작성

- 모든 문제가 공통 Situation Challenge를 사용한다.
- 자유일정이 공통 이벤트 구조와 결과 태그를 사용한다.
- 대표 장면이 일회성 하드코딩에만 의존하지 않는다.
- 두 번째 유사 문제를 기존 구조로 추가할 수 있다.
- 첫 완주가 60분 이내다.

## 17. 실패 기준과 감량 순서

콘텐츠 확대 금지 조건:

- 직접 작성 피로·인식 오류가 핵심 재미를 방해
- 시험·축제·현장이 같은 문제의 외형 변경으로 인식
- 세션별 전용 시스템이 생김
- 자유일정이 보상 최적화 메뉴나 불필요한 대화로만 작동
- 휴식이 명백한 손해 선택
- 메인 동반자가 정답을 대신 제시
- 보조 소환수 운용이 주문 설계보다 복잡
- 첫 완주가 60분을 구조적으로 초과
- 저장·복귀 후 목표를 이해하기 어려움
- 두 번째 콘텐츠에 전용 Scene·코드가 필요

수정 우선순위:

```text
입력 판정·시간 처리·피드백
→ 공통 Situation Challenge
→ 세션별 역할 구분
→ 자유일정 결과 규모
→ 전투 압박·보조 소환수 조작량
→ 축제·관계 연출 분량
→ 전체 세션 길이
```

우선 감량:

```text
완성 주문 스톡
→ 복잡한 소환수 충전·편성
→ 자유일정별 독립 미니게임
→ 다중 상태이상
→ 장문 관계 분기
→ 추가 축제 부스·시험 과목·현장 지역
```

비타협 유지:

- 의미 기반 글자
- 직접 작성
- 상황별 조합
- 설명 가능한 세계 변화
- 수업·시험·축제·현장실습의 역할 차이
- 중요 일정 사이 자유일정 1회
- 학습→증명→표현→응용→기록 순환
