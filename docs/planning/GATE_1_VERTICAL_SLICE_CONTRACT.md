# 스펠 Gate 1 Vertical Slice 계약 — 축약 학기형

## 1. 문서 상태

- 프로젝트: `스펠` (임시)
- 제품 단계: `CONCEPT_APPROVAL`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- Work Mode: `PLAN`
- 결정 ID: `GM-SLICE-01`
- 상태: `VERTICAL_SLICE_CONTRACT_CONFIRMED_PENDING_P0_AMENDMENT`
- 사용자 승인: 2026-07-27, `권장대로진행`
- 사용자 추가 조건: 중요 일정 사이마다 쉬는 타임으로 자유일정 1회 배치
- CORE_POC: `REMOVED_BY_USER_DECISION`
- 검증 방식: `VALIDATION_FIRST_VERTICAL_SLICE`
- 적대적 검토: `AUTHORED_BY_GM-GATE1-REVIEW-01`
- P0 처리 패키지: `USER_DECISION_REQUIRED_GM-GATE1-RISK-01`
- Gate 1 전체: `UNVERIFIED`
- 구현 상태: `NOT_STARTED`

이 문서는 첫 Vertical Slice가 보여줄 학교생활과 핵심 플레이를 정의한다. 적대적 검토에서 현재 제작 범위는 `CONDITIONAL_FAIL`로 판정됐으며, 구조 자체는 유지하되 P0 처리 패키지 승인 후 시간·재사용·자유일정·저장 계약을 보완해야 한다.

> **첫 Vertical Slice는 마법학교의 축약된 한 학기를 네 개의 핵심 세션과 세 번의 자유일정으로 체험하며, 배우고·시험받고·표현하고·실전에 응용해 자신의 주문 활용을 발견하는 완결형 데모다.**

---

## 2. 전체 구조

```text
프롤로그·학교 도착
→ 세션 1: 첫 수업·교내 연습
→ 자유일정 A 1회
→ 세션 2: 첫 실기시험
→ 자유일정 B 1회
→ 세션 3: 학교축제 준비·학교축제
→ 자유일정 C 1회
→ 세션 4: 첫 현장실습
→ 귀환·마도서 기록·다음 학기 예고
```

### 구조 원칙

- 중요 일정 직후 다음 중요 일정으로 바로 넘어가지 않는다.
- 각 중요 일정 사이에 자유일정 슬롯을 정확히 1회 제공한다.
- 자유일정 한 슬롯에서는 한 가지 중심 행동만 선택한다.
- `휴식`은 보상 없는 포기 선택지가 아니라 정식 전략이다.
- 어떤 자유일정 선택도 시험·축제·현장실습 참가를 차단하지 않는다.
- 선택 결과는 작은 이점·관계·정보·준비 상태를 바꾸되 필수 해답을 독점하지 않는다.
- 각 세션은 저장·중단·복귀 경계를 가진다.

## 3. 세션 역할 계약

| 세션 | 핵심 역할 | 기본 압박 | 결과 구조 |
|---|---|---|---|
| 수업·연습 | 글자 의미와 조합을 배움 | 없음 또는 매우 낮음 | 인과 설명과 안전한 수정 |
| 실기시험 | 제한 조건 안에서 이해를 증명 | 제한 횟수·시간·마나 중 하나 | 항목별 평가와 피드백 |
| 학교축제 | 마법으로 개성·관계·비전투 활용 표현 | 전투 압박 없음 | 복수의 긍정적·개성적 결과 |
| 현장실습 | 위험 속 우선순위·응용·재설계 | 적·환경·시간 압박 | 성공·부분 성공·피해 결과 |

플레이어가 다음을 구분할 수 있어야 한다.

```text
수업은 이해하는 곳
시험은 증명하는 곳
축제는 표현하는 곳
현장은 응용하는 곳
```

## 4. 세션 1 — 첫 수업·교내 연습

```text
교수의 짧은 시범
→ 메인 글자 1개 직접 작성
→ 즉각적인 세계 변화 확인
→ 보조 글자 2개 학습
→ 같은 메인 글자에 서로 다른 보조 적용
→ 교내 연습 문제 해결
→ 메인 동반 소환수와 결과 정리
```

필수 증거:

- 첫 5분 안에 직접 작성과 마법 발현
- 메인·보조 글자의 역할 차이
- 보조에 따른 결과 차이
- 입력 실패와 설계 실패의 분리

## 5. 자유일정 A — 시험 전 완충

기존 후보:

- 휴식
- 복습
- 메인 동반자와 대화
- 보조 소환수 기초 훈련

적대적 검토 권장 감량:

```text
휴식
준비 — 시험 복습
교류 — 메인 동반자 또는 핵심 인물
```

최종 선택 수는 `GM-GATE1-RISK-01`에서 결정한다.

---

## 6. 세션 2 — 첫 실기시험

```text
시험 규칙 확인
→ 제한 조건과 평가 목표 제시
→ 문제 관찰
→ 주문 설계·직접 작성
→ 결과 판정
→ 실패 시 원인 확인·재설계
→ 교수 피드백
```

원칙:

- 정답 하나만 강요하지 않는다.
- 최소 두 가지 유효 해결법을 허용한다.
- 입력 실수와 잘못된 설계를 별도 평가한다.
- 전투 보조 소환수는 사용 금지 또는 제한한다.
- 낮은 성적은 진행 실패가 아니라 피드백 차이로 처리한다.

초기 표시 평가 축 권장:

1. 상황 적합성
2. 주문 설계
3. 실행 안정성

## 7. 자유일정 B — 축제 전 완충

기존 후보:

- 휴식
- 축제 준비
- 학생·교수와 교류
- 보조 소환수 조율

적대적 검토 권장 감량:

```text
휴식
준비 — 축제 준비
교류 — 학생·교수·메인 동반자
```

보조 소환수 조율은 자유일정 C의 현장 준비에 통합하는 것을 권장한다.

## 8. 세션 3 — 학교축제

```text
축제 활동 선택
→ 짧은 준비 장면
→ 관계 장면
→ 비전투 마법 활동
→ 작은 문제 발생
→ 자유로운 주문 활용
→ 축제 결과와 관계·기록 변화
```

Vertical Slice에서는 다음 후보 중 하나만 제작한다.

- 마법 공연·전시의 효과 조정
- 부스 장치·장식 복구
- 제한 재료 주문 경연
- 방문객을 돕는 생활 마법 문제

제작성 보호:

- 별도 대형 축제 맵을 만들지 않는다.
- 학교 장면 세트에 장식·NPC·음악 상태를 적용한다.
- 대규모 성공·실패 분기보다 표현 성향 태그를 사용한다.
- `ELEGANT / PRACTICAL / SPECTACULAR` 등 정확한 태그는 후속 결정 대상이다.

기존 후보:

- 휴식
- 현장 조사
- 주문 연구
- 보조 소환수 훈련

적대적 검토 권장 감량:

```text
휴식
준비 — 현장 조사·주문 연구·보조 소환수 조율 중 하나의 장면으로 통합
교류 — 메인 동반자 또는 현장 관계 인물
```

필수 정보는 어떤 선택에도 독점되지 않는다.

## 10. 세션 4 — 첫 현장실습

```text
현장 브리핑
→ 메인 동반 소환수와 상황 관찰
→ 전투 보조 소환수 호출
→ 전투 문제 1개
→ 환경·구조 문제 1개
→ 같은 메인 글자의 다른 목적 활용
→ 실패 원인 확인·주문 재설계
→ 새로운 활용 발견
→ 귀환
```

필수 증거:

- 전투와 환경 문제 모두 포함
- 같은 메인 글자의 다른 목적 사용
- 최소 두 가지 유효 해결법
- 전투 보조 소환수의 수호 또는 견제
- 소환수가 설계·작성을 대행하지 않음

## 11. 귀환·마도서 기록

```text
시험·축제·현장 결과 요약
→ 발견한 주문 활용 기록
→ 실패 원인과 다음 연구 목표 기록
→ 메인 동반 소환수의 관계 반응
→ 다음 수업·학기·전문화 예고
```

완료 감정:

- 학교에서 한 기간을 보냈다는 감각
- 같은 원리가 시험·축제·현장에서 다르게 쓰였다는 이해
- 자신의 활용을 발견했다는 성취
- 다음 학기를 계속하고 싶은 기대

## 12. 공통 Situation Challenge 계약 — P0 제안

수업·시험·축제·현장 문제는 다음 공통 구조를 사용한다.

```text
상황 목표
→ 관찰 가능한 상태
→ 사용 가능한 메인·보조 글자
→ 제한 조건
→ 방향성 결과 미리보기
→ 주문 작성
→ 세계 상태 변화
→ 성공·부분 성공·실패 원인
→ 기록·후속 반응
```

세션 차이는 다음 데이터로 만든다.

- 위험 수준
- 시간 압박
- 허용 자원
- 평가 방식
- 결과 성격
- 소환수 허용 여부
- 실패 후 복구 방식

이 계약은 `GM-GATE1-RISK-01` 승인 전까지 `PROPOSED_P0_AMENDMENT`다.
