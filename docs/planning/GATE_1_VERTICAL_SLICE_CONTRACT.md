# 스펠 Gate 1 Vertical Slice 계약 — 축약 학기형

## 1. 문서 상태

- 프로젝트: `스펠` (임시)
- 제품 단계: `CONCEPT_APPROVAL`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- Work Mode: `PLAN`
- 결정 ID: `GM-SLICE-01`
- 상태: `VERTICAL_SLICE_CONTRACT_CONFIRMED_FOR_GATE_1`
- 사용자 승인: 2026-07-27, `권장대로진행`
- 사용자 추가 조건: 중요 일정 사이마다 쉬는 타임으로 자유일정 1회 배치
- CORE_POC: `REMOVED_BY_USER_DECISION`
- 검증 방식: `VALIDATION_FIRST_VERTICAL_SLICE`
- Gate 1 전체: `UNVERIFIED`
- 구현 상태: `NOT_STARTED`

이 문서는 스펠의 첫 Vertical Slice가 어떤 학교생활과 핵심 플레이를 실제로 보여주고 검증해야 하는지 정의하는 단일 책임 원본이다.

> **첫 Vertical Slice는 마법학교의 축약된 한 학기를 네 개의 핵심 세션과 세 번의 자유일정으로 체험하며, 배우고·시험받고·표현하고·실전에 응용해 자신의 주문 활용을 발견하는 완결형 데모다.**

---

## 2. 전체 구조

```text
프롤로그·학교 도착
→ 세션 1: 첫 수업·교내 연습
→ 자유일정 A 1회
→ 세션 2: 첫 실기시험
→ 자유일정 B 1회
→ 세션 3: 학교축제 준비·학교축제
→ 자유일정 C 1회
→ 세션 4: 첫 현장실습
→ 귀환·마도서 기록·다음 학기 예고
```

### 구조 원칙

- 중요 일정 직후 다음 중요 일정으로 바로 넘어가지 않는다.
- 각 중요 일정 사이에 자유일정 슬롯을 정확히 1회 제공한다.
- 자유일정 한 슬롯에서는 한 가지 중심 행동만 선택한다.
- `휴식`은 보상 없는 포기 선택지가 아니라 컨디션·안전·다음 일정 준비를 회복하는 정식 전략이다.
- 어떤 자유일정 선택도 시험·축제·현장실습 참가 자체를 영구 차단하지 않는다.
- 선택 결과는 작은 이점·관계·정보·준비 상태를 바꾸되 필수 해답을 독점하지 않는다.
- 각 세션은 독립 저장·중단·복귀 지점을 가진다.

---

## 3. 세션별 역할

### 3.1 프롤로그·학교 도착

목적:

- 플레이어가 마법학교 학생이라는 역할 이해
- 메인 동반 소환수와 첫 만남 또는 현재 관계 제시
- 이번 축약 학기의 주요 일정 예고
- 장문 세계관 설명 없이 첫 수업으로 연결

완료 기준:

- 플레이어가 현재 목표와 다음 행동을 이해한다.
- 첫 직접 작성까지 불필요한 설명으로 지연되지 않는다.

### 3.2 세션 1 — 첫 수업·교내 연습

핵심 질문:

> 이 글자는 무엇을 만들고, 보조 글자에 따라 어떻게 달라지는가?

내용:

```text
교수의 짧은 시범
→ 메인 글자 1개 직접 작성
→ 즉각적인 세계 변화 확인
→ 보조 글자 2개 학습
→ 같은 메인 글자에 서로 다른 보조 적용
→ 교내 연습 문제 해결
→ 메인 동반 소환수와 결과 정리
```

필수 증거:

- 첫 5분 안에 직접 작성과 마법 발현
- 메인 글자와 보조 글자의 역할 차이
- 같은 메인 글자가 보조에 따라 달라지는 결과
- 입력 실패와 설계 실패의 다른 피드백

### 3.3 자유일정 A — 시험 전 완충

목적:

- 첫 수업 직후 피로를 풀고 플레이어가 다음 평가를 준비
- 자유 일정과 고정 중요 일정의 혼합 구조 체험

대표 선택:

- `휴식`: 컨디션 회복, 시험 중 안전 보정
- `복습`: 시험 문제의 원리 힌트 또는 재시도 편의
- `메인 동반자와 대화`: 관계 반응과 플레이어의 이해 정리
- `보조 소환수 기초 훈련`: 현장실습에서 사용할 지원 구조 예고

가드레일:

- 한 번에 하나만 선택한다.
- 복습을 고르지 않아도 시험의 필수 정보는 제공된다.
- 휴식은 다른 선택보다 열등한 선택이 아니다.

### 3.4 세션 2 — 첫 실기시험

핵심 질문:

> 나는 배운 원리를 제한 조건 안에서 정확히 이해하고 적용할 수 있는가?

내용:

```text
시험 규칙 확인
→ 제한 조건과 평가 목표 제시
→ 문제 관찰
→ 주문 설계·직접 작성
→ 결과 판정
→ 실패 시 원인 확인·재설계
→ 교수의 항목별 피드백
```

평가 축:

- 글자 작성 판정
- 상황 해석
- 주문 설계
- 마나·시간 효율
- 부가 목표 해결

원칙:

- 정답 하나만 강요하지 않는다.
- 최소 두 가지 유효 해결법을 허용한다.
- 입력 실수와 잘못된 설계를 별도 평가한다.
- 전투 보조 소환수는 사용 금지 또는 제한 상태로 두어 플레이어의 이해를 확인한다.
- 낮은 성적은 진행 실패가 아니라 피드백과 다음 준비의 차이로 처리한다.

### 3.5 자유일정 B — 축제 전 완충

목적:

- 시험 직후 긴장을 해소
- 축제 준비와 학교 관계를 경험
- 학교생활이 평가와 실전만으로 구성되지 않음을 보여줌

대표 선택:

- `휴식`: 시험 피로 회복, 축제 중 실수 보정
- `축제 준비`: 축제 활동의 추가 선택 또는 완성도 보너스
- `학생·교수와 교류`: 관계 반응과 현장실습의 보조 관찰 정보
- `보조 소환수 조율`: 현장실습의 수호·견제 효율에 작은 준비 보너스

가드레일:

- 축제 콘텐츠 접근은 어떤 선택으로도 차단하지 않는다.
- 관계 선택을 하지 않아도 필수 사건과 정보는 제공된다.

### 3.6 세션 3 — 학교축제 준비·학교축제

핵심 질문:

> 마법을 전투나 시험이 아닌 놀이·표현·생활·관계에 어떻게 사용할 수 있는가?

내용:

```text
축제 역할과 활동 선택
→ 짧은 준비 장면
→ 메인 동반 소환수·학생·교수와 관계 장면
→ 비전투 마법 활동
→ 예상하지 못한 작은 문제 발생
→ 자유로운 주문 활용
→ 축제 결과와 관계·평판·기록 변화
```

대표 플레이 문제:

- 마법 공연·전시의 효과 조정
- 부스 장치 또는 장식 복구
- 제한 재료 주문 경연
- 방문객을 돕는 생활 마법 문제

초기 Vertical Slice에서는 위 후보 중 하나만 제작한다.

필수 증거:

- 같은 마법 문법을 비전투 상황에서 사용
- 플레이어의 조합 선택이 표현과 결과 차이로 보임
- 메인 동반 소환수가 관계와 기록을 연결
- 학교가 단순 전투 로비가 아니라 생활 공간으로 인식됨

### 3.7 자유일정 C — 현장실습 전 완충

목적:

- 축제 직후 바로 위험한 현장으로 전환되는 피로를 줄임
- 플레이어가 현장실습 준비 방향을 선택
- 마지막 중요 일정 전에 저장·복귀 가능

대표 선택:

- `휴식`: 컨디션·집중 회복, 첫 피격 또는 입력 실수 안전 보정
- `현장 조사`: 환경 문제의 관찰 단서 하나 추가
- `주문 연구`: 메인·보조 조합의 비교 정보 또는 연습 기회
- `보조 소환수 훈련`: 수호 또는 견제 성능에 작은 보너스

가드레일:

- 조사나 연구를 하지 않아도 현장실습의 필수 정보는 현장에서 얻을 수 있다.
- 보너스는 선택의 의미를 만들되 특정 선택을 정답으로 만들지 않는다.

### 3.8 세션 4 — 첫 현장실습

핵심 질문:

> 배운 원리를 실제 위험과 복합 상황에서 응용하고 새 활용을 발견할 수 있는가?

내용:

```text
현장 브리핑
→ 메인 동반 소환수와 상황 관찰
→ 전투 보조 소환수 호출
→ 전투 문제 1개
→ 환경·구조 문제 1개
→ 같은 메인 글자의 다른 목적 활용
→ 실패 원인 확인·주문 재설계
→ 새로운 활용 발견
→ 귀환
```

필수 증거:

- 전투 문제와 환경·구조 문제 모두 포함
- 같은 메인 글자를 서로 다른 목적에 재사용
- 최소 두 가지 유효 해결법
- 전투 보조 소환수의 수호 또는 견제로 작성 시간 확보
- 보조 소환수 유무에 따른 작성 시간·피격·완주율 비교
- 소환수가 주문 설계와 글자 작성을 대행하지 않음

### 3.9 귀환·마도서 기록·다음 예고

내용:

```text
시험·축제·현장 결과 요약
→ 발견한 주문 활용 기록
→ 실패 원인과 다음 연구 목표 기록
→ 메인 동반 소환수의 관계 반응
→ 다음 수업·학기·전문화 가능성 예고
```

완료 감정:

- 학교에서 한 기간을 보냈다는 감각
- 배운 원리가 시험·축제·실전에서 다르게 쓰였다는 이해
- 자신의 주문 활용을 발견했다는 성취
- 다음 학기를 계속하고 싶은 기대

## 4. 자유일정 시스템 계약

### 4.1 슬롯 수

Vertical Slice에는 총 3개의 자유일정 슬롯을 둔다.

1. 수업·연습 후, 시험 전
2. 시험 후, 학교축제 전
3. 학교축제 후, 현장실습 전

### 4.2 한 슬롯의 기본 흐름

```text
현재 상태와 다음 중요 일정 확인
→ 가능한 행동 3~4개 제시
→ 행동 1개 선택
→ 짧은 플레이·대화·정리
→ 상태·관계·정보·준비 결과 저장
→ 다음 중요 일정으로 이동
```

### 4.3 선택 결과 범위

허용:

- 컨디션·집중 회복
- 작은 판정 보정
- 추가 관찰 정보
- 관계 반응
- 보조 소환수 준비
- 선택형 상세 대화
- 마도서 메모

금지:

- 필수 일정 영구 차단
- 특정 자유일정 선택만 가능한 정답
- 선택하지 않은 관계 때문에 필수 정보 누락
- 자유일정마다 독립 대형 미니게임 제작
- 모든 선택에 별도 지역·전투·장문 분기 요구
- 휴식을 선택했을 때 실질적인 손해만 발생

## 5. 시간·저장 구조

잠정 목표:

| 구간 | 목표 시간 |
|---|---:|
| 프롤로그·수업·연습 | 10~15분 |
| 자유일정 A | 3~6분 |
| 실기시험 | 8~12분 |
| 자유일정 B | 3~6분 |
| 학교축제 | 10~15분 |
| 자유일정 C | 3~6분 |
| 현장실습 | 12~18분 |
| 귀환·기록 | 3~6분 |

전체 예상은 약 52~84분이다. 정확한 시간은 `PLAYTEST_TUNING_REQUIRED`다.

필수 저장 지점:

- 각 핵심 세션 시작 전
- 각 자유일정 선택 전과 완료 후
- 현장실습 진입 전
- 현장실습 내 안전한 문제 전환 지점
- 귀환·기록 완료 후

중단 후 복귀 시 플레이어는 현재 목표, 선택한 자유일정 결과, 보유 글자, 소환수 상태를 즉시 이해할 수 있어야 한다.

## 6. 최소 콘텐츠 범위

### 포함

- 메인 글자 1개
- 보조 글자 2개
- 넓은 허용 범위의 직접 작성 템플릿
- 학교 허브 또는 재사용 가능한 학교 구역 1개
- 수업·시험·축제에 재사용 가능한 학교 장면 세트
- 현장실습 구역 1개
- 시험 문제 1개
- 축제 비전투 문제 1개
- 현장 전투 문제 1개
- 현장 환경·구조 문제 1개
- 적 1~2종
- 메인 동반 소환수 1체
- 수호 또는 견제형 전투 보조 소환수 1체
- 자유일정 슬롯 3개와 각 슬롯의 짧은 선택 3~4개
- 최종 방향에 가까운 핵심 UI·아트·사운드
- 저장·중단·복귀

### 제외

- 3년·6학기 전체
- 다수 시험 과목
- 여러 학교축제 부스와 대형 축제 맵
- 다수 현장실습 지역
- 대규모 관계 분기·연애 시스템
- 다수 보조 소환수 동시 편성
- 희귀도 경제와 복잡한 진화 트리
- 완성 주문 스톡
- 복잡한 소환수 충전·용량 관리
- 다중 상태이상과 광범위한 조합표
- 고정밀 자유 손글씨 인식
- 온라인·협동·풀보이스

## 7. Vertical Slice 통과 기준

### 7.1 핵심 마법 경험

- 첫 5분 안에 플레이어가 `내가 마법을 썼다`고 인식한다.
- 메인 글자와 보조 글자의 역할 차이를 설명할 수 있다.
- 같은 문법이 시험·축제·현장실습에서 다른 목적으로 쓰인다.
- 플레이어가 최소 두 가지 유효 해결법 중 하나를 의도적으로 선택한다.
- 입력 실패와 설계 실패를 구분하고 재설계한다.

### 7.2 학교생활 경험

- 수업은 `배움`, 시험은 `증명`, 축제는 `표현·관계`, 현장실습은 `응용·발견`으로 구분된다.
- 플레이어가 단순 현장 데모가 아니라 축약된 학교 기간을 경험했다고 인식한다.
- 자유일정이 중요 일정 사이의 휴식과 준비로 기능한다.
- 자유일정의 `휴식`이 실제로 유효한 선택으로 인식된다.
- 자유일정 선택이 다음 일정에 작은 차이를 만들지만 진행을 차단하지 않는다.

### 7.3 소환수

- 메인 동반 소환수가 학습·관계·기록을 연결한다.
- 전투 보조 소환수가 작성 시간을 확보한다.
- 두 소환수 계층의 역할을 플레이어가 구분한다.
- 어느 소환수도 주문 설계·글자 작성을 대행하지 않는다.

### 7.4 모바일 UX·기술

- 직접 작성 중 손가락 가림과 반복 피로가 핵심 행동을 방해하지 않는다.
- 완전 정지·감속·실시간 방식을 비교할 수 있다.
- 중요 일정과 자유일정 사이 저장·복귀가 안정적이다.
- 목표 Android 기기와 주요 화면비에서 플레이 가능하다.
- 소환수 명령이 주문 설계보다 큰 인지 부하를 만들지 않는다.

### 7.5 제작성

- 수업·시험·축제·현장실습이 같은 글자·문제·결과 데이터 계약을 재사용한다.
- 자유일정 선택이 공통 이벤트 구조로 제작된다.
- 대표 장면이 일회성 하드코딩에만 의존하지 않는다.
- 두 번째 유사 시험·축제 활동·현장 문제를 기존 구조로 추가할 수 있다.

정확한 정량 임계값은 적대적 검토와 구현 계획에서 `TECHNICAL_REVIEW_PROPOSAL` 및 `PLAYTEST_TUNING_REQUIRED`로 확정한다.

## 8. 실패 기준과 감량 순서

다음 중 하나라도 발생하면 콘텐츠를 확대하지 않는다.

- 직접 작성이 반복 피로나 인식 오류로 핵심 재미를 방해
- 시험·축제·현장실습이 같은 문제의 외형 변경처럼 느껴짐
- 자유일정이 보상 최적화 메뉴 또는 불필요한 대화로만 느껴짐
- 메인 동반자가 정답을 대신 제시
- 보조 소환수 운용이 주문 설계보다 복잡
- 전체 흐름이 지나치게 길어 핵심 세션 완주율이 낮음
- 저장·복귀 후 목표와 선택 결과를 이해하기 어려움
- 각 이벤트가 별도 하드코딩되어 두 번째 콘텐츠 제작이 어려움

수정 우선순위:

```text
입력 판정·시간 처리·피드백
→ 세션별 문제 역할 구분
→ 자유일정 선택 수와 결과 규모
→ 전투 압박·보조 소환수 조작량
→ 축제·관계 연출 분량
→ 전체 세션 길이
```

우선 감량:

```text
완성 주문 스톡
→ 복잡한 소환수 충전·편성
→ 자유일정별 독립 미니게임
→ 다중 상태이상
→ 장문 관계 분기
→ 축제 부스·시험 과목·현장 지역 추가
```

비타협 유지:

- 의미 기반 글자
- 직접 작성
- 상황별 조합
- 설명 가능한 세계 변화
- 수업·시험·축제·현장실습의 역할 차이
- 중요 일정 사이 자유일정 1회
- 학습→증명→표현→응용→기록 순환
