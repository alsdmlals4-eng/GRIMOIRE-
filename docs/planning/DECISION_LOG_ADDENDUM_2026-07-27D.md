## GM-CIRCUIT-09 — 보조 글자 3단계 숙련

### 채택안

```text
미숙
→ 숙련
→ 달인
```

### 확정 방향

- 보조 글자는 메인 글자처럼 Lv.0~Lv.5를 사용하지 않는다.
- `미숙`은 직접 작성으로 기능을 학습하는 단계다.
- `숙련`부터 하위 글자 스톡의 등록 후보가 된다.
- `달인`은 복합 연결 안정성·작성 효율·상위 연구에 기여한다.
- 숙련도가 높아져도 기능 글자 수와 스톡 준비 용량은 할인되지 않는다.
- 단순 반복 버튼으로 최고 등급에 도달하지 않고 수업·직접 작성·현장 활용·시험·연구를 사용한다.
- 1학년부터 핵심 기초 보조 글자 일부를 `숙련`까지 올려 자동화 성장을 체험한다.

상태: `DIRECTION_CONFIRMED`

책임 원본: `docs/planning/SUPPORT_LETTER_MASTERY_SYSTEM.md`

## GM-SUMMON-01 — 소환수의 주문 보조는 스톡 충전만 담당

### 최종 사용자 결정

```text
소환수
→ 회로·보조 글자를 직접 작성하지 않음
→ 지정한 하위 글자 또는 완성 주문 스톡의 충전만 지원
```

### 확정 방향

- 소환수는 현재 회로판에 글자·선·연결을 직접 작성하지 않는다.
- 소환수는 보조 글자 묶음을 자동 연결하지 않는다.
- 소환수의 주문 보조는 스톡 생산량·충전 속도·능동 충전 보너스로만 작동한다.
- 어떤 스톡을 충전할지는 플레이어가 지정한다.
- 소환수는 플레이어 허가 없이 충전 대상을 변경하지 않는다.
- 하위 글자 스톡이 숙련 보조 글자의 자동 배치·연결을 전담한다.
- 완성 주문 스톡은 등록 주문 전체의 즉시 기동을 담당한다.

### 폐기된 해석

`전투 전에 소환수에게 보조 묶음을 장착하고 전투 중 호출해 자동 연결한다`는 안은 사용자의 최신 정정으로 폐기한다.

상태: `REJECTED_BY_LATEST_USER_DECISION`

책임 원본: `docs/planning/SUMMON_SYSTEM.md`

## GM-COMBAT-01 — 1학년부터 스톡·소환수 충전 지원으로 간결화한 전투

### 확정 방향

```text
전투 시작
→ 기본 소환수 1체 전개

일반 직접 시전
→ 메인 글자·핵심 보조는 플레이어 직접 작성
→ 반복 숙련 보조는 하위 글자 스톡으로 삽입

긴급·반복 대응
→ 완성 주문 스톡

소환수
→ 지정 스톡의 충전·생산 지원
→ 전투·수호로 작성 시간 확보
```

- 완성 주문 스톡과 하위 글자 스톡은 1학년부터 사용할 수 있다.
- 첫 학기 안에 직접 작성·스톡·소환수 충전 지원을 모두 경험하게 한다.
- 사용자가 한 주문의 모든 보조 글자를 매번 직접 넣지 않게 한다.
- 신규 글자·상위 조합·핵심 변형은 직접 작성 영역으로 유지한다.
- 고학년의 보조 6개는 최대 설계 복잡도이며 필수 직접 입력량이 아니다.
- 소환수 지원이 없어도 직접 시전과 이미 준비된 스톡으로 전투할 수 있다.
- 스톡이 없어도 직접 시전은 가능하다.

상태: `DIRECTION_CONFIRMED`

책임 원본: `docs/planning/COMBAT_CORE_SYSTEM.md`

## 프로젝트 코어에 미치는 영향

기존 코어 문장 중 “플레이어와 동료가 여러 회로 구간을 동시에 직접 작성한다”는 표현을 다음으로 대체한다.

> 플레이어는 메인 글자와 핵심 변형을 직접 작성하고, 숙련된 반복 보조는 스톡으로 삽입하며, 소환수의 충전 지원을 지휘해 더 복잡한 주문을 빠르게 완성한다.

## DDD 적용

```text
메인·핵심 보조 직접 작성
→ 하위 글자 스톡으로 반복 보조 즉시 삽입
→ 주문 결과 변화 확인
→ 소환수가 다음 지정 스톡 충전
→ 전투 피드백
→ 숙련·충전·성장 보상
```

- DDD는 전투를 자동화하는 것이 아니라 핵심 판단과 결과 사이의 반복 입력을 줄이는 데 사용한다.
- 자동화가 늘어날수록 플레이어는 새로운 글자·즉석 변형·대상·발동 시점·충전 우선순위에 집중한다.
