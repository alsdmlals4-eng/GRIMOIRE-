## 1. 채택안

소환수 주문 보조는 **전투 전에 준비한 보조 글자 또는 보조 묶음을 전투 중 원터치로 호출하는 방식**을 사용한다.

```text
전투 전
→ 소환수 선택
→ 소환수에게 숙련 보조 글자 묶음 설정

전투 중
→ 플레이어가 메인 글자 또는 주문 골격 작성
→ 소환수 보조 호출
→ 준비된 보조 묶음 자동 배치·연결
→ 플레이어가 대상·추가 변형·최종 기동 결정
```

- 소환수 AI가 임의로 보조 글자를 선택하지 않는다.
- 호환되는 모든 주문에 고정 보조가 강제 적용되지 않는다.
- 사용 여부와 시점은 플레이어가 결정한다.
- 같은 메인 글자를 다른 목적으로 사용하는 자유를 유지한다.

## 2. 목적

1. 모바일에서 다수 보조 글자를 매번 직접 작성하는 부담을 줄인다.
2. 소환수를 단순 자동 공격원이 아니라 주문 운용 동반자로 만든다.
3. 플레이어가 주문의 의미와 핵심 판단을 계속 소유하게 한다.
4. 스톡과 다른 재사용형 자동화 수단을 제공한다.
5. 1학년부터 `메인 1 + 보조 2` 조합을 간결하게 경험하게 한다.

## 3. 플레이어와 소환수의 책임

### 플레이어

- 사용할 메인 글자와 주문 목적 선택
- 목표·방향·발동 시점 판단
- 직접 작성할 핵심 보조 선택
- 소환수 보조 호출 여부와 시점 결정
- 필요하면 하위 글자 스톡 추가
- 최종 회로 연결·기동 확인

### 소환수

- 전투 전에 설정된 보조 묶음을 기억
- 호출 시 현재 주문 골격과의 호환성 확인
- 호환되는 위치에 보조 글자 자동 배치·연결
- 지원 행동 중 짧은 연출과 명확한 피드백 제공
- 지원 능력에 따라 재사용 효율·안정성·연결 품질에 기여

소환수는 플레이어의 허가 없이 주문 목표나 메인 글자를 변경하지 않는다.

## 4. 보조 묶음 등록 조건

- 플레이어가 습득하지 않은 보조 글자는 등록할 수 없다.
- 기본적으로 `숙련` 이상인 보조 글자만 등록할 수 있다.
- `달인` 보조 글자는 복합 묶음·상위 조건 구조에서 추가 안정성 후보가 된다.
- 등록한 묶음은 전투 전에 확인·교체할 수 있다.
- 정확한 묶음 수, 묶음당 글자 수와 동시 장착 수는 후속 데이터 설계에서 확정한다.

## 5. 스톡과의 역할 구분

| 수단 | 사용 성격 | 주요 용도 |
|---|---|---|
| 소환수 보조 묶음 | 재사용형 지원 행동 | 반복되는 보조 조합을 한 번에 연결 |
| 하위 글자 스톡 | 소비·충전형 개별 삽입 | 현재 필요한 숙련 글자 하나를 유연하게 추가 |
| 완성 주문 스톡 | 소비·충전형 전체 발동 | 자주 쓰는 등록 주문을 즉시 사용 |

```text
소환수 보조
→ 반복 조합의 재사용형 압축

하위 글자 스톡
→ 상황 대응용 개별 글자

완성 주문 스톡
→ 즉시 전투 대응용 완성 주문
```

소환수 보조 묶음은 공용 스톡 준비 용량을 소비하지 않는다. 대신 소환수의 지원 행동 자원·재사용 대기·현재 스탠스와 연결하는 방향을 우선한다. 정확한 시간과 자원은 `PLAYTEST_TUNING_REQUIRED`다.

## 6. 기본 전투 예시

### 화염탄

```text
플레이어
→ 불꽃 메인 작성

소환수 보조 묶음
→ 투사체 + 발사 자동 연결

플레이어
→ 대상 선택·기동
```

### 변형 화염탄

```text
플레이어
→ 불꽃 메인 작성

소환수
→ 투사체 + 발사 지원

하위 글자 스톡
→ 분열 삽입

플레이어
→ 최종 연결·기동
```

### 긴급 대응

```text
적의 강한 공격 예고
→ 완성 보호 주문 스톡 즉시 사용
→ 소환수는 플레이어 수호 또는 다음 보조 묶음 준비
```

## 7. 1학년 적용

- 기본 소환수 1체를 전투 시작 전에 전개한다.
- 1학년 초반 공통 문법 수업에서 보조 묶음 설정과 호출을 배운다.
- 핵심 기초 보조 글자 두 개가 숙련되면 첫 묶음을 구성할 수 있다.
- 최초 묶음은 `형상 + 전달`처럼 결과가 즉시 이해되는 조합이 적합하다.
- 같은 시기에 기본 하위 글자 스톡과 완성 주문 스톡도 소개한다.

1학년을 긴 직접 입력 튜토리얼로 만들지 않고, 첫 학기 안에 `직접 작성 + 소환수 보조 + 스톡` 세 축을 경험하게 한다.

## 8. 제한과 실패

보조 호출이 불가능한 후보 상황:

- 현재 메인 글자와 보조 묶음이 구조적으로 호환되지 않음
- 소환수가 봉인·행동 불능·지원 자원 부족 상태
- 현재 회로판에 연결 공간 또는 합법적인 연결점이 없음
- 플레이어가 아직 해당 보조 글자를 숙련하지 않음

실패 시:

- 스킬을 조용히 소비하지 않는다.
- 호환 불가 이유를 짧은 아이콘·회로 강조로 알린다.
- 플레이어가 직접 작성하거나 하위 글자 스톡을 사용할 수 있게 한다.
- 잘못된 묶음 때문에 메인 글자와 기존 회로 전체가 삭제되지 않게 한다.

## 9. DDD·피드백

```text
메인 글자 작성
→ 소환수 호출
→ 보조 글자가 즉시 전개되는 시각 피드백
→ 주문 형태 변화 확인
→ 기동·타격·방어 결과
→ 스톡 충전·숙련·관계 보상
```

- 호출과 결과 사이 지연을 짧게 유지한다.
- 소환수별 고유 연출은 읽기 쉬운 실루엣과 효과로 구분한다.
- 자동 연결된 글자를 플레이어가 직접 작성한 글자와 시각적으로 구분할 수 있게 한다.
- 소환수 보조가 발동했는지, 왜 실패했는지 즉시 이해할 수 있어야 한다.

## 10. 가드레일

- 소환수가 상황을 판단해 주문을 임의로 완성하지 않는다.
- 소환수 보조만 반복하는 것이 최적이 되지 않게 한다.
- 보조 묶음이 미습득·미숙 글자를 우회 제공하지 않는다.
- 소환수 보조가 하위 글자 스톡과 완전히 같은 기능·자원을 사용하지 않는다.
- 모든 보조 묶음을 전투 중 복잡한 메뉴에서 다시 편집하게 하지 않는다.
- 자동 연결 때문에 주문 결과를 예측할 수 없게 만들지 않는다.
- 지원 실패로 기존 회로 진행도를 전부 잃게 하지 않는다.

## 11. 추후 결정

- 소환수 한 체가 장착하는 보조 묶음 수
- 묶음당 보조 글자 수와 학년·성장에 따른 확장
- 지원 행동의 재사용 대기·자원·스탠스 상호작용
- 여러 연결 후보가 있을 때 자동 위치 선택 규칙
- 호출 후 취소·되돌리기 방식
- 소환수별 계열 적성과 보조 묶음 효율
- 주문 봉인·마력 봉쇄와 소환수 보조의 관계
