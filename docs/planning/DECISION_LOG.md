## 핵심 확정 상세

### 회로 자동화와 직접 입력

- 초반에는 기초 회로를 직접 그린다.
- 숙달한 메인과 형상·전달은 자동화할 수 있다.
- 이후 보조 회로와 조건·기동 회로를 단계적으로 해금한다.
- 자동화는 직접 그리기의 제거가 아니라 새 문법과 중요한 판단에 집중하기 위한 성장 기능이다.

### 집중 모드와 회로 판정

- 회로 입력 중 전투는 완전히 정지하지 않고 감속된다.
- 모바일 입력을 고려해 성공 판정 기준을 널널하게 설정한다.
- 부정확 패널티는 낮게 유지한다.
- 정확 입력에는 표현과 손맛을 우선한 추가 보상을 제공한다.

### 주문 발견과 회로 문법

- 주문은 직접 조합해 처음 발견한 뒤 마도서 설계도로 등록한다.
- 한 주문의 메인 회로는 정확히 하나이며 복수 메인 결합을 금지한다.
- 초반 최소 주문은 `메인 + 형상·전달`이다.
- 보조 회로는 이후 단계적으로 추가한다.
- 중반에는 조건·기동 회로를 해금한다.

### 마나 시스템

- 마나는 천천히 자동 회복된다.
- 정확 입력, 방어·반격, 주문 연계에는 추가 회복 또는 환급을 제공할 수 있다.
- 마나 회복 메인과 마나 절감 보조를 추가한다.
- 회복·절감 회로로 순마나가 무한 증가하는 구조를 금지한다.

### 소환수 시스템

- 기존 동료를 소환수 같은 마법적 존재로 대체한다.
- 소환수 역할 타입은 없고 능력치·적성·스탠스로 효율을 결정한다.
- 기본 소환수 1체를 전투 전에 준비해 소환 상태로 시작한다.
- 소환수는 전투 보호, 회로 자동작성, 협동 시전, 자동스펠 충전을 보조한다.
- 추가 편성, 교체, 동시 전개 수는 아직 미확정이다.

### 자동스펠과 스톡

- 자동스펠은 원터치와 조건부 발동을 함께 사용하는 혼합형이다.
- 스톡은 미리 지정한 자동스펠 주문의 준비된 사용 횟수다.
- 같은 주문에 여러 스톡을 준비하거나 여러 주문에 분산할 수 있다.
- 플레이어 성장에 따라 전체 스톡 준비 한도가 증가한다.
- 스톡이 없어도 직접 회로 시전은 가능하다.
- 스톡 한 칸당 해당 주문 기존 마나 비용 50%를 최대 마나에서 예약한다.
- 스톡 편성 중 예약 마나는 잠기고 빈 스톡이 되어도 유지된다.
- 전투 중 지정 주문은 자동 충전된다.
- 자동 충전 속도는 플레이어와 소환수 능력치에 비례한다.
- 직접 시전, 정확 입력, 방어·연계, 소환수 지원은 충전을 추가 가속한다.
- 상세 최신 규칙은 `STOCK_SYSTEM.md`와 결정 추가 기록을 따른다.

## 운영 규칙

1. 사용자의 최신 지시가 이전 결정에 우선한다.
2. 변경된 결정은 삭제하지 않고 `SUPERSEDED`, `LATEST_OVERRIDE`, `TRANSFERRED` 상태로 기록한다.
3. 핵심 결정이 추가되거나 기존 결정이 변경되면 책임 원본과 Active Context를 함께 갱신한다.
4. 방향 확정과 세부 목록·수치 확정을 구분한다.
5. 테스트 전 수치를 확정하지 않는다. 단, 사용자가 명시적으로 확정한 50% 예약 비율은 확정 방향으로 기록한다.
6. 구현 파일은 현재 기획 브랜치에 포함하지 않는다.
7. 사용자가 프로젝트 코어를 승인하기 전 `CORE_CONFIRMED`를 사용하지 않는다.
8. 현재 단계에서는 Codex를 실행하지 않는다.
9. 외부 작품은 구조를 참고하되 용어·데이터·고유 분류를 직접 복제하지 않는다.
