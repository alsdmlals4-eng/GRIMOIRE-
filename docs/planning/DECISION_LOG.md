## 핵심 결정 상세

### 자동화와 스톡

- 조건부 자동발동은 사용하지 않는다.
- 완성 주문 스톡은 저장 주문 전체를 원터치로 기동한다.
- 하위 회로 스톡은 숙련 회로 한 구간을 자동 배치·연결한다.
- 스톡은 공용 준비 용량만 사용하며 마나를 소비·예약하지 않는다.
- 자동 충전 대상은 한 번에 1종이다.

### 소환수

- 전투·수호·지정 스톡 생산 지원을 담당한다.
- 회로 직접 작성·협동 작성은 `SUPERSEDED`다.
- 플레이어 허가 없이 충전 대상을 변경하지 않는다.

### 충전과 전환

- 기준 충전시간은 `1.0 + 0.5 × (회로 수 - 1)`이다.
- 충전 대상 변경 시 대상별 진행도를 보존한다.
- 전환 지연 동안 모든 충전을 정지한다.

### 직접 피해에 따른 일시정지

```text
r = 0.25초 직접 피해 체력 손실 합계 / 집계 시작 시 최대 체력
정지시간 = clamp(r × 3.0, 0.10초, 0.80초)
```

- 최종 직접 피해가 0이면 정지하지 않는다.
- 같은 총 직접 피해라면 타격 수와 무관하게 같은 정지시간을 목표로 한다.
- 진행도는 전부 보존하고 자동 재개한다.

### 지속 피해와 상태이상

```text
지속 피해 틱
→ 체력 감소
→ 스톡 충전·전환 정지 없음

마력 교란
→ 충전 속도 감소
→ 진행도·대상·완성 스톡 사용 유지

주문 봉인
→ 완성 주문·하위 회로 스톡 사용 불가
→ 자동 충전·대상 전환·보유량 유지
```

- 회로 혼선과 상태이상 기반 전환 방해는 사용하지 않는다.
- 주문 봉인 중에도 충전은 계속되며 봉인 해제 후 즉시 사용 가능하다.
- 상태이상으로 충전 진행도나 보유 스톡을 삭제하지 않는다.

## 운영 규칙

1. 사용자의 최신 지시가 이전 결정에 우선한다.
2. 변경 결정은 삭제하지 않고 `SUPERSEDED`, `LATEST_OVERRIDE`, `TRANSFERRED`로 기록한다.
3. 핵심 결정 변경 시 책임 원본·결정 원장·Active Context를 함께 갱신한다.
4. 방향 확정과 세부 수치 확정을 구분한다.
5. 구현 파일은 현재 기획 브랜치에 포함하지 않는다.
6. 사용자 승인 전 `CORE_CONFIRMED`를 사용하지 않는다.
7. 현재 단계에서는 Codex를 실행하지 않는다.
