## 최신 결정 상세

### GM-00-01 — 회로 자동화와 수동 입력

- 초반에는 기초 회로를 직접 그린다.
- 숙달한 기초 회로는 이후 자동화할 수 있다.
- 자동화 이후 플레이어는 중급 회로, 연결 회로, 상위 조합 주문에 집중한다.
- 자동화는 직접 그리기의 제거가 아니라 더 복잡한 입력으로의 승격이다.

### GM-00-02 — 집중 모드

- 회로 입력 중 전투 시간은 완전히 정지하지 않는다.
- 적 공격 타이머와 전투가 감속된다.
- 정확한 배율은 PoC에서 검증한다.
- 무한 감속 악용을 방지해야 한다.

### GM-00-03 — 동료 구조

#### 폐기된 이전안

- 전투형, 기초 회로형, 협동 주문형 등 고정 타입으로 역할을 나누는 방식

상태: `SUPERSEDED`

#### 현행안

- 동료에게 고정 타입을 부여하지 않는다.
- 모든 동료는 공격, 수호, 회로 작성, 협동 주문을 원칙적으로 수행할 수 있다.
- 능력치에 따라 각 행동의 효율과 담당 가능한 회로 난도가 달라진다.
- 플레이어가 전투 중 스탠스를 지정해 행동 우선순위를 결정한다.
- 상위 조합 주문 작성 중 동료가 처리 가능한 미완성 구간을 선택해 대신 그린다.
- 동료 성장에 따라 자동완성 대기시간과 작성시간이 단축된다.
- 최종 주문 선택과 기동은 플레이어 책임으로 유지한다.

### GM-00-04 — 주문 발견

- 미발견 주문은 플레이어가 회로를 조합해 직접 실험한다.
- 유효한 주문을 처음 완성하면 마도서에 설계도로 등록된다.
- 등록 후 목표 주문으로 지정할 수 있다.
- 숙련 후 반복 회로 자동화와 동료 보조를 사용할 수 있다.

### GM-00-05 — 스탠스 변경

- 전투 중 스탠스 변경 명령을 허용한다.
- 즉시 모든 역할을 수행하는 방식은 허용하지 않는다.
- 현재 행동이나 회로 작업을 정리한 뒤 새 스탠스로 전환한다.
- 짧은 전환 시간 또는 재지정 대기시간을 적용한다.
- 긴급 전환 시 현재 회로 작업 중단과 플레이어 인계 구조를 검토한다.

## 운영 규칙

1. 사용자의 최신 지시가 이전 결정에 우선한다.
2. 변경된 결정은 삭제하지 않고 `SUPERSEDED` 또는 `LATEST_OVERRIDE`로 기록한다.
3. 핵심 결정이 추가되거나 기존 결정이 변경되면 이 파일과 책임 원본을 함께 갱신한다.
4. 수치와 세부 규칙은 테스트 전 확정하지 않는다.
5. 구현 파일은 현재 기획 브랜치에 포함하지 않는다.
6. 사용자가 프로젝트 코어를 승인하기 전 `CORE_CONFIRMED`를 사용하지 않는다.
7. 현재 단계에서는 Codex를 실행하지 않는다.
