## 핵심 결정 상세

### 회로 입력과 자동화

- 초반에는 `메인 + 형상·전달`을 직접 그린다.
- 한 주문에는 메인 회로를 정확히 하나만 사용한다.
- 보조 회로와 조건·기동 회로는 단계적으로 해금한다.
- 미발견·미숙련·현재 성장 단계의 신규 회로는 자동화하지 않는다.
- 성장 기준 이하의 숙련 회로는 하위 회로 스톡으로 준비한다.
- 완성 주문 스톡은 저장 주문 전체를 원터치로 기동한다.
- 조건부 자동발동은 사용하지 않는다.

### 소환수 최신 역할

- 전투와 적 방해
- 플레이어 수호와 회로 작성 시간 확보
- 지정 스톡 생산량·충전 속도 증가
- 능동 충전 보너스 강화
- 능력치·적성·스탠스에 따른 효율 차이

소환수의 회로 직접 작성·동시 작성·보조 회로 자동작성은 `SUPERSEDED`다.

### 마나와 스톡

- 마나는 직접 회로 시전에만 적용한다.
- 스톡 준비·발동·적용·충전에는 마나를 사용하지 않는다.
- 두 스톡은 회로 수 기반 공용 준비 용량을 공유한다.
- 지정 대상 1종만 자동 충전한다.
- 플레이어와 소환수 능력치가 충전 효율에 기여한다.
- 직접 시전·정확 입력·방어·연계는 충전을 추가 가속한다.

### 충전시간과 대상 전환

- 기준 충전시간은 `1.0 + 0.5 × (회로 수 - 1)`이다.
- 충전 대상은 전투 중 변경할 수 있다.
- 대상별 다음 스톡 진행도를 보존한다.
- 대상 변경 시 전환 지연 동안 충전을 정지한다.
- 완료 후 새 대상의 저장 진행도부터 자동 재개한다.

### 실제 체력 피해 시 처리

- 최종 체력 피해가 0이면 충전과 전환을 정지하지 않는다.
- 실제 체력 피해가 발생해도 충전·전환 진행도는 전부 보존한다.
- 정지시간은 타격 횟수가 아니라 짧은 피해 집계 구간의 총 실제 체력 손실로 정한다.
- 절대 체력값이 아니라 최대 체력 대비 손실 비율을 사용한다.
- 같은 총 손실이라면 단발 강타와 다단 공격은 같은 정지시간을 목표로 한다.
- 정지 종료 후 별도 입력 없이 자동 재개한다.

PoC 권장식은 아직 잠정이다.

```text
r = 집계 구간 실제 체력 손실 합계 / 집계 시작 시 최대 체력
정지시간 = clamp(r × 3.0, 0.10초, 0.80초)
피해 집계 구간 = 0.25초
```

## 운영 규칙

1. 사용자의 최신 지시가 이전 결정에 우선한다.
2. 변경 결정은 삭제하지 않고 `SUPERSEDED`, `LATEST_OVERRIDE`, `TRANSFERRED`로 기록한다.
3. 핵심 결정 변경 시 책임 원본·결정 원장·Active Context를 함께 갱신한다.
4. 방향 확정과 세부 수치 확정을 구분한다.
5. 사용자 승인 전 PoC 권장 수치를 확정값으로 기록하지 않는다.
6. 구현 파일은 현재 기획 브랜치에 포함하지 않는다.
7. 사용자 승인 전 `CORE_CONFIRMED`를 사용하지 않는다.
8. 현재 단계에서는 Codex를 실행하지 않는다.
