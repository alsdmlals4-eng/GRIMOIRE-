# 스펠 Gate 1 벤치마킹·SWOT·VRIO·1인 제작성

## 문서 상태

- 프로젝트: `스펠` (임시)
- 제품 단계: `CONCEPT_APPROVAL`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- Work Mode: `PLAN`
- 결정 ID: `GM-BENCHMARK-01`
- 상태: `BENCHMARK_FRAMEWORK_CONFIRMED_RESEARCH_AUTHORED`
- 사용자 승인: 2026-07-27, `권장안대로`
- 조사 기준일: 2026-07-27
- 상위 세일즈포인트: `GM-SALES-01`
- 프로젝트 코어 전체: `CORE_CANDIDATE`
- Gate 1 전체: `UNVERIFIED`
- 구현 상태: `NOT_STARTED`

이 문서는 확정된 세일즈포인트 3개를 경쟁군과 비교하고, `SWOT`, `VRIO`, 모바일·Godot·1인 개발 제작성 판단으로 연결한다.

> 벤치마크는 외부 작품의 고유 규칙·세계관·콘텐츠를 복제하기 위한 목록이 아니다. 스펠의 가설을 반증하고, 채택·변형·회피할 설계 원칙을 찾기 위한 비교 증거다.

## 1. 확정된 벤치마크 분류

### A. 직접 입력·마법 조작군

검증 질문:

- 손으로 쓰는 입력이 실제 마법 사용자 판타지를 만드는가?
- 입력 판정 실패와 반복 피로를 어떻게 줄이는가?
- 손가락·펜·마우스 입력과 세계 변화가 즉시 연결되는가?
- 실시간 압박 중 입력이 재미를 만드는가, 조작 부담을 만드는가?

주요 작품:

- `Magic Touch: Wizard for Hire`
- `LOSTMAGIC`
- `Arx Fatalis`
- `Ōkami HD`

### B. 조합·시스템 문제 해결군

검증 질문:

- 적은 구성 요소로 다양한 결과를 만들 수 있는가?
- 조합 규칙이 의미와 인과로 이해되는가?
- 복수의 유효한 해결법이 존재하는가?
- 전투와 환경 문제에 같은 문법을 적용할 수 있는가?
- 숨은 규칙과 예외가 플레이어의 발견을 방해하지 않는가?

주요 작품:

- `Magicka` / `Magicka 2`
- `Noita`
- `Mages of Mystralia`
- `Opus Magnum`

### C. 마법학교·학습 성장군

검증 질문:

- 수업이 튜토리얼 반복이 아니라 장기 성장 콘텐츠가 되는가?
- 배운 지식이 실전과 생활 문제로 이전되는가?
- 관계·일상·학교 공간이 핵심 플레이에 영향을 주는가?
- 학교생활 콘텐츠가 1인 개발 범위를 초과하지 않는가?

주요 작품:

- `Ikenfell`
- `Spells & Secrets`
- `Witchbrook` — 2026 출시 예정, 시장 기대와 방향 검증용

## 2. A군 분석 — 직접 입력·마법 조작

### 2.1 Magic Touch: Wizard for Hire

공식 스토어 설명은 손가락으로 화면에 모양을 그리고 풍선의 모양과 일치시키는 직관적 제스처 인식 게임플레이를 핵심으로 제시한다. Google Play 페이지는 1,000만+ 다운로드를 표시한다.

Spell에 주는 증거:

- 모바일에서 `손가락으로 마법을 그린다`는 훅은 즉시 이해 가능하다.
- 짧고 구별되는 심볼은 높은 반복성과 빠른 판정을 제공한다.
- 입력과 결과의 거리가 짧을수록 손맛이 강하다.

한계:

- 심볼을 맞추는 행위 자체가 핵심이며, 의미 기반 주문 설계나 상황 해석은 약하다.
- 스펠이 직접 작성만 강조하면 같은 방식의 단순 필기·반응 게임으로 오해될 수 있다.

판정:

- `ADOPT`: 짧은 심볼, 넓은 인식 허용, 즉시 결과
- `AVOID`: 모양 맞추기 자체를 장기 코어로 사용

### 2.2 LOSTMAGIC

Nintendo 공식 페이지는 터치스크린에 심볼을 그려 주문을 사용하고, 최대 세 주문을 결합하며, 실시간으로 유닛을 조작하는 구조를 설명한다.

Spell에 주는 증거:

- 직접 작성과 제한된 조합을 모바일·터치 환경에서 함께 사용할 수 있다.
- 조합 수를 제한하면 결과 가독성과 학습 가능성을 유지할 수 있다.

한계:

- 실시간 전투, 유닛 조작, 심볼 작성, 조합 판단을 동시에 처리하면 인지 부하가 급격히 커질 수 있다.
- `최대 3개 결합` 같은 수량 제한만으로 의미 기반 설계가 자동 확보되지는 않는다.

판정:

- `ADOPT`: 직접 작성 + 제한 조합
- `ADAPT`: 유닛 조작은 소환수의 단순 지원으로 축소
- `AVOID`: 이동·대상·소환수·주문 작성을 동시 수동 조작

### 2.3 Arx Fatalis

Steam 공식 페이지는 마우스로 공중에 룬을 그리고 제스처를 결합해 50개 주문을 사용하는 시스템을 설명한다.

Spell에 주는 증거:

- 마법을 버튼이 아니라 손동작으로 완성하는 행위는 강한 역할 체현을 만든다.
- 여러 룬을 순서대로 연결하면 주문을 외우고 익힌다는 판타지가 생긴다.

한계:

- 긴 룬 순서와 다수 주문 암기는 모바일 반복 플레이에 부적합하다.
- 엄격한 인식과 기억 실패는 `설계 실패`가 아니라 `입력 실패`로 체감될 수 있다.

판정:

- `ADOPT`: 신규·중요 글자의 직접 작성
- `AVOID`: 긴 룬 문자열 암기, 입력 실패가 전투 실패를 지배하는 구조

### 2.4 Ōkami HD

Capcom 공식 페이지는 13개의 Celestial Brush 기술을 습득하고 붓질로 세계를 회복·변화시키는 플레이를 강조한다.

Spell에 주는 증거:

- 작성 모드에서 전투·세계가 잠시 정리되면 플레이어가 입력과 결과에 집중할 수 있다.
- 그린 선이 환경 변화로 직접 이어질 때 `내가 세계를 바꿨다`는 인과가 매우 선명하다.

한계:

- 기술 수와 입력 패턴이 고정되어 조합 발견보다 도구 선택에 가깝다.

판정:

- `ADOPT`: 집중 모드, 입력 직후 환경 변화
- `ADAPT`: 고정 도구 선택을 메인·보조 의미 조합으로 확장

### A군 결론

```text
직접 작성은 강한 첫인상과 역할 체현을 만든다.
그러나 장기 재미는 작성 모양 자체가 아니라
작성한 의미 단위가 상황과 조합에 따라 다른 결과를 만드는 데서 나와야 한다.
```

필수 설계 규칙:

- 글자는 짧고 시각적으로 구분 가능해야 한다.
- 초기 판정은 성공 중심으로 넓게 설정한다.
- 입력 실패와 설계 실패를 피드백에서 구분한다.
- 작성 중 완전 정지·감속·안전 구간을 비교 테스트한다.
- 플레이어의 손가락이 결과·적·조합 정보를 가리지 않게 한다.

## 3. B군 분석 — 조합·시스템 문제 해결

### 3.1 Magicka / Magicka 2

Paradox 공식 페이지는 원소를 결합하는 동적 주문 시스템을 핵심으로 설명하며, Magicka 2는 한 번에 최대 다섯 원소 결합과 다양한 실험을 제시한다.

Spell에 주는 증거:

- 적은 수의 재료가 문맥과 순서에 따라 많은 결과를 만들 수 있다.
- 원소·환경·상태의 상호작용은 즉흥적 해결과 사고를 유도한다.

한계:

- 실시간 입력, 조합, 조준, 이동, 아군 피해를 동시에 처리하는 구조는 모바일 단독 플레이에 과도하다.
- 복수 핵심 원소 결합은 스펠의 `메인 글자 하나` 원칙과 결과 가독성을 해칠 수 있다.

판정:

- `ADOPT`: 적은 의미 단위의 문맥별 재사용
- `ADAPT`: 메인 하나 + 보조 변형
- `AVOID`: 복수 메인과 고속 동시 입력

### 3.2 Noita

공식 페이지는 모든 픽셀이 물리적으로 시뮬레이션되는 세계에서 플레이어가 직접 만든 주문으로 태우고, 녹이고, 얼리고, 증발시키며 환경을 조작한다고 설명한다.

Spell에 주는 증거:

- 주문 결과가 적뿐 아니라 환경과 물질에 작동할 때 발견의 깊이가 커진다.
- 같은 주문 구성도 주변 물질·공간·위험에 따라 다른 결과를 낸다.
- 플레이어 지식이 다음 시도에 축적되는 구조가 강하다.

한계:

- 방대한 주문 수, 완드 속성, 순서, 숨은 상호작용은 높은 외부 지식 의존을 만든다.
- 실패 원인이 불명확하면 의미 기반 발견이 아니라 시행착오와 위키 학습으로 이동한다.

판정:

- `ADOPT`: 물질·환경 반응과 결과 기반 학습
- `ADAPT`: 숨은 규칙을 명시적 의미·미리보기·실패 설명으로 전환
- `AVOID`: 예외와 외부 지식이 핵심 숙련을 지배

### 3.3 Mages of Mystralia

공식 Steam 설명은 마법 속성을 가진 룬을 결합해 새 주문을 만들고, 같은 주문 제작 시스템으로 전투·환경 퍼즐·보스를 해결하는 구조를 설명한다.

Spell에 주는 증거:

- 전투와 탐색에 같은 주문 문법을 적용할 수 있다.
- 적은 기본 효과에 보조 변형을 추가하는 구조는 스펠의 메인·보조 문법과 가깝다.
- 새로운 룬 획득이 단순 수치 상승보다 해결 가능성 확장으로 작동한다.

한계:

- 조합 수를 마케팅상 크게 강조하면 실제 유효 조합과 의미 있는 선택의 밀도가 흐려질 수 있다.

판정:

- `ADOPT`: 공통 문법으로 전투·환경 문제 해결
- `AVOID`: 조합 총수 자체를 콘텐츠 가치로 과장

### 3.4 Opus Magnum

Zachtronics 공식 페이지는 여러 부품으로 기계를 설계해 동일한 문제를 다양한 방식으로 해결하고, 단순성·속도·크기를 비교하는 개방형 퍼즐 구조를 설명한다.

Spell에 주는 증거:

- 하나의 정답보다 복수의 유효한 해결법을 인정할 수 있다.
- 해결 후 결과를 비교하고 개선하는 과정 자체가 장기 동기가 된다.
- 플레이어가 만든 결과물을 저장·공유·재검토하는 기록 UX의 가치가 크다.

한계:

- 완전한 개방형 설계와 최적화 경쟁은 모바일 10~15분 RPG 세션의 속도와 다를 수 있다.
- 전투 중에 동일한 수준의 설계 자유를 요구하면 흐름이 정지한다.

판정:

- `ADOPT`: 복수 해법, 해결 후 비교, 기록과 개선
- `ADAPT`: 짧은 상황 안에서 제한된 조합으로 압축
- `AVOID`: 모든 전투를 장시간 공학 퍼즐로 전환

### B군 결론

```text
스펠의 장기 재미는 조합 개수보다
의미가 명확한 소수 글자와 상황 반응의 조합 밀도에서 만들어야 한다.
```

필수 설계 규칙:

- 메인·보조의 역할과 적용 범위를 명시한다.
- 조합 전 예상 결과를 완전 정답이 아닌 방향성으로 보여준다.
- 성공·부분 성공·실패 원인을 결과 화면과 마도서에 기록한다.
- 전투·구조·탐색·복구에 같은 문법을 사용한다.
- 최소 두 가지 이상의 유효 해결법을 대표 문제에 설계한다.

## 4. C군 분석 — 마법학교·학습 성장

### 4.1 Ikenfell

Steam 공식 페이지는 마법학교를 탐험하는 학생 집단, 관계 중심 이야기, 타이밍 기반 주문 전투를 핵심으로 설명한다.

Spell에 주는 증거:

- 학교의 교실·기숙사·연구실·정원 같은 공간을 수업·관계·사건에 반복 사용할 수 있다.
- 소수의 반복 등장 학생이 장기 감정선을 만든다.
- 전투 시스템의 명확한 접근성 옵션과 타이밍 보조는 모바일 입력 허용 설계에 참고 가치가 있다.

한계:

- 주문은 캐릭터별 기술 목록이며, 수업에서 원리를 배워 직접 설계하는 구조는 아니다.
- 학교와 관계가 강해도 스펠의 주문 설계 코어를 자동으로 증명하지 않는다.

판정:

- `ADOPT`: 밀도 높은 학교 공간 재사용, 소수 핵심 관계
- `AVOID`: 학교 이야기의 양으로 마법 설계 부족을 보완

### 4.2 Spells & Secrets

공식 페이지는 마법학교를 탐험하며 주문을 창의적으로 사용해 적과 퍼즐을 해결하는 로그라이트 구조를 설명한다.

Spell에 주는 증거:

- 학교 공간과 반복 가능한 전투·퍼즐 세션을 결합할 수 있다.
- 주문을 적뿐 아니라 환경과 미스터리에 사용하는 방향은 스펠과 가깝다.
- 한 학교를 변화하는 반복 공간으로 사용하면 지역 제작량을 줄일 수 있다.

한계:

- 로그라이트 반복과 액션 주문 사용이 수업→원리 이해→새 활용 발견의 학습 순환을 자동 보장하지 않는다.
- 3D, 로컬 협동, 캐릭터 커스터마이징, 다중 플랫폼 규모는 1인 모바일 개발의 직접 기준이 아니다.

판정:

- `ADOPT`: 학교 공간 재사용, 주문의 전투·퍼즐 양면성
- `AVOID`: 협동·3D·대규모 커스터마이징을 초기 범위에 포함

### 4.3 Witchbrook

공식 사이트는 2026년 출시 예정인 마법학교 생활 시뮬레이션·소셜 RPG로, 수업, 실용 마법, 직업, 관계, 계절 활동, 졸업과 그 이후를 제시한다. 2026년 6월 개발 블로그는 학생 생활과 학업·생활비·관계·공동체 활동을 연결하는 방향을 설명한다.

Spell에 주는 증거:

- 2026년 시장에서 마법학교 생활·관계·실용 마법에 대한 기대가 계속 존재한다.
- 수업 지식을 지역사회 문제와 생활 활동에 적용하는 `실용 교육` 방향은 스펠의 학습→현장 적용과 호환된다.

한계:

- 출시 전 작품이므로 실제 유지율·학습 재미·콘텐츠 소모 속도의 증거로 사용할 수 없다.
- 도시, 직업, 로맨스, 계절, 주거, 정원, 4인 플레이를 함께 제공하는 범위는 1인 개발 기준에서 직접 모방 불가하다.

판정:

- `MARKET_SIGNAL`: 마법학교·생활·관계 수요
- `ADAPT`: 실용 수업을 짧은 현장실습으로 압축
- `AVOID`: 도시 생활 시뮬레이션 전체를 코어 검증 전에 제작

### C군 결론

```text
마법학교는 강한 장기 프레임이지만,
학교 콘텐츠의 양이 아니라 배운 원리가 다음 실습의 해결법을 바꾸는지가 핵심이다.
```

필수 설계 규칙:

- 수업은 설명·해금 메뉴가 아니라 바로 사용해 보는 플레이 세션이다.
- 일상·관계는 실습의 정보·동행·관점·후속 반응에 연결한다.
- 학교 장소와 인물을 반복 활용해 콘텐츠 밀도를 높인다.
- 출시 전 시장 기대작은 수요 신호로만 사용하고 성공 사례로 간주하지 않는다.
- 3년·6학기, 대도시, 다수 관계 분기는 CORE_POC 이후 결정한다.

## 5. 통합 경쟁군 판정

이번 검토군에서 다음 세 항목을 동시에 중심 코어로 제공하는 단일 작품은 확인하지 못했다.

```text
손으로 직접 쓰는 마법
+
의미 기반 메인·보조 조합과 상황 반응
+
수업에서 배우고 현장실습에서 발견하는 장기 순환
```

부분적으로 가까운 작품:

- `LOSTMAGIC`: 직접 입력 + 제한 조합 + 실시간 전투
- `Mages of Mystralia`: 조합 + 전투·환경 공통 문법
- `Spells & Secrets`: 마법학교 + 창의적 주문 활용
- `Witchbrook`: 마법학교 생활 + 실용 학습 시장 기대

판정:

- 결합 자체는 `RARE_IN_REVIEWED_SET`이다.
- 시장 가치와 장기 재미는 `UNPROVEN`이다.
- 희소성만으로 성공을 주장하지 않는다.

## 6. SWOT

### Strengths

- 직접 작성은 스크린샷·영상 첫 장면에서 이해되는 강한 시각적 훅이다.
- 메인·보조 글자의 의미 재사용으로 적은 자산에서도 다양한 문제를 만들 수 있다.
- 전투와 환경에 같은 문법을 적용하면 시스템 학습 비용을 재사용할 수 있다.
- 수업→실습→기록 순환은 마법학교 설정과 성장 시스템을 직접 연결한다.
- 모바일 터치와 세계관의 마법 행위가 자연스럽게 일치한다.

### Weaknesses

- 손가락 가림, 인식 실패, 반복 피로가 핵심 훅을 즉시 약점으로 바꿀 수 있다.
- 메인·보조·마나·시간·적·환경·스톡·소환수를 동시에 보여주면 UI가 과밀해진다.
- 조합 결과를 명시하면 발견감이 줄고, 숨기면 시행착오와 외부 지식 의존이 커진다.
- 의미 기반 반응 데이터를 충분히 만들려면 시스템 설계·QA 비용이 높다.
- 학교·관계 콘텐츠가 코어 검증보다 먼저 비대해질 위험이 있다.

### Opportunities

- `Magic Touch`의 대규모 모바일 설치 기록은 손가락 제스처 마법이 즉시 이해되는 훅임을 보여준다.
- `Witchbrook`의 2026년 출시 계획과 지속적인 개발 공개는 마법학교 생활 장르에 대한 현재 시장 관심을 보여주는 신호다.
- 전투뿐 아니라 구조·복구·탐색·생활 문제에 마법을 적용하면 일반 전투 RPG와 차별화할 수 있다.
- 짧은 기본 세션과 선택형 상세 대화를 분리하면 모바일 접근성과 관계 몰입을 함께 노릴 수 있다.
- 플레이어가 발견한 주문 활용을 짧은 영상·이미지로 공유하기 좋은 구조가 될 수 있다.

### Threats

- 직접 작성이 단순 필기 미니게임으로 인식되면 조합·발견 코어가 전달되지 않는다.
- `무한 조합`으로 오해되면 제한된 문법과 실제 콘텐츠 범위에 대한 실망이 생긴다.
- Noita·Magicka 수준의 복잡성이나 Witchbrook 수준의 생활 콘텐츠를 기대받을 수 있다.
- 모바일 실시간 전투에서 입력 지연·발열·화면 크기·중단 상황이 핵심 경험을 훼손할 수 있다.
- 1인 개발에서 조합 반응·관계 분기·지역·마법 연출을 동시에 확대하면 완성도가 분산된다.

## 7. VRIO

### Value — `YES_IF_PROVEN`

직접 작성이 단순 제스처가 아니라 의미 기반 조합과 세계 변화로 이어진다면 플레이어에게 명확한 가치가 있다.

검증 조건:

- 첫 5분 내 `내가 마법을 썼다`는 인식
- 같은 메인 글자의 다른 보조 조합 차이 이해
- 최소 두 가지 유효 해결법 발견
- 실패 원인을 이해하고 재설계

### Rarity — `LIKELY_RARE_IN_REVIEWED_SET`

각 요소의 개별 사례는 존재하지만 세 요소의 결합은 이번 검토군에서 드물다.

주의:

- 전체 시장을 완전 조사했다는 의미가 아니다.
- 희소성은 사용성·재미·시장 규모를 보장하지 않는다.

### Imitability — `MEDIUM`

- 손가락 제스처 입력 자체는 모방하기 쉽다.
- 의미 기반 문법, 상황 반응 데이터, 실패 피드백, 수업→실습 전이 구조를 함께 정교하게 만드는 것은 모방 비용이 높다.
- 장기 방어력은 입력 기술보다 `글자 의미 데이터 + 상황 반응 설계 + 마도서 발견 기록 + 학습 콘텐츠 파이프라인`에서 나온다.

### Organization — `NOT_YET`

현재는 설계 문서 단계이며 다음 조직 능력이 아직 없다.

- 글자·조합·상황 반응 데이터 계약
- 모바일 입력 판정·접근성 기준
- 반복 가능한 문제 제작 템플릿
- 자동 검증·회귀 테스트
- 발견 기록과 밸런스 분석 도구
- 1인 개발 콘텐츠 생산 한도

### VRIO 종합

상태: `VRIO_POTENTIAL_NOT_PROVEN`

```text
가치 가능성 있음
+ 검토군 내 희소성 있음
+ 복합 시스템은 중간 이상 모방 비용
- 제작·검증 조직 능력 미구축
= 지속 경쟁우위 후보, 아직 증명되지 않음
```

## 8. Godot·Android 기술 제작성

Godot 공식 문서는 `InputEventScreenTouch`로 터치 위치·눌림·멀티터치 인덱스를 처리할 수 있고, `Line2D`와 `Curve2D`로 입력 궤적을 표시·샘플링할 수 있음을 제공한다. 공식 Android 내보내기 문서는 AAB와 서명 절차를 지원한다.

기술 판정:

- 터치 궤적 수집·시각화: `TECHNICALLY_FEASIBLE`
- 단순 템플릿 기반 글자 인식: `LIKELY_FEASIBLE_FOR_CORE_POC`
- 다양한 필체를 포괄하는 고정밀 손글씨 인식: `OUT_OF_SCOPE_FOR_INITIAL_POC`
- Android·Google Play 배포: `SUPPORTED_BY_ENGINE`, 실제 프로젝트 설정은 미검증

권장 입력 접근:

```text
정규화된 짧은 궤적
→ 방향 전환점·상대 위치·획 수 비교
→ 넓은 허용 범위
→ 가장 가까운 후보와 시각적 피드백
→ 실패 시 즉시 수정·재시도
```

초기에는 머신러닝 손글씨 인식보다 제한된 심볼 템플릿과 규칙 기반 유사도 비교를 우선한다.

## 10. ADOPT / ADAPT / AVOID

### ADOPT

- 짧고 구분되는 글자와 넓은 입력 판정
- 직접 작성 직후 명확한 세계 변화
- 작성 중 정지·감속·안전 구간 비교
- 적은 의미 단위의 문맥별 재사용
- 메인 하나 + 보조 변형
- 전투와 환경 문제의 공통 문법
- 복수의 유효 해결법
- 실패 원인과 발견 기록
- 밀도 높은 학교 공간과 소수 반복 인물
- 수업에서 배운 원리의 현장 이전

### ADAPT

- `Magic Touch`의 모양 맞추기 → 의미 단위 작성
- `LOSTMAGIC`의 실시간 복합 조작 → 플레이어 작성 중심, 소환수 단순 지원
- `Magicka`의 복수 원소 → 메인 하나 + 보조 효과
- `Noita`의 숨은 상호작용 → 명시적 인과와 방향성 미리보기
- `Opus Magnum`의 개방형 최적화 → 10~15분 상황 단위의 제한된 복수 해법
- `Witchbrook`의 광범위 생활 → 짧은 수업·일상·실습 세션

### AVOID

- 긴 룬 문자열 암기
- 엄격한 필체 인식
- 입력 실패와 설계 실패의 혼동
- 이동·조준·작성·소환수·스톡을 동시에 수동 조작
- 복수 메인·무한 조합 약속
- 숨은 호환 조건과 외부 위키 의존
- 조합 총수를 콘텐츠 가치로 과장
- 전투마다 장시간 설계 화면 강제
- 3D·협동·도시 생활·대규모 관계를 CORE_POC에 포함
- 출시 전 작품의 기대를 성공 증거로 사용

## 11. Gate 1 권장 판정

### 유지

- 세일즈포인트 3개는 벤치마크 결과와 정렬된다.
- 비타협 코어 경계도 유지한다.
- 직접 작성은 첫 훅, 의미 기반 조합은 장기 코어, 학교 학습 순환은 성장 프레임으로 역할을 분리한다.

### 강화

- `집중 모드 또는 감속`을 CORE_POC 비교 가설로 승격한다.
- 입력 실패와 설계 실패를 분리하는 피드백을 비타협 UX 규칙으로 추가한다.
- 대표 문제는 전투 1개와 환경·구조 1개 이상을 포함한다.
- 같은 메인 글자를 서로 다른 보조와 상황에서 재사용하게 한다.

### 보류

- 실시간 전투를 최종 표현으로 확정하지 않는다.
- 완성 주문 스톡의 필요성을 확정하지 않는다.
- 소환수 충전 관리의 핵심성은 확정하지 않는다.
- 3년·6학기와 전체 학교 규모를 약속하지 않는다.

### 제거 후보

CORE_POC에서 세일즈포인트를 강화하지 못하면 우선 제거한다.

- 완성 주문 스톡
- 복잡한 소환수 충전·편성
- 다중 상태이상
- 다수 관계 분기
- 대규모 학기 일정
