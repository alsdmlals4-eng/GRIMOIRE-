다음 질문을 사용했다.

1. 이 기능이 플레이어 약속과 세일즈포인트를 실제 플레이로 증명하는가?
2. 네 핵심 세션이 서로 다른 판단과 감정을 제공하는가?

6. 핵심 입력과 조합이 아트·서사·관계 제작 뒤로 밀리지 않는가?
7. 실패했을 때 무엇을 제거하고 무엇을 끝까지 지킬지 명확한가?

## 3. 유지 가치가 확인된 부분

### 3.1 네 핵심 세션의 제품 역할

```text
수업·연습 = 배움
시험 = 이해의 증명
학교축제 = 표현·관계·비전투 활용
현장실습 = 실제 위험 속 응용·발견
```

이 역할 구분은 스펠이 단순 전투 데모가 아니라 마법학교 RPG임을 증명한다. 현장실습만으로 축소하면 학교생활·평가·표현의 약속이 사라지므로 네 경험 자체는 유지할 가치가 있다.

### 3.2 자유일정의 완충 기능

중요 일정 사이 자유일정 1회는 모바일 세션 분리, 피로 완화, 관계·준비 선택, 저장·복귀 지점이라는 복수 책임을 수행한다. 구조 자체는 유지한다.

### 3.3 동일 문법의 문맥 재사용

메인 글자 1개와 보조 글자 2개를 시험·축제·현장에 재사용하면 적은 콘텐츠로 의미 기반 조합을 증명할 수 있다. 이것은 범위 절감 수단이자 세일즈포인트 증거다.

### 3.4 2계층 소환수

메인 동반 소환수는 모든 세션을 감정적으로 연결하고, 전투 보조 소환수는 현장실습에서만 전술적 기능을 담당한다. 책임 분리가 유지되는 한 제품 구조와 충돌하지 않는다.

## 4. P0 위험 — 승인 전 반드시 처리

## P0-01. 네 세션이 네 개의 별도 게임으로 분열

### 공격

수업, 시험, 축제, 현장실습을 각각 다른 장면 구조·UI·규칙·데이터로 만들면 재사용이 사라진다. 이 경우 Vertical Slice는 다음 네 제작물이 된다.

```text
튜토리얼 게임
+ 시험 퍼즐 게임
+ 축제 미니게임
+ 실시간 전투 게임
```

이는 1인 개발 범위를 초과하고 두 번째 콘텐츠 생산 가능성도 증명하지 못한다.

### P0 처리안

네 세션 모두 하나의 공통 `Situation Challenge` 계약을 사용한다.

```text
상황 목표
→ 관찰 가능한 상태
→ 사용 가능한 메인·보조 글자
→ 제한 조건
→ 방향성 결과 미리보기
→ 주문 작성
→ 세계 상태 변화
→ 성공·부분 성공·실패 원인
→ 기록·후속 반응
```

세션별 차이는 새로운 시스템이 아니라 다음 필드의 조합으로 만든다.

- 위험 수준
- 시간 압박
- 허용 자원
- 평가 방식
- 결과의 성격
- 소환수 허용 여부
- 실패 후 복구 방식

### 통과 조건

- 시험·축제·현장 문제가 같은 데이터 계약으로 정의된다.
- 두 번째 문제를 새 Scene·전용 코드 없이 추가할 수 있다.
- 세션별 전용 미니게임 프레임워크를 만들지 않는다.

## P0-02. 세션별 플레이 역할 중복

### 공격

모든 세션이 `상황 확인→글자 선택→작성→성공`만 반복하면 이름만 수업·시험·축제·현장으로 바뀐 동일 퍼즐이다.

### P0 처리안 — 세션 차별화 계약

| 세션 | 판단 | 압박 | 결과 구조 | 실패 처리 |
|---|---|---|---|---|
| 수업·연습 | 원리 이해·비교 | 없음 또는 매우 낮음 | 즉각적 인과 설명 | 실패보다 수정 유도 |
| 실기시험 | 제한 조건 내 선택·효율 | 제한 횟수·시간·마나 중 하나 | 항목별 점수·피드백 | 진행 차단 없이 평가 하락 |
| 학교축제 | 표현·개성·관계 | 전투 압박 없음 | 복수의 긍정적·개성적 결과 | 실패 대신 다른 분위기·완성도 |
| 현장실습 | 위험 속 우선순위·재설계 | 적·환경·시간 압박 | 성공·부분 성공·피해 결과 | 안전 지점 재시도·원인 기록 |

### 통과 조건

플레이테스트 후 플레이어가 다음을 자기 말로 구분해야 한다.

```text
수업은 이해하는 곳
시험은 증명하는 곳
축제는 표현하는 곳
현장은 응용하는 곳
```

## P0-03. 52~84분 분량이 Vertical Slice 검증을 희석

### 공격

84분은 모바일 외부 테스트에서 중도 이탈과 피드백 손실 가능성이 높다. 긴 플레이가 문제라기보다 핵심 입력·조합 검증에 도달하기 전에 서사·이동·대화가 시간을 소비할 위험이 크다.

### P0 처리안 — 첫 완주 시간 상한

권장 시간 예산:

| 구간 | 권장 상한 |
|---|---:|
| 프롤로그·수업·연습 | 10~12분 |
| 자유일정 A | 2~4분 |
| 실기시험 | 7~10분 |
| 자유일정 B | 2~4분 |
| 학교축제 | 8~12분 |
| 자유일정 C | 2~4분 |
| 현장실습 | 12~16분 |
| 귀환·기록 | 2~4분 |

권장 전체 목표:

- 목표 중앙값: `45~50분`
- 허용 상한: `60분`
- 세션 단위: `2~16분`
- 연속 플레이 강제: 없음

정확한 시간은 플레이테스트 조정 대상이지만, 계약 단계에서 60분을 넘는 신규 콘텐츠를 기본 범위로 추가하지 않는다.

### 통과 조건

- 첫 완주 기준 60분 이내를 목표로 제작한다.
- 첫 5분 안에 직접 작성이 발생한다.
- 15분 안에 보조 글자 차이를 이해한다.
- 현장실습 도달 전 필수 대화·이동이 누적 15분을 초과하지 않는다.

## P0-04. 자유일정 3회가 12개 독립 이벤트로 폭증

### 공격

각 슬롯에 3~4개의 고유 콘텐츠를 만들면 최대 12개의 선택 이벤트와 후속 반응이 필요하다. 관계·보정·정보·소환수 준비를 모두 별도 제작하면 핵심 세션보다 자유일정 제작량이 커질 수 있다.

### P0 처리안 — 공통 행동 원형 3개

모든 자유일정은 다음 세 행동 원형을 재사용한다.

```text
휴식
= 컨디션·집중 회복과 안전 보정

준비
= 다음 일정과 관련된 복습·조사·축제 준비·소환수 조율

교류
= 메인 동반자 또는 핵심 인물과 관계·관점·짧은 정보 획득
```

슬롯별 명칭과 짧은 장면만 문맥에 맞게 바꾼다.

- 자유일정 A 준비: 시험 복습
- 자유일정 B 준비: 축제 준비
- 자유일정 C 준비: 현장 조사 또는 보조 소환수 조율 중 하나

`보조 소환수 훈련`을 매 슬롯의 별도 네 번째 선택으로 반복하지 않는다. 현장 전 준비와 가장 가까운 자유일정 C에 통합하는 것을 권장한다.

### 통과 조건

- 슬롯당 기본 선택은 3개다.
- 공통 이벤트 구조와 결과 태그를 재사용한다.
- 선택 하나당 신규 지역·전투·미니게임을 만들지 않는다.
- 휴식·준비·교류 중 명백한 절대 우위가 없어야 한다.

## P0-05. 터치 입력이 검증되기 전에 전체 콘텐츠·아트를 제작

### 공격

직접 작성은 제품의 첫 훅이지만 손가락 가림, 인식 실패, 반복 피로가 발생하면 전체 Slice의 기반이 무너진다. 이를 마지막에 검증하면 시험·축제·현장 콘텐츠를 모두 다시 만들어야 한다.

### P0 처리안 — Slice 내부 구현 순서

별도 CORE_POC를 만들지 않되 Vertical Slice 내부 체크포인트를 다음 순서로 고정한다.

```text
M0 입력·피드백
→ 짧은 심볼 3개와 넓은 판정
→ 완전 정지·감속·실시간 비교

M1 공통 Situation Challenge
→ 관찰·작성·세계 변화·실패 피드백

M2 학교 세션
→ 수업·시험·축제를 공통 계약으로 연결

M3 현장실습
→ 전투·환경 문제와 보조 소환수 연결

M4 저장·복귀·최종 연출
→ UI·아트·사운드·관계 반응 통합
```

M0~M3는 별도 제품 단계가 아니라 Vertical Slice 내부 구현 체크포인트다.

### 통과 조건

- M0에서 입력 실패와 설계 실패를 구분한다.
- M1이 통과되기 전 축제 전용 연출·장문 대화·다수 자산을 제작하지 않는다.
- M2까지 학교 구역은 단일 장면 세트를 재사용한다.

## P0-06. 저장·복귀 상태가 이벤트 분기보다 복잡해짐

### 공격

핵심 세션 4개, 자유일정 3개, 시험 점수, 축제 결과, 관계 반응, 보조 소환수 준비를 모두 세밀하게 저장하면 초기 저장 시스템이 불필요하게 커진다.

### P0 처리안 — 경계 저장과 최소 상태

초기 Slice는 경계 저장만 지원한다.

필수 저장 지점:

- 핵심 세션 시작·완료
- 자유일정 선택 전·완료
- 현장실습의 전투 문제 완료 후
- 귀환·기록 완료

최소 상태:

```text
current_step
learned_glyphs
free_schedule_A_choice
exam_result_band
free_schedule_B_choice
festival_result_tag
free_schedule_C_choice
field_result_tag
companion_relation_band
support_summon_ready_tag
grimoire_discoveries
```

초기 제외:

- 대화 한 줄 단위 저장
- 자유 위치 저장
- 전투 도중 임의 저장
- 세밀한 관계 수치 다수
- 모든 주문 궤적 기록

### 통과 조건

저장 후 복귀한 플레이어가 10초 안에 다음을 확인할 수 있어야 한다.

- 현재 일정
- 현재 목표
- 직전 자유일정 선택
- 보유 글자
- 다음에 사용할 수 있는 소환수

## 5. P1 위험 — Gate 2 계획 전 처리

## P1-01. 시험 평가 축 과다

현재 후보는 작성 정확성·상황 해석·주문 설계·마나·시간 효율·부가 목표로 확장될 수 있다. 첫 Slice에서는 평가 축을 세 개로 제한한다.

권장:

1. 상황 적합성
2. 주문 설계
3. 실행 안정성

세부 수치는 내부 기록으로 남기고 플레이어에게는 세 축만 보여준다.

## P1-02. 학교축제의 결과 분기·자산 팽창

축제 활동은 대표 문제 하나만 제작한다. 별도 축제 맵 대신 학교 구역에 장식 오버레이·NPC 배치·음악을 바꾸는 방식으로 재사용한다.

축제 결과는 대규모 분기 대신 다음 태그 중 하나로 제한한다.

- `ELEGANT`
- `PRACTICAL`
- `SPECTACULAR`

성공·실패보다 플레이어의 표현 성향을 기록한다.

## P1-03. 메인 동반자의 대화 분기 폭증

메인 동반자는 모든 선택에 독립 장문 대사를 가지지 않는다.

권장 반응 구조:

```text
기본 반응
+ 자유일정 유형 반응
+ 시험·축제·현장 결과 태그 반응
```

관계 단계는 Slice에서 최대 3단계로 제한한다.

## P1-04. 보조 소환수의 전투 시스템 독립화

Slice에서는 수호 또는 견제 중 하나만 구현한다. 공격·충전·다중 편성·진화는 제외한다. 플레이어 명령은 `소환/해제` 또는 자동 발동 조건 하나로 제한한다.

## P1-05. 결과 미리보기와 발견감 충돌

완전한 정답을 미리 보여주지 않는다. 대신 다음 수준의 방향성만 제시한다.

- 영향 대상
- 예상 범위
- 위험 가능성
- 소모 경향

정확한 결과와 새로운 활용은 사용 후 기록한다.

## P1-06. UI 정보 과밀

전투·현장 작성 화면에서 동시에 고정 표시하는 정보는 다음으로 제한한다.

- 현재 목표
- 선택한 메인 글자
- 선택한 보조 글자
- 마나 또는 사용 가능 횟수
- 위험 경고

소환수 상세 정보, 마도서, 관계, 시험 세부 점수는 작성 화면 밖으로 분리한다.

## 6. P0 처리 후 권장 최소 계약

## 6.1 콘텐츠

- 메인 글자 1개
- 보조 글자 2개
- 직접 작성 심볼 총 3개
- 학교 장면 세트 1개
- 축제 장식 상태 1개
- 현장실습 구역 1개
- 핵심 인물 최소 2명: 교수 1명, 학생 또는 관계 인물 1명
- 메인 동반 소환수 1체
- 수호 또는 견제형 보조 소환수 1체
- 적 1종, 변형 또는 역할 차이 1종 선택 가능

## 6.2 플레이 문제

- 교내 연습: 안내형 비교 문제 1개
- 실기시험: 제한 조건 문제 1개
- 학교축제: 비전투 표현 문제 1개
- 현장실습: 전투 문제 1개 + 환경 문제 1개

모든 문제는 같은 `Situation Challenge` 계약을 사용한다.

## 6.3 자유일정

각 슬롯 공통:

- 휴식
- 준비
- 교류

총 슬롯 수는 3개를 유지한다. 총 고유 대형 이벤트는 0개다.

## 6.4 시간

- 목표: 45~50분
- 상한: 60분
- 세션별 저장·복귀
- 첫 5분 직접 작성

## 7. P0 처리 패키지 — 권장안

다음 여섯 항목을 하나의 패키지로 승인하는 것을 권장한다.

1. `Situation Challenge` 공통 계약으로 수업·시험·축제·현장을 제작
2. 세션별 판단·압박·결과·실패 역할을 명시적으로 분리
3. 전체 첫 완주 45~50분 목표, 60분 상한
4. 자유일정은 슬롯당 `휴식 / 준비 / 교류` 세 원형으로 통일
5. 입력·피드백→공통 문제→학교 세션→현장→연출 순서로 구현
6. 저장은 세션 경계와 현장 문제 전환 지점 중심의 최소 상태로 제한

이 패키지는 수업·시험·학교축제·현장실습과 자유일정 3회를 제거하지 않는다. 사용자 요구를 유지하면서 제작 단위를 재사용 가능한 하나의 게임으로 압축한다.

## 8. 최종 적대적 판정

### 현재 계약 그대로

`NO-GO_FOR_GATE_1_FINAL_APPROVAL`

이유:

- 전체 시간 상한이 없음
- 자유일정 콘텐츠 수가 폭증할 수 있음
- 세션별 전용 시스템 분열 위험
- 공통 문제 데이터 계약이 없음
- 입력 검증보다 콘텐츠 제작이 앞설 수 있음
- 저장 상태 범위가 열려 있음

### P0 패키지 승인 후

`CONDITIONAL_GO_CANDIDATE_FOR_GATE_1_FINAL_APPROVAL`

남는 미검증:

- 터치 작성의 재미와 피로
- 정지·감속·실시간 최종안
- 시험·축제·현장 차별성
- 자유일정 세 선택의 균형
- 보조 소환수 효용
- Android 성능·화면비·저장 안정성
- 외부 플레이어의 60분 완주율

이 미검증 항목은 구현과 플레이테스트에서 확인하며, 실행 전에는 `BLOCKED_UNVERIFIED`로 유지한다.
