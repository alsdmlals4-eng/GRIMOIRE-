# Spell 회로 문법 벤치마킹

## 1. 문서 상태

- 상태: `REFERENCE_REVIEWED`
- 기준 날짜: 2026-07-25
- 용도: 회로 문법 설계 참고
- 결정 권한: 벤치마크는 제안 근거이며 사용자 승인 전 확정하지 않음
- 관련 문서: `docs/planning/CIRCUIT_SYSTEM.md`

## 2. 현재 확정 문법과 벤치마크 결론

사용자 결정으로 다음 방향을 확정했다.

```text
메인 회로 1개
+
형상·전달 회로
→ 초반 최소 주문

이후 보조 회로 단계적 추가
→ 숙련 후 소환수 자동작성 가능

중반 조건·기동 추가
→ 반복 주문은 자동스펠 후보
```

- 메인 회로는 항상 하나이며 복수 메인 결합을 허용하지 않는다.
- 형상·전달을 초반부터 분리해 주문 목적과 발현 방식을 구분한다.
- 보조와 조건을 단계적으로 해금해 모바일 학습 부담을 통제한다.
- 진행할수록 직접 입력 총량이 늘어나는 대신 자동화 계층을 추가한다.

## 3. 벤치마크 요약

| 작품 | 핵심 문법 | Spell 적용 판단 |
|---|---|---|
| Arx Fatalis | 여러 룬 제스처를 순서대로 그려 주문 완성 | `ADAPT`: 손으로 마법을 작성하는 감각. `AVOID`: 긴 룬 암기와 인식 실패 부담 |
| LOSTMAGIC | 터치로 심볼을 그리고 제한된 수의 주문을 조합 | `ADOPT`: 모바일 터치와 제한된 조합 규모. `ADAPT`: 기초 자동화와 소환수 분담 |
| Magicka | 원소를 실시간으로 결합해 다양한 주문 생성 | `ADAPT`: 적은 재료의 문맥별 재사용. `AVOID`: 복수 메인과 무제한 조합 확대 |
| Noita | 효과 주문과 modifier를 순서·범위에 따라 결합 | `ADOPT`: 핵심 효과와 보조 효과 구분, 연결 적용 범위. `AVOID`: 불투명한 예외 |
| Path of Exile | 활성 스킬과 지원 요소를 태그 호환성으로 연결 | `ADAPT`: 명시적 호환과 미리보기. `AVOID`: 외부 지식이 필요한 작동 규칙 |
| Fictorum | 기본 주문을 shaping rune으로 즉석 강화 | `ADOPT`: 적은 기본 주문과 다양한 보조 변형, 작성 중 감속 |
| Mages of Mystralia | 룬 조합을 전투와 환경 퍼즐에 활용 | `ADAPT`: 전투와 탐색에 같은 문법 사용 |
| Tyranny | Core, Expression, Accent/Enhancement를 분리 | `ADOPT`: 메인, 형상·전달, 보조의 계층 구분 |

## 4. 작품별 핵심 관찰

### Arx Fatalis

- 룬을 직접 그리고 여러 제스처를 조합해 주문을 사용한다.
- Spell에 적용할 핵심은 `마법을 버튼이 아니라 손동작으로 완성한다`는 판타지다.
- 긴 룬 조합 암기와 엄격한 인식은 반복 피로와 실패 불쾌감을 만들 수 있으므로 넓은 판정과 자동화가 필요하다.

### LOSTMAGIC

- 터치스크린에 심볼을 그려 주문을 발동한다.
- 제한된 수의 심볼 조합은 모바일에서 결과를 읽기 쉽게 만든다.
- Spell은 조합 크기 제한과 함께 메인 하나 원칙을 사용한다.

### Magicka

- 적은 수의 원소가 문맥에 따라 많은 결과를 만든다.
- Spell은 개별 회로 수를 무한히 늘리기보다 같은 보조가 메인과 형상에 따라 다르게 작동하도록 한다.
- 복수 메인 결합은 Spell의 결과 가독성과 데이터 범위를 해치므로 채택하지 않는다.

### Noita

- 실제 효과와 modifier가 구분되며 순서와 적용 범위가 결과에 영향을 준다.
- Spell의 메인·보조 분리와 연결·흐름 문법을 지지한다.
- Noita 수준의 숨은 규칙과 예외는 모바일 접근성을 해치므로 피한다.

### Path of Exile

- 활성 효과와 지원 요소의 호환이 태그를 중심으로 결정된다.
- Spell은 연결 전에 적용 가능 여부, 결과, 비용, 담당 가능한 소환수를 즉시 보여줘야 한다.

### Fictorum

- 기본 주문에 다중 투사체, 폭발, 지속, 관통 같은 변형을 추가한다.
- 적은 기본 주문으로 여러 상황에 대응하는 구조와 시전 준비 중 감속은 Spell에 적합하다.

### Mages of Mystralia

- 전투와 환경 퍼즐이 같은 룬 문법을 공유한다.
- Spell의 탐색 메인도 전투와 별도 미니게임으로 분리하지 않고 같은 메인+형상+보조 문법을 사용하는 방향이 적합하다.

### Tyranny

- 마법의 핵심 성질과 발현 형태, 추가 효과를 계층적으로 분리한다.
- Spell이 초반부터 메인과 형상·전달을 분리하는 직접 근거가 된다.
- Spell은 여기에 중반 조건·기동과 소환수·자동스펠 자동화를 추가한다.

## 5. 종합 개선안

### 5.1 초반 최소 문법

```text
메인 1 + 형상·전달 1
```

- 주문 목적과 발현 형태를 분리해 학습
- 두 회로를 직접 그려 손맛 확보
- 숙련 후 자동화

### 5.2 초중반 변형 문법

```text
자동화된 메인+형상
+
직접 그리는 보조
```

- 보조 회로를 한꺼번에 열지 않고 단계적으로 추가
- 같은 보조가 메인·형상 문맥에 따라 다르게 작동
- 숙련 후 소환수가 자동작성 가능

### 5.3 중반 반응 문법

```text
메인 1 + 형상·전달 + 보조 + 조건·기동
```

- 적중, 피격, 지연, 반복, 방어 성공 등의 반응 규칙 추가
- 조건·기동을 처음부터 자동화하지 않고 직접 학습
- 반복 사용 설계도는 자동스펠 후보

### 5.4 연결선 자체를 문법으로 활용

- 직접 연결된 구조에만 보조 적용
- 방향으로 실행 순서 표현
- 분기로 다중 대상 표현
- 합류로 여러 보조 효과를 한 기동점에 모음
- 반복 고리는 조건·기동 해금 후 제한적으로 허용

### 5.5 피로도 완화 계층

```text
기초 회로 자동화
→ 소환수의 보조 회로 자동작성
→ 등록·숙련 주문 자동스펠
```

- 신규 발견과 즉석 변형은 직접 시전
- 반복 주문은 자동스펠
- 자동화가 플레이 판단과 조합 발견을 대신하지 않게 한다.

## 6. ADOPT / ADAPT / AVOID

### ADOPT

- 메인 효과와 보조 효과 구분
- 주문 목적과 발현 형태 구분
- 모바일에서 제한된 조합 규모
- 연결 전 호환성과 결과 미리보기
- 전투와 탐색의 공통 회로 문법

### ADAPT

- modifier 선택 → 직접 그리는 보조 회로
- 발현 형태 선택 → 형상·전달 회로
- 반복 주문 단축 → 등록·숙련 조건이 필요한 자동스펠
- 회로 보조 → 소환수의 능력치·적성·스탠스 기반 자동작성

### AVOID

- 복수 메인 결합
- 긴 룬 조합 강제 암기
- 숨겨진 호환 조건
- 실패 원인을 알 수 없는 조합
- 진행할수록 직접 입력 총량이 계속 증가하는 구조
- 보조 회로가 많을수록 무조건 강한 구조
- 자동스펠이 직접 시전의 완전한 상위 호환이 되는 구조
- 무한 조합을 콘텐츠 수로 착각하는 설계

## 7. 검증 순서

1. 메인 2종과 형상·전달 2종으로 최소 조합 PoC
2. 메인·형상 자동화 전후의 피로도 비교
3. 보조 회로 2종 추가 후 결과 가독성 확인
4. 소환수의 보조 회로 자동작성 체감 확인
5. 자동스펠과 직접 시전의 선택 이유 확인
6. 조건·기동 1종 추가 후 중반 복잡도 검증
