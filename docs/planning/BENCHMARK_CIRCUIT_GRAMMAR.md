# Spell 회로 문법 벤치마킹

## 1. 문서 상태

- 상태: `PLANNING_IN_PROGRESS`
- 용도: 회로 문법 설계 참고
- 결정 권한: 벤치마크는 제안 근거이며 사용자 승인 전 확정하지 않음
- 기준 날짜: 2026-07-25
- 관련 문서: `docs/planning/CIRCUIT_SYSTEM.md`

## 2. 벤치마크 요약

| 작품 | 핵심 문법 | Spell 적용 판단 |
|---|---|---|
| Arx Fatalis | 여러 룬 제스처를 순서대로 그려 주문 완성 | `ADAPT`: 손으로 마법을 작성하는 감각. `AVOID`: 긴 룬 암기와 전투 중 인식 실패 부담 |
| LOSTMAGIC | 터치로 심볼을 그리고 최대 3개 주문을 조합 | `ADOPT`: 모바일 터치와 제한된 조합 개수. `ADAPT`: 기초 자동화와 동료 분담 추가 |
| Magicka | 원소를 실시간으로 결합해 다양한 주문 생성 | `ADAPT`: 조합 결과의 즉시성과 실험성. `AVOID`: 무제한에 가까운 경우의 수와 초보자 혼란 |
| Noita | 실제 효과 주문과 modifier 주문을 순서·범위에 따라 결합 | `ADOPT`: 메인/보조 구분, 연결 순서와 적용 범위. `AVOID`: 불투명한 상호작용과 과도한 예외 |
| Path of Exile | 활성 스킬과 지원 요소를 태그 호환성으로 연결 | `ADAPT`: 명시적 태그 호환과 미리보기. `AVOID`: 작동 여부를 플레이어가 외부 지식으로 확인하는 구조 |
| Fictorum | 기본 주문을 만든 뒤 shaping rune으로 범위·연쇄·다중 투사체 등을 즉석 강화 | `ADOPT`: 적은 기본 주문과 다양한 보조 변형, 작성 중 시간 감속. `ADAPT`: 터치 회로 그리기와 결합 |
| Mages of Mystralia | 기본 주문 구성요소와 여러 룬을 연결해 전투·퍼즐 주문 제작 | `ADAPT`: 전투와 탐색에 같은 문법 사용. `AVOID`: 모바일에서 모든 조합 노드를 한 화면에 노출 |
| Tyranny | Core가 마법 종류, Expression이 발현 형태, Accent/Enhancement가 보조 효과 결정 | `TEST`: 메인과 보조 사이에 형상·전달 계층을 분리할 근거. 다만 Spell에서는 단계적으로 해금해야 함 |

## 3. 작품별 핵심 관찰

### 3.1 Arx Fatalis

- 마우스로 룬을 직접 그리고 여러 제스처를 조합해 주문을 사용한다.
- Spell과 가장 가까운 부분은 `마법을 버튼이 아니라 손동작으로 완성한다`는 판타지다.
- 장시간 플레이에서 긴 룬 조합 암기와 인식 실패가 피로가 될 수 있으므로, Spell의 넓은 판정·기초 자동화 방향이 필요하다.

### 3.2 LOSTMAGIC

- Nintendo DS 터치스크린에 심볼을 그려 마법을 발동한다.
- 별도 주문을 최대 3개까지 조합하는 제한된 문법을 사용한다.
- 모바일에서 조합 수를 제한해 읽기 쉬운 결과를 만드는 직접적인 참고 사례다.

### 3.3 Magicka

- 원소 조합으로 실시간 주문을 만든다.
- 적은 수의 기본 재료가 많은 결과를 만들어내는 점이 강점이다.
- 반대로 조합 수가 많아질수록 정답 조합 암기와 실수 입력이 부담이 될 수 있다.
- Spell은 자유 조합보다 `발견 가능한 문법 + 설계도 등록`으로 범위를 통제하는 편이 적합하다.

### 3.4 Noita

- 실제 효과를 만드는 projectile 계열과, 다른 효과를 수정하는 modifier 계열이 구분된다.
- 보조 효과의 순서와 적용 범위가 결과에 영향을 준다.
- 이는 Spell의 메인/보조 회로 방향을 직접 지지한다.
- 다만 Noita 수준의 예외와 숨은 계산식을 그대로 도입하면 모바일 게임의 가독성과 접근성이 붕괴한다.

### 3.5 Path of Exile

- 활성 스킬과 지원 요소의 호환은 태그를 중심으로 판단한다.
- 강한 빌드 다양성을 만들지만, 호환 여부가 불명확하면 초보자가 혼란을 겪는다.
- Spell은 보조 회로 선택 시 적용 가능 여부와 바뀌는 결과를 즉시 미리 보여줘야 한다.

### 3.6 Fictorum

- 기본 주문에 multi-shot, explosive, persist, pierce 같은 shaping rune을 추가한다.
- 적은 기본 주문으로 다양한 상황 대응을 만든다.
- shaping 중 시간이 느려지는 구조는 Spell의 집중 모드와 특히 유사하다.
- 보조 회로는 고정 장착만이 아니라 시전 순간 얼마나 강하게 그릴지 조절하는 축으로도 확장 가능하다.

### 3.7 Mages of Mystralia

- 룬을 조합해 전투와 환경 퍼즐 모두에 사용한다.
- Spell의 탐색 메인 회로가 전투 시스템과 별도 미니게임으로 분리되지 않고 같은 문법을 공유할 근거가 된다.
- 다만 모바일에서는 복잡한 연결도를 한꺼번에 보여주지 않고 단계별 편집이 필요하다.

### 3.8 Tyranny

- 마법 종류를 정하는 Core와 발현 형태를 정하는 Expression이 분리되고, 추가 보조 요소가 효과를 강화한다.
- Spell의 메인 회로가 목적·속성·형상까지 모두 떠안는 문제를 해결할 수 있는 참고 구조다.
- `형상·전달`을 독립 계층으로 분리할지는 PoC 이후 결정해야 한다.

## 4. 종합 개선 제안

### 4.1 플레이어 노출은 2계층, 내부 문법은 확장 가능하게

초반 플레이어에게는 메인과 보조만 가르친다.

```text
메인
→ 무엇을 하는가

보조
→ 어떻게 더 강하거나 효율적으로 만드는가
```

시스템 내부 데이터는 다음 역할을 구분할 수 있게 설계 후보를 유지한다.

- 목적
- 속성
- 형상·전달
- 보조 효과
- 조건·기동
- 연결·흐름

이렇게 하면 초기 UX는 단순하지만 후반 확장 시 데이터 구조를 다시 뜯지 않아도 된다.

### 4.2 조합 상한을 단계별로 제한

- 초반: 메인 1 + 보조 0~1
- 중반: 메인 1 + 보조 1~2 또는 형상 후보 1
- 후반: 메인 1~2 + 보조 + 조건·연결 후보

정확한 개수는 확정하지 않지만, 한 번에 모든 문법을 열지 않는다.

### 4.3 같은 보조 회로의 문맥별 결과

보조 회로 수를 늘리기보다 메인 회로에 따라 결과를 변환한다.

- 확대 + 공격 = 공격 범위 증가
- 확대 + 방어 = 보호 범위 증가
- 확대 + 탐색 = 탐지 범위 증가
- 지속 + 회복 = 지속 회복
- 지속 + 방어 = 유지형 결계

### 4.4 연결선 자체를 문법으로 활용

- 직접 연결된 메인에만 보조 적용
- 방향으로 순서 표현
- 분기로 다중 효과 표현
- 합류로 복합 효과 표현

연결 문법을 별도 아이템 목록으로 만들지 않고 플레이어가 직접 그리는 행위에 포함하면 프로젝트 정체성이 강화된다.

### 4.5 호환성과 결과의 즉시 피드백

- 연결 가능한 노드 강조
- 작동하지 않는 조합은 이유 표시
- 예상 효과와 마나 변화 미리보기
- 미발견 조합은 정답 대신 방향성 힌트 제공
- 작성 후 어느 회로가 어떤 결과를 만들었는지 분해 표시

## 5. Spell에 우선 적용할 판단

### ADOPT

- 메인 효과와 보조 효과 구분
- 모바일에서 조합 개수 제한
- 보조 회로의 적용 범위와 순서를 시각적으로 표현
- 집중 모드에서 주문을 변형하는 즉시성
- 전투와 탐색이 같은 회로 문법을 공유

### ADAPT

- 속성·형상·조건은 초반에 별도 대분류로 모두 노출하지 않음
- 자유 조합은 설계도 등록과 허용 문법으로 통제
- 자동화와 동료 보조는 숙달한 반복 구간에만 적용

### AVOID

- 긴 룬 조합 강제 암기
- 숨겨진 호환 조건
- 실패 원인을 알 수 없는 조합
- 보조 회로가 많을수록 무조건 강해지는 구조
- 초반부터 모든 속성·형상·조건을 한 화면에 노출
- 무한 조합을 콘텐츠 수로 착각하는 설계
