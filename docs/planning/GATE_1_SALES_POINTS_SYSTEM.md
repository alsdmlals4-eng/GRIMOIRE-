# 스펠 Gate 1 세일즈포인트

## 문서 상태

- 프로젝트: `스펠` (임시)
- 제품 단계: `CONCEPT_APPROVAL`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- Work Mode: `PLAN`
- 결정 ID: `GM-SALES-01`
- 상태: `SALES_POINTS_CONFIRMED_FOR_GATE_1`
- 사용자 승인: 2026-07-27, `그래`
- 상위 플레이어 약속: `GM-PROMISE-01`
- 상위 코어 경계: `GM-CORE-BOUNDARY-01`
- 프로젝트 코어 전체: `CORE_CANDIDATE`
- Gate 1 전체: `UNVERIFIED`
- 구현 상태: `NOT_STARTED`

이 문서는 스펠을 처음 접하는 플레이어·심사자·협업자에게 한 문장과 세 장면으로 전달해야 하는 세일즈포인트 최대 3개와 표현 경계를 책임진다.

> 세일즈포인트는 아직 검증되지 않은 기능을 과장하는 광고 문구가 아니라, 승인된 프로젝트 코어를 가장 빠르게 이해시키는 표현이어야 한다.

## 1. 통합 한 문장

> **마법 글자를 직접 쓰고 조합해, 수업에서 배운 원리로 전투와 환경의 새로운 해답을 발견하는 모바일 마법학교 RPG.**

이 문장은 다음 세 가지를 동시에 전달한다.

1. 입력 차별점: 직접 쓰는 마법
2. 사고 차별점: 상황에 맞게 조합하는 주문
3. 성장·세계 차별점: 수업에서 배우고 실전에서 발견하는 마법학교

## 2. 세일즈포인트 1 — 손으로 직접 쓰는 마법

### 핵심 문구

> 버튼을 누르는 대신 마법 글자를 직접 그려 발동한다.

### 플레이어에게 약속하는 경험

- 손가락으로 글자를 완성하는 순간 마법이 발현된다.
- 신규·미숙·중요 글자는 직접 작성한다.
- 작성 결과는 즉각적인 불꽃·바람·빛·보호·변형 등으로 확인한다.
- 정밀 필기 시험보다 마법을 실제로 다룬다는 손맛과 주체성을 우선한다.

### 대표 장면 1

```text
교수의 짧은 시범
→ 플레이어가 첫 메인 글자를 직접 작성
→ 글자가 빛나며 환경에 현상 발생
→ 손의 입력과 세계 변화가 한 화면에서 연결
```

### 증거 기준

- 첫 마법 발현까지 걸린 시간
- 입력 성공률과 재시도율
- 플레이어가 `내 손으로 마법을 썼다`고 인식하는지
- 손가락 가림·피로·인식 오류가 재미를 방해하지 않는지

### 금지 표현

- 단순한 화면 낙서 미니게임으로 보이게 하지 않는다.
- 획 정확도 경쟁이 핵심인 것처럼 홍보하지 않는다.
- 모든 반복 글자를 영구적으로 직접 써야 한다고 약속하지 않는다.

## 3. 세일즈포인트 2 — 상황에 맞게 만드는 주문

### 핵심 문구

> 메인 글자와 보조 글자를 조합해 같은 마법도 전투·구조·탐색·환경 해결에 다르게 사용한다.

### 플레이어에게 약속하는 경험

- 메인 글자는 핵심 현상을 만든다.
- 보조 글자는 형상·전달·출력·지속·조건 등 작동 방식을 바꾼다.
- 적·환경·목표·위험을 보고 주문을 변형한다.
- 하나의 정답 레시피보다 복수의 유효한 해결법을 허용한다.
- 결과와 실패 원인은 글자의 의미와 상황의 상호작용으로 설명할 수 있다.

### 대표 장면 2

```text
같은 불꽃 메인 글자
├─ 확대 보조: 다수의 적을 밀어내는 넓은 화염
├─ 집중 보조: 얼어붙은 장치를 녹이는 좁고 강한 열
└─ 지속 보조: 어두운 장소를 밝히고 추위를 막는 불꽃
```

실제 글자·효과 명칭과 수치는 별도 콘텐츠 설계 및 CORE_POC 전까지 예시다.

### 증거 기준

- 플레이어가 결과 차이의 원인을 설명할 수 있는지
- 첫 실습에서 수업 조합을 그대로 반복하지 않고 변형하는지
- 복수 해결법이 단순 수치 우열이 아니라 역할 차이로 느껴지는지
- 실패가 무반응이 아니라 재설계 정보로 작동하는지

### 금지 표현

- 무한 조합이나 모든 상상 구현을 약속하지 않는다.
- 조합 수 자체를 핵심 가치로 내세우지 않는다.
- 미리 정해진 레시피 수집을 자유 설계로 과장하지 않는다.

## 4. 세일즈포인트 3 — 수업에서 배우고 실전에서 발견하는 마법학교

### 핵심 문구

> 수업에서 원리를 배우고, 현장실습에서 나만의 활용법을 발견해 마도서에 기록한다.

### 플레이어에게 약속하는 경험

- 수업은 완성 주문을 지급하는 상점이 아니다.
- 교내 연습에서 글자의 의미와 조합 결과를 안전하게 익힌다.
- 현장실습은 배운 주문을 그대로 재생하는 시험이 아니라 새로운 변수에 맞게 응용하는 장소다.
- 성공한 활용과 실패 원인을 마도서에 기록한다.
- 일상·관계는 다음 실습의 동행·정보·설계 관점과 감정적 의미를 강화한다.

### 대표 장면 3

```text
수업에서 글자 원리 학습
→ 교내에서 기본 조합 연습
→ 현장실습에서 예상 밖의 변수 발견
→ 플레이어가 조합을 변형해 해결
→ 새 활용이 마도서에 기록되고 교수·동료가 반응
```

### 증거 기준

- 수업의 지식이 현장 판단으로 실제 이전되는지
- 발견 기록이 플레이어 자신의 선택 결과로 느껴지는지
- 학교·관계가 별도 메뉴가 아니라 다음 학습·실습과 연결되는지
- 기본 대화가 짧아도 목표와 위험을 이해할 수 있는지

### 금지 표현

- 대규모 학교생활 시뮬레이션을 현재 핵심으로 약속하지 않는다.
- 3년·6학기, 등장인물 수, 관계 분기량을 고정 판매 포인트로 사용하지 않는다.
- 장문 서사나 연애 요소를 마법 설계보다 앞세우지 않는다.

## 5. 한 문장 + 세 장면 전달 구조

```text
한 문장
마법 글자를 직접 쓰고 조합해, 수업에서 배운 원리로 전투와 환경의 새로운 해답을 발견하는 모바일 마법학교 RPG.

장면 1
손가락으로 글자를 쓰자 즉시 세계에 마법이 발현된다.

장면 2
같은 메인 글자에 다른 보조를 연결해 전투와 환경의 결과가 달라진다.

장면 3
수업에서 배운 원리를 현장실습에서 변형해 새 활용으로 기록한다.
```

세 장면은 `입력→판단→성장·세계` 순서로 보여준다.

## 6. 세일즈포인트 우선순위

1. `직접 쓰는 마법`
2. `상황에 맞게 만드는 주문`
3. `수업에서 배우고 실전에서 발견하는 마법학교`

단, 실제 게임의 재미 우선순위는 다음과 같이 구분한다.

```text
플레이 이해를 끄는 첫 시각 요소
= 직접 쓰는 마법

장기적으로 반복되는 핵심 재미
= 의미 기반 조합·상황 반응·발견

콘텐츠와 성장의 장기 프레임
= 수업·현장실습·마도서·관계
```

직접 작성은 가장 눈에 띄는 훅이지만, 프로젝트 코어의 최우선 재미는 조합하고 발견하는 지적 재미다.

## 7. 스토어·트레일러·스크린샷 적용 원칙

### 스토어 짧은 설명 후보

> 마법 글자를 직접 쓰고 조합해, 수업에서 배운 원리로 전투와 환경의 해답을 발견하세요.

### 트레일러 첫 구간

```text
0. 직접 글자 작성
→ 1. 즉각적인 마법 발현
→ 2. 보조 글자 변경으로 결과 차이
→ 3. 현장실습 문제 해결
→ 4. 새 활용 마도서 기록
```

정확한 초 단위와 영상 구성은 실제 시제품 이후 확정한다.

### 우선 스크린샷 역할

1. 글자를 직접 작성하는 장면
2. 같은 메인 글자의 서로 다른 조합·결과 비교
3. 수업→실습→마도서 발견이 연결되는 장면

## 8. 보호 원칙

- 세일즈포인트는 비타협 코어를 표현하며 미검증 지원 기능을 핵심처럼 과장하지 않는다.
- `무한 자유 조합`, `무엇이든 가능한 마법`, `완전한 손글씨 인식`을 약속하지 않는다.
- 직접 작성만 보여주고 의미 기반 조합과 결과 해석을 숨기지 않는다.
- 학교생활만 보여주고 핵심 주문 설계를 뒤로 미루지 않는다.
- 실시간 전투·완성 주문 스톡·소환수 충전은 검증 전 대표 세일즈포인트로 사용하지 않는다.
- 기본 설명과 대화는 짧게 유지하되 선택형 상세층으로 세계와 관계의 깊이를 확장한다.
- 세일즈포인트를 증명하지 못하는 기능은 CORE_POC 또는 Vertical Slice 범위에서 우선 제거한다.

## 9. 검증 질문

### 이해도

- 한 문장만 읽고 플레이어가 직접 작성·조합·학교 실습을 예상하는가?
- 세 장면만 보고 세 포인트의 차이를 구분하는가?
- 직접 작성이 단순 필기 미니게임으로 오해되지 않는가?

### 차별성

- 경쟁작과 비교해 직접 작성과 의미 기반 조합의 결합이 드러나는가?
- 마법학교가 장식이 아니라 학습→응용→발견 구조로 이해되는가?
- 상황 해결이 전투 속성 상성 이상의 시스템으로 보이는가?

### 제작성

- 세 장면을 작은 CORE_POC와 Vertical Slice로 실제 증명할 수 있는가?
- 한 장면을 만들기 위해 과도한 글자·적·지역·캐릭터 수가 필요하지 않은가?
- 모바일 화면에서 작성·조합·결과가 동시에 읽히는가?
