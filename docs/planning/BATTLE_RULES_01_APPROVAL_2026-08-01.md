# BATTLE-RULES-01 승인 — 상황 해결형 전투 규칙

## 1. 결정 상태

```yaml
decision_id: GM-BATTLE-RULES-01
status: APPROVED_SITUATION_RESOLUTION_RULES
approved_at: 2026-08-01
approved_by: USER_BATCH_APPROVAL_RECOMMENDED_OPTION
benchmark_id: GR-BM-BATTLE-RULES-01
implementation_authority: NONE
runtime_validation: NOT_RUN
human_validation: NOT_RUN
```

사용자의 일괄 승인에 따라 벤치마킹 권장안을 프로젝트 기획 정본으로 확정한다.

## 2. 기본 전투 약속

> 플레이어는 적의 체력을 0으로 만들어 처치하는 대신, 글자의 의미를 상황에 맞게 적용해 폭주·압력·불안정의 원인을 해소하고 적을 진정시킨다.

## 3. 전투 상태

### 적·현상

- 기본 적에게 일반 `HP`를 사용하지 않는다.
- 핵심 상태는 `불안정도(Instability)`다.
- 전투 시작 시 불안정도는 최대 상태이며, 상황에 맞는 주문 결과로 감소한다.
- 불안정도 `0`에 도달하면 마지막 유효 시전의 결과로 즉시 진정·해결 상태에 진입한다.
- 별도 포획·Finish·두 번째 게이지를 요구하지 않는다.

### 플레이어

- 플레이어는 `HP`와 `마나`를 가진다.
- HP는 적의 주기공격과 위험한 결과에 의해 감소한다.
- HP `0`은 전투 패배다.
- 마나는 `[구현]` 승인과 유효성 검증 뒤 실제 시전 시점에만 소모한다.
- 마나가 부족하면 시전하지 않고 작성 Draft를 유지한다.

### 환경

- 상황별 핵심 환경 대상은 `보존도 / 상태 태그`로 관리한다.
- 환경 보존도는 기본 승리 여부보다 `완전 성공 / 부분 성공 / 피해를 감수한 성공`을 구분한다.
- 시나리오가 명시한 치명적 환경 대상이 완전히 붕괴하면 상황 실패가 될 수 있다.
- 환경 실패 조건은 Situation 데이터에 명시하며 UI가 임의로 판정하지 않는다.

## 4. 주문 결과 규칙

모든 유효 주문은 다음 결과 축을 가진다.

```text
불안정도 변화
+ 다음 공격 위험 변화
+ 환경 상태 변화
+ 부작용·희생
```

- 현재 원인·대상·위험에 적합한 주문은 불안정도를 의미 있게 낮춘다.
- 유효하지만 부적합한 주문은 일시적으로 공격을 늦추거나 환경을 바꿀 수 있으나 불안정도 감소가 작거나 부작용을 만든다.
- 입력 실패는 주문 결과를 만들지 않는다.
- 문법 실패는 시전되지 않으며 자원을 소모하지 않는다.
- 상황 설계 실패는 시전될 수 있으나 결과와 실패 원인을 설명한다.
- `집중`과 `분산` 중 하나를 전역 최적해로 만들지 않는다.

## 5. 승리·부분 성공·패배

### 승리

```text
적·현상 불안정도 0
→ 진정·해결 연출
→ Result
→ 원래 Field 상태 변화 반영
→ Grimoire 기록
```

### 결과 품질

승리 후 다음을 기준으로 결과 태그를 만든다.

- 보호 대상의 보존 상태.
- 플레이어가 감수한 피해.
- 발생한 부작용과 희생.
- 사용한 글자·의도·해결 방식.
- 자유일정 태그와 관계 반응.

결과 품질은 보상 차이를 만들 수 있지만 단일 최적 루트를 강제하지 않는다.

### 패배

- 플레이어 HP `0`.
- Situation이 미리 선언한 치명적 환경 실패.
- 시스템 오류·입력 인식 실패는 게임 내 패배로 계산하지 않는다.

패배 후에는 안전 Checkpoint로 복구하며, 인식 오류 때문에 Story Progress를 영구 손실시키지 않는다.

## 6. 적 공격·방어

- 적은 승인된 Attack Timer에 따라 한 번에 하나의 공격을 예고한다.
- 공격은 `의도 / 남은 시간 / 대상 / 위험 유형`을 색 외 아이콘·게이지·문구로 표시한다.
- 공격 해결 중 시간은 정지한다.
- 방어는 별도 실시간 회피 액션보다 주문 결과와 수호 소환수에 의해 처리한다.
- 일반 적은 단일 페이즈이며 공격 패턴 변화는 상태·환경 태그로 표현한다.

정확한 공격 간격·피해량·방어 계산식은 Prototype Tuning 항목이다.

## 7. 수호형 보조 소환수

Slice의 수호형 소환수는 다음 계약을 따른다.

- 플레이어가 수동으로 발동한다.
- 다음 적 공격의 피해 또는 환경 피해를 완화해 작성 Draft를 보존할 여유를 준다.
- 적 공격 타이머를 정지시키지 않는다.
- 글자 선택·작성·조합·대상 지정·시전을 대신하지 않는다.
- 상시 무적·자동 발동·무제한 반복을 제공하지 않는다.
- 전장에는 상태 배지와 짧은 보호 Cut-in/FX로 표현한다.

정확한 완화율·사용 횟수·재충전 방식은 `GUARDIAN-SUMMON-TUNING`으로 후행한다. Vertical Slice 초기 Prototype은 `전투당 제한된 사용 횟수`로 검증한다.

## 8. 전투 UI 필수 정보

- 적·현상의 불안정도.
- 다음 공격과 남은 시간.
- 현재 플레이어 HP·마나·상태.
- 환경 목표와 위험 상태.
- 작성 패널의 글자·후보·조합·비용·`[구현]`.
- 현재 시간 상태 `1.0× / 감속 / 정지`.
- 결과 원인과 부작용.

## 9. 일반 전투 제작 상한

- 기본 적 `1체`.
- 일반 전투 `1페이즈`.
- 적 전용 정답 퍼즐 금지.
- 공통 글자·상태·환경 태그로 해결.
- 잡몹·웨이브·별도 포획 미니게임 금지.
- 일반 적의 다중 형태·다중 페이즈 자산 금지.

## 10. 후행 결정

- `BOSS-PHASE-01`: 보스 페이즈 수·전환·회복·작성 상태 유지.
- `BATTLE-TUNING-01`: 공격 간격·HP·마나·불안정도 변화량.
- `GUARDIAN-SUMMON-TUNING`: 완화율·횟수·재충전.
- `RESULT-GRADING-01`: 환경 보존도·부분 성공 임계값.

이 후행 항목의 수치는 사용자 승인만으로 검증 완료가 되지 않으며 Prototype과 사람 검증이 필요하다.

## 11. 대체·금지

다음 기본형은 사용하지 않는다.

- 적 HP 0 처치가 기본 승리.
- HP 0 후 별도 포획·진정 게이지.
- 상황마다 다른 전용 정답 상호작용.
- 공격력·DPS만으로 최적 주문을 판단.
- 수호 소환수로 시간 정지 또는 자동 해결.
