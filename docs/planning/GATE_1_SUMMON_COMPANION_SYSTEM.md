## 1. 확정된 2계층 구조

```text
메인 동반 소환수
= 항상 같은 개체가 플레이어와 동행
= 수업·연습·일상·현장실습·복귀·기록
= 관계·서사·관찰·기록의 중심

전투 보조 소환수
= 전투 준비 또는 전투 중 호출
= 공격·견제·수호·지정 충전 등 전투 지원
= 전투 종료 후 기본적으로 해제
```

핵심 분리:

- 메인 동반 소환수는 `누구와 계속 함께하는가`를 책임진다.
- 전투 보조 소환수는 `이번 전투에서 어떤 지원을 받을 것인가`를 책임진다.
- 두 계층은 별도 슬롯과 성장 목적을 가진다.
- 전투 보조 소환수 수집이 메인 동반자 관계를 대체하지 않는다.

---

## 2. 메인 동반 소환수

### 정체성

- 게임 초반부터 플레이어와 함께하는 고정된 하나의 존재다.
- 학교·일상·수업·연습·현장실습·복귀 장면에 계속 등장한다.
- 외형과 기능은 성장할 수 있지만 동일한 인격과 관계를 유지한다.
- 정확한 종족·기원·외형·이름은 세계관 설계에서 확정한다.

### 역할

#### 학습 동반자

- 교수의 설명과 시범에 반응한다.
- 플레이어가 사용한 글자와 결과 차이를 짧게 되짚는다.
- 이미 제공된 정보 안에서 관찰점을 환기한다.
- 수업과 현장실습 사이의 학습 전이를 감정적으로 연결한다.

#### 관계·일상 중심

- 학교생활에서 반복 등장하는 감정적 기준점이 된다.
- 플레이어의 선택·실패·성공·전문화 방향에 반응한다.
- 다른 학생·교수·지역과 대화를 연결할 수 있다.
- 선택형 상세 대화의 주요 상대가 된다.

#### 기록 동반자

- 새 활용법·실패 원인·현장 관찰을 마도서 기록에 연결한다.
- 기록 내용을 대신 결정하지 않는다.
- 다음 수업이나 연구 목표를 상기시킨다.

#### 현장 동행

- 전투 여부와 무관하게 현장실습에 함께 간다.
- 위험과 환경에 대한 관찰 반응을 제공한다.
- 전투 중 존재할 수 있으나 주력 전투 유닛 역할은 맡지 않는다.

### 허용되는 가벼운 지원

- 첫 위험을 알리는 짧은 경고
- 튜토리얼 단계의 안전 보정
- 전투 종료 후 상태 확인과 기록
- 입력 실패와 설계 실패를 구분하는 설명 보조
- 플레이어가 이미 발견한 규칙의 재확인

### 금지 역할

- 정답 주문 또는 최적 조합 직접 제시
- 메인·보조 글자 대신 선택
- 글자·회로 대신 작성·배치·연결
- 플레이어 허가 없이 주문이나 스톡 자동 사용
- 필수 정보 독점
- 전투 보조 소환수보다 강한 상시 전투 성능
- 플레이어의 발견을 동반자의 발견으로 대체

## 3. 전투 보조 소환수

### 정체성

- 전투 또는 위험 상황에서 호출하는 전술 지원 존재다.
- 학교와 일상에서 항상 따라다니는 파티원이 아니다.
- 여러 종류를 수집·계약·연구할 수 있으나 초기 범위는 소수로 제한한다.
- 전투 종료 후 기본적으로 해제한다.

### 역할 후보

| 역할 | 책임 |
|---|---|
| 공격 | 적 피해와 약한 적 처리 |
| 견제 | 적 이동·행동·시야 방해 |
| 수호 | 플레이어가 글자를 작성할 시간 확보 |
| 충전 | 플레이어가 지정한 스톡 1종 보조 |
| 동조 | 직접 시전·정확 입력의 능동 보상 강화 |

### 조작 원칙

- 기본 AI와 전투 전 설정을 우선한다.
- 호출은 한 번의 명확한 선택으로 처리한다.
- 이동·조준·스탠스·충전 대상을 동시에 수동 제어하지 않는다.
- 플레이어는 상황 판단과 주문 설계에 집중한다.
- 보조 소환수는 전투를 자동 해결하지 않는다.

## 4. 공통 책임 경계

```text
플레이어
= 상황 판단
= 메인·보조 글자 선택
= 직접 작성
= 대상·위치·연결·기동 결정

소환수
= 관찰·관계·기록 연결
= 공격·견제·수호·충전 지원
```

공통 금지:

- 글자·회로 직접 작성
- 메인·보조 글자 자동 선택
- 회로 자동 연결
- 주문 자동 설계·실행
- 문제 정답 제시
- 소환수만으로 전투 자동 해결

## 5. 성장 구조

### 메인 동반 소환수

- 관계 단계
- 기억·기원 해금
- 반응·대화 변화
- 마도서 기록 기능 확장
- 외형·연출 변화
- 제한적 안전·편의 보조

공격력과 희귀도 상승을 중심으로 삼지 않는다.

### 전투 보조 소환수

- 공격·견제·수호·충전·동조 적성
- 유지 시간과 재사용 대기
- 특정 글자 계열과의 효율
- 편성 비용 또는 소환 용량
- 고유 지원 능력

희귀도만으로 하위 소환수를 폐기하지 않는다.

### 성장축 분리

```text
메인 동반 소환수
= 관계·기억·기록·학교생활 성장

전투 보조 소환수
= 편성·적성·전술 지원 성장
```

한 계층의 성장 재화가 다른 계층을 필수적으로 잠그지 않게 한다.

## 6. Validation-First Vertical Slice 적용

별도 CORE_POC를 만들지 않는다. 다음 검증을 Vertical Slice에 직접 포함한다.

### 필수 포함

- 메인 동반 소환수 1체
- 짧은 수업 반응 1회
- 현장실습 동행과 결과 기록 1회
- 전투 보조 소환수 1체
- `수호` 또는 `견제` 역할 1개
- 보조 소환수 유무에 따른 작성 시간·피격·완주율 비교
- 두 계층의 역할 구분 이해도 확인

### 초기 제외

- 다수 메인 동반자 선택
- 메인 동반자 교체·연애·대규모 분기
- 전투 보조 소환수 다중 편성
- 복잡한 소환 용량·속성 상성
- 완성 주문 스톡 자동 충전
- 진화 트리와 희귀도 경제
- 소환수별 장문 개인 서사

### 통과 질문

- 메인 동반자가 학습·관계·기록의 연속성을 강화하는가?
- 정답을 알려 주지 않고도 플레이어 이해를 돕는가?
- 전투 보조 소환수가 직접 작성 시간을 실제로 확보하는가?
- 보조 소환수 조작이 주문 작성보다 큰 인지 부하를 만들지 않는가?
- 두 계층의 역할을 플레이어가 즉시 구분하는가?
- 소환수를 제거해도 주문 설계 코어는 작동하는가?

## 7. 기존 결정에 대한 영향

### 유지

- 소환수의 회로 직접 작성 금지

- 수호·견제·공격·충전 지원 후보
- 소환수 수집이 주문 설계보다 중요해지지 않도록 제한

### 대체

기존 `전투 시작 전 기본 소환수 1체를 선택해 미리 소환` 원칙은 다음으로 대체됐다.

```text
항상 동행하는 메인 동반 소환수 1체
+
전투에서 호출하는 보조 소환수
```

상태: `SUPERSEDED_BY_GM-MASCOT-01`

### 보류

- 보조 소환수 편성 수

- 메인 동반자의 구체적 정체성과 외형
- 보조 소환수 획득·계약·성장 방식
