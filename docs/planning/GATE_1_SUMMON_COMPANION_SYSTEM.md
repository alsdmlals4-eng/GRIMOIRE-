## 2. 확정된 2계층 구조

```text
메인 동반 소환수
= 항상 같은 개체가 플레이어와 동행
= 수업·연습·일상·시험·축제·현장·복귀·기록
= 관계·서사·관찰·기록의 중심

전투 보조 소환수
= 위험·전투에서 호출
= 수호·견제·공격·충전 등 전술 지원 후보
= 전투 종료 후 기본적으로 해제
```

핵심 분리:

- 메인 동반 소환수는 `누구와 계속 함께하는가`를 책임진다.
- 전투 보조 소환수는 `이번 전투에서 어떤 지원을 받을 것인가`를 책임진다.
- 두 계층은 별도 슬롯과 성장 목적을 가진다.
- 전투 보조 소환수 수집이 메인 동반자의 관계를 대체하지 않는다.

## 3. 메인 동반 소환수

### 정체성

- 게임 초반부터 함께하는 고정된 하나의 존재
- 동일한 인격과 관계를 유지하며 성장
- 학교·일상·수업·시험·축제·현장·복귀 장면에 반복 등장
- 원소와 정령성을 우선하는 시각 방향
- 동물 형상은 가능하지만 소환수 전체를 동물형으로 고정하지 않음

### 역할

#### 학습 동반자

- 교수의 설명과 시범에 반응
- 플레이어가 사용한 글자와 결과를 짧게 되짚음
- 이미 제공된 정보 안에서 관찰점을 환기
- 수업과 현장실습의 학습 전이를 감정적으로 연결

#### 관계·일상 중심

- 학교생활의 반복적인 감정 기준점
- 플레이어의 선택·실패·성공·전문화 방향에 반응
- 선택형 상세 대화의 주요 상대

#### 기록 동반자

- 새 활용·실패 원인·현장 관찰을 마도서 기록에 연결
- 기록 내용을 대신 결정하지 않음
- 다음 수업·연구 목표를 상기

#### 현장 동행

- 전투 여부와 무관하게 현장실습에 동행
- 위험과 환경에 대한 관찰 반응
- 전투 중 존재할 수 있으나 주력 전투 유닛이 아님

### 금지

- 정답 주문·최적 조합 제시
- 메인·보조 글자 대신 선택
- 글자·회로 작성·배치·연결 대행
- 플레이어 허가 없는 주문·스톡 자동 사용
- 필수 정보 독점
- 전투 보조 소환수보다 강한 상시 전투 성능
- 플레이어의 발견을 동반자의 발견으로 대체

---

## 4. 전투 보조 소환수

### 정체성

- 전투 또는 위험 상황에서 호출하는 전술 지원 존재
- 학교와 일상에 항상 따라다니는 파티원이 아님
- 여러 종류의 장기 확장은 가능하지만 초기 범위는 소수
- 전투 종료 후 기본적으로 해제
- 메인 동반자와 같은 세계관의 원소·정령 시각 언어 사용

### 역할 후보

| 역할 | 책임 | 상태 |
|---|---|---|
| 공격 | 적 피해와 약한 적 처리 | 장기 후보 |
| 견제 | 적 이동·행동·시야 방해 | Slice 후보 |
| 수호 | 작성 시간 확보·피격 방지 | Slice 후보 |
| 충전 | 플레이어 지정 스톡 1종 보조 | 후행 후보 |
| 동조 | 직접 시전·정확 입력의 능동 보상 강화 | 후행 후보 |

공격·견제·수호·보조 4역할 이미지는 비교 콘셉트이며, 전체 역할 체계가 사용자 승인된 것은 아니다.

### 조작 원칙

- 기본 AI와 전투 전 설정 우선
- 호출은 한 번의 명확한 선택
- 이동·조준·스탠스·충전 대상을 동시에 수동 제어하지 않음
- 플레이어는 상황 판단과 주문 설계에 집중
- 보조 소환수만으로 전투를 자동 해결하지 않음

## 5. 공통 책임 경계

```text
플레이어
= 상황 판단
= 메인·보조 글자 선택
= 직접 작성
= 대상·위치·기동 결정

소환수
= 관찰·관계·기록 연결
= 수호·견제·공격·충전 지원
```

공통 금지:

- 글자·회로 직접 작성
- 메인·보조 글자 자동 선택
- 회로 자동 연결
- 주문 자동 설계·실행
- 문제 정답 제시
- 소환수만으로 전투 자동 해결

## 6. 성장 책임 분리

```text
메인 동반 소환수
= 관계·기억·기록·외형·동행 기능 성장

전투 보조 소환수
= 편성·적성·전술 지원 성장 후보
```

한 계층의 성장 재화가 다른 계층을 필수적으로 잠그지 않게 한다.

메인 동반자의 4단계 성장, 이전 형상 선택과 장기 탑승 방향은 다음 원본이 책임진다.

## 7. Vertical Slice 적용

### 필수 포함

- 메인 동반 소환수 1체
- 초기 성장 형상 1개
- 수업·자유일정·현장·기록 반응
- 전투 보조 소환수 1체
- 수호 또는 견제 역할 1개
- 보조 소환수 유무에 따른 작성 시간·피격·완주율 비교
- 두 계층의 역할 구분 확인

### 초기 제외

- 메인 동반 소환수 2~4단계 전체 런타임 자산
- 표시 형상 선택 UI 구현
- 탑승
- 전투 보조 소환수 전체 역할군
- 다중 편성·복잡한 소환 용량
- 보조 소환수 진화·희귀도 경제
- 완성 주문 스톡 자동 충전
- 소환수별 장문 개인 서사

### 통과 질문

- 메인 동반자가 학습·관계·기록 연속성을 강화하는가?
- 정답을 알려 주지 않고 플레이어 이해를 돕는가?
- 전투 보조 소환수가 직접 작성 시간을 확보하는가?
- 소환수 조작이 주문 작성보다 큰 인지 부하를 만들지 않는가?
- 두 계층 역할을 플레이어가 즉시 구분하는가?
- 소환수를 제거해도 주문 설계 코어가 작동하는가?
