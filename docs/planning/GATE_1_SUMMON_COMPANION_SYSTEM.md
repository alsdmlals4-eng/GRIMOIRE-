# 스펠 Gate 1 소환수·동반자 구조

## 문서 상태

- 프로젝트: `스펠` (임시)
- 제품 단계: `CONCEPT_APPROVAL`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- Work Mode: `PLAN`
- 결정 ID: `GM-MASCOT-01`
- 상태: `TWO_TIER_SUMMON_STRUCTURE_CONFIRMED_FOR_GATE_1`
- 사용자 승인: 2026-07-27
- 프로젝트 코어 전체: `CORE_CANDIDATE`
- Gate 1 전체: `UNVERIFIED`
- 구현 상태: `NOT_STARTED`

이 문서는 소환수를 `메인 동반 소환수`와 `전투 보조 소환수`의 두 계층으로 분리하고, 각 계층의 역할·금지 책임·성장 경계·CORE_POC 범위를 정의한다.

> **메인 동반 소환수는 항상 플레이어와 함께 배우고 관계를 쌓으며 기록한다. 전투 보조 소환수는 전투에서만 호출되어 플레이어가 주문을 작성할 시간을 확보하고 전술적 지원을 제공한다.**

---

## 1. 확정된 2계층 구조

```text
메인 동반 소환수
= 항상 같은 개체가 플레이어와 동행
= 수업·연습·일상·현장실습·복귀·기록에 참여
= 관계·서사·관찰·기록의 중심

전투 보조 소환수
= 전투 준비 또는 전투 중 소환
= 공격·견제·수호·지정 충전 등 전투 지원
= 전투 종료 후 기본적으로 해제
```

두 계층은 같은 `소환수` 범주에 속하지만 슬롯, 책임, 성장 목적을 공유하지 않는다.

### 핵심 분리 원칙

- 메인 동반 소환수는 `누구와 계속 함께하는가`를 책임진다.
- 전투 보조 소환수는 `이번 전투에서 어떤 지원을 받을 것인가`를 책임진다.
- 메인 동반 소환수 교체를 전투 빌드 변경처럼 취급하지 않는다.
- 전투 보조 소환수 수집이 메인 동반자 관계를 대체하지 않는다.

---

## 2. 메인 동반 소환수

### 2.1 정체성

- 게임 초반부터 플레이어와 함께하는 고정된 하나의 존재다.
- 학교, 일상, 수업, 교내 연습, 현장실습, 복귀 장면에 계속 등장한다.
- 외형 변화나 성장 단계는 가능하지만 동일한 인격과 관계를 유지한다.
- 정확한 종족, 기원, 외형, 이름은 세계관 설계에서 확정한다.

### 2.2 핵심 역할

#### 학습 동반자

- 교수의 설명과 시범에 반응한다.
- 플레이어가 사용한 글자와 결과의 차이를 짧게 되짚는다.
- 이미 제공된 정보 안에서 관찰점을 환기한다.
- 수업과 현장실습 사이의 학습 전이를 감정적으로 연결한다.

#### 관계·일상 중심

- 학교생활에서 반복 등장하는 감정적 기준점이 된다.
- 플레이어의 선택, 실패, 성공, 전문화 방향에 반응한다.
- 다른 학생·교수·지역과 대화를 연결하는 매개가 될 수 있다.
- 선택형 상세 대화의 주요 상대가 된다.

#### 기록 동반자

- 새 활용법, 실패 원인, 현장 관찰을 마도서 기록 장면에 연결한다.
- 기록 내용을 대신 결정하지 않고 플레이어가 선택한 핵심을 정리하도록 돕는다.
- 다음 수업이나 연구 목표를 상기시킨다.

#### 현장 동행

- 전투 여부와 무관하게 현장실습에 함께 간다.
- 위험과 환경에 대한 관찰 반응을 제공한다.
- 전투 중에는 시각적·서사적으로 존재할 수 있으나 주력 전투 유닛 역할은 맡지 않는다.

### 2.3 허용되는 가벼운 지원

메인 동반 소환수의 지원은 전투 보조 소환수와 경쟁하지 않는 범위로 제한한다.

- 첫 위험을 알리는 짧은 경고
- 튜토리얼 단계의 안전 보정
- 전투 종료 후 상태 확인과 기록
- 실패 시 입력 실패와 설계 실패를 구분하는 설명 보조
- 플레이어가 이미 발견한 규칙의 재확인

다음은 CORE_POC 이후 별도 검증한다.

- 1회성 비상 보호
- 소량의 회복 또는 안전장치
- 마도서 기록과 연동된 수동 보조 능력

### 2.4 금지 역할

- 정답 주문 또는 최적 조합을 직접 제시
- 메인·보조 글자를 대신 선택
- 글자·회로를 대신 작성·배치·연결
- 플레이어 허가 없이 주문이나 스톡을 자동 사용
- 선택형 상세 대화를 보지 않으면 필수 정보가 누락되는 구조
- 전투 보조 소환수보다 강한 상시 공격·수호 성능
- 플레이어의 발견을 메인 동반자의 발견으로 대체

## 3. 전투 보조 소환수

### 3.1 정체성

- 전투 또는 위험 상황에서 호출하는 전술 지원 존재다.
- 학교와 일상에서 항상 따라다니는 파티원이 아니다.
- 여러 종류를 수집·계약·연구할 수 있으나 초기 범위는 소수로 제한한다.
- 전투 종료 후 기본적으로 해제되며, 유지 방식은 후속 설계에서 확정한다.

### 3.2 기본 역할 후보

```text
공격
→ 적에게 피해를 주거나 약한 적을 정리

견제
→ 적 이동·행동·시야를 방해

수호
→ 플레이어가 글자를 작성할 시간을 확보

충전
→ 플레이어가 지정한 스톡 1종의 생산·충전 효율 보조

동조
→ 직접 시전·정확 입력·방어 성공 등 능동 행동의 보상 증폭
```

한 전투 보조 소환수가 모든 역할을 최고 수준으로 수행하지 않는다.

### 3.3 소환 방식 원칙

- 전투 전에 편성한 후보 중 호출한다.
- 반복 소환 입력이 직접 주문 작성의 피로와 겹치지 않도록 단순 호출을 우선한다.
- 소환에는 마나, 소환 용량, 재사용 대기시간 또는 유지 비용 중 최소 하나의 제약이 필요하다.
- 정확한 편성 수, 동시 전개 수, 교체 규칙은 `PLAYTEST_TUNING_REQUIRED`다.

### 3.4 전투 책임 경계

전투 보조 소환수는 플레이어가 주문을 설계할 시간을 만들지만 주문 설계 자체를 대신하지 않는다.

```text
플레이어
→ 상황 판단
→ 메인·보조 선택
→ 직접 작성 또는 스톡 삽입
→ 대상·위치·기동 결정

전투 보조 소환수
→ 적 견제·수호·공격·지정 충전
→ 플레이어의 판단 시간을 확보
```

### 3.5 금지 역할

- 회로·글자 직접 작성
- 보조 글자 자동 선택
- 회로 자동 연결
- 최적 주문 자동 추천 후 자동 실행
- 플레이어 명령 없이 충전 대상 변경
- 소환수만으로 일반 전투 자동 해결
- 고등급 소환수가 없으면 직접 시전이 불가능한 구조
- 소환수 수집과 등급이 주문 이해보다 강한 성장축이 되는 구조

## 4. 두 계층의 상호작용

### 4.1 수업

```text
교수의 원리 설명
→ 플레이어 작성·설계
→ 메인 동반 소환수의 반응과 기록
```

전투 보조 소환수는 기본 수업의 중심이 아니다. 소환술·전술 수업에서만 별도 학습 대상으로 등장한다.

### 4.2 교내 연습

- 메인 동반 소환수는 결과 차이와 실패 원인을 기록한다.
- 전투 보조 소환수는 안전한 모의 전투에서 역할별 지원을 연습한다.
- 플레이어는 동일 주문을 지원 유무에 따라 비교할 수 있다.

### 4.3 일상

- 메인 동반 소환수의 관계·성격·기억·변화가 진행된다.
- 전투 보조 소환수는 연구실, 계약, 생태, 소환술 수업 등 필요할 때만 등장한다.
- 전투 보조 소환수 전체에 대규모 개별 관계 분기를 만들지 않는다.

### 4.4 현장실습

```text
메인 동반 소환수와 현장 동행
→ 상황 관찰·목표 확인
→ 전투 발생 시 보조 소환수 호출
→ 플레이어 주문 작성·재설계
→ 메인 동반 소환수와 결과 기록
```

### 4.5 복귀·마도서

- 메인 동반 소환수가 현장 결과를 함께 회고한다.
- 전투 보조 소환수의 기여는 전투 기록과 적성 데이터로 남긴다.
- 발견한 주문의 주체는 플레이어로 유지한다.

## 5. 성장 구조

### 5.1 메인 동반 소환수 성장

성장의 중심은 관계와 공동 학습이다.

- 관계 단계
- 기억·기원 해금
- 반응·대화 변화
- 마도서 기록 기능 확장
- 외형·연출 변화
- 제한적인 안전·편의 보조

순수 공격력과 등급 상승을 중심으로 삼지 않는다.

### 5.2 전투 보조 소환수 성장

성장의 중심은 전투 적성과 지원 효율이다.

- 공격·견제·수호·충전·동조 적성
- 유지 시간과 재사용 대기
- 특정 글자 계열과의 효율
- 편성 비용 또는 소환 용량
- 고유 지원 능력

희귀도만으로 하위 소환수를 완전히 폐기하는 구조를 피한다.

### 5.3 성장축 분리

```text
메인 동반 소환수
= 관계·기억·기록·학교생활 성장

전투 보조 소환수
= 편성·적성·전술 지원 성장
```

한 계층의 성장 재화가 다른 계층을 필수적으로 잠그지 않게 한다.

## 6. 모바일 UI·인지 부하 원칙

- 메인 동반 소환수는 별도 전투 명령 UI를 상시 점유하지 않는다.
- 보조 소환수 호출은 한 번의 명확한 선택으로 처리한다.
- 동시에 표시할 전투 보조 소환수 명령은 최소화한다.
- 공격 대상·스탠스·충전 대상의 동시 수동 제어를 초기 범위에 넣지 않는다.
- 보조 소환수는 기본 AI와 사전 설정으로 행동하고, 플레이어는 주문 설계에 집중한다.
- 메인 동반자의 대사는 전투 중 입력 영역을 가리지 않는다.

## 7. CORE_POC 적용

### 필수 포함

- 메인 동반 소환수 1체
- 수업 또는 시작 장면의 짧은 반응 1회
- 현장실습 동행과 결과 기록 1회
- 전투 보조 소환수 1체
- `수호` 또는 `견제` 역할 1개
- 보조 소환수 유무에 따른 작성 시간·피격·완주율 비교

### 초기 제외

- 다수 메인 동반자 선택
- 메인 동반자 교체·연애·대규모 분기
- 전투 보조 소환수 다중 편성
- 복잡한 소환 용량·속성 상성
- 완성 주문 스톡 자동 충전
- 보조 소환수 진화 트리와 희귀도 경제
- 소환수별 장문 개인 서사

### 검증 질문

- 메인 동반자가 학습·관계·기록의 연속성을 강화하는가?
- 메인 동반자가 정답을 알려 주지 않고도 플레이어의 이해를 돕는가?
- 전투 보조 소환수가 직접 작성 시간을 실제로 확보하는가?
- 보조 소환수 조작이 주문 작성보다 더 큰 인지 부하를 만들지 않는가?
- 두 계층의 역할을 플레이어가 즉시 구분하는가?
- 소환수를 제거해도 주문 설계 코어는 작동하는가?

## 8. 보호 결정

- 메인 동반 소환수는 항상 같은 개체가 동행한다.
- 전투 보조 소환수는 전투에서 소환해 지원을 받는다.
- 메인 동반 소환수와 전투 보조 소환수는 별도 슬롯과 성장 책임을 가진다.
- 어느 소환수도 글자·회로를 직접 작성·배치·연결하지 않는다.
- 어느 소환수도 메인·보조 글자 선택과 주문 설계를 대신하지 않는다.
- 하위 글자 스톡의 자동 배치 책임을 소환수에 돌리지 않는다.
- 직접 시전은 소환수 없이도 가능하다.
- 메인 동반자는 필수 정보 독점이나 정답 제시를 하지 않는다.
- 보조 소환수는 플레이어가 작성할 시간을 확보하는 지원자이지 자동 전투의 주체가 아니다.

## 9. 기존 결정에 대한 영향

### 유지

- 소환수의 회로 직접 작성 금지
- 플레이어 지정 스톡만 충전 보조
- 수호·견제·공격·충전 지원 후보
- 소환수 수집이 주문 설계보다 중요해지지 않도록 제한

### 대체

기존 `전투 시작 전 기본 소환수 1체를 선택해 미리 소환` 원칙은 다음으로 대체한다.

```text
항상 동행하는 메인 동반 소환수 1체
+
전투에서 호출하는 보조 소환수
```

상태: `SUPERSEDED_BY_GM-MASCOT-01`

### 보류

- 보조 소환수 편성 수
