## 1. 승인 방향과 범위

사용자 최신 지시: 메인/보조의 고정 구분을 없애고 모든 글자를 본편과 미니게임에서 공용으로 쓴다. `소환+열`은 불속성 소환수 2서클, `구속+지속`은 장기 구속이다. 1학년의 도달 목표와 현재 카드게임 상한은 3서클이며, 별형 연출 대신 1서클당 1겹의 서클을 쌓는다.

유지하는 사용자 결정: 집중 효과 증가 `+50%×C`, 분산 추가 대상 `+2×C`, 고서클의 큰 마력 소비, 플레이어 실행 주체, 턴/라운드 구분, 그 라운드의 미사용 준비 주문은 라운드 종료에 발동, 플레이어 잔여 마력으로 라운드 승부, 먼저 2라운드 승리, 잔여 예산 20은 시작 마력 7/7/6으로 분할, 각성/봉인 제외.

승인된 방향과 이 문서의 세부안을 구분한다. 32개 글자의 독립 사용 예, 신규 레시피 이름/세부 결과, 순서 독립 판정 방식, 시험 비용·소수 처리·초-턴 환산은 검토안이다. 기존 본편의 직접 글자 작성, 대상 선택, 명시 시전, 원자 소비와 취소/오류 복구는 보존한다.

## 2. 플레이어 경험과 읽기 지도

> 글자를 따로 외우는 것이 아니라, 같은 글자가 다른 글자와 만났을 때 무엇을 바꾸는지 배운다.

```text
본편: 관찰 → 글자 배우기·쓰기 → 조합 → 결과·비용 확인 → 대상 → 명시 시전 → 복기
```

공용인 것은 글자 의미·합성·서클 성장·비용 원리다. 본편 자원 재고와 카드 대전의 손패·마력 통장은 별개다. 독립 미니게임에서 배운 `소환+열`의 의미가 본편에서 다른 효과로 바뀌면 안 된다.

## 3. 글자에 고정 역할을 두지 않는다

- 한 개의 `GlyphCatalog`에 모든 글자를 둔다. `MAIN_ONLY` / `SUPPORT_ONLY`는 사용하지 않는다.
- `열`은 단독 가열, `소환+열`에서는 불속성 소환 결과, `보호+열`에서는 열을 다루는 보호 결과에 참여한다.
- `지속`은 연장 가능한 기존 효과를 대상으로 단독 사용할 수 있고, `구속+지속`에서는 구속 기간을 늘린다.
- 첫 입력 글자·링 위치·반시계/시계 배치가 숨은 메인 역할이나 성능 차이를 만들지 않는다.
- 단독 사용에도 적절한 대상·기존 현상이 필요할 수 있다. 이는 고정 역할 제한이 아니라 대상 조건이다.
- 모든 조합이 무조건 유효하다는 뜻은 아니다. 의미·대상·소비자가 없으면 이유를 표시하고 임의 결과로 바꾸지 않는다.

### 해석 방식 비교

| 방식 | 이득 | 비용/위험 | 판정 |
|---|---|---|---|
| 첫 글자를 중심으로 순차 해석 | 입력이 단순하다. | 숨은 메인 역할과 순서 암기를 다시 만든다. | 현재 방향에 비추천 |
| 모든 조합을 즉흥적 AI 해석 | 표현 자유도가 높다. | 재현·비용·멀티 컨텍스트 일치·테스트가 어렵다. | runtime 기본안 제외 |
| 순서 무관 공통 규칙 + 명시 레시피 + 결과 preview | 예측·재사용·교정이 가능하다. | 의미 충돌과 모드별 지원 범위를 정의해야 한다. | 권장 세칙 |

`열+보호`처럼 합리적 해석이 여럿이면 결과 의도를 플레이어가 고르게 한다. 보호/공격의 선택은 완성 결과의 의도이며 글자 자체의 영구 역할이 아니다. 알려진 결과를 가장 유리한 답으로 자동 선택하지 않는다.

## 4. 서클과 1학년 목표

```text
글자 1개 = 1서클 = 1겹
글자 2개 = 2서클 = 2겹
글자 3개 = 3서클 = 3겹
글자 4개 이상 = 현재 1학년/카드게임 실행 범위에서 불가
```

이것은 입력한 카드 개수가 아니라 참여한 글자의 구성 서명 기준이다. 2서클 마법사 내장 주문에 글자 하나를 붙이면 3서클이고, 둘을 붙이면 4서클이라 차단한다. 3서클 내장 주문에 글자 하나를 더 붙이는 것도 차단한다. 높은 마법사 등급이나 소환수·복사·반복·저장 주문으로 현재 상한을 우회하지 않는다.

이미 활성화된 3서클 주문을 '1서클 지속'으로 다시 강화하는 경우도 원래 서명과 새 glyph를 합산한다. 변경된 전체 결과가 4서클이면 현재 실행 불가다. 단순 전달·예약은 원 주문의 서명을 보존한다. 생존 중 주문 위력 +1 같은 카드 고유 수치 보정은 글자 추가와 구분한다.

동일 glyph 중복 금지는 기존 계약을 이어받는 초기 검토안이다. 초기에는 `집중+집중` 등으로 배율을 중복 적용하지 않는다. 손으로 원을 정확히 그렸는지, 원의 크기·위치·회전 방향은 서클 수와 효과를 바꾸지 않는다.

### 학습 단계

| 단계 | 질문 | 과제 예 |
|---|---|---|
| 1서클 | 글자 하나가 무엇을 바꾸는가? | 열로 작은 현상을 바꾸고 비용·결과 확인 |
| 2서클 | 무엇과 만나면 의미가 달라지는가? | 소환+열, 구속+지속 비교 |
| 3서클 | 강화·범위·기간 중 무엇을 더할까? | 소환+열+집중 또는 구속+지속+분산 |
| 1학년 도달 관찰 | 왜 그 조합과 서클을 골랐는가? | 다른 유효 조합과 잔여 마력까지 설명 |

3서클 목표는 시작부터 모든 글자가 해금되거나 숙련도가 최대라는 뜻이 아니다. 글자 접근·숙련·교육 목표는 분리한다. 상위 학년의 4서클 이상 상세 진행은 이번 범위가 아니다. 현재 카드게임에는 4~6서클 예외를 넣지 않는다.

## 5. 집중·분산·마력

`C`는 완성된 주문의 서클이다.

```text
집중 적용 효과 = 해당 서클의 기본 수치 효과 × (1 + 0.5×C)
분산 최대 대상 = 기본 대상 수 + 2×C
```

| C | 집중 증가 | 최종 배율 | 분산 추가 | 기본 1대상일 때 |
|---|---|---|---|---|
| 1 | +50% | 1.5 | +2 | 3 |
| 2 | +100% | 2 | +4 | 5 |
| 3 | +150% | 2.5 | +6 | 7 |

집중은 복리가 아니다. 분산은 반복 타격이나 분배 피해 감소가 아니다. 없는 대상의 몫을 같은 대상에게 여러 번 적용하지 않는다. 1서클 행은 단독 글자의 유효 현상 대상 활용을 설명한다. `열+집중`은 2서클 배율이다.

3서클 기본 효과가 4라는 시험 예에서 집중+분산은 최대 7대상 각각 10, 최대 총량 70이다. 이는 **같은 3서클 기본량**의 17.5배다. 1서클과 비교하려면 기본 성장률까지 필요하므로 1서클 대비 17.5배라고 쓰지 않는다.

메인/보조 고정 분류를 없애도 각 글자의 기본 효과와 비용 성장은 남는다. 수치·대상·시간·반복·소환 등급을 각자 정의한다. 도발·소유권처럼 불연속적인 기능을 2.5배로 만들지 않는다. 소환+집중은 정해진 강화 스칼라를 대상으로 하며 생존력·회복·공격을 모두 자동 배율 적용하지 않는다.

### 비용 검토안

시험 최소 비용만 1서클=1, 2서클=3, 3서클=7이다. 최종 가격표나 모든 3서클 주문의 고정 가격이 아니다.

```text
총비용 = max(서클 최소 비용, 효과·대상·기간·반복·소환을 포함한 가격)
추가 융합 비용 = max(0, new_total_cost-paid_cost)
```

고서클의 효과 증가를 충분한 마력 증가로 가격에 반영한다. 집중+분산, 영역+지속, 다수 소환, 반복·반사는 총 이득을 함께 본다. 절감은 비용을 무료/음수로 만들지 않고 하한을 보존한다.

준비·융합 때 비용을 한 번 지불하는 안을 권장한다. 종료 발동 때 같은 금액을 다시 청구하지 않는다. 이미 준비한 것을 값싼 구성으로 바꿔 마력을 자동 환급받는 행동은 허용하지 않는다. 확정 전 취소와 확정된 준비물 변경은 별도 상태다. 비공개 정보 공개 뒤 대상 수를 무료로 늘리거나 비용을 다시 계산하지 않는다.

소수점은 내부에서 정확한 값으로 유지하고 최종 적용 때 한 번 내림하는 시험안이다. 최종 반올림과 +1/−1 potency 처리 순서는 세부 검토 대상이다. 메인 현상의 정확한 성장 곡선과 레시피별 가격은 미확정이다.

### 카드 경기의 초기 마력

```text
R = 총 편성 예산 − 덱 편성 비용 합계
q = R // 3, r = R % 3
앞 r개 라운드: q+1
나머지 라운드: q
R=20 → 7 / 7 / 6
```

사용한 카드 비용이 돌아왔다고 R을 재계산하지 않는다. 기존 R 전액 시작 지급 + 라운드 기본 수입식으로 회귀하지 않는다. 추가 드로우와 라운드 잔액 이월은 이 문서에서 임의 확정하지 않는다.

## 8. 카드 미니게임에 연결

카드 종류는 마법사 / 공격주문 / 방어주문 / 소환수의 네 가지다. 이는 카드가 제공하는 실행 콘텐츠 분류이며 글자의 고정 신분이 아니다. 글자 전용 다섯 번째 카드 종류나 별도 비전 덱을 자동 신설하지 않는다.

| 종류·효과 | 계약 |
|---|---|
| 마법사 | 강한 필드 유닛. 지정된 턴 종료 주문을 제공. 손패 임의 소비·주문 사용 자격 독점 없음 |
| 공격주문 | 공용 글자 조합을 직접 또는 준비 후 사용 |
| 방어주문 | 보호·회복·완충의 공용 결과를 사용 |
| 소환수 | 소환마법으로 등장. 생존 중 지속 효과 또는 내 턴 종료 효과 |
| 마력 정령 | 내 턴 종료 플레이어 마력 +1 |
| 수호 정령 | 생존 중 도발 |
| 보호 정령 | 생존 중 상대 주문 위력 −1. 턴마다 영구 스택 아님 |
| 증폭 정령 | 생존 중 내 주문 위력 +1. 턴마다 영구 스택 아님 |

턴 종료 효과와 생존 중 aura를 분리한다. round-end는 추가 turn-end가 아니다. 라운드 종료에는 그 라운드에 준비된 미사용 주문만 해결하고, 소비된 주문·융합 재료·제물은 다시 발동하지 않는다. 해결 후 필드 카드 합계가 아니라 **플레이어의 남은 마력**을 비교한다. 먼저 두 라운드를 이긴 플레이어 승리다.

내장 주문도 공용 구성·서클·비용·대상 계산에 들어간다. mage 등급은 지원 주문 수준을 바꾸되 현재 3서클 상한보다 높일 수 없다. 단독·내장·융합 모두 같은 규칙을 공유한다. 소환은 높은 마력 또는 제물 등 명시된 비용을 지불하며, 제물은 이후 보상/재료로 재사용하지 않는다.

무행동 turn-end 반복으로 +1을 무한 확보하는 경로를 허용하지 않는다. 무행동 종료를 round pass로 처리하는 안을 우선 비교한다. 패스한 플레이어에게 회복용 빈 턴을 계속 주지 않는다. 실제 pass 세칙과 턴 수는 미확정이다.

### 선택 장면

내 마력 7, 상대의 마력 정령이 계속 회복할 상황에서 열·소환·집중이 있다. 열 1서클로 제거하면 적은 비용으로 수입을 끊지만 큰 조합의 재료를 소비한다. 소환+열 2서클은 이후 턴 이득을 노리지만 적 수입을 당장 막지 못할 수 있다. 세 글자 3서클은 강화 소환수를 확보하지만 더 많은 비용으로 잔여 마력이 낮아진다. 비용·피해가 아직 미확정이므로 어떤 선택이 최적이라고 선언하지 않는다.

미결정: 유닛 생존 수치, 플레이어 직접 공격, 동점, 라운드 사이 필드/마력 유지, 종료 주문 우선순위, 도발과 다중 대상, 내장 주문 비용, 조건부 타깃 상실. 이 문서의 예시가 이 항목을 자동 승인하지 않는다.

## 9. 겹서클 연출·화면·자산

별 꼭짓점·교차선·중앙 메인 강조를 새 표시에서 제거한다. 직접 쓴 글자와 완성 주문 이름은 유지한다.

| 상태 | 연출·정보 |
|---|---|
| 첫 글자 | 글자가 놓이고 첫 원형 층. 1서클·단독 결과·비용 |
| 두 번째 | 첫 층 위에 두 번째 층이 쌓임. 2서클·변한 의미·추가 비용 |
| 세 번째 | 세 번째 층 완성. 3서클·현재 상한 |
| 네 번째 시도 | 기존 3겹 보존, 제한 이유 표시, 비용/글자 소비 없음 |
| 시전 | 층들이 정렬·수렴하고 효과가 명시 대상에 도달 |

원형 층은 같은 축에 높이·크기 차이를 주어 쌓인 느낌으로 표현하는 안이다. 위치·원 크기·회전에는 숨은 성능 차이가 없다. 네이비/금색 구조, 푸른 마법빛, 학습자 관점의 따뜻한 학원 톤을 유지한다. 그림 정확도·입력 모드·저동작 연출에 따라 효과나 비용을 차별하지 않는다.

화면 상태: 빈 구성, 편집, 해석 선택, 대상 필요, 마력 부족, 서클 초과, 확정, 시전, 취소, 오류 복구. 상태별 사유와 결과 preview를 제공하고 자동 최적 조합·자동 대상 선택을 하지 않는다. 본편은 글자 작성과 장면 타깃, 카드게임은 손패/필드 재료지만 같은 구성·조건의 계산 결과는 같아야 한다.

후보 노드 책임: `CircleComposerView(Control)` + `GlyphSelection` + `CircleLayerHost` + `ResultPreview` + `TargetSelection` + `CommitBar` + `AnimationPlayer`. 이름·경로는 구현 단계에서 실제 convention에 맞춘다. 기능 텍스트와 수치는 live UI다.

| 소비처 | 필요한 자료 | 이번 상태 |
|---|---|---|
| 글자 목록 | 기존 승인 6글자 자산 재검토, 신규/누락 글자 형태 | 도감·reuse 대상만 정리 |
| 겹서클 | 투명 원형 층과 완성/부족/해제 상태 | 연출 브리프 |
| 카드 준비 | 뒷면·확대·선택·비활성·소비 상태 | 소비처 정의 |
| 소환체 | 첫 카드 풀의 몸체·피격·제거 상태 | 기획 후보 |
| 오디오 | 글자 추가·층 완성·비용 부족·시전·해제 | 이벤트 명세 |

이번에는 이미지를 생성하지 않았다. 향후 실제 이미지는 이미지 모델 후보→검수→사용자 승인→manifest→runtime 경로로 진행한다. SVG/Canvas/Python drawing/Godot primitive로 시안을 대신 만들지 않는다. 표·text flow는 정확한 구조 정보다. 저동작 모드는 회전 대신 짧은 페이드와 층수 라벨을 사용한다.

## 10. 공용 데이터와 모드별 상태

| 공유 | 분리 |
|---|---|
| GlyphCatalog, 조합 의미, 서클·성장·비용 | 본편 Stock과 대전 손패 |
| 동일 구성의 결과와 실패 사유 | 본편 마력과 대전 마력 통장 |
| 소환체 프로필·effect op | 퀘스트/대전 결과와 보상 |
| duration_units·반복 한도 | 초/턴을 실행하는 scheduler와 환산표 |
| 겹서클 표시 계약 | 화면 진입·상대 AI·저장 슬롯 |

기간 환산은 명시적인 모드 입력이다. 카드게임에서 같은 글자가 다른 의미나 비공개 비용 배율을 쓰면 안 된다. 공간/정밀 consumer가 없는 곳에서는 `UNSUPPORTED_IN_CURRENT_MODE`를 반환하고 사용 가능성을 거짓으로 표시하지 않는다.

### DAT-01 스키마 제안

| 계약 | 책임 필드 |
|---|---|
| GlyphDefinition | id, name_key, standalone_effect, semantic_tags, combination_hooks, circle_growth, cost_profile, target_constraints, presentation_key |
| SpellComposition | glyph_ids, source_instance_ids, source_signatures, intent_id, target_spec, rules_version |
| ResolvedSpell | circle, effect_ops, target_capacity, duration_units, total_cost, cost_breakdown, unsupported_reasons |
| PreparedSpellState | instance_id, owner, definition_ref, paid_cost, visibility, consumed, scheduled_window, round_id |
| EffectEvent | root_event_id, source_id, phase, sequence, target_ids, payload, resolved_once |

고정 MAIN_ONLY/SUPPORT_ONLY 필드는 없다. 원본 Resource는 불변 참조 후보이고 준비·숨김·피해·소유권은 인스턴스 상태다. UI나 애니메이션이 gameplay authority를 대신하지 않는다. 새로운 거래 서비스를 복제하지 말고 실제 본편 원자 시전 authority에 결과를 전달하는 thin mapping을 검토한다. 위 표는 스키마 기획이며 실제 코드가 아니다.

## 11. 실제 구현과 이행 대상

조사 SHA에서 v1 어휘는 MAIN/SUPPORT 배열, validator는 `validate(main, auxiliaries)`와 별 vertex0..4, calculator는 비대칭 mastery `main*.45+avg(aux)*.35+min(aux)*.20`을 사용한다. 새 역할 독립 정의가 이미 구현되었다고 주장하지 않는다.

## 12. 검증·증거·학습

현재 문서 데이터와 산술 검사는 15개 그룹을 실행해 15 PASS, 0 FAIL이었다. 이는 다음 범위만 증명한다.

- 32개 ID 유일성, 기존 20개 ID 보존, 각 글자의 단독/결합/성장/주의 정의.
- 24개 예제의 ID 참조·2/3서클 구성·중복 없음.
- 24개 예제 구성의 96개 순열이 같은 정규 키를 갖는 산술/데이터 확인. 실제 주문 resolver 구현 증거가 아님.
- 집중 배율 1.5/2/2.5, 분산 기본 1대상에서 3/5/7, 같은 3서클 기본 효과 4의 예시 10×7=70.
- R=0..1000의 3라운드 배분 합 보존·앞 라운드 나머지 우선, R=20의 7/7/6.
- 사람용 PDF 31페이지·목차 bookmark31개, 모든 glyph ID의 텍스트 추출, 페이지 번호·범위·한글·공식 링크 검사.

PDF는 모든 페이지를 이미지로 렌더링해 배치·표 경계를 확인했다. 게임 화면을 실행한 검수나 새로운 그림 제작이 아니다. 발행 때 최종 source commit과 readback을 PDF footer에 기록한다.

향후 실제 검증: main/card parity, 4서클 직접·마법사·소환·linked-effect 우회 차단, 부적합 타깃·비용 오류, 거래 중복/취소/rollback, turn/round 중복, innate spell 손패 오소비, 소환 슬롯 부족, 반복/반사 유한성, legacy save, Human 이해·모바일 조작·성능.

현재 열린 세부 결정: 레시피별 정확한 효과/비용, 기존 mastery의 역할 독립화, 내장 주문 비용, 시간 환산, 카드 라운드/타깃 세칙. 이 결정들은 draft 또는 implementation gate다. 승인된 공용화·역할 제거·3서클·겹연출 방향을 다시 묻는 항목이 아니다.
