# 스펠 Gate 1 프로젝트 코어 경계

## 문서 상태

- 프로젝트: `스펠` (임시)
- 제품 단계: `CONCEPT_APPROVAL`
- 실행 프로필: `PLANNING_ONLY_PROFILE`
- Work Mode: `PLAN`
- 결정 ID: `GM-CORE-BOUNDARY-01`
- 상태: `PROJECT_CORE_BOUNDARY_CONFIRMED_FOR_GATE_1`
- 사용자 승인: 2026-07-27, `권장안대로`
- 상위 플레이어 약속: `GM-PROMISE-01`
- 상위 Loop: `GM-LOOP-01`
- 상위 경험 곡선: `GM-CURVE-01`
- 프로젝트 코어 전체 상태: `CORE_CANDIDATE`
- Gate 1 전체: `UNVERIFIED`
- 구현 상태: `NOT_STARTED`

이 문서는 스펠에서 제거하거나 대체하면 정체성이 붕괴하는 **비타협 프로젝트 코어**, 코어를 증폭하는 **지원 시스템**, 제작 범위와 테스트 결과에 따라 교체 가능한 **변경 가능한 외피**의 경계를 책임진다.

> 이 경계의 승인만으로 `CORE_CONFIRMED`, Gate 1 통과, CORE_POC 통과 또는 구현 승인을 선언하지 않는다.

## 1. 채택 방향

권장안 A인 **마법 학습·설계 코어**를 채택한다.

```text
의미를 가진 마법 글자를 배운다
→ 상황과 문제를 읽는다
→ 메인 글자와 보조 글자로 주문을 설계한다
→ 중요하거나 새로운 글자를 직접 작성한다
→ 주문이 적·환경·사건을 어떻게 바꾸는지 확인한다
→ 새 활용과 실패 원인을 발견·기록한다
→ 다음 문제를 더 영리하게 해결한다
```

마법학교, 관계, 스톡, 소환수와 실시간 전투는 위 순환을 강화해야 하지만, 그 자체가 핵심 판단을 대체해서는 안 된다.

## 2. 경계 판정 기준

### 2.1 제거 테스트

- 제거하면 일반적인 스킬 선택·자동 전투 RPG로 변하는가?
- 제거하면 플레이어가 `내가 주문을 설계했다`고 느낄 근거가 사라지는가?
- 제거하면 글자의 의미와 결과의 인과를 학습할 수 없는가?
- 다른 표현이나 규모로 교체해도 플레이어 약속이 유지되는가?

### 2.2 분류 규칙

| 분류 | 판정 기준 |
|---|---|
| `NON_NEGOTIABLE_CORE` | 제거·대체 시 플레이어 약속과 뾰족한 재미가 붕괴 |
| `CORE_SUPPORT` | 코어의 가독성·성장·압박 조절·몰입을 강화하지만 다른 방식으로 대체 가능 |
| `CHANGEABLE_SHELL` | 세계관 세부·콘텐츠 규모·수치·표현 방식으로, 테스트와 제작 여건에 따라 변경 가능 |
| `UNPROVEN_OPTION` | 효용이 아직 입증되지 않아 CORE_POC 또는 플레이테스트 전 확정 불가 |

## 3. 비타협 프로젝트 코어

### 3.1 의미 기반 마법 글자

마법 글자는 공격력 수치가 다른 버튼이 아니라 세계에 발생시키는 현상과 변형의 의미를 가져야 한다.

- 메인 글자: 주문의 핵심 현상·물질·개념
- 보조 글자: 형상·전달·출력·지속·조건 등 작동 방식 변화
- 결과는 글자의 의미와 연결되어 설명 가능해야 한다.

분류: `NON_NEGOTIABLE_CORE`

### 3.2 `메인 1개 + 보조 0개 이상` 조합 문법

- 메인 글자 하나만으로 기본 주문이 성립한다.
- 보조 글자는 같은 현상을 상황에 맞게 변형한다.
- 복수 메인 글자를 결합하지 않는다.
- 하나의 정답 레시피보다 복수의 유효한 해결법을 허용한다.

분류: `NON_NEGOTIABLE_CORE`

### 3.3 신규·중요 글자의 직접 작성

- 새로 배우거나 미숙한 글자는 직접 작성한다.
- 전투·문제 해결에서 핵심 판단을 표현하는 글자는 직접 작성한다.
- 작성은 마법을 실제로 다룬다는 손맛과 주체성을 제공한다.
- 인식 정밀도와 반복량은 주체성을 해치지 않는 범위에서 완화한다.

분류: `NON_NEGOTIABLE_CORE`

### 3.4 상황을 읽고 주문을 변형하는 판단

플레이어는 적·환경·목표·위험을 관찰하고 주문의 성질을 바꿔야 한다.

```text
상황 관찰
→ 필요한 현상 선택
→ 보조 효과 선택
→ 작성·기동
→ 결과 해석
→ 유지·수정·교체
```

전투 화력뿐 아니라 구조·보호·탐색·복구·생활 문제에서도 같은 문법을 사용한다.

분류: `NON_NEGOTIABLE_CORE`

### 3.5 즉각적이고 설명 가능한 세계 변화

- 주문 결과가 적·환경·사건에 가시적으로 반영된다.
- 성공과 실패의 원인을 이해할 수 있다.
- 한 번의 결과가 다음 주문 설계를 바꾼다.
- 무반응·불명확한 실패보다 원인 피드백과 재설계를 우선한다.

분류: `NON_NEGOTIABLE_CORE`

### 3.6 수업→연습→현장실습→발견·기록의 학습 순환

- 수업에서 글자와 원리를 배운다.
- 교내 연습에서 안전하게 조합과 사용을 익힌다.
- 현장실습에서 새로운 변수에 맞게 변형한다.
- 성공한 활용과 실패 원인을 마도서에 기록한다.
- 기록이 다음 수업·연구·실습의 선택을 변화시킨다.

이 순환은 배움과 실전을 연결하는 코어다. 단, 정확한 학년 수와 일정 개수는 코어가 아니다.

분류: `NON_NEGOTIABLE_CORE`

## 4. 코어 지원 시스템

### 4.1 마법학교 프레임

역할:

- 새로운 글자와 문제 공급
- 교수·학생·연구 관점 제공
- 수업·연습·실습의 인과 연결
- 장기 성장과 전문화의 의미 제공

학교는 중요한 정체성 지원층이지만, 정확한 규모·학년 수·일정 구조는 변경 가능하다.

분류: `CORE_SUPPORT`

### 4.2 일상·관계

역할:

- 동행 인물과 팀 관계 변화
- 다른 설계 관점과 정보 제공
- 실습 결과의 감정적·서사적 의미 축적
- 선택형 상세 대화로 학교생활 확장

관계는 실습과 학습을 강화해야 하며 단독 호감도 메뉴가 되어서는 안 된다.

분류: `CORE_SUPPORT`

### 4.3 마도서·발견 기록

역할:

- 플레이어가 발견한 주문·활용법·실패 원인 보존
- 학습과 성장의 인과 가시화
- 새 조합과 숙련 목표 제시

표현 UI는 교체 가능하지만 발견을 기록하고 다시 활용하는 기능은 코어 순환을 강하게 지원한다.

분류: `CORE_SUPPORT`

### 4.4 숙련과 하위 글자 스톡

역할:

- 이미 이해한 반복 작성 감소
- 더 복잡하고 새로운 설계에 집중
- 직접 작성 경험 이후 성장 보상 제공

스톡은 주문 전체를 대신 결정하지 않으며, 첫 자동화는 숙련 보조 글자 한 단위부터 시작한다.

분류: `CORE_SUPPORT`

### 4.5 소환수

역할:

- 전투·수호로 작성 시간 확보
- 지정 스톡 생산·충전 지원
- 관계와 동반자 판타지 제공

소환수는 글자·회로를 직접 작성·배치·연결하거나 주문 조합을 대신 결정하지 않는다.

분류: `CORE_SUPPORT_WITH_UNPROVEN_EFFICIENCY`

## 7. 비타협 설계 규칙

- 핵심 문제는 미리 준비된 정답 스킬 버튼만으로 해결되지 않는다.
- 주문 결과는 글자의 의미와 상황의 상호작용으로 설명 가능해야 한다.
- 신규·미숙·중요 글자의 직접 작성 경험을 유지한다.
- 스톡·소환수·자동화는 플레이어의 조합 판단을 제거하지 않는다.
- 수업은 완성 주문 상점이 아니다.
- 현장실습은 배운 주문을 그대로 재생하는 시험이 아니다.
- 관계는 필수 정답을 숨기는 장벽이 아니라 추가 관점과 의미를 제공한다.
- 정확한 세계관 규모나 콘텐츠 수보다 CORE_POC에서 코어 인과를 먼저 검증한다.

## 8. 범위 축소 우선순위

제작 범위를 줄여야 할 경우 다음 순서로 축소한다.

```text
세부 관계 분기·선택형 상세 대화량
→ 학교 지역·인물·학기 수
→ 완성 주문 스톡·복잡한 충전 관리
→ 소환수 편성·성장 복잡도
→ 실시간 전투 압박과 부가 상태 시스템
```

다음은 축소 대상이 아니다.

```text
의미 기반 글자
+ 직접 작성
+ 상황에 따른 조합·변형
+ 설명 가능한 세계 변화
+ 수업·연습·실전·발견의 학습 순환
```

## 9. CORE_POC에 주는 영향

CORE_POC는 학교 3년 전체나 관계 시스템 전체를 검증하지 않는다. 다음 최소 인과를 검증해야 한다.

```text
짧은 원리 학습
→ 메인·보조 글자 직접 작성·조합
→ 서로 다른 상황 반응
→ 결과 원인 이해
→ 주문 재설계
→ 새 활용 발견·기록
```

우선 위험 가설:

- 직접 작성과 상황 판단이 모바일에서도 재미와 가독성을 유지하는가?
- 조합 결과가 레시피 암기가 아니라 의미 기반 발견으로 이해되는가?
- 실시간 또는 감속 압박이 생각을 강화하는가, 방해하는가?
- 숙련 보조 스톡이 판단을 보존하면서 반복만 줄이는가?

## 10. 미검증·보류

- 실시간 전투가 코어에 가장 적합한 표현인지
- 집중 모드의 정확한 작동 방식
- 소환수 지원이 제작비 대비 충분한 체감을 주는지
- 완성 주문 스톡이 필요한지
- 스톡 초기 용량과 충전 수치
- 첫 CORE_POC에서 포함할 관계·학교 표현 범위
- 학교 기간·학기 수·콘텐츠 총량
