# GR-BM-FULL-GAME-MAGIC-CURRICULUM-20260802-01 — 마법 글자 커리큘럼 정본 대조

## 1. 목적

최신 Vertical Slice 정본과 구형 장기 마법 교육 문서 사이의 범위 충돌을 확인하고, 전체 게임에 적합한 글자 확장 방식을 비교한다.

이 문서는 외부 사례 조사가 아니라 프로젝트 내부 권위 자료의 `CANON_RECONCILIATION`이다.

## 2. 대조한 프로젝트 자료

### 최신 승인 정본

`GRIMOIRE_PLANNING_CANON_2026-07-31.md`

- 메인 글자: `흐름`.
- 보조 글자: `집중 / 분산`.
- Slice 조합: 메인 1 + 보조 0~1.
- 다중 보조·순서 의존·완성 주문 스톡: Slice 제외.
- 직접 작성 필수 성공 7회, 복구 포함 목표 상한 10회.
- Mobile 우선과 직접 작성 피로 검증이 후속 Gate로 존재.

### 구형 장기 방향 문서

`CIRCUIT_SYSTEM.md`, `WORLD_MAGIC_CURRICULUM_SYSTEM.md`와 연계 문서.

- 열·물·바람·빛·생명·보호·이동·감지·소환·변환 등 다수 메인 계열 후보.
- 3개 학년과 메인 글자 Lv.0~5 후보.
- 보조 역할 10종 후보.
- 학년별 메인 1 + 보조 0~2 / 0~4 / 0~6 후보.
- 전문화·스톡·독립 연구까지 확장.

해당 문서 자체도 다수 항목을 `PROVISIONAL`, `PLANNING_DEFAULT`, `후속 결정`으로 표시한다.

## 3. 충돌 판정

구형 장기 방향을 그대로 활성화하면 다음 문제가 발생한다.

1. 새 메인 계열과 보조 역할의 곱으로 조합·상황·설명·QA 경우의 수가 급증한다.
2. Mobile에서 직접 작성해야 할 글자 수와 전투 판단 시간이 증가한다.
3. 계열 레벨 반복 숙련이 현장 판단보다 효율적인 성장 루트가 될 수 있다.
4. 플레이어가 많은 글자를 배워도 실제 콘텐츠가 일부 최적 조합만 요구할 위험이 있다.
5. Solo 제작 범위에서 각 계열의 수업·교수·VFX·상황을 충분히 차별화하기 어렵다.

따라서 구형 문서는 삭제 대상이 아니라 **장기 가능성 라이브러리**로 보존하고, 전체 게임의 실제 출시 범위는 새 Decision으로 재승인해야 한다.

## 4. 비교 기준

- 새 글자가 기존 글자를 다시 생각하게 만드는가.
- 새 글자가 단순 상위 호환이 아닌 새로운 대가를 만드는가.
- 직접 작성 피로와 Mobile 판독을 통제하는가.
- 조합·상황·원인 설명의 검수 범위를 통제하는가.
- 학교 수업과 현장 적용이 같은 학습 나선으로 이어지는가.
- 플레이어의 해결법 선택을 지나치게 잠그지 않는가.
- Solo 제작에서 글자·VFX·수업·상황을 충분히 차별화할 수 있는가.

## 5. A안 — 제한된 의미 나선 / 권장

### 기본 원칙

각 Chapter는 기본적으로 **새 학습 부담 하나**를 도입한다.

```text
새 메인 글자 1개
또는
새 보조 글자·문법 1개
```

Chapter 1의 `흐름 + 집중/분산`은 대비 학습이 필요한 승인된 튜토리얼 예외로 유지한다.

### 확장 규칙

- 새 글자는 이전 글자와 최소 한 번 이상 함께 재해석된다.
- 새 글자는 기존 글자의 단순 강화판이 아니라 다른 대상·조건·대가를 연다.
- Chapter 핵심 상황은 `새 글자 + 소수의 이전 글자`로 검수 가능한 범위를 만든다.
- 배운 글자는 마도서에서 유지되지만, 각 Chapter는 QA를 보장하는 `인증 조합 범위`를 명시한다.
- 인증 범위 밖 조합을 임의로 자동 성공시키지 않으며, 지원하지 않는 이유를 상황·문법·안정성 중 하나로 설명한다.
- 메인 글자 레벨 반복 파밍보다 서로 다른 상황에서의 활용 기록과 평가를 우선한다.
- 다중 보조·순서 문법·스톡은 본편 범위 결정 전 자동 활성화하지 않는다.

### 장점

- Chapter의 새 질문과 새 글자를 한 쌍으로 연결할 수 있다.
- 이전 글자를 버리지 않고 새 맥락에서 재사용한다.
- 직접 작성과 QA 경우의 수를 Chapter 단위로 제한한다.
- 기존 다수 계열 후보를 필요할 때 선택적으로 끌어올 수 있다.

### 위험

- 인증 범위가 지나치게 좁으면 자유 조합 판타지가 약해질 수 있다.
- 새 글자가 적은 게임으로 보일 수 있다.

### 보정

- 글자 수보다 한 글자의 전투·환경·관계·표현 활용 폭을 우선한다.
- 숨겨진 정답 잠금이 아니라 명시적인 의미·상황 규칙으로 실패를 설명한다.
- 인증 범위의 정확한 글자 수는 본편 범위 결정에서 `TEST_VALUE`로 확정한다.

## 6. B안 — 다계열 수강·전문화 트리

플레이어가 여러 메인 계열 수업 중 일부를 선택하고 계열별 Lv.0~5를 성장시킨다.

장점:
- 학교 RPG와 빌드 선택 감각이 강하다.
- 재플레이에서 다른 계열 선택을 제공하기 쉽다.

위험:
- 선택하지 않은 계열용 수업·상황·Asset도 제작해야 한다.
- 레벨과 전문화가 복수 해법보다 전투 효율 중심으로 수렴할 수 있다.
- 현재 Vertical Slice가 전체 게임의 대표 구조가 되기 어렵다.
- Solo·Mobile 범위를 크게 초과할 가능성이 높다.

## 7. C안 — 소수 메인·다수 문법 확장

메인 글자는 소수로 유지하고 집중·분산 이후 형상·전달·시간·조건·순서 같은 보조 문법을 주로 늘린다.

장점:
- 같은 현상을 다양한 방식으로 설계하는 문법 판타지가 강하다.
- 메인 계열별 VFX·수업 제작량을 줄일 수 있다.

위험:
- 화면과 직접 작성 복잡도가 빠르게 증가한다.
- 조건·순서 문법이 완성 주문 프로그래밍처럼 보일 수 있다.
- 상황의 의미보다 회로 최적화가 중심이 될 수 있다.

```yaml
  - 구형 다수 계열 후보는 장기 가능성 라이브러리로 보존

  - 구형 3개 학년·Lv.0~5·보조 2/4/6을 자동 본편 약속으로 간주
  - 반복 시전만으로 글자 숙련 최대화
  - 새 글자를 기존 글자의 상위 호환으로 설계
```
