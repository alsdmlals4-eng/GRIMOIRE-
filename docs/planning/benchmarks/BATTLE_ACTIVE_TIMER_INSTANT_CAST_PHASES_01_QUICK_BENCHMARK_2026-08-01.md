# GR-BM-BATTLE-ACTIVE-TIMER-INSTANT-CAST-PHASES-01 QUICK 벤치마킹

## 목적

승인된 단일 강적 전투에 다음 규칙을 결합할 때의 구조를 비교한다.

- 적은 일정 시간마다 행동한다.
- 플레이어는 마법을 작성하고 `[구현]`을 누르면 즉시 사용한다.
- 일반 전투는 단일 페이즈다.
- 보스만 다중 페이즈를 사용한다.

## 비교

| 구조 | 설명 | 장점 | 위험 | 판정 |
|---|---|---|---|---|
| 턴 교대형 | 적과 플레이어가 순서대로 행동 | 이해가 쉬움 | 직접 작성의 실시간 압박과 즉시 구현 감각이 약해짐 | 비권장 |
| 적 타이머 + 플레이어 자유 행동형 | 적 행동 타이머는 진행되고 플레이어는 작성 완료 시 즉시 시전 | 적 의도 관찰과 작성 압박이 결합됨 | 작성 시간이 길면 불공정하게 느껴질 수 있음 | 권장 |
| 완전 실시간 연속행동형 | 적·플레이어 모두 쿨다운과 연속행동 | 역동적 | 화면·입력·밸런스 복잡도가 크게 증가 | Slice 비권장 |

## 권장 구조

`적 타이머 + 플레이어 자유 행동 + 즉시 구현`을 기본으로 한다.

```text
적 행동 예고·카운트다운
→ 플레이어가 글자 작성
→ 인식·조합 유효성 확인
→ [구현]
→ 마나 검증
→ 즉시 시전·결과 반영
→ 다음 적 행동 또는 전투 종료
```

## 페이즈 구조

- 일반 전투: 단일 페이즈.
- 보스 전투: 필요한 경우 2개 이상의 페이즈.
- 일반 적에게 페이즈를 부여해 콘텐츠량을 부풀리지 않는다.
- 보스 페이즈 전환은 새 전투를 로드하는 것이 아니라 동일 전투 상태 안에서 규칙·행동·표현 세트를 교체한다.

## 위험과 방어

- 작성 시간이 긴 플레이어가 적 공격을 연속으로 맞을 위험.
  - 정확한 시간 정지·감속·계속 진행 여부는 `BATTLE-TIME-FLOW-01`에서 결정한다.
- `[구현]` 연타로 중복 시전될 위험.
  - Commit token과 입력 잠금이 필요하다.
- 마나 부족 시 획이 사라지는 불공정.
  - 작성 결과는 유지하고 부족 사유만 표시한다.
- 보스 페이즈 전환 때 자원·상태 초기화 누락.
  - 전투 세션은 유지하고 보스 페이즈 데이터만 교체한다.
