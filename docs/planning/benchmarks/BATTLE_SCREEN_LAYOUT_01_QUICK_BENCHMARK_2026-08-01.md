# GRIMOIRE 전투 화면 레이아웃 QUICK 벤치마킹

## 1. 상태

```yaml
benchmark_id: GR-BM-BATTLE-SCREEN-LAYOUT-01
decision_id: GM-BATTLE-SCREEN-LAYOUT-01
scale: QUICK
status: COMPLETE
source_type: USER_PROVIDED_VISUAL_REFERENCES_AND_APPROVED_PROJECT_BOARD
implementation_authority: NONE
```

이 벤치마킹은 전투 규칙이나 밸런스를 변경하지 않고, 전투 화면의 시각 집중도와 직접 글자 작성 영역을 정리하기 위한 것이다.

## 2. 검토 근거

### Reference A — 적 중심 전투 화면

사용자가 제공한 첫 번째 이미지 상단 구조에서 다음 원리를 추출했다.

- 적 또는 보스가 전투 화면의 가장 큰 시각 영역을 차지한다.
- 플레이어 캐릭터 몸체를 전장에 상시 배치하지 않아 적의 행동·표정·위험 상태가 잘 읽힌다.
- 아군 행동 UI는 전장과 분리된 하단 영역에서 처리한다.

### Reference B — 아군 얼굴 상태 요약

사용자가 제공한 두 번째 이미지에서 다음 원리를 추출했다.

- 아군은 좌측 하단 얼굴 초상으로 압축할 수 있다.
- 초상 주변에 HP·MP·상태·행동 가능 여부를 결합하면 전장 공간을 절약한다.
- 여러 아군을 전장 SD로 동시에 표시하는 것보다 시선 이동이 짧다.

### GRIMOIRE 고유 요구

- 오른쪽에 직접 마법 글자·마법진을 그리는 큰 입력 영역이 필요하다.
- 입력 실패와 주문 설계 실패를 구분해야 한다.
- 적의 위험 예고·대상·환경 목표가 작성 중에도 보여야 한다.
- PC 우선이며 모바일 카드·조이스틱 UI를 그대로 복제하지 않는다.

## 3. ADOPT / ADAPT / REJECT

### ADOPT

1. 적·환경 목표가 전장 영역을 독점하는 적 중심 구도.
2. 아군을 좌측 하단 초상·상태 요약으로 표현.
3. 마법 작성 영역을 우측에 독립 배치.
4. 작성 중에도 적의 위험 예고와 대상 상태 유지.

### ADAPT

1. 카드 손패·에너지 UI가 아니라 GRIMOIRE의 `글자 선택 → 작성 → 인식 → 조합 → 시전` 흐름에 맞춘다.
2. 전장 상단은 적의 전신 또는 핵심 실루엣·환경 목표를 보여 주고, 하단은 최소 HUD만 사용한다.
3. 수호 소환수는 상시 전장 유닛이 아니라 좌측 하단 상태 배지와 짧은 발동 연출로 표현한다.
4. 우측 작성 영역은 일반 전투에서는 축소 상태, 작성 시작 시 확장되는 방식을 우선안으로 둔다.

### REJECT

1. 참고 이미지의 캐릭터·배경·색·카드 UI 복제.
2. 화면 절반 이상을 차지하는 손패·장비 목록.
3. 적을 가리는 파티 SD·수호 소환수 상시 배치.
4. 모바일 Touch Button과 가상 Joystick의 PC 화면 상시 노출.
5. 이미지 속 수치·파티 인원·적 수를 게임 규칙으로 확정.

## 4. 프로젝트 적용 결론

권장 구조:

```text
상단·중앙 60~70%
= 적·환경 목표·위험 예고

좌측 하단
= 아군 얼굴 초상·HP/MP·상태·행동 순서

우측 30~40%
= 직접 글자·마법진 작성 영역
```

일반 전투에서는 우측 영역을 축소할 수 있고, 작성 상태에서 확장한다. 적의 핵심 실루엣과 위험 예고는 작성 영역에 완전히 가려지지 않아야 한다.

## 5. 검증 경계

- 레이아웃 방향만 승인 대상으로 한다.
- 실제 비율·픽셀·초상 수·전투 인원·HP/MP 항목은 후행 기획 및 `ASSET-SPEC-01`에서 확정한다.
- Godot Scene·Control 구현은 시작하지 않는다.
