## 3. 시각 한 줄 정의

> **청명하고 품위 있는 마법학교의 일상 속에서, 손으로 쓴 빛나는 글자가 상황과 전술을 실제로 바꾸는 2D 판타지 RPG.**

핵심 감정:

1. 학교에서 배우는 설렘과 소속감.
2. 직접 쓴 글자가 읽히고 작동하는 손맛.
3. 정답 복제가 아니라 책임 있는 해결법을 설계하는 성취감.
4. 작은 정령 동반자와 함께 성장하는 애착.
5. 전투와 현장 문제가 원래 장소의 변화로 돌아오는 인과감.

피해야 할 인상:

- 공포·폐허 중심의 다크 판타지 조사 게임.
- 캐릭터 수집형 모바일 RPG의 과밀 로비·버튼 배치.
- 화면마다 화풍·인체·UI가 바뀌는 합성 이미지 느낌.
- 종이 질감·안개·블룸이 전체 화면을 덮는 저대비 연출.
- 마법 글자보다 파티클과 장식이 먼저 보이는 화면.

# PART A. 비주얼 권위 기준

## 5. 전체 렌더링 언어

### 5.1 배경

- 방향: `SOFT_STORYBOOK_ENVIRONMENT`.
- 공간: 고정 3/4 장면, 전경·플레이 영역·중경·원경의 최소 3단 깊이.
- 질감: 회화적 브러시와 부드러운 재질 변화.
- 건축: 밝은 석재·목재·스테인드글라스·아치·학원 문장.
- 자연: 청명한 하늘, 녹지, 꽃·빛·물의 제한된 포인트.
- 플레이 영역: 캐릭터 발밑과 상호작용 동선은 주변보다 명도 차와 형태 반복을 줄인다.
- 금지: 전체 화면 종이 질감, 과도한 안개, 플레이 영역을 가르는 장식 전경, 카메라 회전 전제 정보.

### 5.2 캐릭터

- 방향: `CLEAN_ANIME_CEL_CHARACTER_OVER_STORYBOOK_BACKGROUND`.
- 외곽선: 배경보다 선명하고 형태 판독이 빠른 셀 계열 선.
- 명암: 큰 면 중심의 제한된 단계. 작은 재질 묘사보다 얼굴·손·마법 동작을 우선.
- 채도: 배경과 분리되지만 형광색 캐릭터가 되지 않는 중간~높은 채도.
- 일관성: SD·반신·전투 SD가 동일한 머리·얼굴·의상·색 키를 공유한다.

### 5.3 UI

- 방향: `NAVY_GOLD_MAGIC_ACADEMY_FRAME`.
- 기본 패널: 짙은 네이비 또는 먹색 반투명 면.
- 테두리: 얇은 금색·황동색 선과 제한된 모서리 장식.
- 활성 강조: 청색·청록 발광.
- 경고·과부하: 따뜻한 주황·적갈색을 보조로 사용하되 색만으로 상태를 전달하지 않는다.
- 기본 Text: 밝은 크림·백색.
- 장문 Text: 장식 서체가 아니라 높은 한글 가독성의 본문 계층.
- 금지: 모든 패널에 큰 장식 문양, 유리·금속·양피지 재질 혼용, 화면마다 다른 테두리 체계.

### 5.4 마법 FX

- 핵심은 `획 → 인식 → 조합 → 대상 → 결과`의 인과가 읽히는 것이다.
- 글자 획은 배경·캐릭터·전투 FX보다 우선하는 최고 대비 요소다.
- `흐름`: 방향성과 경로가 읽히는 선·화살·곡선 이동.
- `집중`: 좁은 중심·강한 코어·압축된 입자·작은 영향 범위.
- `분산`: 넓은 외곽·다중 파동·낮은 밀도·넓은 영향 범위.
- 위험·저항: 색 외에 테두리, 점선, 진동 패턴, 아이콘, 문구를 병행.
- 금지: 발동 FX가 글자 획·대상·위험 범위를 덮음, 전 화면 블룸, 긴 섬광, 결과 전에 판정이 가려지는 연출.

## 6. 캐릭터 일관성 규칙

### 6.1 주인공

잠긴 기준판에서 보호할 시각 키:

- 짙은 머리색의 단정한 학생 실루엣.
- 네이비 중심 마법학교 제복.
- 금색 또는 따뜻한 금속색 포인트.
- SD에서 식별 가능한 앞머리·외투·하의 실루엣.
- 반신과 SD에서 같은 눈색·머리 묶임·의상 장식 관계.

검토가 필요한 경계:

- 잠긴 기준판의 정확한 얼굴과 성별 표현까지 최종 고정할지.
- 의상 세부 문양과 학교 문장.
- 마법 도구의 종류와 휴대 위치.

### 6.2 교수·동급생

- 교수: 안정된 수직 실루엣, 과도한 권위 장식보다 교육자·연구자 인상.
- 동급생: 주인공과 같은 학교 언어를 공유하되 머리·대표색·소지품으로 즉시 구분.
- 핵심 관계 인물만 반신을 제작한다.
- 일반 NPC는 필드 SD 또는 배경 군중 처리하며 모든 NPC의 반신 제작을 금지한다.

### 6.3 메인 동반 정령

- Slice 필수는 작은 늑대형 초기 형상 1개.
- 흰색·옅은 청색 몸체, 둥근 얼굴, 큰 귀·꼬리·작은 원소광으로 친근함을 우선.
- 필드에서 주인공보다 작고, 대화에서 화자의 얼굴·Text를 가리지 않는다.
- 전투에서도 주력 공격 유닛처럼 거대화하지 않는다.
- 이름·정확한 원소·최종 종족은 이미지 Text만으로 확정하지 않는다.

### 6.4 전투 보조 소환수

- 메인 동반 정령보다 크고 방어·견제 역할이 읽히는 실루엣.
- 갑주·결정·방패·넓은 어깨 등 수호 키를 제한적으로 사용.
- 청색 계열을 공유하더라도 명도·크기·모서리 형태로 메인 동반자와 구분.
- Slice에서는 수호형 1체만 필수. 이미지에 보이는 다수 형태는 장기 참고이며 제작 의무가 아니다.

## 8. 화면별 권위 규칙

### SCREEN-FIELD — 학교 탐색·자유일정

- 월드가 화면의 대부분을 차지한다.
- 목표·상태 HUD는 상단 또는 좌측 소형 영역에 제한한다.
- 상호작용 대상은 말풍선·테두리·바닥 표식 중 1~2개 채널로 표시.
- PC 파생 화면에는 영구 가상 조이스틱을 사용하지 않는다.
- Mobile 후속안은 별도 파생 Board에서 Touch UI를 검증한다.

### SCREEN-DIALOGUE — 반신 대화

- 같은 장소 배경을 유지해 사건 연속성을 보존.
- 기본 강조 화자 1명, 필요 시 2명까지.
- 반신은 대화창과 목표 정보를 가리지 않는다.
- 동반 정령은 작은 반응 슬롯 또는 필드 위치 반응으로 제한.
- 표정만으로 필수 정보를 전달하지 않는다.

### SCREEN-WRITING-FIELD — 비전투 작성

- 현재 장면을 감속·암전하되 대상과 목표는 남긴다.
- 작성 영역은 화면 중앙 또는 중앙 우측의 가장 큰 단일 상호작용 영역.
- 메인 글자·보조 글자·목표·비용·위험만 상시 표시.
- 마도서 전체·관계 상세·장문 설명은 이 화면에서 제외.

### SCREEN-BATTLE — 별도 전술 전투장

- 필드의 건축·지형·핵심 대상 색과 형태를 계승.
- 주인공·적·수호 소환수·환경 목표가 동시에 식별 가능.
- HUD는 전투 목표·위험 예고·자원·작성 진입을 우선.
- 잠긴 이미지의 파티 초상 수·적 3체·수치 자체는 Placeholder.

### SCREEN-WRITING-BATTLE — 전투 중 작성

- 위험 범위·대상·수호 상태를 암전 뒤에서도 확인.
- 작성 획이 가장 밝고 선명한 정보.
- 전투용 따뜻한 강조색은 위험·과부하·Commit 상태에만 제한적으로 사용.
- 완전 정지·감속 비율은 Playtest Tuning에서 결정.

### SCREEN-RESULT-RETURN — 결과·원래 장면 복귀

- 성공·부분 성공·실패 원인을 짧게 보여 준다.
- 획득량보다 `무엇이 어떻게 바뀌었는가`가 먼저 보인다.
- 결과 확인 후 원래 장소로 복귀하고 손상·복구·구조 상태를 반영.
- 전투장에 고립된 장기 정산 화면을 만들지 않는다.

### SCREEN-GRIMOIRE — 마도서·보유 지식 관리

- 잠긴 기준판에 완성 화면이 없으므로 `PROPOSED_DERIVATIVE_SCREEN`이다.
- 전통 장비 인벤토리가 아니라 상황·글자·의도·결과·부작용·발견을 관리.
- 자동 최적 조합·기록 클릭 자동 시전 금지.
- Art Bible 승인 후 별도 화면 Board로 검토한다.

### SCREEN-MAIN — 시작 화면

- 잠긴 기준판에 완성 화면이 없으므로 `PROPOSED_DERIVATIVE_SCREEN`이다.
- 학교 전경·마도서·빛나는 글자·동반 정령 중 1~2개 상징만 사용.
- 로비형 캐릭터 수집 UI로 확장하지 않는다.
- `새 게임 / 이어하기 / 설정` 중심의 최소 구조.

# PART B. Vertical Slice 제작 기준

## 9. 제작 단순화 원칙

### 반드시 유지

- SD·반신·전투 SD의 동일 인물성.
- 네이비·금색 UI와 청색 글자 대비.
- 학교→대화→작성→별도 전투→결과 복귀 구조.
- 작은 메인 동반 정령과 큰 수호 소환수의 역할·실루엣 분리.
- 상황별 배경 색 변화와 원래 장소의 인과.

### 줄여도 되는 것

- 배경의 작은 장식·군중 디테일.
- UI 모서리 장식과 금속 질감 단계.
- SD의 작은 의상 무늬.
- 반신의 재질 묘사와 장신구 수.
- 전투 FX 입자 수와 잔상 수.

### Slice에서 제외

- 메인 동반 정령 성장 2~4단계 런타임 자산.
- 전투 보조 소환수 다역할·다중 편성.
- 모든 NPC 반신.
- 화면마다 별도 UI 프레임 세트.
- 축제·시험을 위한 완전 별도 학교 맵.
- 고프레임 컷신·자유 카메라·대형 전투장.
- 완성 주문 스톡을 위한 별도 시각 자산군.

## 10. 제작 복잡도 상한

정확한 수량·픽셀·파일 규격은 `ASSET-SPEC-01`에서 확정한다. Art Bible은 다음 복잡도 상한만 잠근다.

| 자산군 | Slice 기준 | 장기 확장 |
|---|---|---|
| 학교 배경 | 공용 기반 장면 + 수업/시험/축제 상태 변형 | 추가 장소 |
| 현장 배경 | 현장 기반 장면 + 같은 장소 전술장 | 추가 현장 |
| 주인공 | 필드·전투 공유 디자인 + 반신 | 추가 의상 |
| 교수·동급생 | 필드 SD + 핵심 반신 | 관계별 추가 표정 |
| 일반 NPC | 필드 SD 또는 군중 | 핵심 인물만 승격 |
| 메인 동반 정령 | 초기 형상 1개 | 성장 2~4단계·탑승 |
| 보조 소환수 | 수호형 1체 | 견제·공격·충전 등 |
| 글자 | 흐름·집중·분산 | 추가 글자군 |
| UI | 공용 Panel·Button·Icon·Text 계층 | 장기 시스템별 변형 |
| FX | 획·후보·대상·성공·실패의 최소 세트 | 상위 마법 연출 |

## 11. UI 구성 규칙

### 정보 계층

1. 현재 목표·위험·대상.
2. 플레이어가 지금 조작할 요소.
3. 비용·조건·예상 결과.
4. 보조 상태와 상세 설명.
5. 장식·세계관 문양.

### Button

- Primary: 밝은 청색 또는 금색 강조 1개.
- Secondary: 어두운 네이비 면과 얇은 금색 선.
- Destructive/Cancel: 형태·문구를 병행하며 경고색 남용 금지.
- Disabled: 불투명도만 낮추지 않고 잠금 아이콘·사유 Text 제공.

### Font

- 실제 Font 파일과 라이선스는 `ASSET-SPEC-01`에서 검수.
- 제목: 품위 있는 명조 또는 장식 Serif 계열 후보.
- 본문·HUD: 한글 가독성이 높은 고딕 계열.
- 숫자·비용: 빠르게 비교 가능한 탭형 숫자 폭 후보.
- 장식 서체를 장문 대사·튜토리얼·오류 설명에 사용하지 않는다.

### PC Safe Frame

- 기준: 16:9.
- 핵심 목표·대사·작성 영역·Confirm/Cancel은 화면 가장자리 장식 밖에 둔다.
- PC는 Mouse/Keyboard 중심으로 Persistent Touch Controls를 표시하지 않는다.
- 18:9~20:9 확장은 배경·월드 여백을 늘리고 핵심 UI는 16:9 Safe Frame에 유지.
- Mobile은 별도 Safe Area·손가락 가림·Touch Control 검증을 수행한다.

---

## 12. 모션·연출 기준

- Scene 전환: 짧은 Fade·마법 획 Wipe 등 반복 가능한 방식.
- 대화: 표정 Crossfade·작은 호흡·동반 정령 반응 정도.
- 작성: 입력 획이 즉시 따라오고 인식·후보·Commit 단계를 분리.
- 전투: 판정 순간의 짧은 Hit Stop·방향성 FX. 판정 전에 긴 연출 금지.
- 결과: 원래 장소 변화가 Reward 숫자보다 먼저 읽힘.
- Motion Reduced: 화면 흔들림·Flash·Particle 수를 낮춰도 판정 정보 유지.
- 무음 상태에서도 Text·Icon·Shape로 성공·실패·위험을 이해 가능.

## 13. 접근성·가독성 Gate

- 글자 획과 배경의 명도 차가 낮으면 FAIL.
- 위험 경고가 색상 하나에만 의존하면 FAIL.
- 반신이 대사 Text 또는 선택지를 가리면 FAIL.
- SD와 반신을 같은 인물로 즉시 인식하지 못하면 FAIL.
- 필드와 전투가 다른 장소처럼 느껴지면 FAIL.
- 화면 장식이 목표·대상·입력보다 먼저 보이면 FAIL.
- PC 화면에 모바일 조이스틱이 상시 남아 있으면 FAIL.
- 작은 화면에서 주인공·메인 동반자·수호 소환수 실루엣이 섞이면 FAIL.

## 14. Art Review 체크리스트

### 프로젝트 고유성

- [ ] 마법학교 일상과 현장 책임이 함께 보인다.
- [ ] 직접 쓴 글자가 화면의 핵심 행동으로 보인다.
- [ ] 작은 정령 동반자와의 애착이 유지된다.
- [ ] generic dark fantasy·수집형 RPG UI로 보이지 않는다.

### 캐릭터 일관성

- [ ] SD·반신·전투 SD의 머리·색·의상 키가 동일하다.
- [ ] 메인 동반자와 보조 소환수가 크기·형태·역할로 구분된다.
- [ ] 핵심 인물만 반신 자산을 사용한다.

### 화면 가독성

- [ ] 첫 3초 안에 목표·대상·행동을 이해한다.
- [ ] 글자 획이 FX와 배경보다 선명하다.
- [ ] UI Panel이 월드를 과도하게 덮지 않는다.
- [ ] 결과 원인이 Reward 수치보다 먼저 보인다.

### 제작 가능성

- [ ] 학교·시험·축제는 공용 배경 상태 변형으로 처리된다.
- [ ] 필드·전투 SD의 디자인 체계를 재사용한다.
- [ ] Slice에 성장 4단계·다수 소환수·모든 NPC 반신이 들어가지 않는다.
- [ ] 새 화면마다 새 UI 프레임을 만들지 않는다.

## 15. 금지 사례

1. 잠긴 기준 이미지를 직접 편집한 파생본.
2. 이름·수치·파티 수·적 수를 이미지에서 읽어 게임 규칙으로 확정.

10. 결과를 숫자 보상 창에서 끝내고 원래 장소 변화를 보여 주지 않음.
