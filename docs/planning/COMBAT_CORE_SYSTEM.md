## 1. 플레이어 약속

> 플레이어는 마법 글자의 의미와 조합을 판단하는 마법사가 되어, 핵심 글자는 직접 쓰고 반복되는 보조는 소환수와 스톡에 맡기며 실시간으로 주문을 설계·발동한다.

전투의 차별점은 모든 글자를 매번 직접 그리는 노동이 아니라 다음 판단의 결합이다.

- 어떤 메인 글자를 사용할 것인가
- 어떤 보조 구조가 현재 문제에 적합한가
- 직접 작성·소환수 보조·스톡 중 무엇을 사용할 것인가
- 언제 주문을 완성하고 발동할 것인가
- 한정된 스톡과 소환수 지원을 어디에 사용할 것인가

## 2. 뾰족한 재미 후보

```text
상황을 읽는다
→ 핵심 마법 글자를 직접 쓴다
→ 소환수 보조 묶음으로 반복 구조를 빠르게 붙인다
→ 필요한 글자는 스톡으로 보완한다
→ 주문 결과가 즉시 변화한다
→ 더 좋은 조합과 운용법을 학습한다
```

직접 작성의 손맛, 조합 설계의 발견, 자동화 성장의 편리함을 한 전투 안에서 순환시키는 것이 핵심이다.

## 3. 전투 준비

전투 전에 다음을 준비한다.

1. 기본 소환수 1체
2. 소환수에게 장착할 보조 글자 묶음
3. 완성 주문 스톡
4. 하위 글자 스톡
5. 자동 충전 대상 1종
6. 필요하면 소환수 스탠스

```text
전투 준비
→ 소환수 선택
→ 보조 묶음 설정
→ 공용 준비 용량 안에서 스톡 편성
→ 자동 충전 대상 지정
→ 소환수 전개 상태로 전투 시작
```

## 4. 전투 중 네 가지 주문 운용 방식

### 4.1 메인 글자 단독 직접 시전

```text
메인 글자 작성
→ 기본 발현
```

- 가장 빠르고 마나·작성 부담이 낮다.
- 간단한 적 처리, 생활·환경 상호작용, 빠른 대응에 사용한다.
- 고학년에도 효율적인 선택으로 남긴다.

### 4.2 직접 작성 + 소환수 보조

```text
플레이어가 메인 글자 작성
→ 소환수 보조 묶음 호출
→ 준비된 보조 글자 자동 연결
→ 대상·기동 결정
```

- 일반적인 직접 시전의 기본형이다.
- 플레이어는 주문 목적과 핵심 판단을 담당한다.
- 반복 형상·전달·안정 구조는 소환수가 압축한다.

### 4.3 직접 작성 + 소환수 + 하위 글자 스톡

```text
메인·핵심 보조 직접 작성
→ 소환수 보조 묶음 연결
→ 상황 대응용 하위 글자 스톡 삽입
→ 최종 기동
```

- 기존 주문을 현장 상황에 맞게 빠르게 변형한다.
- 신규·상위 보조 글자는 플레이어가 직접 작성할 수 있다.
- 숙련 글자는 소환수와 스톡으로 압축한다.

### 4.4 완성 주문 스톡

```text
등록 주문 선택
→ 대상·방향 지정
→ 즉시 기동
```

- 강한 공격 예고, 반복 적 처리, 긴급 방어처럼 즉시 대응이 필요한 상황에 사용한다.
- 스톡이 없으면 직접 시전으로 같은 주문을 만들 수 있다.
- 완성 주문 스톡은 직접 작성의 대체가 아니라 준비와 판단의 보상이다.

## 5. 1학년 기본 전투

1학년부터 다음 세 축을 모두 사용한다.

```text
직접 작성
+
기본 소환수 1체와 보조 묶음
+
완성 주문·하위 글자 스톡
```

권장 학습 순서:

```text
메인 글자 단독 발동
→ 첫 보조 글자 직접 작성
→ 메인 1 + 보조 2 주문 완성
→ 기본 보조 글자 숙련
→ 소환수 보조 묶음 등록
→ 하위 글자 스톡 사용
→ 첫 완성 주문 스톡 사용
→ 현장실습에서 세 수단을 조합
```

스톡과 소환수 보조는 1학년 안에 열리며, 전체 학년을 직접 작성만 하는 튜토리얼로 사용하지 않는다.

## 6. 시스템 책임 경계

| 시스템 | 핵심 책임 | 사용 성격 |
|---|---|---|
| 직접 작성 | 발견·학습·핵심 판단·즉석 변형 | 마나 사용, 실시간 입력 |
| 소환수 보조 묶음 | 준비된 숙련 보조 조합의 재사용형 연결 | 호출형, 소환수 지원 제한 |
| 하위 글자 스톡 | 숙련 글자 하나의 소비형 즉시 삽입 | 공용 준비 용량·자동 충전 |
| 완성 주문 스톡 | 등록 주문 전체의 소비형 즉시 발동 | 공용 준비 용량·자동 충전 |
| 소환수 전투·수호 | 플레이어의 작성 시간 확보와 위험 완화 | 자동 행동·스탠스 |

## 7. 간결화 원칙

- 사용자가 현재 주문의 모든 보조 글자를 매번 직접 넣지 않게 한다.
- 자주 반복하는 형상·전달 묶음은 소환수에게 준비한다.
- 한 번만 필요한 상황 대응 글자는 하위 글자 스톡으로 넣는다.
- 긴급·반복 주문은 완성 주문 스톡으로 발동한다.
- 새로운 글자, 상위 조합, 중요한 변형은 플레이어가 직접 작성한다.
- 고학년의 `메인 1 + 보조 6`은 최대 설계 복잡도이지 매 시전 필수 입력량이 아니다.

## 8. 전투 Core Loop

```text
적 행동·환경 위험 인지
→ 사용할 메인 글자와 주문 방식 선택
→ 직접 작성 또는 스톡 기동
→ 필요하면 소환수 보조 호출
→ 주문 완성·발동
→ 피해·방어·상태·환경 변화 피드백
→ 마나·스톡·소환수 상태 갱신
→ 다음 위협과 조합 판단
```

## 9. DDD 보상 사다리

### Micro

- 글자 인식 성공
- 보조 묶음 자동 연결
- 주문 형태의 즉시 변화
- 정확 작성 피드백
- 타격·방어·환경 반응

### Session

- 주문 발견과 마도서 등록
- 보조 글자 숙련 상승
- 스톡 편성 개선
- 소환수 보조 묶음 확장
- 현장실습의 다른 해결법 발견

### Meta

- 메인 글자 레벨 상승과 전문화
- 보조 글자 달인화
- 학년별 보조 운용량 증가
- 새로운 계열 수업·실습·연구실 접근
- 소환수 성장과 진로·졸업 주문 형성

## 10. 실패·복구

- 글자 작성 실패 시 마나·시간 손실 후보를 두되 주문 전체 진행도를 과도하게 삭제하지 않는다.
- 소환수 보조 호환 실패 시 이유를 표시하고 직접 작성·스톡 대안을 유지한다.
- 스톡이 부족해도 직접 시전은 가능하다.
- 소환수가 행동 불능이어도 플레이어는 직접 작성과 스톡을 사용할 수 있다.
- 직접 피해로 스톡 충전이 일시 정지돼도 진행도는 보존한다.
- 패배 후에는 수업·편성·보조 묶음·스톡 구성을 수정해 재도전할 수 있게 한다.

## 11. CORE_POC에서 검증할 위험 가설

1. 메인 글자 직접 작성만으로도 플레이어가 주문의 주체라고 느끼는가.
2. 소환수 보조 묶음이 편리하지만 자동 전투처럼 느껴지지 않는가.
3. 소환수 보조와 하위 글자 스톡의 역할 차이를 즉시 이해하는가.
4. 1학년 `메인 1 + 보조 2` 주문이 충분한 조합 재미를 주는가.
5. 집중 모드에서 직접 작성·소환수 호출·스톡 사용이 모바일 화면에서 혼잡하지 않은가.
6. 짧은 기본 주문과 복잡한 주문이 모두 유효한 선택으로 남는가.
7. 소환수 지원이 없을 때도 전투가 불가능해지지 않는가.
