## 1. 플레이어 약속

> 플레이어는 마법 글자의 의미와 조합을 판단하는 마법사가 되어, 핵심 글자는 직접 쓰고 숙련된 반복 보조는 스톡으로 삽입하며, 소환수의 충전 지원을 지휘해 실시간으로 주문을 설계·발동한다.

전투의 차별점은 모든 글자를 매번 직접 그리는 노동이 아니라 다음 판단의 결합이다.

- 어떤 메인 글자를 사용할 것인가
- 어떤 보조 구조가 현재 문제에 적합한가
- 어떤 글자를 직접 작성하고 어떤 글자를 스톡으로 사용할 것인가
- 완성 주문 스톡을 언제 소비할 것인가
- 소환수의 전투·수호·생산 스탠스를 어떻게 운용할 것인가
- 자동 충전 대상을 언제 바꿀 것인가

## 2. 뾰족한 재미 후보

```text
상황을 읽는다
→ 핵심 마법 글자를 직접 쓴다
→ 숙련 보조 글자를 스톡으로 빠르게 붙인다
→ 소환수가 필요한 스톡을 계속 충전한다
→ 주문 결과가 즉시 변화한다
→ 더 좋은 조합·편성·충전 우선순위를 학습한다
```

직접 작성의 손맛, 조합 설계의 발견, 스톡 편성의 준비 전략과 소환수 운용을 한 전투 안에서 순환시키는 것이 핵심이다.

## 3. 전투 준비

전투 전에 다음을 준비한다.

1. 기본 소환수 1체
2. 완성 주문 스톡
3. 하위 글자 스톡
4. 자동 충전 대상 1종
5. 필요하면 소환수 스탠스

```text
전투 준비
→ 소환수 선택
→ 공용 준비 용량 안에서 스톡 편성
→ 자동 충전 대상 지정
→ 소환수 전개 상태로 전투 시작
```

소환수에게 보조 글자나 회로 묶음을 장착하지 않는다. 소환수의 주문 보조는 스톡의 충전·생산으로만 작동한다.

## 4. 전투 중 세 가지 주문 운용 방식

### 4.1 직접 시전

```text
메인 글자 작성
→ 필요한 보조 글자를 직접 작성
→ 연결·대상·기동 결정
```

- 새로운 글자·미숙 글자·즉석 변형을 사용할 수 있다.
- 메인 단독 주문은 가장 빠르고 마나·작성 부담이 낮다.
- 고학년에도 짧고 효율적인 주문은 계속 유효하다.

### 4.2 직접 작성 + 하위 글자 스톡

```text
플레이어가 메인 글자·핵심 보조 작성
→ 숙련 보조 글자 스톡 터치
→ 글자 자동 배치·연결
→ 필요하면 추가 작성
→ 최종 기동
```

- 일반적인 복합 직접 시전의 기본형이다.
- 자주 반복하는 형상·전달·안정 글자를 매번 직접 넣지 않아도 된다.
- 상황에 맞춰 어떤 하위 글자 스톡을 넣을지 플레이어가 결정한다.
- 신규·상위 보조 글자는 플레이어가 직접 작성한다.

### 4.3 완성 주문 스톡

```text
등록 주문 선택
→ 대상·방향 지정
→ 즉시 기동
```

- 강한 공격 예고, 반복 적 처리, 긴급 방어처럼 즉시 대응이 필요한 상황에 사용한다.
- 스톡이 없으면 직접 시전으로 같은 주문을 만들 수 있다.
- 완성 주문 스톡은 직접 작성의 대체가 아니라 준비와 판단의 보상이다.

## 5. 소환수의 전투 역할

```text
전투
→ 적 공격·방해

수호
→ 플레이어의 작성 시간 확보

생산
→ 지정 스톡 충전 속도·생산 효율 강화

동조
→ 정확 작성·방어·연계로 얻는 능동 충전 보너스 강화
```

- 소환수는 회로판에 글자·선·연결을 직접 작성하지 않는다.
- 소환수는 하위 글자 스톡과 완성 주문 스톡을 더 빨리 충전해 간접적으로 주문을 보조한다.
- 소환수는 플레이어 허가 없이 충전 대상을 변경하지 않는다.
- 소환수가 행동 불능이어도 플레이어의 직접 시전과 이미 준비된 스톡은 유지된다.

## 6. 1학년 기본 전투

1학년부터 다음 세 축을 모두 사용한다.

```text
직접 작성
+
완성 주문·하위 글자 스톡
+
기본 소환수 1체의 전투·수호·스톡 충전 지원
```

권장 학습 순서:

```text
메인 글자 단독 발동
→ 첫 보조 글자 직접 작성
→ 메인 1 + 보조 2 주문 완성
→ 기본 보조 글자 숙련
→ 첫 하위 글자 스톡 편성·사용
→ 소환수 생산 스탠스로 지정 스톡 충전
→ 첫 완성 주문 스톡 사용
→ 현장실습에서 직접 작성·스톡·소환수를 조합
```

- 완성 주문 스톡과 하위 글자 스톡은 1학년부터 사용할 수 있다.
- 첫 학기 안에 직접 작성·스톡·소환수 충전 지원을 모두 경험하게 한다.
- 1학년 전체를 직접 작성만 하는 긴 튜토리얼로 사용하지 않는다.

## 7. 시스템 책임 경계

| 시스템 | 핵심 책임 | 사용 성격 |
|---|---|---|
| 직접 작성 | 발견·학습·핵심 판단·즉석 변형 | 마나 사용, 실시간 입력 |
| 하위 글자 스톡 | 숙련 글자 하나의 소비형 즉시 삽입 | 공용 준비 용량·자동 충전 |
| 완성 주문 스톡 | 등록 주문 전체의 소비형 즉시 발동 | 공용 준비 용량·자동 충전 |
| 소환수 전투·수호 | 플레이어의 작성 시간 확보와 위험 완화 | 자동 행동·스탠스 |
| 소환수 생산·동조 | 지정 스톡 충전과 능동 충전 보너스 강화 | 플레이어가 충전 대상 지정 |

## 8. 간결화 원칙

- 사용자가 현재 주문의 모든 보조 글자를 매번 직접 넣지 않게 한다.
- 자주 반복하는 숙련 보조 글자는 하위 글자 스톡으로 넣는다.
- 긴급·반복 주문은 완성 주문 스톡으로 발동한다.
- 소환수는 이 스톡들을 더 빠르게 충전한다.
- 새로운 글자, 상위 조합, 중요한 변형은 플레이어가 직접 작성한다.
- 고학년의 `메인 1 + 보조 6`은 최대 설계 복잡도이지 매 시전 필수 입력량이 아니다.
- 스톡의 사용 시점·대상·삽입 순서는 플레이어가 결정한다.

## 9. 전투 Core Loop

```text
적 행동·환경 위험 인지
→ 사용할 메인 글자와 주문 방식 선택
→ 직접 작성 또는 완성 주문 스톡 기동
→ 필요하면 하위 글자 스톡 삽입
→ 주문 완성·발동
→ 피해·방어·상태·환경 변화 피드백
→ 소환수 행동·마나·스톡 충전 상태 갱신
→ 충전 대상과 다음 조합 판단
```

## 10. DDD 보상 사다리

### Micro

- 글자 인식 성공
- 하위 글자 스톡 즉시 삽입
- 주문 형태의 즉시 변화
- 정확 작성 피드백
- 타격·방어·환경 반응
- 스톡 충전 완료 알림

### Session

- 주문 발견과 마도서 등록
- 보조 글자 숙련 상승
- 스톡 편성과 충전 우선순위 개선
- 소환수 생산·수호 운용 숙련
- 현장실습의 다른 해결법 발견

### Meta

- 메인 글자 레벨 상승과 전문화
- 보조 글자 달인화
- 학년별 보조 운용량 증가
- 전체 스톡 준비 용량과 생산 능력 성장
- 새로운 계열 수업·실습·연구실 접근
- 소환수 성장과 진로·졸업 주문 형성

## 11. 실패·복구

- 글자 작성 실패 시 마나·시간 손실 후보를 두되 주문 전체 진행도를 과도하게 삭제하지 않는다.
- 하위 글자 스톡이 부족하면 해당 글자를 직접 작성할 수 있다.
- 스톡이 부족해도 직접 시전은 가능하다.
- 소환수가 행동 불능이어도 직접 시전과 이미 준비된 스톡을 사용할 수 있다.
- 직접 피해로 스톡 충전이 일시 정지돼도 진행도는 보존한다.
- 패배 후에는 수업·스톡 편성·충전 대상·소환수 스탠스를 수정해 재도전할 수 있게 한다.

## 12. CORE_POC에서 검증할 위험 가설

1. 메인 글자와 핵심 보조 직접 작성만으로도 플레이어가 주문의 주체라고 느끼는가.
2. 하위 글자 스톡이 편리하지만 조합 설계의 의미를 제거하지 않는가.
3. 하위 글자 스톡과 완성 주문 스톡의 역할 차이를 즉시 이해하는가.
4. 소환수의 생산 지원이 체감되지만 단순 대기 보너스로만 느껴지지 않는가.
5. 1학년 `메인 1 + 보조 2` 주문이 충분한 조합 재미를 주는가.
6. 집중 모드에서 직접 작성과 스톡 사용이 모바일 화면에서 혼잡하지 않은가.
7. 짧은 기본 주문과 복잡한 주문이 모두 유효한 선택으로 남는가.
8. 소환수 지원이 없어도 전투가 불가능해지지 않는가.
